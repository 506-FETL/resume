# 代码审查技能使用指引

本规则用于判断何时启用 [code-review-skill](../skills/code-review-skill/SKILL.md)，不要求每个任务都执行完整代码审查。

## 适用时机

- 用户明确要求 CR、Code Review、代码审查、PR 审查或检查代码中的问题时，必须读取并使用该技能。
- 需要审查重要业务逻辑、权限与数据安全、异步并发、性能或架构变更时，按实际范围使用该技能及其对应参考指南。
- 完成重要功能或重构、准备提交或合并且需要审查时，可使用该技能检查实现结果。
- 纯文案、格式调整、简单查询等无需审查的任务，不自动扩展为全项目审查。

## 执行方式

1. 先读取 `.agents/skills/code-review-skill/SKILL.md`，再按技术栈查阅其中的 React、TypeScript、安全、性能等相关指南。
2. 明确审查基线与范围：PR、指定提交、工作区改动或当前项目代码；用户未限定为 diff 时，不擅自缩减为未提交改动。遵守用户指定的排除项。
3. 先了解业务入口、状态管理和数据调用链，再检查逻辑正确性、边界条件、权限、数据一致性、错误处理与性能。遵循 `AGENTS.md` 中的仓库约定。
4. 结合调用方、服务端约束和已有工具验证疑点；优先运行与问题相关的现有检查。不得仅凭代码风格、缺少测试或未经验证的假设判定业务缺陷。
5. 只提出有证据、可行动的问题，说明触发条件、实际影响和修复方向，并提供准确的文件位置。

## 输出与边界

- 使用简体中文，按严重程度排列问题：`[blocking]` 必须修复、`[important]` 建议修复、`[nit]` 可选建议；必要时附上 P1/P2/P3 优先级。
- 先给出审查发现，再说明覆盖范围、验证结果与未验证部分。没有发现问题时如实说明，不等同于保证没有缺陷。
- 代码审查本身不授权修改业务代码；未经用户要求，不顺手修复、重构、格式化或覆盖已有改动。
- 不因执行审查而自动提交、推送或部署。是否实施修复及其后续操作遵循用户授权和仓库规则。
