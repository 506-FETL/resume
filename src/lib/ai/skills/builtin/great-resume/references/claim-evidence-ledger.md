# 主张与证据清单

本参考帮助简历提升在对话中保留事实来源、个人边界和确认状态。它不是数据库、文件账本或评分系统；请将清单写在当前对话的分析和交付中，不创建或要求用户上传本地 JSON 文件。

## 何时使用

出现任一情况时，整理或更新对话内事实清单：

- 同一经历需要适配多个岗位；
- 材料的时间、GPA、指标、职责或成果存在冲突；
- 出现「主导、负责人、Owner、从 0 到 1、核心作者」等强主张；
- 用户希望准备面试追问或复盘投递材料；
- 需要把公开链接、用户提供的截图说明或简历事实用于后续改写。

只生成一句开场白且材料清楚时，不必创建完整清单。

## 每条主张应包含

| 项目         | 内容                                                       |
| ------------ | ---------------------------------------------------------- |
| 原始事实     | 用户原话或已读取简历中的事实，不做包装                     |
| 建议写法     | 可用于简历或沟通的候选表达                                 |
| 证据         | 证据类型与定位，例如已读取的简历模块、用户确认或公开链接   |
| 责任边界     | 参与、负责模块、主导方案或交付、项目负责人；并说明团队分工 |
| 确认状态     | 已确认、待确认、已过期或不采用                             |
| 适用范围     | 目标岗位或材料类型                                         |
| 面试细节     | 可展开的决策、难点、验证和结果                             |
| 风险或待补项 | 冲突、缺口或定稿前要解决的问题                             |

证据只记录定位所需信息。不要复制密码、验证码、邮件全文、内部代码、客户数据或其他敏感内容。

## 状态规则

- **已确认**：用户明确确认，或用户提供的材料足以支持。可以进入正式简历，但仍需保留个人边界。
- **待确认**：存在冲突、证据不足或用户未确认。只能出现在审计稿和待补清单；正式简历中不得作为事实。
- **已过期**：会随时间变化，例如当前年级、论文状态或岗位。更新前不得当作最新事实。
- **不采用**：不准确、无关或用户不希望公开。保留原因供本轮对话参考，但不用于对外材料。

## 冲突与交付检查

同一事实有多个版本时，不选择更有利的版本。说明冲突来源，标记为「待确认」，请用户确认唯一可用版本。

交付前检查：每个强主张都能回到一项原始事实或证据；团队成果没有自动变成个人成果；指标包含时间、口径和范围；改写没有篡改原始事实。
