# 简历模板维护手册

适用版本：2026-10-21，默认模板第一期。设计背景见 `superpowers/specs/2026-10-21-resume-template-architecture-design.md`，执行记录见 `superpowers/plans/2026-10-21-resume-template-foundation-validation.md`。

## 1. 当前交付范围

模板库只提供 `default@1`，沿用项目原有单栏样式。用户可直接使用应届生示例，或在预览弹窗选择社招前端示例，再创建完整简历并进入已有编辑器。快速创建也使用默认模板和应届生示例，保留名称、描述和既有存储模式。

模板配置保存在前端；没有模板数据库读取、模板发布后台、第二套模板或用户自定义设计工作台。旧工作台前端已移除，数据库旧模板记录保留。普通简历内容仍按原本的本地或云端方式保存。

## 2. 代码边界

| 职责 | 位置 | 维护原则 |
| --- | --- | --- |
| 配置协议 | `src/lib/resume-template/definition-schema.ts` | Zod 严格白名单，引用明确能力版本 |
| 模板定义 | `src/lib/resume-template/definitions/default/v1.ts` | 唯一 `default@1` 定义，不放正文或业务逻辑 |
| 目录元数据 | `src/lib/resume-template/catalog/default.ts` | 名称、说明、当前版本、可选示例 |
| 示例内容 | `src/lib/resume-template/examples/` | 独立版本，使用现有正文 schema 和虚构信息 |
| 数据源装配 | `src/lib/resume-template/source/index.ts` | 对外导出 `resumeTemplateSource`，当前指向本地实现 |
| 本地版本索引 | `src/lib/resume-template/source/local.ts` | 按精确 ID / 版本读取，返回深复制数据 |
| 内容映射 | `src/lib/resume-template/content/` | 教育、工作等映射到内容类型，保留字段身份 |
| 布局和视觉部件 | `src/components/resume/template-layouts/`、`template-parts/` | 按视觉能力组织，版本化目录 |
| 能力注册 | `src/lib/resume-template/registry/visual-components.tsx` | 仅引用受支持的编译期组件 |
| 公共字段 | `src/components/resume/fields/` | 复用评论投影和富文本净化 |
| 运行时与分页 | `src/components/resume/runtime/`、`pagination/` | 只读渲染，统一布局签名与导出门禁 |
| 加载缓存 | `src/store/resume-template/` | 目录、定义、示例分开加载，精确 key 去重 |
| 创建操作 | `src/lib/resume-template/create/`、`src/store/resume-creation/` | 一次准备、完整插入、同一操作重试 |
| 模板页面 | `src/pages/template/` | 页面 store 只保存预览目标与示例选择 |
| 旧数据兼容 | `src/lib/resume-template/compatibility/` | 只读适配，不批量改写旧记录 |

一份模板是一个完整的布局和样式组合。教育、工作、实习等经历共用模板选择的经历部件；同一份模板的模块标题共用一个标题部件。增加条目时只增加业务数据，自然使用当前部件，不生成另一份模块设计。

配置、正文、目录和示例互相独立。示例只在新建时复制，打开、刷新、分享、历史恢复或协作时不再播种。`visibility` 的既有语义是 **true 表示隐藏**。

## 3. 默认配置如何工作

`default@1` 指向 `single-column@1` 布局、`centered-profile@1` 页头、`underline-heading@1` 标题、`plain-entry-list@1` 经历列表，以及富文本、技能、字段列表和标签的通用部件。模块排序和隐藏来自简历正文；外观取当前快照的字体、颜色、间距，创建时才使用模板默认外观。

新简历保存 `{ source: 'official', templateId: 'default', templateVersion: 1 }`。旧简历的缺省绑定、旧 official / user / community 绑定只在读取时映射为默认模板；明确指定的新版本不存在或配置无效时显示错误，不偷偷替换为默认模板。

默认布局保留旧实现的隐藏模块占位间距，以保持默认几何基线。标题和带边框标签标记 `data-pagination-atomic`，分页不能从其内部截断；超大原子元素无法放入一页时应明确失败，不能放宽字体或布局签名校验来强行导出。

## 4. 后续新增模板

### 4.1 已有能力可以组合出的设计

1. 新建 `definitions/<template-id>/v1.ts`，使用 `parseTemplateDefinition` 校验完整配置。
2. 新建对应目录项，指定展示名、说明、当前版本和示例引用。
3. 在本地 Source 注册定义与目录。需要新的示例时增加独立的版本化示例，并在 `src/pages/template/const.ts` 补充展示名称。
4. 通过字段覆盖、评论投影、分页、分享和导出验收后再加入正式目录。

无需复制表单、简历 store、协作、评论、分享页面或导出服务。首期协议只接受已实现的默认视觉能力，因此不能仅填写一个尚未注册的布局名称就期望它工作。

### 4.2 需要新视觉能力的设计

以绿色时间轴为后续示例：若现有部件无法表达，新增时间轴经历部件、带图标的章节标题部件和对应页头；如果整体区域布局也改变，再新增布局部件。教育、工作和实习继续复用同一个时间轴经历部件以及现有内容映射，不分别复制业务 Renderer。

先扩展 `definition-schema.ts` 的受支持组件联合及必要参数，再注册组件。参数传递必须类型化，不能增加任意 JavaScript、任意组件路径、任意 HTML 模板执行或不受约束的 CSS。新增能力应消费已有 `ContentField` / `ExperienceContent` 等类型，使用公共评论字段渲染正文，装饰文字和图标放在评论字段外。

图标、章节号、圆点、卡片装饰都属于呈现；`entryId`、字段键、评论 `nodeKey`、富文本 fragment 和正文顺序仍属于业务数据。新增任何视觉能力不得重建这些身份。

首期分享序列化器明确只支持 `default@1`。开放第二套模板或新版本前，必须扩展 `compatibility/share-manifest.ts` 的发布兼容协议和验证样本；不能仅新增目录就宣称新模板完整可用。该限制会显式报错。

### 4.3 大量模板的维护规模

大多数模板维护的是小型配置、目录元数据和静态资源。React 源码只随新的视觉能力增加。现有能力不能表达的设计需要实现新能力，配置不能凭空产生布局。后续远端目录应按需加载版本及资源，避免把上千份模板和预览资源一次打入首屏。

## 5. 版本更新、下架和回滚

| 变更 | 做法 | 已有简历 |
| --- | --- | --- |
| 名称、说明 | 修改目录元数据 | 正文和绑定不变 |
| 示例文案 | 新示例版本，更新目录引用 | 已创建正文不变 |
| 模板外观 | 新模板版本，如 `default@2` | 保留 `default@1` |
| 公共部件视觉行为改变 | 新能力版本并由新定义引用 | 旧模板继续使用旧能力 |
| 下架推荐 | 从可选目录撤回，保留版本和资源 | 仍可解析原引用 |
| 新版本回滚 | 目录恢复推荐稳定版本 | 不自动改写已经绑定新版本的简历 |

不要原地覆盖已发布定义。模板版本、配置协议版本和组件能力版本是不同维度。首次发布前的实现修正不等于对外发布后的版本覆盖；非视觉、安全或稳定性修复也必须复查默认几何、分页及评论基线。

将来开放主动升级时：所有者预览候选版本，确认后通过服务端权威校验同步模板字段；升级不以旧正文快照覆盖协作期间的新编辑。权限、冲突和事务规则属于第二期必做能力，首期没有升级按钮，也不声称现有 setter 已提供所有者权限保证。

## 6. 协作、评论、分享与导出约束

- 正文继续使用既有 Zustand / Automerge / 富文本同步链路。只读内容映射不写回正文，不为切换预览重新创建协作文档。
- 新建示例时统一生成新条目 ID；重试复用准备好的快照。读取旧简历、手动上传、历史恢复、派生和分享不得重新分配条目身份。
- 历史预览、历史 PDF 和发布分享使用各自快照的外观与评论参考日期，不能读取当前编辑器的全局外观。
- 分享冻结正文与精确模板 definition。旧信封先校验再适配；新信封即使 `definition` 为 null 也必须拒绝，不能降级走旧协议。公开正文继续删除隐藏内容和内部模板绑定。
- PDF 必须等模板、字体、分页及打印布局签名一致；本期仍用浏览器打印生成 PDF。Word 保持现有 HTML `.doc` 导出，允许简化排版，不能标为 DOCX。
- 评论定位继续使用现有字段投影、块序号和可见页根节点；测量源、隐藏分页副本、示例预览不能成为真实简历的评论目标。

## 7. 创建失败如何处理

创建操作固定模式、操作 UUID、云端所有者和完整快照。保存前按 ID 查询；写入响应丢失时再次查询同一 ID，找到就确认成功，查询失败就保留待确认状态。不使用 upsert 覆盖用户后来编辑的正文，不因登录失效转为本地创建。

连击复用进行中的 Promise。关闭弹窗不丢弃结果未确认的操作；重试继续原操作。首期只保证当前页面会话内的重试，没有刷新后的创建事务恢复能力，也不把正文复制到 localStorage。

## 8. 将来迁移远端配置

新增实现相同 `TemplateSource` 接口的远端 Provider，在 `source/index.ts` 更换装配。资源缓存、创建与分享均消费这个入口。旧分享兼容层仍固定引用本地 `default@1`，不通过网络猜测旧版本。

后续服务需要目录摘要、不可变版本、配置校验、配置哈希、版本化字体和图片、访问控制、缓存及失败策略；首期没有实现这些服务。先发布支持新组件的前端，再发布引用该能力的配置。远端请求失败不能解释为版本不存在，更不能静默采用当前最新版本。

保留 `templateId` / `templateVersion` 和示例 ID / 版本，避免迁移用户正文。旧私有模板表不直接充当官方模板目录。远端模板可存储 JSON 数据和资源地址，不承载可执行代码。

## 9. 发布前验证

执行 `pnpm verify:templates`、两个 TypeScript 配置检查、变更文件 ESLint、`pnpm build` 和 `git diff --check`。固定样本在 `scripts/fixtures/resume-template/`；不得通过改写评论基线掩盖身份变化。

实际浏览器覆盖：新旧绑定、两份示例、本地与云端创建及重试、两人协作、评论选区与回复解决、旧新分享及口令、历史恢复与派生、长短 PDF、Word、移动端和减少动效。弹窗至少两轮完整开关及退出中重开。

验收结论分清协议脚本、浏览器实测、源码核对和受环境限制未验证的项目。具体本期结果和遗留限制以执行记录为准。
