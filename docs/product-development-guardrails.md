# 产品开发防回归清单

更新日期：2026-10-25。适用所有后续分期开发。

本清单来自当前会话、仓库 `AGENTS.md` 和已有规格、计划、验收复盘。它是可追溯的持久规则，不代表已经读取所有历史聊天。后续发现新问题时补充“触发场景、根因、约束、验收方式”，避免只记住一次性的修复。

## 1. 分期与产品承诺

- 按已授权的期次完成实现和验证，最后交用户审查。已明确授权的范围不重复索要批准；重大范围变化或无法取得的外部权限才请求用户介入。
- 用户未要求下一期时，不自动进入下一期。实施状态、验证状态、用户审查状态分别记录。
- 不提供点击无结果、上传无后续、升级未开放却仍可点击的假功能。状态未知、加载中、失败与真正空数据明确区分。
- 评分名称与依据相符，不把关键词比例包装成概率或行业样本结果；AI 不编造经历、数字或招聘效果。
- 开始前阅读涉及模块的历史资料，选择必要回归项；存在冲突时以最新用户明确要求为准并更新文档。

## 2. UI、布局与交互

- 沿用现有 PageLayout、PageHeader、表单、空态和反馈组件；优先调整任务层级与内容密度，不无关更换字体、颜色或导航体系。
- 验证桌面、窄屏、长标题、空内容和错误消息。容器可收缩，长内容不能撑出水平溢出；同组信息对齐，主动作清晰。
- 各模块独立使用真实加载依赖；已有内容在重取时尽量保留，错误提供重试。不能以跨模块共享 loading 或 Promise.all 阻塞无关模块。
- 异步完成、自动回填与远端更新不抢焦点、不打断输入。关闭弹窗和折叠内容后焦点回到有效触发点，退出内容不参与点击和键盘导航。
- 每个 DialogContent 都有 DialogDescription；Radix 与 Base UI 使用各自状态属性，不能照搬选择器。

## 3. 动效

- 使用 `src/lib/motion.ts` 的 EASE、DURATION、SPRING 和已有 variants；新增动效全部接入 `useReducedMotion()`，减少动效时归零时长或去掉位移、缩放。
- 覆盖进入、退出、重复操作与快速反向切换，不能以首次挂载成功代替完整验收。
- 弹窗至少两轮完整打开/关闭，加一轮退出中再次打开。共享 Dialog 动画变化同时检查遮罩、内容和创建简历、创建分享、简历优化三个代表入口。
- 折叠使用仓库既有动画及 overflow-hidden，退出短于进入。避免用延时或重复 remount 掩盖生命周期问题。
- 在 AnimatedContent 或带 key 的过渡容器中重挂载 variants 子项时，必须由同一新子树的显式 initial/animate 驱动，不能等待外层已经完成的动画再次触发。验收要检查实际 opacity 与可见性，DOM 中存在文本不代表用户看得见。

## 4. 数据、账户与异步任务

- 请求、缓存和 finally 都受账户/目标/操作版本约束；旧账户响应不能覆盖新账户，登出清理相关状态。
- 简历切换、模板切换、离开编辑器的保存捕获目标 ID 与快照；实际成功前不标记“已保存”，迟到响应不覆盖新编辑。
- 本地同步只移除成功项，失败项保留并可重试。上传新头像与更新引用成功后再清理旧资源。
- 历史比较、恢复、投递快照保持正文、外观和精确模板绑定一致。JD 改写核验目标条目、原文与可写字段，未知路径不能静默成功。
- 助手停止、重试和编辑消息必须尊重持久历史与取消状态，不能在取消后继续写入。

来源：[业务复盘](superpowers/specs/2026-10-13-business-review-fixes-design.md)、[看板账户隔离](superpowers/specs/2026-10-15-tracker-account-isolation-design.md)。

## 5. 分享、评论与协作

- current 分享随已保存内容更新，history 分享固定快照；正式投递与持续审阅使用明确语义，不能偷偷改变已有链接契约。
- 隐藏模块与条目在服务端公开投影中也要过滤。分享权限、有效期和密码变更应真实生效。
- 协作需要有效授权；评论绑定真实文段和版本。无法唯一重连时保留待处理状态，不错误附到另一段原文。
- 评论分页按实际返回事件推进游标；通知只是提示，断线要补齐。订阅销毁后不复活，不对同 topic 重复断连。

来源：[当前分享约定](superpowers/specs/2026-10-24-live-current-share-design.md)、[业务复盘](superpowers/specs/2026-10-13-business-review-fixes-design.md)。

## 6. 性能与模板资源

- 模板目录只加载摘要和必要静态图；按可见范围、打开详情与用户意图加载资源，不能每张卡片都启动完整分页引擎。
- 复用请求、缓存和并发限制；测量稳定前保留已有展示，避免文档突然缩成一页导致滚动跳动。
- 已发布模板与素材保持精确版本与不可变引用；缺少指定资源明确报错，不静默降级成其他模板。
- 优化前定位真实瓶颈，比较加载、交互和内存表现。不能以删掉验证、内容或降级正确性来制造“变快”。

来源：[模板页性能](superpowers/specs/2026-10-24-template-page-performance-design.md)、[模板加载](superpowers/specs/2026-10-23-template-gallery-loading-design.md)、[模板维护](resume-template-maintenance.md)。

## 7. 分页与导出

- 测量、展示、打印正文几何和字体一致；装饰不占正文布局。不放宽布局签名来掩盖差异。
- 所有模板复用 print-color-adjust；打印背景开和关都要验证。
- 触及模板、公共打印或分页时，覆盖短内容、临界页底、多页长内容、默认模板，并通过真实导出检查 PDF 的文本、样式与分页。
- Word 独立核对实际排版；构建与协议校验不替代真实文件验收。

详细依据：[模板维护手册](resume-template-maintenance.md)第 10 节“导出问题复盘与回归要求”。

## 8. 代码与交付

- 在当前分支工作，保护已有未提交修改；没有明确要求不 push。中文提交信息遵循仓库格式。
- 页面创建或重构遵循 history-style 结构，组件用文件夹 index.tsx；页面共享状态与动作放 store，避免多级 props。
- 全局与复杂状态用 Zustand，组件子树 UI 状态才用 Context，临时单组件状态用 useState；不要为简单局部状态增加全局耦合。
- 按职责留空行，遵循两空格、单引号、无分号；改动文件先 Prettier 再 ESLint layout 修复，格式调整不得夹带逻辑变化。
- 不强制 TDD，不创建只复述实现的测试。需要的临时验证和夹具统一放 tests/，结束删除；scripts/ 不放验收脚本。
- 根据变更执行必要类型、lint、构建和产品流程验证，记录实际结果与限制。没有最新证据不能声称已完成。
- 涉及 Supabase 迁移或 Edge Functions 时，开发与隔离验证后完成当前链接项目的部署、账本、函数版本与线上 smoke；只有确实缺少权限或凭据才请求用户介入。

## 9. 文案与沟通

一期审查中，用户指出文案像 AI 生成的，读起来不自然。问题包括首页堆叠“下一次机会”“从真实经历开始”等口号，把内部分析术语写进页面，以及反复强调真实性，让普通操作提示像一份规范。

- 标题说清页面或任务，按钮说清点击后的动作。例如“继续编辑简历”，不用“继续打磨你的下一次机会”。
- 说明写用户当下需要知道的内容。例如“暂时不能购买额外额度”，不用“尚未提供付费扩容”。能删掉而不影响理解的口号、重复标题和套话直接删掉。
- 建议落到具体内容。例如“补充你负责哪部分、做了什么”，不用“强化能力证据、完善内容画像”。确实需要专业术语时，用一句话解释它指什么。
- 用正常、克制的中文，不为了显得亲切加入语气词、网络用语或刻意鼓励。不要把所有提示都写成三段排比，也不要用“不是……而是……”反复说教。
- 简短不等于省略事实。文件支持范围、数据保存位置、额度状态和评分依据仍需说明；AI 提示保留不编造、不清楚先问、由用户确认事实的要求。
- 文档和日常回复也遵守这些要求。先讲结果或问题，再讲必要细节，不用一串流程术语代替说明。

验收时先在实际页面按标题、说明、按钮、状态提示的顺序通读：是否像正常中文，是否知道下一步能做什么，有没有重复或无关的劝导。再检查桌面和窄屏的换行、按钮宽度、空态与错误态；不能只靠关键词扫描判断文案是否合格。
