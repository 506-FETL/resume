# 产品开发防回归清单

更新日期：2026-10-25。适用所有后续分期开发。

本清单来自当前会话、仓库 `AGENTS.md` 和已有规格、计划、验收复盘。它是可追溯的持久规则，不代表已经读取所有历史聊天。后续发现新问题时补充“触发场景、根因、约束、验收方式”，避免只记住一次性的修复。

## 1. 分期与产品承诺

- 按已授权的期次完成实现和验证，最后交用户审查。已明确授权的范围不重复索要批准；重大范围变化或无法取得的外部权限才请求用户介入。
- 用户未要求下一期时，不自动进入下一期。实施状态、验证状态、用户审查状态分别记录。
- 不提供点击无结果、上传无后续、升级未开放却仍可点击的假功能。状态未知、加载中、失败与真正空数据明确区分。
- 评分名称与依据相符，不把关键词比例包装成概率或行业样本结果；AI 不编造经历、数字或招聘效果。
- 开始前阅读涉及模块的历史资料，选择必要回归项；存在冲突时以最新用户明确要求为准并更新文档。

## 2. UI、布局与交互

- 组件必须先复用：项目已有的 shadcn/ui、Magic UI 与封装 → 官方组件或 registry → 成熟的 shadcn 风格组件 → 确实不适用才自建。先查再写，业务组件通过组合实现，不用原生下拉框、手写弹层或按钮重复已有能力。自建原因记录在计划中，并保持当前 shadcn 的视觉、键盘、焦点和禁用行为。普通语义布局与隐藏文件输入无需多余封装。
- 交付检查覆盖本次新增/修改的交互控件，不能仅凭“引入过 shadcn”认定符合规范。此次填写建议和导入核对都绕过了已有 Select，导致原生下拉框风格不一致；回归检查选择、方向键、Escape、滚动、禁用状态和关闭后的焦点。
- 沿用现有 PageLayout、PageHeader、表单、空态和反馈组件；优先调整任务层级与内容密度，不无关更换字体、颜色或导航体系。
- 验证桌面、窄屏、长标题、空内容和错误消息。容器可收缩，长内容不能撑出水平溢出；同组信息对齐，主动作清晰。
- 会话列表等行内操作覆盖长标题时，遮罩必须覆盖整组按钮及间距，并使用半透明背景、背景模糊和边缘渐隐；仅渐变透明会让文字穿过图标。检查选中/未选中、悬停与键盘聚焦。
- 各模块独立使用真实加载依赖；已有内容在重取时尽量保留，错误提供重试。不能以跨模块共享 loading 或 Promise.all 阻塞无关模块。
- 异步完成、自动回填与远端更新不抢焦点、不打断输入。关闭弹窗和折叠内容后焦点回到有效触发点，退出内容不参与点击和键盘导航。
- 聚焦节点不能先被 aria-hidden 或 inert。抽屉、确认框要在内容节点实际就绪时交接焦点，记录并恢复入口；Portal 延迟挂载时，父组件 effect 不保证早于背景隐藏。入口已移除或只是 body/documentElement 时回到有效的备用控件。
- 无障碍回归同时检查浏览器 warning 和焦点，不只检查 pageerror。覆盖鼠标、键盘、取消、确认后节点移动和快速关闭；不得通过删除 aria-hidden 或屏蔽日志掩盖问题。
- 每个 DialogContent 都有 DialogDescription；Radix 与 Base UI 使用各自状态属性，不能照搬选择器。

## 3. 动效

- 简历检查的原文定位高亮使用现有 Magic UI `Highlighter`，设置 `action="highlight"`，不叠加圆角色块、文字变色或下划线。按用户 2026-10-25 的明确要求，这一处设置 `animate={true}`，即使开启减少动效也保留一次荧光笔划过动画；该例外不扩展到其他交互，组件未指定 `animate` 时仍遵循系统偏好。
- 使用 `src/lib/motion.ts` 的 EASE、DURATION、SPRING 和已有 variants；新增动效全部接入 `useReducedMotion()`。除用户明确指定的上述高亮例外，减少动效时归零时长或去掉位移、缩放。
- 覆盖进入、退出、重复操作与快速反向切换，不能以首次挂载成功代替完整验收。
- 弹窗至少两轮完整打开/关闭，加一轮退出中再次打开。共享 Dialog 动画变化同时检查遮罩、内容和创建简历、创建分享、简历优化三个代表入口。
- 折叠使用仓库既有动画及 overflow-hidden，退出短于进入。避免用延时或重复 remount 掩盖生命周期问题。
- Tab 切换让选中指示条连续移动，内容容器保持稳定。退出面板禁用交互前先将焦点移到目标 Tab，不能假设 pointer down 已完成默认聚焦；保留语义、方向键操作和切换时的草稿保存，减少动效时归零。
- 在 AnimatedContent 或带 key 的过渡容器中重挂载 variants 子项时，必须由同一新子树的显式 initial/animate 驱动，不能等待外层已经完成的动画再次触发。验收要检查实际 opacity 与可见性，DOM 中存在文本不代表用户看得见。

## 4. 数据、账户与异步任务

- 请求、缓存和 finally 都受账户/目标/操作版本约束；旧账户响应不能覆盖新账户，登出清理相关状态。
- 简历切换、模板切换、离开编辑器的保存捕获目标 ID 与快照；实际成功前不标记“已保存”，迟到响应不覆盖新编辑。
- 本地同步只移除成功项，失败项保留并可重试。上传新头像与更新引用成功后再清理旧资源。
- 历史比较、恢复、投递快照保持正文、外观和精确模板绑定一致。JD 改写核验目标条目、原文与可写字段，未知路径不能静默成功。
- 助手停止、重试和编辑消息必须尊重持久历史与取消状态，不能在取消后继续写入。

来源：[业务复盘](superpowers/specs/2026-10-13-business-review-fixes-design.md)、[看板账户隔离](superpowers/specs/2026-10-15-tracker-account-isolation-design.md)。

## 5. 分享、评论与协作

- current 分享随已保存内容更新，history 分享固定快照；正式投递与持续审阅使用明确语义，不能偷偷改变已有链接契约。
- 隐藏模块与条目在服务端公开投影中也要过滤。分享权限、有效期和密码变更应真实生效。
- 协作需要有效授权；评论绑定真实文段和版本。无法唯一重连时保留待处理状态，不错误附到另一段原文。
- 评论分页按实际返回事件推进游标；通知只是提示，断线要补齐。订阅销毁后不复活，不对同 topic 重复断连。

来源：[当前分享约定](superpowers/specs/2026-10-24-live-current-share-design.md)、[业务复盘](superpowers/specs/2026-10-13-business-review-fixes-design.md)。

## 6. 性能与模板资源

- 模板目录只加载摘要和必要静态图；按可见范围、打开详情与用户意图加载资源，不能每张卡片都启动完整分页引擎。
- 复用请求、缓存和并发限制；测量稳定前保留已有展示，避免文档突然缩成一页导致滚动跳动。
- 已发布模板与素材保持精确版本与不可变引用；缺少指定资源明确报错，不静默降级成其他模板。
- 优化前定位真实瓶颈，比较加载、交互和内存表现。不能以删掉验证、内容或降级正确性来制造“变快”。
- 编辑检查不能在每次按键时反复扫描整份正文。停笔后合并执行，排版结果变化复用文字规则；关闭的导出弹窗不计算检查摘要。高频订阅放在独立组件，不能让检查结果带动整个编辑页重绘。
- 延迟检查必须保留正确性：导出读取最新正文，确认和采用建议前重新校验当前内容，切换简历时丢弃旧结果；正文改变后立即取消过期 AI 校对。性能验收使用相同数据和连续输入场景，对比实际调用次数，不能只凭主观感受。

来源：[模板页性能](superpowers/specs/2026-10-24-template-page-performance-design.md)、[模板加载](superpowers/specs/2026-10-23-template-gallery-loading-design.md)、[模板维护](resume-template-maintenance.md)。

## 7. 分页与导出

- 测量、展示、打印正文几何和字体一致；装饰不占正文布局。不放宽布局签名来掩盖差异。
- 所有模板复用 print-color-adjust；打印背景开和关都要验证。
- 触及模板、公共打印或分页时，覆盖短内容、临界页底、多页长内容、默认模板，并通过真实导出检查 PDF 的文本、样式与分页。
- Word 独立核对实际排版；构建与协议校验不替代真实文件验收。

详细依据：[模板维护手册](resume-template-maintenance.md)第 10 节“导出问题复盘与回归要求”。

## 8. 代码与交付

- 在当前分支工作，保护已有未提交修改；没有明确要求不 push。中文提交信息遵循仓库格式。
- 页面创建或重构遵循 history-style 结构，组件用文件夹 index.tsx；页面共享状态与动作放 store，避免多级 props。
- 全局与复杂状态用 Zustand，组件子树 UI 状态才用 Context，临时单组件状态用 useState；不要为简单局部状态增加全局耦合。
- 按职责留空行，遵循两空格、单引号、无分号；改动文件先 Prettier 再 ESLint layout 修复，格式调整不得夹带逻辑变化。
- 不强制 TDD，不创建只复述实现的测试。需要的临时验证和夹具统一放 tests/，结束删除；scripts/ 不放验收脚本。
- 根据变更执行必要类型、lint、构建和产品流程验证，记录实际结果与限制。没有最新证据不能声称已完成。
- 涉及 Supabase 迁移或 Edge Functions 时，开发与隔离验证后完成当前链接项目的部署、账本、函数版本与线上 smoke；只有确实缺少权限或凭据才请求用户介入。

## 9. 文案与沟通

一期审查中，用户指出文案像 AI 生成的，读起来不自然。问题包括首页堆叠“下一次机会”“从真实经历开始”等口号，把内部分析术语写进页面，以及反复强调真实性，让普通操作提示像一份规范。

- 标题说清页面或任务，按钮说清点击后的动作。例如“继续编辑简历”，不用“继续打磨你的下一次机会”。
- 说明写用户当下需要知道的内容。例如“暂时不能购买额外额度”，不用“尚未提供付费扩容”。能删掉而不影响理解的口号、重复标题和套话直接删掉。
- 建议落到具体内容。例如“补充你负责哪部分、做了什么”，不用“强化能力证据、完善内容画像”。确实需要专业术语时，用一句话解释它指什么。
- 用正常、克制的中文，不为了显得亲切加入语气词、网络用语或刻意鼓励。不要把所有提示都写成三段排比，也不要用“不是……而是……”反复说教。
- 简短不等于省略事实。文件支持范围、数据保存位置、额度状态和评分依据仍需说明；AI 提示保留不编造、不清楚先问、由用户确认事实的要求。
- 文档和日常回复也遵守这些要求。先讲结果或问题，再讲必要细节，不用一串流程术语代替说明。

验收时先在实际页面按标题、说明、按钮、状态提示的顺序通读：是否像正常中文，是否知道下一步能做什么，有没有重复或无关的劝导。再检查桌面和窄屏的换行、按钮宽度、空态与错误态；不能只靠关键词扫描判断文案是否合格。

## 10. 求职跟进布局与统计

来源：[统计与布局修正](superpowers/specs/2026-10-25-tracker-layout-counts-design.md)。

- 阶段计数使用当前状态，与列表筛选和看板使用相同的搜索、归档范围。历史投递与响应率使用独立字段，不能让“已投递”把面试、录用职位一起算入。无数据、加载失败与零分开显示。
- 看板普通列固定为合理宽度，超出时内部横向滚动。不能为了填满屏幕，让唯一有内容的列和卡片无限拉宽，也不能把空列压得标题无法阅读。验证宽屏、手机和侧栏展开/收起。
- 职位卡片以职位名、公司和必要辅助信息为主，默认紧凑两行；跟进内容存在时再增加一行。长公司、地点、薪资和批量复选框一起验收，不能只测短字段。hover 使用轻微边框、背景与阴影过渡，避免突然位移；先确认底层组件实际使用 border 还是 ring。
- 定位、筛选和归档提示放在阶段筛选旁，不额外占据一行职位展示空间。窄屏可在工具栏自然换行。批量操作按用户最后要求保持原有位置与样式，不套用标签上移规则。
- 跟进安排使用紧凑入口和 Popover，保存摘要在入口可见。编辑草稿与保存值分开，关闭弹层后重开不丢草稿，失败不假装保存成功；日历与外层弹层逐层关闭，退出节点不参与交互。验收重复开关、反向切换、失败重试、手机尺寸和减少动效。

## 11. 简历导入与核对

- 解析结果是待核对的内容，不自动当成事实。原文完整保留；不确定的字段留空或未归类，不把职责、技术栈猜成公司或岗位。
- 日期正则覆盖 1～12 月、两位月份的完整边界、单独日期行和“至今”。经历不能只凭日期或分隔符切段；标题识别与分组使用同一份依据，缺少标题时安全保留内容。
- DOCX 的文本框、正文、页眉和页脚可能存在嵌套段落，每个文本节点只能计入一次；解析限制同时检查压缩输入和实际展开体积。
- 文件读取与自动整理、填充预览和最终创建是三个状态。取消读取或整理不覆盖原输入；确定未发送创建请求时允许返回修改；结果未知时保留操作身份，先查询再重试，刷新后也不能重复创建。
- 本设备保存不等于不需要账户隔离。导入原文、草稿和检查记录都按账户隔离，游客使用独立范围；异步继续动作核对发起时的账户和操作。
- 保存失败时不能同时显示“已保存”。从其他页面打开既有组件时，按组件的实际依赖加载数据，不能假设用户此前访问过某个列表页面。
- 富文本与纯文本互转不能在每次输入时裁掉换行和末尾空格，核对输入框必须实测连续输入、多行和刷新恢复。
- PDF 文本块不是词。按基线和实际字间距恢复行与字段，避免给相邻汉字强行插空格；兼容字形只在提取副本中规范化。须用平台实际导出的中文 PDF 回读，覆盖姓名、中文标题、公司岗位分隔及 10～12 月日期。
- 本地转云端和岗位定制产生新简历 ID 时，要同时接续本浏览器中的原文、示例、AI 来源和处理记录。来源读取或保存失败不能当成“没有记录”；只读取当前账户和明确同步的游客内容，不能扫描其他账户的数据。
- 重试身份必须来自稳定的用户操作，不依赖模型返回的关键词或随机结果。同步删除本地副本前，确认上传内容与当前本地内容一致；云端记录存在不等于本次内容已成功保存。重置未完成的派生内容失败时，不能继续标记完成。
- 导出检查忽略不打印的“不填”选项及纯展示配置；经历已有正文却缺少公司、学校或项目名称时要提醒。忽略理由与确认结果绑定具体条目和内容，不能把旧确认套用到新内容。
- 编辑检查只处理正确性和阅读提醒；经历表达、职责成果、岗位相关性与关键词证据留在第四期 P4-05。
- 明确错误标红，待核对标黄，建议标蓝。AI 来源只汇总提醒。按用户 2026-10-26 的要求，导出不要求勾选确认：有明确错误时按钮标红并允许直接导出，只有提醒时维持默认样式；只有文件本身不能生成才禁用对应格式。
- AI 校对必须匹配可见字段、原文证据和内容签名。不能靠编辑距离把“前端”改成“后端”、把“本科”改成“专科”；未知词只提示核对，明确错词表才能提供一键更正。大小写风格不当作红色错误，命令与代码语境保守处理。
- 定位覆盖层与正文、测量及打印副本分离；页内重复源内容必须按实际页面和区域裁剪，不能高亮其他页的隐藏副本。采用、保留和撤销都核对稳定条目与内容签名，撤销不得覆盖后续编辑。
- 检查入口、填写/检查切换、字段反馈和导出摘要使用相同等级；总体颜色取未处理问题的最高等级：错误 > 待核对 > 建议，全部处理后恢复默认。不能只给检查列表上色，其余入口仍为中性样式。
- 预览高亮必须同时核对面板可见、当前检查 tab、问题展开和筛选可见性。切换填写、收起问题、关闭面板或进入历史版本后清除；原有定位状态不等于当前仍在查看检查。定位换目标前不能复用上一处的测量矩形。
- 填写字段直接标记标签与控件边框，说明复用 shadcn Tooltip 并提供无障碍描述；不另占一行显示遗留问题标题。重排后按稳定条目 ID 匹配字段，确认或修改后清除，签名校验依赖不能误标成问题字段。
- 编辑页的工具栏居中，不展示面包屑；填写/检查切换与保存、协作、分享共用操作行。手机工具栏全部用有明确名称的图标按钮。窄屏换行时页头高度必须随内容变化，不能用固定高度让按钮覆盖正文。
- 模块内部滚动触顶或触底后应自然传递给外层列表，不能用 overscroll-contain 把滚动困在模块中。验收必须用真实滚轮连续滚动，不能仅检查 overflow 样式或设置 scrollTop。

## 12. 创建简历向导

来源：第二期用户审查，2026-10-25；覆盖此前“从零创建空白页”和自动恢复步骤的设计。

- 从零创建按求职阶段填入明确标记的示例，并记录来源供导出检查；不能只显示“姓名”的空白页。导入创建只使用从原文填充或用户修改的正文，不混入模板示例，不要求逐模块勾选确认。
- 两种创建方式都先选模板，再保存。使用已发布模板的精确版本，保留正文顺序与可见性。返回修改同份内容时保留选择；请求发出后冻结正文、模板和操作身份。
- 导航与草稿内容分开。每次打开固定在三个入口，只有主动点击继续才恢复草稿；保存结果未知的操作仍能继续确认，不能因回入口而重复创建。
- 标题与主动作固定，正文在有高度边界的容器中滚动。长输入尽量由主容器滚动；保留独立原文滚动时，触底后滚轮必须能交给父容器。验收需记录连续滚动、中段反向、触底反向，不能只看到滚动条就判通过。
- 选择页只保留简短差异说明，去掉重复保存提示和空页脚。文件类型、上限、数据用途保留简短提示；详细错误在发生时说明。
- 同一创建操作刷新重试时，正文条目 ID 必须稳定；不同创建使用不同身份。示例证据按最终正文条目记录，不能出现简历已恢复但检查记录无法匹配的情况。
- 步骤切换的标题、正文、页脚必须同步进入新布局。不能让旧正文等待退出时仍参与高度计算、而新标题和页脚已经改变尺寸；外框按实际测量的宽高平滑过渡，内容保持目标宽度，避免文字跟着外框反复折行。测量使用布局尺寸，不能把弹窗入场缩放后的视觉尺寸作为下一次布局依据。
- 模板选择高亮画在卡片内侧，不改变卡片尺寸。不能依赖超出边界的 ring，导致第一行、首列或滚动边缘被裁切；同时检查鼠标选择和键盘焦点。
- 填写建议分清“写什么”和“参考示例”，每条建议只说一件事。原文仅在存在时提供折叠入口；保存位置说明跟随原文，不把来源记录、存储实现和无关空态堆在建议上方。

## 13. 自动填充与免费识别

来源：2026-10-25 用户反馈上传后的手动核对过于复杂，且基础导入成本不应由用户承担。规格见 [自动导入设计](superpowers/specs/2026-10-25-automatic-resume-import-design.md)。

- 文件选择后自动提取、归类、填入并进入预览；上传和粘贴作为两个替代入口。“修改内容”按需打开，主动作直接选择模板。未知内容显示非阻断摘要并保留原文，空结果不能宣称成功。
- 本地提取与解析用于回退，字段非空不能证明分类正确。登录后非空导入使用一次独立免费识别（沿用缓存与限额），不接入付费 llm-proxy 或任何积分预留/扣减动作。文字会发送服务端及模型的事实必须在上传前明确说明，不能继续声称全文仅本地处理。
- 模型只归类原文，服务器返回校验后的行/字符范围；原始提取文字独立保存，规范化正文不冒充原始字节。账号＋摘要＋协议版本原子去重，限额按上游尝试计数，缓存仅保存位置索引，失败重试与租约都有上限。
- AI 合法但不完整的结果不能清空本地字段。经历比较先规范化日期，使用同一来源中的完整公司/岗位去重；部分岗位名称不能变成第二条经历。删除元数据时先合并重叠索引，相同起止日期不能重复删除正文。
- 正文去重和未归类清理使用完整行/明确来源匹配；禁止任意子串去重，例如 Java 不能被 JavaScript 吞掉，AI 未映射的 Java 必须仍有未归类提醒。
- 回归覆盖真实 PDF/DOCX、公司简称、重复年月、年份中文格式、部分字段、未映射技能、取消/更换/关窗的操作版本保护、跨账户缓存、并发限额和租约恢复。线上使用合成简历与临时账户验证积分不变，清理测试账户。配置必须核对既有函数使用的实际环境变量名；当前 DeepSeek 服务兼容 OPENAI_API_KEY。
- 来源依据：[真实 PDF 分类修复](superpowers/specs/2026-10-25-import-source-ownership-design.md)。模块及条目须按来源行号合并，`·`、`|` 等展示分隔符不能成为岗位/专业字段。不同标题行的任期不能靠同公司同岗位合并；字段匹配只兼容无来源旧结果。
- 同源字段允许采用 AI 的语义角色；仅当本地值是同字段连续原文的严格扩展时保留长值，不能用“非空且在原文”维护已经反转的公司/岗位。明确原文模块优先于 AI 的工作/实习标签。
- 续页标记接续前条经历，不把下一页内部技术小标题升级为新公司；保护依据原文父级，不依赖 AI section。续页标题冒号后的正文必须保留。“技术栈：React”等经历内说明不能无条件切成顶层模块。
- 文本模块或新识别经历转移时，从原条目移走对应来源行，避免同一正文归属两处。只消费实际保留的行，不能将因本地范围裁剪而未保留的文字同时从未归类中清除。验收覆盖实际 PDF、构造合法映射与正式 organize 入口；区分本地回放和真实模型调用。

## 14. 编辑输入性能

来源：[编辑输入卡顿复盘](superpowers/specs/2026-10-26-editor-input-performance-design.md)，2026-10-26。

- 性能验收必须测实际输入事件，普通字段和富文本分别连续快打至少 10 秒，并测 10 秒反复粘贴（含多段与单段）。不能以检查次数减少代替打字响应；覆盖中文组合输入、已有警告、多页预览，记录处理时长、长任务及内容完整性，区分输入期间和停笔后的预览更新。
- 表单数据同步在独立子组件订阅，复用字段级更新和光标保护；禁止让整个 FormProvider 随每个字符重绘。字段反馈上下文只随问题或条目路径变化，不能因无关正文更新重新创建。
- 测量页与各展示页共用同一快照的评论及内容投影。预览仅订阅正文和外观，缓存键包含投影日期；旧快照用 WeakMap 释放。HTML 缓存仍必须走原有净化，不能为提速关闭安全处理。
- 预览可以低优先级更新，输入写入与保存不能因而推迟到失焦。导出同时验证预览包含最新正文及外观、分页已就绪；不得导出旧快照或放宽打印签名校验。
- 拆分订阅后必须验证远端字段更新、经历新增/删除/重排、光标、保存刷新和最终导出末尾文字，不能只测渲染次数。

- 顶层布局不能用扫描整页后代的 `:has()` / `group-has-*` 判断侧栏状态；优先使用已有状态，结构判断限定直属子节点。输入卡顿同时检查浏览器样式重算与布局，不能只看 React 重绘。
- 富文本工具栏只订阅按钮需要的 can/isActive 等状态；不要订阅完整 EditorState。隐藏的浮层不应因滚动发送定位事务，选区变化后仍需验证按钮与浮层行为。
- 连续输入可合并预览更新，但必须保持即时写入、既有保存策略，以及导出最新快照检查。测试输出应放在开发服务已忽略的目录，避免生成 HTML 等文件触发热更新、污染测量或中断保存。
