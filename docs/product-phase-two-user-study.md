# 第二期首次使用试用记录

状态：试用流程已准备，尚未招募或开展真实用户试用。以下表格不代表测试结果。

## 参与者与材料

邀请 5～8 位近期有求职需求的人，覆盖应届生、有工作经验和转岗者。每人使用自己的旧简历，至少覆盖 PDF、DOCX 和粘贴三种输入。提前说明本次用于观察产品使用问题；记录使用过程前征得同意，不在报告里收集姓名、电话、邮箱和简历正文。

试用从首页开始，使用独立浏览器配置。向参与者说明原文件在浏览器读取，核对草稿和检查记录留在本设备；云端简历需要登录后保存。结束后让参与者决定保留或清理测试内容，不替其公开分享或提交申请。

## 给参与者的任务

“请把你这份旧简历整理到平台上，检查内容后导出一份准备投递的简历。可以按自己的习惯操作。”

开始前不演示步骤。观察者在卡住时先询问参与者在找什么；只有参与者明确求助才解释，并记录帮助发生的位置。观察者不代为核对联系方式或经历。

随后补充两个短任务：关闭页面后找回未完成的核对；更改一段内容，处理导出前提示并再次导出。检查最终文件能否打开，姓名、联系方式、经历和时间是否符合参与者原意。

## 汇总方式

- 独立完成率：不依赖操作讲解，完成本人核对并得到可读文件的人数 / 实际参加人数。
- 帮助后的完成单列，不能计入独立完成。失败、取消和中途退出也保留在分母中，并记录原因。
- 耗时从进入首页开始，到本人确认第一份文件可用为止。先分别列独立完成与帮助后完成的时长，再计算各自中位数；未完成者不补一个虚构时长。
- 每个问题记录触发条件、影响和原话，优先处理造成内容错误、找不回草稿和无法导出的阻断问题。
- 首轮先建立真实基线，再确定时间目标。本期不以开发者模拟流程代替真实用户试用。

汇总结果：尚未开展，暂不评价完成率和耗时。
