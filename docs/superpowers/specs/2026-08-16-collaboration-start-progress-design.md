# 实时协作开启阶段反馈设计

## 背景

开启实时协作时，`activateSession` 先等待 `resume-comments` 的协作评论权限注册，之后进入 `enableCollaborationSession` 才设置 `isConnecting`。因此用户点击“确认开启”后，网络请求已经开始但按钮仍无反馈，直到前置请求结束才出现加载状态。

该前置注册用于保证实时编辑和评论权限属于同一协作会话，不能删除或与连接步骤盲目并行，否则可能出现实时连接成功但评论权限未建立的半完成状态。

## 目标

- 点击“确认开启”后同步进入第一阶段反馈。
- 文案反映真实异步阶段，而不是笼统的“正在开启”。
- 所有入口共用同一阶段状态，并保持现有错误恢复和禁用规则。
- 不增加额外网络请求，不改变协作会话协议。

## 状态模型

在协作 store 中增加可空阶段：

```ts
type CollaborationConnectionPhase = 'registering' | 'connecting' | 'syncing' | null
```

`isConnecting` 继续作为通用布尔兼容现有按钮和禁用逻辑；阶段与它必须一起更新：阶段非空时 `isConnecting=true`，连接成功、失败或停止时阶段回到 `null`。

阶段文案固定为：

- `registering`：正在创建协作会话
- `connecting`：正在连接协作服务
- `syncing`：正在同步当前简历

## 数据流

1. `startSharing` 在首个 `await` 前同步设置 `registering`，并清除旧错误。
2. `registerCollaborationCommentSession` 成功后切换为 `connecting`。
3. Automerge 协作适配器连接成功、需要保存 host 初始快照时切换为 `syncing`。
4. `createConnectedSessionState` 清空阶段并进入共享状态。
5. 任一步失败都清空阶段、恢复按钮并显示已有错误信息。

加入会话和恢复 host 使用相同阶段字段；它们没有“确认开启”弹窗，但外层协作按钮会立即显示加载图标。

## 界面

确认按钮在连接期间保持禁用，文本直接显示当前阶段文案并保留旋转图标。取消按钮在连接期间禁用，避免用户关闭弹窗但后台继续创建会话。对话框的关闭行为在连接期间同样被阻止；失败后可正常关闭或重试。

## 边界与验证

- 快速双击只触发一次会话创建。
- 评论权限注册失败时永远不会进入实时连接。
- 实时连接失败时执行现有评论会话清理。
- 初始快照保存失败时恢复非共享状态。
- 成功后 URL 参数、分享链接、参与者和成功提示保持不变。
- 使用网络限速验证三个阶段按真实顺序出现，首帧点击后即可看到 `registering`。
