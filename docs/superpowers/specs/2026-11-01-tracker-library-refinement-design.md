# 求职进度、读取性能与页面布局修正

日期：2026-11-01。范围来自用户本次明确提出的七项问题，实施已授权；完成、验证、用户审查分别记录。

## 业务规则

- 进入下一阶段即完成实际经过的上一阶段。完成显示勾；跳过的中间阶段显示灰色短横线。进入录用或结束后，未进行的后续阶段同样显示灰色短横线。当前阶段保留强调，未到达的阶段不误标完成。依据现有阶段详情、转换活动和终态来源判断，不凭当前位置把所有前序阶段都补成完成。
- 顶部“已投递”统计已投递、测评、筛选、笔试、面试中的在办岗位，排除已保存、已录用、已结束；计数和点击后的筛选共用规则。看板中点击该指标，定位到当前范围内确实有在办岗位的最早阶段，不再固定跳到可能为空的已投递列。阶段菜单与看板各列仍按精确阶段筛选。历史投递和响应率保持真实投递事实口径。

- 返修补充：回退会重算当前阶段状态，不应抹去进度图中的真实经历。终态逐个结合进入日期、推进/回退活动和恢复流程记录恢复勾选，不用最深阶段推断中间节点，也不改变明确记录的最后结束来源。

## JD 读取

现状：getJobSubmissionJd 调用 material Edge Function，函数 select(\*) 后还查岗位，回传简历正文和模板等原件字段；折叠内容卸载后失去组件内结果，下次打开重复请求。

改为受现有账户 RLS 保护的两字段读取，只获取 jd_text、jd_updated_at。检查列授权与岗位归属条件；如需迁移，由代理完成隔离验证及已链接云端部署。结果与在途请求按账户和记录复用，账户切换及投递记录更正后失效。失败可重试，空 JD 仍显示真实空态。不扩大为全应用缓存改造。

## 视觉与滚动

采用 redesign-existing-projects 的层级整理方法，保留项目组件与字体。比较了“全部塞进更多菜单”“仅允许自动换行”“固定职责分层”三种方案，采用职责分层，避免隐藏高频操作或让断点改变操作顺序。

- 桌面求职工具栏分两层：第一层为职位数量、列表/看板和关注/归档/批量管理；第二层为搜索、阶段、公司筛选，分组和排序靠右。窄桌面允许筛选行自然分组，搜索保留可用宽度。手机保留已确认列表布局和快捷阶段，不恢复看板。
- 分享管理及我的简历建立有高度边界的内容滚动区，标题、筛选与页签不随正文滚动；简历分页继续在列表之后，翻页只重置内容区滚动并聚焦列表。保留加载、错误、空态及已缓存内容。
- 优化评分区保持开放布局，无围合边框与矩形背景边缘；采用在容器内部四周衰减的径向光晕，保留真实分数水印、等级色与阅读层级，兼容深浅色和三位分数。
- 复用现有 Button、Input、CompanyPicker、FilterMenu、SortMenu、Tabs、Collapsible；不新增组件库。所有变化沿用公共时长、缓动及动态减少动效。

## 示例姓名

扫描页面、占位提示、内置简历与演示资料中的真人姓名。创建向导和联系人提示使用“示例用户”“示例联系人”等通用称呼。官方模板既有示例已在模板维护资料中明确为虚构履历，本次核对其精确资源，不为替换既有虚构姓名发布新模板；不覆盖不可变资源。不批量改写用户已保存的简历、账户资料或联系人。

## 验收

覆盖逐级推进、跨级跳过、直接录用/结束、结束后恢复、当前阶段；统计与筛选一致；JD 首次读取、重复开合、失败重试、账户隔离、结果失效；桌面 1440/1024/768 与手机 390/320、深浅色、长内容、滚轮、键盘、焦点、连续开关及快速反向、动态减少动效。复用真实页面组件，合成数据只放 tests，禁止写入用户真实数据。完成后删除临时脚本和数据。

静态验证执行改动文件 Prettier、ESLint layout、类型检查及构建。涉及数据库则核验线上迁移账本、现有函数版本和实际读取 smoke。最终在防回归清单记录触发场景、根因、约束与验证方式。
