# AI 回复结束后空白修复

日期：2026-11-13。用户授权修复“AI 输出完成后下方出现大块空白，刷新后消失”。属于已授权助手升级的缺陷修复，不开启新一期功能。

后续用户审查指出：发送时仍有轮次占位，结束时会突然跳转。本记录保留首轮终态验收证据；其中完成后清占位的方案已被 [发送与完成连续性修复](2026-11-13-assistant-scroll-continuity-acceptance.md) 替代，不能沿用本记录宣称全过程已通过。

## 复现与根因

采用 `systematic-debugging`，先读取本地 Scroller 与 Motion 源码，再在隔离浏览器中挂载真实 MessageList、项目 CSS、MemoryRouter 和 SidebarProvider。夹具只向页面 store 写合成消息，网络隔离，不调用模型或修改用户简历。

稳定复现了两处问题：

1. 30 条历史、40 段回复完成 1.5 秒后，DOM 仍有第 33 行 `streaming`。它高 1234px，opacity 为 0、inert 和 aria-hidden 为 true，实际消息应只有 32 行。刷新同等会话后该行消失。含额外行的滚动高度为 7053px，重载后为 5795px，差异包含该行和行间距。
2. 移除这行后，单段短回复仍留下 548px 的 Scroller spacer。新轮次对齐用户消息时会创建该占位，库不会依据业务 streaming=false 自动结束锚定；重新加载则走默认滚到底部并清空占位。

已安装 Motion 12.38.0 的嵌套 AnimatePresence 在 propagate=true 时登记到父级；当前确认区为空，无子项 onExit 回调调用 safeToRemove，导致外层一直等待。上一轮只验收了可见性和完成区域，没有断言临时行实际卸载、完成与重载高度相同，因此漏掉透明节点占位。

## 修复边界

- 确认区取消 propagate，由已有外层 StreamingMessage 保留确认卡退出宿主和公共 fast 时长。确认区继续根据 pending 变化执行自身退出，退出行保持 inert。
- 外层退出完成后等待下一帧提交卸载，再用官方 Scroller API 释放空间。最新内容已可见时滚到实际底部；向上阅读时按首个可见行的原偏移定位，移除 spacer 而不改变阅读位置。
- 会话已变化、下一轮已开始或用户正在搜索定位时，不执行旧轮次的定位修正。搜索冲突曾在调试中实际复现，加入目标检查后回归通过。
- 不修改依赖源码、不增加高度兜底或延迟隐藏，不改 AI 业务处理器、用量、数据保存和账户隔离逻辑。
