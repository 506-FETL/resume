# 历史版本布局优化

用户已确认上一轮评估建议并授权实施。沿用 brainstorming 的上下文与方案判断，本次优化时间线密度、版本身份、辅助信息和动作层级；不重复请求批准，不修改首页、真实版本数据、恢复语义、模板或打印引擎。

## 方案

保留左侧时间线、右侧真实预览，以及窄屏列表 / 详情切换。比较整体重构为单列文档列表、保留原面板仅去边框、保留面板并调整内容组织，采用第三种。

- 左侧：当前内容仍固定在顶部；减少头部、当前内容、搜索之间的横线与留白。历史版本以名称为第一行，版本号 / 来源 / 时间为第二层；说明最多一行，标签和重点标记紧凑显示。日期分组、筛选与搜索继续可用，选中背景和圆角保留。
- 右侧：版本名为 20 / 24px 主标题，版本号、来源、时间和重点标记作为次级摘要。当前内容的同步状态保留。
- 版本信息：以既有 Collapsible 组合成可展开辅助区，放在文档上方，同一滚动区域内连续阅读。去掉与标题重复的版本号、来源、日期及重点标记；说明、标签、岗位和投递日期紧凑显示，缺失状态不伪装成真实内容。编辑时展开原有字段表单，保留取消、保存和未保存离开确认。
- 操作：全局保存当前版本保留；历史版本的对比成为明显的局部入口，恢复为次级按钮，桌面导出和编辑收为带 Tooltip 的图标操作。手机继续沿用已确认的全部 36px 图标同排。保留真实处理函数及确认流程。
- 预览：组件保持常驻，展开信息不会卸载简历；继续使用已有快照缓存，切换版本沿用当前快照获取和日期投影逻辑。不能为各条时间线挂载完整预览。

组件检索已确认现有 Button、Collapsible、Tooltip、DropdownMenu、Skeleton、版本表单和 HistoryResumePreview 足够，不新增 UI 库。动效复用 useHistoryMotion、公共 Collapsible 动画及 useReducedMotion；不改全局组件样式。

## 验收

正式组件和应用外壳中检查当前内容、历史版本、展开信息、编辑与取消；多版本、长名称、完整 / 缺失说明与标签；1440 / 1024 / 390 / 320px、深浅色、加载 / 空态、两轮展开关闭和快速反向、键盘焦点及减少动效。真实页面只读验证；多版本与编辑数据在 tests/ 隔离内存样本验证，完成后删除。验证预览 DOM 在信息开关时保持同一实例。
