## 创建入口与手机布局

模板目录的“使用此模板”先进入填写信息，不能直接写入简历。名称和描述默认值、空白兜底、精确模板与示例、来源模式及幂等创建逻辑保持一致。此处原定复用既有创建工作区，已被用户最新要求取代：模板页必须在当前预览窗口内完成，不打开“我的简历”向导；见[原地创建修正](2026-11-11-template-inline-creation-design.md)。保留用户在目录中选择的示例，不改用模板默认示例。返回后仍能继续比较和修改，不丢表单输入。

桌面沿用用户已明确的左侧铺满背景、向右渐隐、右侧表单。手机仍采用铺满正文宽度、向下渐隐的背景。用户明确纠正：之前的问题是展示高度太少，不是要换成独立的完整纸张缩略图；200px 纸张方案已被否定。背景高度采用 clamp(20rem, 44svh, 24rem)，约 320–384px，顶部 40% 保持清晰，再逐渐淡出；图片等比例铺满并顶部对齐。表单仅衔接最后 24px 的近透明区域，不遮挡主要预览。正文为一个滚动容器，标题和操作页脚常驻，320px 窄屏和 400px 短屏通过正文滚动到达表单；使用 svh 避免键盘展开时背景跟着缩小。

返回模板列表时定位已选项到目录可视区，再恢复焦点；尊重减少动效，不滚动页面外壳。刚恢复草稿时，目录条目查询与图片解码都视为真实加载，显示公共 Spinner。缺失、失败与加载明确区分，失败可重试，不能先展示缺失图标再突然变为图片。预览只使用真实所选模板与示例。

复用已有 Dialog / Drawer、Button、Field、Input、Textarea、Spinner、Motion 布局投影及公共动效预设，不新增 UI 或动画依赖。选中纸张、其余卡片和表单保留衔接，返回、连续开关和快速反向都遵守减少动效。

## 求职推进与保存

已确认根因：Drawer 的 handleProgressChange 在 changeJobStatus 发起后立即 setViewingStage(null)，而 applied 状态需要先等待记录投递弹窗，导致浏览中的阶段先被清除。查看阶段属于界面状态，不能在打开弹窗时更改；取消保留查看位置，成功后显示真实已提交阶段，失败保留输入和原持久状态。

已确认重复链路：recordSubmission 完成写入后读取单个目标职位，SubmissionForm 随后又 await reloadJobs 重读全表，才关闭弹窗。删除多余全量等待，保持真实持久化确认、旧字段保存队列、岗位归属、当前账户代次与并发字段合并。更正材料和未知结果查询也不得无条件重载全表。复用可信响应、只更新目标以及精确失效投递缓存，不能用提前关弹窗假装提速。

继续检查浏览器 API、Edge 与数据库内部请求和响应载荷。以实际确认记录成功和界面接受目标状态为终点，分别记录请求数、载荷、地区和耗时。需要修改 Edge 或迁移时，完成隔离验证后由代理部署已链接项目并完成线上 smoke；未经过同数据实测，不承诺固定倍数。

## 验收与交付

- 创建入口：目录预览、卡片入口、创建向导和继续草稿；名称/描述默认、留空、失败重试及真实示例一致；返回后已选项在视口内，输入保留。
- 视觉：桌面、320/390px 手机、400px 短屏、深浅色；手机背景铺满宽度，能看到更多正文后向下渐隐，表单清晰，页脚固定；键盘操作与焦点有效，两轮完整开关和退出中反向，动态减少动效。
- 加载：慢目录、慢图片、加载失败、缺失资源、失败重试、恢复非首屏模板；真实等待显示 Spinner，不能显示假空态。
- 求职：推进到已投递的打开、取消、保存、失败、未知结果确认；已有材料与无材料，普通阶段推进及更正；保存队列不丢修改，账户 A→B→A 旧响应不回填，其他职位不重读。
- 临时验收只放 tests/，完成后删除；Prettier、ESLint layout、类型和构建通过后记录证据。浏览器连接失败只记录限制，不能计为页面验收通过。
