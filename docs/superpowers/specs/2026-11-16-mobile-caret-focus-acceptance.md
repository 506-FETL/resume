## 已复现的聚焦问题

之前只检查编辑器 CSS 与桌面浏览器的手机视口，没有覆盖原生 iOS 上的抽屉聚焦链路，漏掉了下面可复现的聚焦异常。该异常不能解释用户随后反馈的全部遮挡现象。

当前安装的 Base UI `DrawerVirtualKeyboardProvider` 会接收冒泡的 `touchstart`，随后在 `touchend` 阻止默认点按行为。它的 `focusKeyboardInputWithoutPageScroll` 在同步调用 `focus()` 前，将目标设置为 `opacity: 0` 和 `translateY(-2000px)`，聚焦后立即恢复。这用于抑制页面被键盘带动滚动，但本项目的富文本在 iOS 18.2 中会因此聚焦成功、可以输入，却没有可见原生光标。

验证使用正式 SimpleEditor、Drawer、VirtualKeyboardProvider、SideTabs 与 ViewPort，合成正文通过受控 HTML 回填。XCTest 驱动 iPhone 16 Pro / iOS 18.2 的 WKWebView，截取原生屏幕；不是桌面 WebKit 改一个 viewport。

| 对照                                                          | 观察结果                                     |
| ------------------------------------------------------------- | -------------------------------------------- |
| 普通页面内的编辑器                                            | 原生光标可见。                               |
| 普通页面加 SVG 页签容器                                       | 原生光标仍可见。                             |
| 原有抽屉及键盘聚焦处理                                        | 聚焦、键盘正常，连续四帧无光标。             |
| 改掉滚动层、isolation、SVG、抽屉 transform 或 backdrop-filter | 未消除抽屉内光标不可见；这些试验改动均撤回。 |
| 保留原生富文本点按聚焦，其他容器保持原样                      | 光标恢复，连续帧能看到正常闪烁。             |

所以，本次不能把 SVG 或单纯 z-index 写成根因；初期的层级判断已被完整对照排除。也没有引入自绘光标、聚焦后反复重绘或定时重新设选区。

## 最终实现与长期约束

`DrawerPrimitive.Content` 只在触摸实际可编辑的 HTML 节点时阻止 `touchstart` 继续冒泡，避免进入抽屉的隐藏后聚焦路径。没有调用 `preventDefault`，浏览器仍原生处理点按、光标位置、输入和长按；内部编辑器事件先正常执行。

普通 input、textarea、工具栏及不可编辑区域继续走原处理。VirtualKeyboardProvider 保留，继续通过真实 focus/viewport 事件处理键盘避让。绘制层、抽屉尺寸、页签结构、手势手柄和动效配置不变。

原生聚焦还暴露出编辑器继承抽屉 14px 字号的问题：iOS 会放大页面到约 1.142 倍，原键盘适配在缩放状态下暂停避让。手机编辑根节点改为 1rem 后，实测 scale 保持 1、scrollY 为 0；软件键盘出现时识别到 346px inset，输入位置可见。只影响编辑区文字，不修改简历模板或导出字号，不限制用户主动缩放。

长期要求：富文本光标问题必须检查聚焦瞬间的状态，不能只看恢复后的 computed style。测试需要含真实手机容器和原生 iOS 绘制，至少截取一个完整闪烁周期；桌面浏览器、系统模拟器和实体手机的结论分别记录。

## 验收结果

- 原生 iOS：空白及已有中文正文中，点按后均有可见光标；输入数字、换行、删除通过真实 TextView 操作并核对值。普通输入框输入后返回富文本，新增字符写入正确目标，光标仍可见。长按后光标保持可见。
- 原生最终回归通过（XCTest：1 项测试，0 失败，42.61 秒）。空白/正文的聚焦、输入、重新聚焦及长按共七组状态，每组采样四帧，均至少三帧有编辑区内的紫色原生光标，其余为正常闪烁期间的熄灭帧。软件键盘出现后，当前输入位置可见；没有将键盘的蓝色按钮或普通 input 的蓝色光标计为富文本光标。
- Chromium、WebKit：分别覆盖 320、390、768、1440 px，共八组。每组两轮打开、输入、换行、删除、页签往返、关闭回焦；随后退出中重开、运行中开启减少动效、清空后输入，全部通过，无页面异常。
- 浏览器在真实 focusin 捕获阶段记录样式：富文本不再经过透明、移出屏幕的聚焦状态；普通 input 仍保留原键盘处理。没有替换业务函数或编辑器实现。
- 原生验收最初用字母触发中文输入法组合输入，导致“删除一个字母后立即读取值”的测试断言不稳定；改用数字验证换行、删除与目标输入。该失败未记为通过，也不宣称已穷尽所有输入法组合行为。
- 字号对照时，初始验证壳额外增加的外层滚动与占位内容造成一次空白画面；改为正式移动编辑入口的外层裁切、页签内部滚动结构后，重新验证字号、软件键盘及光标。该次仅 XCTest 动作成功但截图空白的运行不算视觉验收通过。
- 空白编辑器输入后，名称框会滚到当前可见区域上方。早期脚本按无障碍树坐标直接点按该框，导致未聚焦而输入失败；最终先用系统 Done 收起键盘，再在页签内实际向下滑动露出名称框，完成普通字段输入和返回富文本。已有正文场景另行覆盖键盘保持打开时直接往返。这里只修正验收操作，没有为测试改业务布局。
- 未操作用户简历、未写云端数据；没有验证实体 iOS/Android 手机、全部第三方输入法或远端协同保存。数据与保存流程未改动。
