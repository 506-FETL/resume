# 求职跟进移动端列表布局

日期：2026-10-31。最新授权：手机取消看板和拖动，只保留列表，围绕列表改善主次与 App 感；桌面端和首页不动。此决定替代同轮较早的手机看板方案。

## 范围

- 视口小于 768px 固定显示列表，没有看板切换或拖动。
- 768px 及以上保持现有列表 / 看板偏好、拖动、布局和操作；手机不得改写桌面 viewMode。
- 保留详情抽屉及三个页签、搜索、公司、关注、归档、批量、排序与公司分组。
- 不改首页、统计口径、数据库、写入确认、投递和公司流程规则。

## 布局和交互

页头采用 24px 标题与右侧新增，数量和响应率独立为辅助行；不再另起统计条。搜索是 44px 轻底主输入，排序与公司分组使用旁边的图标入口。常用筛选只展示“全部、待跟进”，八阶段及其数量收进现有 DropdownMenu，避免长横条堆叠和截断。公司选择与关注 / 归档 / 批量三个图标同排，降低边框和字重，保留焦点、选中态和直接入口。

筛选入口常驻，空结果仍能切回全部；阶段选择后显示具体阶段名称。数量按当前搜索 / 公司 / 归档 / 关注范围计算。复用 Tabs 和 DropdownMenu，保留键盘、回焦、连续指示动画及减少动效。

列表以职位名称和公司为中心，状态、关注与更多为次级；下一步事项和今天 / 逾期 / 未来日期按真实数据呈现。条目内部不再加分割线：跟进事项缩进在职位信息下方，每个职位之间只保留一条外部分隔线与足够留白，避免用户误认成独立记录。保持连续列表，不恢复卡片墙。点开原详情抽屉，返回仍在列表原处。

阶段切换使用现有缓存，只本地筛选，不重取、不出现加载闪烁。移动批量全选必须按当前列表筛选范围选择，不能因为桌面偏好是看板而选中隐藏阶段。加载、失败、真实空数据分开，手机加载也使用列表骨架。

## 验收

320 / 390 / 767 / 768 / 1024 / 1440px、深浅色、单职位 / 多职位 / 长字段 / 空 / 失败；筛选与计数、搜索、公司、关注、归档、排序分组和批量范围；详情两轮开关、返回位置；快速切换、键盘和减少动效。确认手机没有看板入口或拖动 DOM，桌面基线与首页不受影响。

实施、技术验证和用户审查分别记录。
