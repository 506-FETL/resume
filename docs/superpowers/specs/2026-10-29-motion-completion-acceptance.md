## 实测中发现并修复的问题

1. 编辑抽屉在视觉视口缩到 500px 后，姓名框仍处于 y632–668。接入 provider 并调整 viewport/popup 后，抽屉范围变为 y8–492，输入可滚动到可见区。640×390、视觉视口高 260px 时，原固定区域挤得正文只剩 9.8px；局部收紧留白后正文为 65.8px，姓名框 y200–236 完整处于抽屉内。
2. 把 CSS 时长设为零不会立即结束已启动的过渡。现在减少动效变化时结束 Popup/Overlay 自身及直属 content/handle 的 CSS transition；不处理任意业务后代或独立无限动画。嵌套开关途中切换偏好后，80ms 检查 opacity 已到目标且没有运行中过渡；回调 ref 各清理一次，style(state) 和自定义无限 WAAPI 保留。
3. 拖拽到无溢出或滚动边界时，原实现仍持续续帧；鼠标 Escape 也没有取消。已按实际 offset 判断、统一取消清理，并验证回源中间帧。拖后点击抑制同时修正为保留键盘 Enter 与下一次正常点击。
4. 保存失败按钮退出时，原文字与入口不统一，焦点可能留在退出内容。现在整个状态一起切换，隔离旧节点之前交接焦点；退出按钮不可继续触发重试。

这些触发场景、根因、长期约束与验收要求已写入[防回归清单第 16 节](../../product-development-guardrails.md#16-六项动效补齐复盘)。

## 对照结果及含义

数字 0→100 的一次隔离采样中，首次显示终值约从 3,173ms 降至 233ms。配置总时长为 280ms，整数四舍五入可能提前显示终值；不能把这一采样等同所有数字的完成时间。公共页签此次采样约 234ms，代码中的退出加进入预算为 210ms。

拖拽同一 JS 任务分发 60 次 pointermove：同步几何读取从 240 次降至 0 次，下一帧后的累计读取从 270 次降至 6 次。无溢出列底部停留 350ms，自动续帧从 21 帧降至 0。该测量证明事件合并与边界停止，不代表手机帧率。

## 验收范围

- 核心组件覆盖 320/390/1440px，无页面横向溢出，未出现 pageerror 或 aria-hidden 焦点警告。浮层覆盖连续两轮开关、退出中重开、运行中开启和恢复减少动效。移动主回归仅记录了 Motion 对减少动效设置的正常提示。
- 历史详情使用真实容器及加载预览槽，探针输入只验证 DOM 身份和 scrollTop=160 保留；助手画布使用真实控制器、四个常驻面板及隔离内容槽，草稿和 scrollTop=480 保留。两者均不冒充云端历史或真实简历预览写入验证。
- 真实登录页面只读抽查首页、跟进、助手、历史的 1440/390px，确认内容加载、无横向溢出及浏览器异常。助手另等骨架消失后检查最终页面。移动编辑在独立浏览器与合成离线简历中操作，未改用户数据。
- 导入草稿和本地同步的已有反馈分支已核对源码；共享通知生命周期经过浏览器验证，本轮没有执行云端同步写入。助手使用真实流式组件和重试控制器，外部执行/持久化边界使用合成结果，未发起付费模型请求。
- visualViewport 与 CDP touch 是浏览器模拟，尚未覆盖真实 iOS/Android 系统键盘、Safari 系统焦点、手机 GPU 或实际屏幕阅读器播报。本轮未改模板正文、分页和导出；上轮记录的默认模板空模块分页待核对项仍独立保留。
