# 全项目按需读取和独立加载

本次覆盖浏览器入口、页面与状态、Supabase 客户端和 Edge 查询、IndexedDB 读写及生产资源。用户已授权直接实施、复扫，最终由用户验收。

从界面实际显示、工具实际返回的数据向上追溯。单条操作限定目标，数量用真实计数，分页把排序、筛选和边界放在数据源。独立页面区域分别维护成功、等待和失败状态。权限、快照、账户代次与写入队列继续按业务依赖执行。资源加载以实际访问和生产请求为依据。

另查本地开销。模板缓存每次写入读出全部正文并多次计算容量，应在保留旧缓存和淘汰语义的前提下改读小型容量记录。助手初始化只使用前十项简历和总数，恢复操作只使用一个版本；验收需覆盖足量数据、空数据及失败。

按改动逐项收集请求字段、行数、执行轮次、可见内容或缓存操作。对照使用相同数据；生产云端、隔离接口和本地浏览器分别记载。实现后重新检查同类调用和构建依赖，直到本轮覆盖范围内没有尚未处理的、可复现且可安全修复的问题。

逐页验收按左侧导航的实际顺序执行。依次从 AI 助手、首页、我的简历、职业档案、分享管理、求职跟进、简历模板、简历优化、历史版本进入，操作本页特有的控件，记录正文或保存结果，再核对请求、大小和状态。注册、登录、公开分享、官网、个人设置、更新日志和编辑器另作入口回归。

首页最近卡片与全量数量分别建模，保留云端与本地独立完成。分享管理每页至多 20 张，按搜索、简历与状态精确统计；组跨页时仍显示完整匹配数。统计与卡片各自刷新。求职跟进列表用到搜索、排序及流程的字段，在用户展开详情时读取所选岗位的 JD 或联系人。简历优化选择框和助手上下文按各自消费的数据量读取。
