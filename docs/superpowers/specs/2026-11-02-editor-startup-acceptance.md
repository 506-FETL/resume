# 编辑页内部加载优化验收

日期：2026-11-02。用户已授权本期实施；实现完成，验证完成，用户审查待进行。当前分支工作，没有提交或推送，没有改动用户原有暂存内容。本期仅前端，无数据库迁移或 Edge Functions 变更。

## 根因与改动

1. **未打开的表单也参与入口加载。** 栏目常量静态导入 12 个表单，继而引入 Tiptap。现在栏目元信息保持轻量，各表单在实际展开时加载，原 Accordion、手机抽屉与检查 Tab 生命周期保留。
2. **隐藏面板仍带来静态代码依赖。** 检查、评论、协作、模板选择、填写建议、导出和快捷分享的重正文改为按需加载。标题、关闭入口、权限、未读数、检查计数、模板会话、退出中的数据与跨关闭控制状态继续存在。检查列表首次访问后保留当前 Workspace 内的 DOM。
3. **WASM 初始化挡在文档请求之前。** owner 读取拆成轻量入口，与 manager 动态加载并行；原保存队列完成后才开始读取，存在性、账户、请求代次检查之后才初始化、修复或保存。字段写入与保存克隆仍由已初始化 manager 同步执行，克隆仍发生在进入保存队列之前。
4. **协作状态间接带入富文本引擎。** 首轮拆分后，生产图仍有约 532 KB 的 Tiptap 依赖，经 `session/store → richtext/store → collab-extensions/seed` 引入。现于 host/guest 的已有异步准备流程中加载，并在连接频道之前完成；沿用会话代次复查、取消和失败清理，种子化及监听顺序不变。
5. **检查来源再次查询整份简历。** `useDerivedMetadata` 改为只读 `derived_metadata`，继续使用原 owner 过滤、缺失错误和离线访问协议。没有增加正文缓存或用显示副本代替 Automerge。
6. **模板请求启动偏晚。** 真实文档的精确绑定取得后，立即复用既有模板资源缓存预取；首建或修复时可与必要保存重叠，不猜测默认版本、不增加配置查询。
7. **延迟加载需要完整交互。** 共用边界保留成功模块和在途请求，失败支持局部重试，不刷新页面；加载和错误反馈复用公共动效并接入减少动效。字段定位在原短窗口后等待真实 DOM 挂载，定位成功、无有效路径、切换目标或取消操作时断开；关闭编辑区或切换模式不会留下迟到焦点。

基线是用户已暂存的上一轮优化结果，不是最初未优化版本。独立 Chrome 上下文、同一份合成简历、同一真实默认模板版本、真实 React/Zustand/Automerge/Supabase SDK；HTTP 和 WebSocket 在边界隔离，不写入真实账户数据。REST 固定延迟 180 ms。每组冷上下文 3 轮，时间取中位数。

### 请求前置阻塞与模板

给真实原生 WASM 初始化额外增加 1 秒时，原 store 的两条 owner GET 从约 132/139 ms 延至约 1,130/1,119 ms；本期后正常约 101/92 ms，增加延迟后约 93/98 ms。包含真实 loader 的组合探针同样验证 GET 在约 155–159 ms 发出，不再等待这 1 秒。这里只证明请求前置阻塞被移除，不代表文档在 100 ms 内完整可编辑。

精确模板 GET 与新建 POST 同时启动；缺绑定时与修复 POST 重叠，缺条目 ID 时覆盖必要 POST/PATCH 等待。普通已有文档仍须等解码后的真实绑定。模板读取失败进入既有资源错误状态，显式重试恢复；正文没有因此被改成默认模板。

离线生产手机与开发桌面分别验证冷载、热刷新和路由返回，均无 owner 文档请求、无 WASM 文件请求；真实 store 探针还确认离线路径 WASM 实例化为零。热返回只复用精确模板资源，云端正文重入仍读取真源。
