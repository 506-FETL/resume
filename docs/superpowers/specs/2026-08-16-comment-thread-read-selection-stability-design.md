# 评论线程已读与划词按钮稳定性设计

## 背景

评论系统当前只有 scope 级 `last_read_event_seq`。只要评论面板可见 500ms，`useCommentReadReceipt` 就把游标推进到最新事件，导致打开面板立即清除外层圆点，用户没有机会确认哪些讨论是新的。

划词评论按钮同时监听根节点 `pointerup` 和全局 `selectionchange`。选择开始/结束只在局部冒泡阶段跟踪，键盘扩选和在根节点外结束的手势没有完整生命周期；旧的延迟计算也可能在新一轮拖选期间提交，造成按钮提前出现并跟随选区。

## 目标

- 采用用户确认的 B 方案：整条讨论线程级已读。
- 打开评论面板不产生已读回执。
- 仅高亮包含新根评论或新回复的最外层讨论卡片。
- 点击卡片进入详情时，该线程当前已有的新评论与回复一起已读。
- 新回复在之后到达时，该线程重新进入未读高亮。
- 全部线程已读后，编辑器外层评论按钮圆点消失。
- 评论面板标题区提供“全部已读”。
- 已读状态服务端持久化，并在本地缓存中提供离线即时反馈与联网补偿。
- 任何输入方式都必须在选择手势结束且选区稳定后才显示划词评论按钮。

## 非目标

- 详情内部不逐条高亮回复。
- 不以滚动进入可视区域作为已读条件。
- 编辑、删除、解决、锚点变化和文档同步不单独产生“新评论”高亮。
- 不改变评论创建、回复、解决或重关联权限。

## 线程已读数据模型

### 服务端

新增私有表 `resume_comment_thread_read_states`，记录：

- `scope_id`
- `thread_id`
- principal 类型与 user/anonymous ID
- `last_read_event_seq`
- `updated_at`

用户和匿名访问者分别通过部分唯一索引保证每个 scope/thread 只有一条状态。表启用 RLS，浏览器角色无直连权限，仅 `service_role` 可由 `resume-comments` Edge Function 读写。

scope 级 `resume_comment_read_states` 继续作为“全部已读”游标。线程是否未读按以下规则计算：该线程 `thread_created` / `comment_replied` 的最大事件序号，大于 scope 全部已读游标与该线程已读序号的较大值。

### 写入行为

- `mark_thread_read` 原子推进指定线程游标；若已经没有其他未读线程，同时推进 scope 全部已读游标。
- `mark_read` 保留为“全部已读”，推进 scope 游标并清理已被覆盖的线程状态。
- 评论作者自己的写入只推进对应线程游标，不再推进 scope 全局游标，避免清除其他讨论的未读提醒。
- `document_synced` 不再推进评论已读游标。

现有事务函数通过保留原签名的安全包装层调整读游标副作用，避免复制评论写入主体并保持 Edge Function 兼容。所有新增函数仅授予 `service_role`。

### Bootstrap 与缓存

Bootstrap 在同一个数据库 RPC 内返回每个线程的 `latestCommentEventSeq` 与 `lastReadEventSeq`，不新增 Edge 到数据库的串行往返。客户端把它归一化为 `threadReadStateById`。

本地缓存按 scope/principal 保存线程游标。点击线程时先乐观更新 UI，再写缓存和服务端；网络失败保留待同步状态，下一次 bootstrap 在本地游标领先时补偿提交。服务端返回更大的游标时只向前合并，绝不回退用户已确认的状态。

## 评论面板交互

- 删除 `visible + 500ms` 自动已读 effect。
- 列表卡片根据线程未读状态对最外层容器使用统一背景、边框和“新评论”徽标；内部根评论和回复不单独染色。
- 点击卡片先打开详情并乐观标记该线程已读；服务端失败时恢复高亮并给出非阻塞错误提示。
- 标题区显示未读讨论数量，并在数量大于 0 时显示“全部已读”按钮。
- “全部已读”立即清除所有卡片高亮和外层圆点，再持久化 scope 游标；失败时恢复状态并提示。
- 外层 `CommentBookmark` 的 `unread` 由“是否存在未读线程”派生，不再直接比较 scope 的两个全局序号。
- 来源选择器继续通过 scope 全部已读游标显示“新”；当最后一个线程被处理时服务端原子推进全局游标，使跨来源提示同步消失。

## 划词手势状态机

选择监听改为捕获阶段的完整手势状态：

- `pointerdown` / `selectstart`：进入指针选择中，取消旧计算并立即清除划词按钮。
- 全局 `pointerup` / `pointercancel`：结束指针选择，等待浏览器提交最终选区后再计算。
- Shift + 方向键、Home、End、PageUp、PageDown 的 `keydown`：进入键盘选择中并隐藏按钮；对应 `keyup` 后再计算。
- `selectionchange`：手势进行中只负责保持按钮隐藏；非手势状态下通过短暂稳定窗口合并连续事件。
- `blur`、页面隐藏和组件卸载：取消待执行计算并清除手势状态。

每次计划计算都带 generation 标识；新手势开始会使旧任务失效。最终提交前再次检查当前没有活跃指针/键盘手势、选区非折叠、唯一 range 属于简历根节点且几何可见。

减少动态效果只影响按钮进出动画，不改变显示时机。

## 数据迁移与兼容

- 新迁移创建线程已读表、私有包装函数和 bootstrap 扩展。
- 历史 scope 游标作为所有线程的初始下界，因此不会把过去已读内容重新标为未读。
- 迁移前已经被错误推进为已读的内容无法可靠恢复；迁移后的新事件按线程语义处理。
- Edge Function 与前端必须在数据库迁移后部署；数据库包装层保持旧客户端继续可用。

## 验证

- 打开面板并停留不会改变未读状态。
- 两个线程未读时先打开较新的线程，较旧线程仍高亮且外层圆点保留。
- 打开最后一个未读线程后圆点与全部已读按钮消失。
- 已读线程收到新回复后重新高亮。
- 点击“全部已读”一次清除所有高亮，并在刷新、换设备后保持。
- 自己在一个线程回复不会清除其他线程未读。
- 鼠标拖选停顿、拖出简历区域释放、触摸选择手柄、Shift 键盘扩选期间按钮均不出现。
- 选择结束后按钮只出现一次，并固定在最终 range 的最后矩形附近。
- `Escape`、折叠选区和无效跨节点选区继续清除按钮。
