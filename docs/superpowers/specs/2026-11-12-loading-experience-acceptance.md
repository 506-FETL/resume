# 加载体验调整验收记录

日期：2026-11-12。依据：[评估与取舍](2026-11-12-loading-experience-design.md)、[实施计划](../plans/2026-11-12-loading-experience.md)。

用户已授权根据评估直接实施、最后审查。本轮代码已实施；类型、构建、全项目格式检查与本记录列明的浏览器验收通过；用户最终审查尚未进行。前端未发布，没有数据库迁移或 Edge Functions 变更，没有 commit 或 push。

## 1. 实际变更

- 页面与内容首次读取：列表、填写表单、首页模块、优化报告、求职详情、历史元信息和分享链接采用对应的局部骨架。已知标题、导航与动作保留。
- 图片与简历：模板目录、创建向导、模板切换、首页与简历库缩略图采用固定比例纸张占位；仍等待真实图片解码或预览成品，失败保留重试。没有改测量、分页或打印正文。
- 共享入口：19 个延迟组件注册改用表单或内容占位；路由分包采用轻量结构。简历库的路由与数据读取共用原条目骨架，保留 88/132px 左侧纸张、正文滚动及固定页脚。
- 刷新与短操作：求职刷新保留已有职位和统计，失败提供局部重试；公司选择器只留控件内一处反馈；自动保存文字与读屏状态即时更新，Spinner 延后 200ms。已存在的简历库、分享与历史缓存/刷新机制保留。
- 助手：会话列表返回后立即展示；消息失败重试只重读消息，保留成功列表。首次失败有实际重试入口，不再冒充空对话。
- 公开分享：网络失败与链接不可用分开；网络失败可重试，密码验证网络失败保留表单和输入；权限失效仍走原 unavailable/password 分支。
- 继续保留：保存、创建、删除、上传、绑定、同步、生成、识别、检测、导出与加载更多的必要就地反馈，不增加虚假百分比。

| 使用 PageLoading             |   11 处 / 7 个文件 |   3 处 / 1 个文件 |

## 2. 浏览器与状态验收

正式模板页使用本地开发服务的真实公开目录与图片；其余登录态场景用临时 `tests/loading-audit/` 夹具挂载正式组件和 Zustand store。助手与分享使用正式 hook / API 入口，仅在浏览器网络边界返回合成响应；未调用真实 AI、未写入云端业务数据。夹具结果不能作为线上性能或持久化验收。

| 手机模板慢图     | 390×844，可见 Spinner 为 0，无横向溢出；解除延迟后真实图片完成，首张自然宽度 794px。                                                                                                                  |

| 弹窗与焦点       | 模板预览/信息步骤、优化选择简历各连续两轮打开关闭，关闭后焦点回到触发器；退出中再次打开后仍正常显示。仅填写临时输入，没有点击最终创建、没有持久化业务记录。                                           |
| 延迟分包         | 使用真实 createDeferredComponent 加载临时模块：等待时为表单骨架、无 Spinner，加载后输入可用；主动中断模块请求时保留标题/关闭与错误重试，解除中断后重试成功。                                          |

| 公司选择         | 慢读取时仅 1 个 Spinner，输入高度保持 36px；展开/退出可用，失败有具体错误。夹具保持匿名 scope，重试按钮的网络持久化链路未在此项验收。                                                                 |
| 自动保存         | 进入 saving 后早期 0 个 Spinner；约 80ms 内完成仍为 0，持续保存后为 1。文字和读屏状态不等待延迟计时。                                                                                                 |
| 动态减少动效     | 挂载后切为 reduce，骨架 animate-pulse 类归零，document.getAnimations() 中运行的动画为 0；切回后脉冲恢复。保留必要状态信息。                                                                           |
| 助手独立就绪     | 正式 bootstrap：消息仍挂起时列表已有 2 项，loadingConversations=false、initializing=true。                                                                                                            |
| 助手错误重试     | 消息失败有重试；重试时仍保留 2 项、列表 loading=false，列表请求仍只有 1 次。消息随后成功展示；列表本身失败不显示“暂无对话”，重试后恢复。                                                              |
| 助手迟到响应     | 消息切换挂起期间退出本地合成会话，再释放旧响应，conversations/messages 均保持 0；重新建立合成会话后恢复，并通过 A→退出→B→退出→A 的列表归属检查。没有使用真实用户凭据。                                |
| 分享操作去重     | 正式桌面卡片、快捷链接行和手机抽屉各自验证：无操作弹窗时保留 1 个圈，设置弹窗提交时总数仍为 1（仅弹窗按钮），关闭后保留的 shareId 不会抑制后续行内反馈。真实 busy 仍控制禁用与 aria-busy。            |
| 分享状态         | 首次为纸张占位，0 个 Spinner；503 显示“暂时无法加载简历”及重试。重试进入密码表单；验证网络失败后输入保留；wrong_password 与 404 分别显示密码错误、链接不可用。                                        |

验收时修正了两个断言口径：离屏缩略图按需加载，其纸张占位不表示“列表尚未显示”，应以卡片与名称为准；状态过渡截图等待既有动画结束后再评估最终布局。受控中断的 503、图片失败、模块失败控制台日志是预期场景，不记作正常入口错误。

## 3. 独立代码与动效审查

按 `requesting-code-review` 独立检查五个任务及跨模块关系，按 `review-animations` 检查公共参数、减少动效、过渡和主题属性。初审三项问题均已修复并复核：

| 发现                            | 修正与验证                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------------- |
| 助手消息重试清空已成功列表      | 错误状态保留失败消息目标，仅重读消息；浏览器核对列表仍显示及请求次数。账户切换仍清除重试目标。    |
| 新图片淡入覆盖 dark:opacity-60  | 外层执行 opacity 淡入，img 保留主题 CSS；实际深浅色 computed opacity 验证。                       |
| 路由骨架与真实简历/求职布局不同 | 提取并复用轻量简历条目骨架；求职手机用列表、桌面用真实阶段列名。依赖不引入页面 store 或编辑引擎。 |

最终剩余 Spinner 盘点补齐分享叠层弹窗的背景反馈去重，新增选择器同时检查 open 和对应 shareId，已通过独立增量审查。

独立最终源码审查结论：五个任务符合本期主要规格，无剩余必须修复项。实施和代码审查不等于用户已经审查通过。
