# 求职看板拖拽落位验收

日期：2026-11-11。

- 实施：完成。仅调整共享拖拽收尾和看板卡片交接，沿用现有 Motion、WAAPI、卡片及确认组件。
- 验证：首轮 22 组浏览器场景通过；收尾返修新增 15 组复测通过，返修后的类型检查、构建和全仓格式检查也已通过。
- 用户审查：首轮用户反馈落位末端仍有卡顿，本次返修等待复查。技术验收不代替用户对拖拽手感的最终审查。

## 问题与处理

用户反馈跨列拖动松手后卡片像瞬移。旧实现将悬浮预览在松手位置淡出，同时在目标列重新挂载卡片，播放上移 8px 的列表入场；两个位置之间没有连续运动。

本轮保留松手后的预览，等真实卡片 DOM 就绪再测量其位置和尺寸，以公共时长和 `EASE.out` 完成落位。首轮为 280ms，收尾返修后改为 `DURATION.base`（200ms）。预览移动时保持不透明，真实卡片暂时透明、保留布局与指针命中，落稳后直接交接；源列和目标列的其他卡片继续使用原有布局动画。普通首次入场保留原有错峰。

异步保存排队期间不猜测目标坐标，也不为动画提前修改岗位状态。实际布局更新后即可落位，不必等待远端响应；失败发生在收尾期间时，从当前视觉位置重新向回滚后的真实卡片移动。投递补充、恢复流程和录用 / 结束确认仍走原入口，等待用户决定时预览先回源。

逐帧测试还发现 WAAPI 完成后立刻 `cancel()`，会在 React 卸载预览前露出原始 transform，产生一帧回闪。现在先保留终点 transform 和 opacity，再清理动画与预览。重新拾取和运行中开启减少动效仍能中断收尾。

这是已有交互的局部修复，按仓库轻量任务规则直接实施，未另建规格和实施计划。已阅读防回归清单，以及 2026-10-29 动效补齐的拖拽设计、计划和验收；参考 `transitions-dev` 的位置过渡原则，具体时长与缓动继续使用仓库预设。

## 首轮浏览器验证

使用本机 Chrome、真实 `BoardView` / `CrossListDragProvider` / 卡片 / 确认弹窗和 Zustand store，在隔离浏览器中加载合成岗位。普通保存的外部边界用可控异步结果覆盖延迟和失败；投递补充、恢复流程使用真实 store 队列入口。验收阻断远端请求，没有写入用户岗位或调用模型。

22 组场景均通过，浏览器运行错误和记录到的无障碍警告为 0：

- 跨列落位逐帧连续、预览与真实卡片不重复可见；连续两轮往返。
- 同列放下、Escape 取消、容器外放下、源卡移除。
- 450ms 延迟更新布局、落位中保存失败回源、快速再次拾取且旧保存完成不清除新预览。
- 录用确认两轮取消后确认、退出中再次拖入、已结束取消与确认；取消后焦点回到卡片。
- 键盘移动、拖后立即用标题 Enter 打开详情。
- 初始减少动效、落位中开启减少动效、跟手时切换减少动效。
- 13 张卡片的长列表和深色、1024px 横向滚动、长标题和跟进内容的高度交接。
- 真实投递补充与恢复流程队列不留下悬浮预览。
- CDP 模拟触摸的长按移动、松手落位与取消。

最终逐帧样本中，预览从 `(1121, 320)` 连续到达真实卡片的 `(1089, 119)`，位置和尺寸交接误差小于 1px。动画阶段预览 opacity 保持 1、真实卡片保持 0；交接后预览移除，真实卡片 opacity 为 1。这里的坐标仅用于同机场景验收，不表示任意设备的固定布局或性能承诺。

实际通读了看板标题、职位、公司、空列和确认文案，没有新增产品提示或调整布局。手机仍沿用现有列表入口；触摸检查属于浏览器模拟，未宣称完成 iOS / Android 实机或 Safari 验收。未更改数据库、Edge Functions 或保存协议，前端未发布到线上。

## 落位收尾返修

用户复查后指出，最后落到目标位置时仍有明显卡顿。首轮验证了位置和可见性，没有覆盖两份卡片外观的完整交接。

再次采样发现，接近终点时还有较长的减速尾段，悬浮卡片的 `shadow-xl` 和外圈却一直保持全量，到预览卸载时突然消失。鼠标停在落点内时还复现了另一处差异：透明的真实卡片已经进入悬停背景和边框，预览仍保持普通外观，交接时样式直接切换。

返修将落位缩短到公共 200ms，保留原缓动；阴影和外圈单独放在装饰层，以 opacity 在落位过程中退去，不逐帧动画 box-shadow。卡片预览存在期间暂不启用真实卡片的悬停样式，交接后沿已有 CSS 过渡恢复悬停反馈，指针命中和快速重新拾取仍保留。

本机 Chrome 的稳定开发页面连续三次采样，最大帧间隔分别为 17.3、17.5、17.5ms，未记录到超过 50ms 的主线程长任务；这只说明该隔离场景，不代表所有设备和页面负载。最终预览阴影 opacity 已为 0，坐标与真实卡片一致；鼠标留在落点内时，预览存在的各帧背景、边框也与真实卡片一致。

15 组返修复测全部通过，浏览器错误和记录到的无障碍警告为 0：阴影逐帧消退、落点悬停交接、两轮往返、收尾中再次拾取、Escape / 同列 / 容器外回位、慢队列、失败回滚、初始及运行中减少动效、深色长列表和长卡片、1024px 横向滚动、确认弹窗两轮取消与回焦、键盘和拖后 Enter、CDP 触摸移动与取消。使用真实组件和同样的隔离持久化边界，未写入真实用户数据。

返修证据保存于 `.superpowers/tracker-drop-end-20261111/`，包括修复前后逐帧结果、三次稳定采样、悬停交接样本、15 组检查结果和截图。

## 动效复核

按 `review-animations` 检查，仓库已确认的时长、缓动和减少动效规则优先于技能通用建议。

| 原表现                                               | 本轮处理                                                                                                | 原因                                       |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 预览在原地淡出，目标卡片另播入场                     | `cross-list-drag.tsx:249` 测量真实节点并连续落位；`board/index.tsx:58` 关闭交接期间的重复入场和布局投影 | 保持松手位置与目标位置之间的连续性         |
| 等待异步状态时没有可衔接的落点                       | 共享拖拽接收保存 Promise，先保留预览，布局就绪后落位；需要用户操作的队列先回源                          | 动效跟随真实状态，不跳过业务确认           |
| 动画完成清理时闪回原始 transform                     | 完成回调先写入终点样式，再取消动画与卸载                                                                | React 提交之前也保持终点，消除最后一帧回闪 |
| 若用 visibility 隐藏真实卡片，会失去快速重新拾取入口 | 交接期间只让真实卡片透明，保留指针命中；新拖动清理旧收尾                                                | 快速反向可以中断，旧完成回调不影响新拖动   |

补充复核：`board/index.tsx:168` 将阴影装饰与卡片内容分离，落位时淡出；`column-card.tsx:42` 在预览期间保持普通外观，交接后恢复悬停过渡。`cross-list-drag.tsx:298` 使用公共 200ms 收尾，缩短减速尾段。

结论：Approve。新增收尾仅动画 transform / opacity，复用公共 200ms 曲线；没有新增高频几何读取循环，减少动效实时生效。保留原有键盘行为和组件复用。用户对手感的最终审查仍待进行。
