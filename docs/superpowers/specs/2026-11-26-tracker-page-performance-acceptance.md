# 求职跟进性能验收

## 复测口径

前后使用同一份合成岗位，包含公司、阶段笔记、子轮次和跟进活动。通过本地生产构建的真实页面测量，接口使用固定延迟的浏览器夹具。首岗以数据卡片可见且能够接收操作为准。数据库查询、权限与保存另行使用 PostgreSQL 和已链接的云端项目验证。

## 本轮覆盖

- 桌面看板每阶段首批 12 条，桌面和手机列表首批 32 条。查询多读一行判定是否有后续。输入法组合期间保留输入，完成后再按公司、岗位、地点或薪资搜索。
- 首屏独立启动岗位和统计读取。候选和详情随对应操作加载。行内操作保留目标岗位的写入顺序和数据库返回值。离开再返回、分页失败重试、账户切换和已归档的页外深链分别检查。
- 中文公司名称排序与公司分组需要保持既有顺序。完整范围操作按当前筛选取得摘要，界面仍分批挂载。全选以完整匹配结果为准。

## 数据库与真实写入

- 在隔离 PostgreSQL 中创建 1,208 个岗位，其中常规 1,058 个、归档 150 个。旧全量响应为 5,201,298 B。新列表首批 33 行含探测行，共 17,763 B，看板八列首批共 104 行，55,979 B，统计另为 472 B。读完常规列表用了 34 页，末页 2 项。核对了八组排序与 576 种旧流程、回退和已结束的历史响应率计算。
- 执行计划显示，加入分页索引前，第一页仍关联 1,058 个岗位的投递记录。索引生效后，看板每列关联 13 个岗位，列表关联 33 个。相同数据的本机 PGlite 采样中，看板查询中位数从 16.610 ms 降至 1.342 ms，列表从 27.504 ms 降至 0.424 ms。
- 已链接云端的两个临时账户用于检查登录读取、归档、匿名拒绝及跨账户隔离。对 7 岗位账户的六轮交替公网读取，旧响应耗时中位数 396.5 ms，新首批岗位 347.5 ms、统计 339 ms，每轮取两项较晚完成者的中位数 347.5 ms。旧解压响应 55,288 B，新岗位及统计合计 3,787 B。样本量及网络条件限制了这些耗时的可推广性。
- 真实页面完成新增、编辑、跨页简历绑定、保留既有历史的跟进追加、冻结版本投递及原件更正。旧版选择投递原件读取 4,900 B 简历目录及 5,805 B 版本目录，新版只读取该岗位绑定简历的名称（35 B），展开版本才读一页。更正原件调用一次现有 Edge Function，响应地区为 us-east-1，岗位更新时间与数据库中的原值一致。
- 开发包的 42 项和生产包的 45 项批量归档均注入一次失败，最多并发 4 个写入。生产包其余 44 项成功落库，列表查询 0 次，统计更新 1 次。重新归档失败项目后，未归档数归零。需要用户确认的两个岗位依次打开正式投递和恢复流程表单。对刻意延迟的统计，批量写入结束即可操作。
- 迁移 20261126090600 和 20261126094600 已部署，两项索引均有效。云端与本地 91 条迁移记录逐项一致。沿用现有 Edge Functions。云端权限及操作验证使用的临时账户和数据已清理。操作账户关联的岗位、公司、简历、版本、投递与修订六张表分别确认零残留。

## 交互与请求边界

- 149 条岗位时，桌面看板默认展开的七列首挂 84 项，手机首挂 32 项。滚动可到第 149 项。查找唯一的第 149 项只传回一条卡片，测试夹具解压 JSON 为 605 B。中文组合输入只提交最终词。完整范围已缓存时，直接按本地摘要匹配。
- 进入批量模式的岗位请求为 0 次，点击全选后得到 149/149。搜索“样本岗位14”再全选得到 11/11，其中包含首批之外的岗位。
- 将首批列表延迟 3.2 秒，深链仍可独立按主键打开第 149 个岗位。再次返回列表显示原首批。重点关注深链只发起该条件的首批与统计。验证了统计或分页各自失败后单独重试，以及账户 A→B→A 期间的迟到响应。
- 对真实分包模拟慢响应和 HTTP 503，核验关闭、再次打开、快速反向切换、局部重试和键盘回焦。另核验桌面键盘跨阶段拖动与取消、窄屏减少动效、匿名入口无岗位业务读取。
- 公司选择器按名称、ID 分页。154 家公司样本保留既有 Intl.Collator 名称匹配。足够显示一页即停，关闭或换词停止后续扫描。罕见或无匹配的搜索可能读完公司名称，同名歧义只补读对应公司的代表岗位。

## 首屏加载顺序复查

初版将岗位请求前移后，标题绘制慢了约 0.17 秒。对照资源瀑布发现，认证、外壳和页面代码开始争用网络。最终在直达求职跟进时优先发起工作台主入口，认证、当前视图和岗位读取继续并行。单独改变这一项，桌面标题三轮中位从 1.808 秒降至 1.360 秒，手机从 1.760 秒降至 1.360 秒。实际可操作岗位单独计时。

## 最终生产包对照

使用 Chrome for Testing 158、固定 75 ms 网络延迟、900 KiB/s 下载、2 倍 CPU 降速，分别以 1365 × 900 和 390 × 844 测量。48 个合成岗位分属 12 家公司、8 个阶段。两版各使用全新浏览器上下文，以交替运行的三轮中位数记录。最终包入口为 `index-BZTr8AIn.js`。

| 指标                             | 桌面旧版 → 最终版   | 手机旧版 → 最终版   |
| -------------------------------- | ------------------- | ------------------- |
| 最大内容绘制（页面标题）         | 1,596 → 1,340 ms    | 1,576 → 1,340 ms    |
| 首个岗位请求发出                 | 3,916 → 2,319 ms    | 3,800 → 2,327 ms    |
| 首个岗位可见且可操作             | 4,303 → 2,702 ms    | 4,187 → 2,688 ms    |
| 首屏 JavaScript（gzip）          | 773,236 → 454,481 B | 773,236 → 448,959 B |
| 首屏业务响应（解压 JSON）        | 87,342 → 29,516 B   | 87,342 → 20,398 B   |
| 搜索唯一岗位直到出现             | 29 → 26 ms          | 196 → 598 ms        |
| 首次打开岗位直到真实跟进记录出现 | 217 → 619 ms        | 194 → 653 ms        |
| 再次打开同一岗位                 | 135 → 127 ms        | 140 → 112 ms        |
| 离开再返回页面                   | 212 → 210 ms        | 211 → 203 ms        |

首屏业务请求在两版中都是两次。旧版请求公司目录和完整岗位工作流。最终版并行读取岗位摘要和统计，手机首次仅获取 32 条展示记录。桌面样本的看板首批已覆盖当前范围，搜索直接使用本地摘要。手机的同次搜索需要读取尚未加载范围的匹配结果。桌面首次从看板切换至列表从 231 ms 变为 364 ms。

首次点开详情额外下载约 69 KB gzip 的功能代码，同时读取该岗位的流程。重复打开或离开再返回时，两种设备的岗位业务读取次数均为零。这些数据是受控条件下的对照，线上用户的网络、岗位数量与正文长度会影响实际耗时。
