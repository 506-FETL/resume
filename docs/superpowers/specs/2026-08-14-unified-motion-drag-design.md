# 全仓库 Motion 拖拽统一设计

## 1. 背景与目标

移动端“调整模块顺序”已经使用 `motion/react` 的 `Reorder`、独立拖拽手势和滚动隔离，解决了首次拖动失效、Drawer 手势竞争和非 cancelable `touchend` 警告。仓库其余排序仍依赖 `@hello-pangea/dnd`，导致两套手势、动画和可访问性实现并存。

本次改造的目标是：

- 全部**排序或跨容器移动**统一使用 Motion 方案；
- 保留各页面既有的数据语义和视觉结构；
- 原来有拖拽手柄的入口继续使用手柄，原来整卡拖拽的入口继续整卡拖拽，不额外增加手柄；
- 首次拖动即可生效，拖拽与滚动、点击、展开、开关等操作互不竞争；
- 删除 `@hello-pangea/dnd` 依赖和所有相关类型、Portal 补丁。

## 2. 范围

### 2.1 纳入迁移

| 场景 | 现有行为 | 迁移方式 |
| --- | --- | --- |
| 移动端简历模块排序 Drawer | 纵向排序，有手柄 | 保留 `Reorder`，接入共享行为与验证 |
| 桌面端简历侧栏模块标签 | 横向排序，有手柄 | `Reorder.Group axis="x"` |
| 桌面端简历编辑面板 | 纵向排序，有手柄，展开项拖动时收起内容 | `Reorder.Group axis="y"` |
| 模板结构面板 | 主栏/侧栏内排序及跨栏移动，整卡拖动 | Motion 跨列表拖拽控制器 |
| 求职看板 | 职位卡片跨列改变状态，整卡拖动 | Motion 跨列表拖拽控制器 |

### 2.2 不纳入迁移

- 图片上传区和简历文件导入的文件拖放；
- 浏览器原生文件 `dragover/drop`；
- 非排序用途的滑块、画布缩放、Drawer 打开/关闭手势。

这些交互不依赖 `@hello-pangea/dnd`，也不属于列表排序。

## 3. 统一交互规范

### 3.1 启动区域

- **原来有手柄：** 设置 `dragListener={false}`，只允许手柄调用 `useDragControls().start(event)`；手柄使用 `touch-action: none`，不影响列表其他区域滚动。
- **原来没有手柄：** 整张卡片是拖拽启动区，不新增任何图标。按钮、开关、链接、输入框及带交互语义的后代必须从启动判断中排除。
- 点击但未形成拖动时，继续执行原来的选择、打开详情或展开行为。

### 3.2 拖动反馈

- 拖动项轻微放大到 `1.015`，提高阴影并提升层级，不旋转、不做夸张位移。
- 同列表兄弟项通过 `layout="position"` 和统一弹簧参数平滑让位。
- 跨列表拖动显示 Motion 浮层，原位置保留弱占位；目标列表高亮，并在预计落点显示插入提示。
- 尊重 `prefers-reduced-motion`，关闭缩放和弹簧位移动画，但功能保持可用。

### 3.3 滚动与边缘自动滚动

- 拖拽区只拦截拖动所需的指针序列，不全局阻止 `touchmove/touchend`。
- 所有 `preventDefault()` 调用前检查 `event.cancelable`，不得再出现 `cancelable=false` 警告。
- 单列表根据主轴在容器边缘自动滚动；横向标签滚动 x 轴，纵向列表滚动 y 轴。
- 求职看板在左右边缘滚动整个看板，在列顶部/底部滚动当前列。
- Drawer 内容继续使用原生纵向滚动；拖拽手柄和 Drawer 的关闭手势通过 `data-base-ui-swipe-ignore` 隔离。

### 3.4 数据提交

- Motion `onReorder` 只更新组件内草稿顺序，避免拖动经过每个位置都写入 Zustand、Automerge 或后端。
- `onDragEnd` 只在最终顺序变化时提交一次。
- 外部顺序在未拖动时变化，草稿立即同步；拖动期间保持当前手势快照，结束后再与外部状态对齐。
- 取消、落在无效区域或回到原位均不提交。

## 4. 架构设计

### 4.1 单列表排序原语

在 `src/components/ui/` 下提供共享 Motion 排序能力，职责包括：

- 草稿值与外部值同步；
- 拖动开始/结束状态；
- 键盘前移/后移；
- 边缘自动滚动；
- 统一动画参数和 reduced-motion 处理。

页面仍负责渲染自身卡片和提交最终业务顺序，不把简历、模板或看板领域逻辑放入 UI 原语。

### 4.2 跨列表拖拽控制器

模板结构面板和求职看板不能直接使用 `Reorder.Group` 完成跨容器移动，因此使用共享的 Motion 跨列表控制器：

1. 注册可放置容器及其滚动元素；
2. 启动时记录源容器、源索引、原始矩形和指针位置；
3. 使用 Motion 浮层跟随指针，避免被 `overflow` 容器裁剪；
4. 通过已注册容器矩形和子项中心点计算目标容器与目标索引；
5. 只更新拖动预览和高亮，不提前写业务状态；
6. 结束时将 `{ itemId, source, destination, destinationIndex }` 交给页面；
7. 页面继续调用现有 `reorderSections`、`moveSectionRegion` 或职位状态更新逻辑。

模板结构面板保留栏内排序与主栏/侧栏互移。求职看板保留跨列状态变更；落到“已录用”或“已终止”继续弹出原有确认框，未确认前不落库。

### 4.3 页面迁移边界

- `SortableTab` 与 `SectionRow` 不再接收第三方拖拽 props/ref；改为接收 Motion 控制器、拖动状态和业务事件。
- 展开的 `SectionRow` 开始拖动后只展示紧凑表头，结束后恢复内容；不再 `createPortal`。
- 模板卡片中的显隐开关继续阻止拖动启动和卡片选择。
- 求职卡片内部可点击操作继续正常工作；只有从非交互区域形成有效位移后才进入拖动。

## 5. 键盘与无障碍

- 现有手柄使用 `role="button"`、可聚焦，并声明方向键快捷键。
- 纵向列表使用 `ArrowUp/ArrowDown`，横向列表使用 `ArrowLeft/ArrowRight`。
- 每次键盘移动只提交一次最终顺序，并通过可访问文本更新当前位置。
- 整卡拖拽场景不强行增加视觉手柄；保持卡片原有焦点入口，不把内部按钮包进新的嵌套按钮。

## 6. 错误与竞争态处理

- 指针取消、窗口失焦、组件卸载时必须清理浮层、监听器、滚动循环和 `user-select` 临时状态。
- 同一时间只允许一个活动拖拽；新的启动请求在旧拖拽清理前被忽略。
- 拖动过程中业务数据刷新不重建活动拖拽节点；结束后以最新外部数据校验目标仍存在。
- 目标容器折叠或卸载时视为无效落点，不提交。
- 服务端更新失败继续使用页面既有回滚与错误提示，不在通用拖拽层处理业务错误。

## 7. 验证标准

### 7.1 静态验证

- 源码中不存在 `@hello-pangea/dnd`、`DragDropContext`、`Droppable`、`Draggable` 及其类型；
- `package.json` 和锁文件不再包含旧依赖；
- TypeScript、目标 ESLint、生产构建和 `git diff --check` 通过。

### 7.2 交互验证

- 每个入口第一次拖动都能改变顺序或目标容器；
- 有手柄的入口只能从手柄拖动，无手柄入口不出现新增图标；
- 开关、按钮、展开和卡片点击不误触拖动；
- 长列表可以正常滚动，拖到边缘会自动滚动；
- Drawer 内拖拽与 Drawer 内容滚动均正常；
- 模板可以栏内排序和跨栏移动；
- 求职卡片可以跨列移动，终态确认与失败回滚正常；
- 控制台没有触摸取消、非 cancelable 事件、ARIA 或 React 更新深度警告。

## 8. 非目标

- 不新增看板职位的持久化“同列手工排序”字段；当前看板的数据语义仍是跨列改变状态。
- 不改变模板 manifest、简历 Automerge 文档或职位数据表结构。
- 不重设计卡片外观、不新增拖拽手柄、不改变现有业务提示文案。
