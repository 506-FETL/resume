## 实际改动

- 正文读取与生成器模块加载同时开始，恢复正文后预取其精确模板定义。两份准备任务共用现有模板缓存和在途请求，重排版最多运行一份；不再把所有读取串在上一份完整预览之后。
- 缩略图直接使用 `CanonicalPagedDocument firstPageOnly` 和同一模板运行时。完整正文的测量、字体等待、分页签名和首页内容保持一致，生成阶段只挂一张展示纸页，省去其余整页副本及缩放组件的重复测量。完整预览和打印默认仍渲染全部页面。
- 成品缩放使用 `ResizeObserverEntry.contentRect.width`，断点使用 `MediaQueryList.matches`，不再为这两个位置重读同步布局宽度。原动效和运行中的减少动效偏好保留。
- 保留账户代次、目标/版本/模板/日期缓存键、40 份 / 32 MiB 限额及 Blob URL 生命周期。不可见且未开始的任务移除，读取完成后无消费者就不进入排版，正在生成的结果仍可缓存；失败保留局部重试。

## 生产构建同条件对照

修改前复制当前工作区的 `src` 与 `dist`，不把 Git HEAD 或上一轮 81 分的不同样本当作本轮基线。前后均使用生产构建、同机 Chrome 157、相同 gzip 与缓存响应头。每轮全新浏览器上下文、关闭 HTTP 缓存；页面为真实 `/workspace`。

隔离环境使用两个官方精确模板 `default@3` 与 `classic-ribbon@3`，读取原始公开定义并保留生产哈希校验。两份相同合成长正文各含 18 项工作、72 段中英混排，完整文档各 3 页。使用合成认证会话和 API 响应，没有访问或改写用户私有简历；正文响应固定等待 750ms，其他必要 API 等待 100ms。这是前端机制对照，不是实际公网数据库平均耗时。

## Lighthouse 分数与原始时间分开记录

另以 Lighthouse 13.6.0 的默认 mobile / simulate 运行三轮。与用户原报告的 13.5.0、开发 5173、不同正文及字体集合分开，不宣称把用户的 35 分直接提高到了本次分数。

| ------------ | ------: | ------: |
| Performance  |      79 |      75 |
| 模拟 FCP     |  0.603s |  0.605s |
| 模拟 LCP     |  4.989s |  6.046s |
| 模拟 TBT     | 161.5ms | 167.0ms |
| Speed Index  |  3.147s |  3.063s |

分数下降和模拟 LCP 增长已记录，不能以真实预览变快为由省略。三轮原始 LCP 前为约 450–457ms、后为 464–475ms，候选始终是标题下方说明。简历 Noto/Tinos 字体均晚于该原始 LCP；UI 的 Inter 字体在之前完成。补采完整 trace 和 DevTools 日志后，使用同版本 Lantern 离线复算，逐毫秒复现该次 5.010s / 5.596s。归因如下：

- 原三轮 before 的 8 个摘要辅助脚本中有部分尚未结束或执行，6 次预检都在原始 LCP 后；after 全部辅助脚本和 6 次预检进入了 LCP 截取边界。总下载资源没有增加，但模型认为需要参与该指标竞争的节点增加。
- 补采 after 的图包含共同的 82 个网络节点、8 个摘要脚本和 1 次预检。仅把同一 trace 的 LCP 截点向后移 20ms，不改网络或 CPU 数据，图就多纳入另 5 次预检，模拟 LCP 变成 6.046s。before 截点向后移 50ms，同样变为 6.062s。
- 对扩张后的 after 图移除预检节点，模拟值从 6.046s 降至 5.295s；再移除额外纳入的 8 个摘要脚本，降至 4.995s。统一参数并使用双方共同依赖图，before 为 4.990s、after 为 4.987s，相差 3ms。此处是诊断消融，不是修改浏览器行为或重新计算正式成绩。
- 该版本模型中这些预检仅依赖主 HTML，因而在模拟 HTML 完成约 602ms 时同时进入网络竞争；实际请求是在首次 React 布局之后由业务 API 触发。截取边界和依赖简化共同放大了差异，最终最晚节点仍为同一个 Inter latin 字体；简历 Noto/Tinos 不在这两张 LCP 图中。没有发现新增真实 LCP 必需资源的证据。

因此保留官方报告的 79 → 75 分，不把离线消融改写为提分结果，也不以推迟必要请求来改变取样边界。真实限速 LCP 基本相同、预览完成更快是本轮可确认的用户侧结果。
