## 发现与复验

首轮发现一项字段级缺失问题：合成上游只返回 `completion_tokens=70`、`reasoning_tokens=20` 而不返回输入用量时，`onStepFinish` 因输入未知跳过整个快照更新，最终界面会把这两个已知值写成“未返回”。累计账单已收到输出 70，说明数据在界面快照路径丢失。

主代理随后将“用输入校准”与“合并本步已知字段”分开：输入未知时保留实际请求估算，同时保留独立返回的输出和推理。独立复验通过，包括只有输出、只有推理、两个字段均返回以及 null / 空 usage。

同时复查不完整总量的下限表达：百分比四舍五入或 compact 向上舍入会把“至少”抬高。修复后 7051 已知 token 显示“≥ 7,051”和“≥ 10%”；输入 1000、已知推理 70、总输出未知时显示“≥ 1,070”，输出仍为“未返回”。这两条均已通过真实组件验收。

## 运行器与计数：21 项通过

| 场景                                         | 实际结果                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------------ |
| 相同完整请求连续三次，固定模拟输入 7000      | 28 个工具，估算为 7329 → 8400 → 8400；三次实测均为 7000，没有再次膨胀          |
| 估算和实际输入                               | 每轮请求前标为估算；真实 usage 到达后使用实测输入和输出                        |
| 工具定义增加                                 | 同一消息下估算从 1837 增到 13135，变化来自真实序列化工具定义                   |
| 消息前缀改变                                 | 同工具下估算从 1837 增到 5704，不复用旧前缀数值                                |
| 已测前缀追加                                 | `1000 + 新消息估算 = 1037`；传入 5000 工具回退开销也不会重复相加               |
| 前缀被替换                                   | 真实 counter 回退到消息估算与给定开销，结果 5070                               |
| 两步真实 SDK 工具循环                        | 最后快照为输入 4500、输出 50、推理 30；累计账单为输入 7500、输出 70、合计 7570 |
| usage 整体缺失、空对象、字段 null            | 保留估算输入，未知字段保持未知，不伪造实际 0                                   |
| 只有输出、只有推理、已知输出与推理但输入缺失 | 已知值独立保留，输入继续标记估算                                               |
| 输入已知、输出缺失                           | 输入实测保存，输出不伪造 0                                                     |
| 明确返回 0                                   | 输入、输出、推理均保留真实 0                                                   |
| 推理缺失、真实 0、正常值                     | 三种情况分别保存，不因 SDK 补 0 混淆                                           |
| 请求前停止                                   | AbortError；模型请求数和统计事件数均为 0                                       |
| 流式中停止                                   | AbortError；保留已读正文和估算快照，不生成实测 usage                           |
| 请求失败                                     | 原错误传出；仅请求一次，不自动重试，不伪造实测用量                             |

7329 是修复后 provider 实际序列化输入的初始估算；旧规格中的 9470 来自修复前不同计数路径，不将两个数值当作同一测量口径。

## 正式组件：28 项通过

- 新会话与首次输入均显示“未发送”；已有统计时连续打字、引用变化、目标变化保留草稿和“上次调用”。
- 发送准备及技能加载保留上次统计；本次请求出现后优先显示本次估算，再切换实测。
- 输入 7000、总输出 100、推理 40 显示总量 7.1K、文字输出 60、推理 40；推理没有重复加入总量。
- 真实零值显示 0；缺失输出和推理显示“未返回”；下限总量不向上舍入，已知推理计入下限。
- 最新 assistant 没有 usage 时显示“未记录”，不会退回更旧记录；新用户消息不会自行抹掉前次 assistant 的统计。
- 换会话、切换读取中和账户变化不显示旧百分比；读取失败有独立状态。
- HoverCard 两轮完整关闭与打开、退出中反向打开、Escape 关闭与回焦通过；键盘 Tab 聚焦后可用 Enter 打开，Escape 后不会立即重开。
- 320 / 390 / 1440 px 的深浅色浮层均在视口内，无水平溢出。实际查看了深色桌面截图并通读本次文案。
- 运行中切换减少动效后，浮层实际 animation-duration 为 0s。
- 没有 pageerror；隔离浏览器没有向外部域名发出请求。
