# 文件读取与后续对话修复

2026-11-17。用户已授权修复上传文件无法读取、后续轮次丢失来源及文件页数限制。本期完成实现与验证后交用户审查，不重复申请实施许可。

## 原因与方案

上传已改为只保存原件，但 `read_experience_source` 遇到零段落直接失败，目录又排除了 `kind=file`，导致首次附件读不到、下一轮附件消失。旧简历提取器包含 30 页和 60000 字符限制，不能直接当作普通文件读取器。

采用按需读取原件：上传只检查单文件 10 MB，任意格式与空文件可保存；助手读取时下载已授权的明确版本，在浏览器用已有 PDF.js、fflate、SheetJS 解析支持的文字格式。不上载提取结果，不修改档案正文，不调用额外模型。上传时提前提取会恢复旧限制；每轮注入全部文件会增加等待与上下文，均不采用。

## 边界

- PDF、DOCX、TXT、Markdown、CSV、XLS/XLSX 支持正文读取；PDF 不限制页数，文字不截到 60000 字符。长资料仍分段、分页返回模型，保留真实页码及稳定段落 ID。空白页可跳过，但明确说明未读到文字的页码，不能把扫描页当作已读。
- 不支持的格式、扫描件、加密或损坏文件只影响内容读取，不阻止保存。错误说明真实原因；不能让用户反复重传已经保存的有效文件。
- 原件读取与已有 Blob 缓存共用账户/资料/版本身份；成功与在途解析复用，失败不作为空数据缓存，账户或资料变化取消旧解析。旧版本引用继续读取指定版本。
- 全库和当前对话目录包含文件元信息，不提前下载全部正文。显式附件优先；无显式附件时包括职业档案和当前对话附件，其他对话附件继续不可读。历史投影与压缩指纹同步升级。
- 搜索保留已有已提取文本检索；对未索引文件返回准确的可读候选，模型按名称和目录选择读取，不把未索引解释为无相关内容，不自动下载整个库。
- 真实出处点击复用同一按需读取器，不能生成无法定位的临时出处。详情仍默认原件，不提前解析。所有布局、控件和动效沿用现状。
- 本期普通文件上传覆盖档案与助手附件，不重写简历创建向导、投递附件等独立业务流程。发现旧协议页数限制需一并解除时，保留正文/页码一致性与权限约束并完成后端部署。

## 验收

真实入口上传 DOCX、超过 30 页 PDF、超过 60000 字符 TXT、未知格式、空文件与超 10 MB 文件；核对上传无解析、仅超大小拒绝、原件下载字节一致。助手首轮概括、无附件追问、刷新重开、明确附件范围、不同会话与账户隔离、历史版本、分页末尾及出处定位。失败后重试，不支持与扫描页说明真实。执行局部格式、ESLint、TypeScript、构建及全仓格式检查；临时脚本与数据放 tests/source-file-reading，结束清理。

状态：设计与实施完成；验证通过；用户审查待进行。

## 用户追加：避免每 8 段重复调用模型

用户实测看到连续多次读取并指出速度不可接受。本节覆盖前文的固定分段返回要求。根因是把阅读器每批段落数直接用于模型工具；本地解析复用只省解析，不能省每批一次的模型网络与推理。

官方依据（2026-11-17 核对）：[OpenAI File inputs](https://developers.openai.com/api/docs/guides/file-inputs) 支持文档直接进入上下文并建议大文件使用 File Search；[File Search](https://developers.openai.com/api/docs/guides/tools-file-search) 组合关键词与语义检索；[Claude Projects RAG](https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects) 在接近上下文上限时切换检索；[Gemini 文件处理](https://ai.google.dev/gemini-api/docs/document-processing) 区分直接文件输入与复用文件引用，[上下文缓存](https://ai.google.dev/gemini-api/docs/caching) 复用重复输入。上述是官方能力，不代表本项目已经接入供应商文件存储、向量检索或缓存服务。

本期采用适合现有文字模型的全文/检索混合：普通文档在本轮实际剩余 token 和字节预算内一次返回全部正文与出处；长文件首读给出明确的局部预览与范围信息，支持对整份已解析正文做关键词检索，定位后直接返回相关段落及邻文。保留 offset/blockIds 兼容旧记录和明确的继续阅读，但不把 8 段作为默认。不能用局部预览冒充全文总结，超出模型上下文的全文分析仍需分批任务。此次不增加向量数据库、额外模型费用或后台自动摘要。

预算使用 provider 实际组装的 messages/tools，预留既有输出与工具空间；同一步多个工具输出共享剩余额度，不能各自吃满。已保存旧段落由应用在一次工具内聚合，必要 API 分页不再让模型逐页发起。新原件复用完整解析缓存。验证同一 35 段 DOCX 从多次工具读取变为一次完整读取；长文档尾部关键词一次命中，预算边界不截断或冒充全文，原出处/账户隔离/取消继续通过。

## 实施中发现的出处关联

真实追问复用全文后，UI只认可本条回复工具证据，导致出处无法定位。既有消息按该轮冻结来源从同账户、同会话、当前消息之前的已读记录回退；新回复只保留实际链接到的、范围内的历史段落证据，随回复JSONB保存，不伪造工具调用，不复制全文。流式、停止、保存失败恢复和模型历史范围投影同步支持。验证原工具位于最近30条以外，刷新仍可点击出处，以及换版本、范围撤除、伪造引语和未来消息拒绝。
