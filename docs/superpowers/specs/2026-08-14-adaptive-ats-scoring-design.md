# ATS 内容自适应评分设计

## 背景

现有 ATS 分析把经过 `normalizeResumeFormData` 补齐后的完整简历结构直接交给大模型。即使用户从未填写工作经历、项目经历、证书、自我评价等模块，这些模块仍会以默认空对象或空数组出现在输入中。同时，现有提示词只约束输出结构和各维度上限，没有定义模块适用性、跨模块证据替代关系和可复现的评分量表；岗位基准工具还直接使用“已填板块数 / 12”以及项目、证书、自我评价的固定数量目标。

这会使模型把“没有使用某个模板模块”误判成“简历内容不合格”，也会忽略工作、实习、项目、校园经历之间能够互相证明能力的事实。

## 目标

- 只依据用户实际提供的内容进行 ATS 评估，不按固定模板模块数量扣分。
- 由大模型综合判断候选人画像、目标方向、内容适用性和证据强度。
- 保留真正影响简历可用性的必要检查，例如缺少联系方式、有效内容过少或已有经历内部信息残缺。
- 开启大模型思考模式，同时保证最终结构化 JSON 的完整性和可校验性。
- 将 ATS 总分统一为 100 分，并向用户解释评分依据。
- 支持所有真实经历条目，不再只允许定位每个数组的第一项。
- 移除岗位基准工具中与固定模块数量绑定的指标和建议。
- 兼容已有 1.0 ATS 报告，不要求迁移历史数据。

## 非目标

- 不把 ATS 通用评估替换成用户提供 JD 后的精确关键词匹配；已有 JD 对比工具继续承担该职责。
- 不为用户编造经历、公司、学校、技能、结果或量化数据。
- 不把大模型思考过程持久化到数据库或原样展示给用户。
- 不修改 ATS 表结构；新信息存储在现有 JSONB 字段中。

## 核心原则

### 模块缺失不等于内容缺失

整个可选模块完全空白时，将其排除在大模型输入之外，不扣分、不生成补齐建议。工作、实习、项目、校园、教育等内容可以互相提供岗位能力证据；证书、自我评价、兴趣爱好等可选模块不存在时保持中性。

### 已使用条目允许检查内部完整性

重复型经历只要任意业务字段存在有效内容，就视为用户主动使用的条目。此时公司、岗位、时间、职责描述等内部字段的缺失可以被指出，因为问题来自一条真实存在但不完整的经历，而不是模板模块本身。

### 必要信息按实际影响评分

联系方式缺失会影响招聘方联系和 ATS 可用性，因此可以降低 ATS 可解析性。没有显式求职意向时，如果现有经历和技能仍能稳定推断方向，不因“求职意向模块为空”机械扣分；只有整体定位确实模糊时才影响岗位定位与相关性。

### 分数基于整份简历的证据覆盖

评分不向模块分配配额。模型先识别候选人画像和目标方向，再建立能力、职责、成果与可信度证据图，最后按统一量表评分。

## 输入建模

新增纯函数构建 `AtsAssessmentInput`，输入为规范化的 `ResumeSchema`，输出包含：

- `sections`：只包含有意义的真实内容。
- `locationCatalog`：本次允许使用的动态定位目录，覆盖所有真实条目和必要字段。
- `scope`：确定性生成的已评估模块、被忽略的全空可选模块和必要信息信号。

整个全空的可选模块不进入 `sections`。对于已使用的数组条目，保留原数组索引、稳定 `entryId`、条目标签和核心字段；空字段可以保留，以支持指出条目内部缺失。基础信息和联系方式通过必要信号显式表达，不依赖模型自行遍历模板默认值。

`ignoredEmptySections` 只供客户端验证和诊断，不序列化给大模型；模型请求只包含实际 `sections`、已评估范围和必要信息信号，避免用“已忽略模块名称”再次暗示固定模板要求。

动态定位目录是模型可引用路径的唯一来源。目录使用原始数组索引，确保建议能够应用回第二、第三或更多条经历；模型不得输出目录之外的路径。

## 评分模型

总分固定为 100 分：

| 维度键 | 展示名称 | 满分 | 判断重点 |
| --- | --- | ---: | --- |
| `job_match` | 岗位定位与相关性 | 25 | 目标方向是否可推断、经历与能力是否形成一致定位 |
| `content_completeness` | 内容充分度 | 25 | 现有内容是否足以证明候选人适合目标方向，而非填写模块数量 |
| `impact_quantification` | 成果与证据强度 | 20 | 职责边界、技术或业务细节、成果、规模、作品、数据与可验证性 |
| `ats_parsing` | ATS 可解析性 | 15 | 联系方式、日期、岗位和组织名称等关键信息是否清晰可提取 |
| `format_readability` | 表达与阅读体验 | 15 | 层次、句式、冗余、信息密度和扫读体验 |

数字和百分比只是成果证据的一种。模型不得因所有经历都没有数字而直接给低分；明确的影响范围、交付物、复杂度、职责边界、用户或业务结果同样属于有效证据。

等级由程序根据总分确定：0–39 为“较低”，40–59 为“中等”，60–79 为“良好”，80–100 为“优秀”。`summary.overall_score`、每项 `max` 和 `grade` 均由程序确定性校正。

## 大模型评估流程

ATS 保持单次模型调用，但开启 `thinking: { type: "enabled" }`。提示词要求模型在内部依次完成：

1. 判断候选人画像和可推断的目标方向。
2. 从有效内容建立能力、职责、成果和可信度证据。
3. 判断内容适用性与跨模块替代关系。
4. 按五维量表评分并生成证据充分的问题与建议。

最终只输出结构化 JSON。思考流用于现有分析进度，不进入持久化结果。`max_tokens` 提升至 16384，并减少强制凑数：

- `top_risks`：0–3 条。
- `next_actions`：0–4 条。
- `fixChecklist`：0–6 条。
- `findings`：允许全部为空。

建议只能针对动态定位目录中的真实内容或确实必要的缺失信息。不得为全空可选模块创建 Finding、Checklist 或填充建议。

## 结果契约与校验

在现有 JSONB 结构内扩展可选字段，保持历史报告兼容：

- `meta.rubricVersion = "2.0"`
- `meta.assessment`：候选人画像、推断方向、评分依据摘要、实际评估模块和内容信号。
- `scores[*].rationale`：该维度的简短评分理由。

新增运行时解析与规范化逻辑：

- 校验五个评分键存在且分数为有效整数。
- 强制覆盖五项 `max`，并重新计算总分和等级。
- 校验所有 Locate 来自动态目录。
- 校验 Evidence 和 Suggestion 的原始值与输入目录一致。
- 移除无效建议；Finding 如果失去有效证据或定位则整体移除。
- 禁止保存针对被忽略空白可选模块的建议。
- 核心结构无法恢复时中止保存，并给出明确的重新分析提示。

## 页面展示

新报告在评分区域展示“本次评分依据”，包含候选人画像、推断方向、实际评估内容和综合判断。雷达图使用新五维名称与 100 分制上限，维度详情展示 `rationale`。

当没有修复项时，优化完成度显示 100%，文案为“当前未发现必须修改项”。旧版报告没有 2.0 元数据时继续使用已有展示，不渲染评分依据卡片。

## 岗位基准工具

删除以下固定模板指标和建议：

- 已填板块数 / 12。
- 固定项目数量。
- 固定证书数量。
- 固定自我评价长度。
- 强制补齐项目、技能、自我评价等模块的文案。

基准工具改为内容证据画像，展示：

- 有效能力证据数量。
- 有实质描述的经历比例。
- 成果或影响证据比例。
- 内容定位一致性。
- 当前 ATS 综合评分。

这些指标明确标注为参考信息，不直接参与 ATS 总分。

## 数据兼容

ATS 表的 `meta`、`summary`、`scores` 和 `findings` 已是 JSONB。2.0 的扩展信息写入现有 JSONB，不新增列、不修改 RLS、不创建数据库迁移。TypeScript 新字段保持可选，使已有 1.0 数据继续可读。

## 验证场景

- 资深候选人只有充分的工作经历，没有项目、证书和自我评价，不因这些模块缺失而扣分或生成建议。
- 应届生使用项目、实习或校园经历证明能力，没有工作经历时不机械扣分。
- 只有姓名和求职方向的简历因缺少有效能力证据得到低分。
- 已使用的工作条目缺少时间或职责时能够被指出。
- 第二、第三条经历能生成正确路径，并通过结果校验。
- 全空可选模块不会出现在评估输入、Finding 或 Checklist 中。
- 思考模式开启后能够同时处理 reasoning 流和完整正文 JSON。
- 1.0 历史报告能够继续展示。

实现后执行专项验证脚本、类型检查、相关 ESLint、生产构建和 `git diff --check`。在线大模型结果具有非确定性，若未使用用户额度执行真实请求，需要在交付时明确区分静态/夹具验证与线上端到端验证。
