# 官方简历模板远端数据源设计

日期：2026-10-22。承接已确认的模板架构 §17，用户本次明确要求先实施 Supabase 迁移并重点优化性能。在当前分支、当前会话顺序实现，不引入模板切换／升级界面。

## 目标与边界

将两套模板定义、两份示例及目录元数据迁入当前已链接的 Supabase。保留 default@1、classic-ribbon@1、graduate@1、frontend@1 的原始内容和身份。业务简历、协作文档、评论、历史及分享快照不批量改写。

线上数据库是运行时资源真源。本地定义只用于迁移、验证和既有旧分享协议兼容，不在远端失败时回退为别的模板。保留已校验资源的本地缓存，冷启动离线且无缓存时显示可恢复的资源错误，正文仍可编辑。

## 方案选择

采用 Supabase Data API + 公共只读表 + IndexedDB／内存缓存。整库下载会增加首屏负担；额外 Edge Function／CDN 聚合层会增加维护面，当前公开只读配置无需代理。未来若访问规模要求 CDN，可在 transport 层替换，不改渲染协议。

## 数据与权限

- `official_resume_template_versions`：template_id、version 联合主键，content 保存原 JSON 文本，content_hash 为 SHA-256，published_at 区分草稿与发布。数据库校验 ID／版本及哈希。
- `official_resume_example_versions`：example_id、version 联合主键，相同的版本、完整性和发布约束。
- `official_resume_template_catalog`：模板 ID、当前版本、排序、上架状态、metadata；metadata 包含名称、介绍、风格、布局和带文案的示例引用。当前版本外键及发布检查保证目录只指向可用资源。
- 已发布版本拒绝原地修改和删除；下架只撤回目录推荐，精确版本仍可读取。新外观发布新版本。
- 全部表启用 RLS。游客和登录用户仅能读取上架目录和已发布版本，不可写入。受控维护流程使用服务端权限；前端仅使用公开 API key，不等候用户认证，不携带私有简历数据。
- 筛选选项通过只读 SECURITY INVOKER RPC 获取，显式权限和固定 search_path。无需新增或修改 Edge Functions。

## 加载与性能

目录默认每页 12 项，服务端筛选、稳定排序，多读取一项判断下一页，不在列表携带完整正文或定义。目录和筛选选项独立并发加载。AI 列表工具也采用有界分页。

卡片接近可见区域才挂载真实预览；不可见时卸载预览，限制字体测量、分页 DOM 和渲染成本。保留现有卡片／预览交互及减少动效规则。

所有调用方共用 Source 的内存缓存和请求去重，避免预览、创建、分享重复读取。不可变版本按资源种类、精确 ID、版本缓存；目录与筛选选项缓存 5 分钟。IndexedDB 按 Supabase URL 隔离并设数量上限，资源先校验哈希／协议／引用再使用；缓存损坏则移除并重取。缓存不可用时降级到内存和网络。网络并发最多 4，单请求超时 10 秒，失败不永久缓存，支持重试。

## 兼容与失败行为

快照绑定、正文、条目 ID 和评论投影不变。分享仍直接使用发布时的冻结 definition，读分享不强制联网读取目录。迁移工具验证本地和线上 content_hash 一致；未知能力、版本不存在、网络错误区分处理，不自动选择最新版本。

## 验收与发布

验证已发布版本不可变、RLS 游客／登录只读、草稿不可见、目录下架后版本仍可读、索引和批量目录读取。验证冷读／热读／刷新／离线缓存、并发去重、缓存损坏恢复、精确版本错误和失败重试。记录真实请求数与耗时，不把网络环境差异说成性能保证。

两套模板完成预览、创建、刷新、评论字段身份、冻结分享及 PDF 回归；导出覆盖临界页底、多页和背景打印开关。执行类型检查、专项校验、变更文件 ESLint、构建和 diff 检查。

先隔离数据库验证，再部署新增迁移；保留已有迁移账本，不重放无关迁移。迁移完成后核对线上账本、数据哈希、公开读取与禁止写入；无 Edge 变更则核对现有函数版本未改变。前端源码交付不等同于已经部署前端站点。
