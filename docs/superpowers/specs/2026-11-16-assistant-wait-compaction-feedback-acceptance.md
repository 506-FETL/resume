# 助手等待状态与压缩反馈修复

日期：2026-11-16。范围为用户追加的“思考后短暂空白”和“压缩后上下文数字不变”。本轮是既有状态判断和反馈修复，直接在当前分支实施；不修改模型、额度、压缩策略或云端协议。

## 根因与复现

使用正式 MessageBubble、ContextUsage、useChatStream、runAgent、DeepSeek provider 和 Supabase SDK。合成历史包含 6 轮、12 条消息；在请求边界提供固定响应或挂起响应，不替换业务函数，不调用真实付费模型。

- 初次模型请求组装时，onContextUsage 先把统计部件放入 streamingParts。MessageBubble 仅用 parts.length 判断是否已有回复，因此立刻移除“正在思考”，但统计部件不会渲染。修改前实际页面只剩“AI 助手”标题。
- 同一统计部件总在数组末尾，正文渲染又按数组最后一项判断 streaming。正式 SDK 收到第一段 reasoning_content 后，页面立即显示“查看思考过程”，并默认收起文本；流式正文的动效标志也被这项统计截断。
- 手动压缩真实保存摘要检查点，但 ContextUsage 仍展示历史消息内的最后一次模型用量。修改前固定输入 11400、输出 562 的测试在检查点保存后仍显示 18%。这是上次调用快照未区分压缩完成的展示问题，不能据此判定云端摘要失败。
- 带资料标签时还存在实际复用问题：手动入口使用 freezeSourceScope([], references)，冻结资料缺少 updatedAt；正常发送会补齐实时元信息，指纹因此不同。同一份未变化资料的隔离复现中，压缩检查点已保存，下一次准备仍返回 12 条消息且没有摘要。

## 实施与约束

1. 消息可见性与流式末尾采用同一判断：非空思考、非空正文、技能活动和工具调用。统计、来源范围及空文本不结束等待。保留原数组索引和工具标识作为 key，流式增量与保存不重置手动展开状态。
2. 手动压缩整体完成、摘要检查点保存成功且仍属当前视图后，记录本次整理的消息数。入口显示“压缩中”或“已压缩”，详情明确上次调用用量，以及下次发送后更新。已存在可复用摘要时显示“较早对话已压缩，无需再次整理”，不虚构本次整理条数；无摘要的短历史、失败和停止不生成成功状态。
3. 上次调用快照继续保留输入、输出、推理与未知值语义。不用局部历史估算替换包含系统提示、资料及工具定义的完整输入；下一次实际请求组装产生新统计时，清理压缩完成反馈并采用该统计。
4. 完成反馈仅属于当前会话视图；切换会话、账户和 reset 清理，不写入持久缓存。重新打开历史显示上次调用快照，不宣称已重算当前上下文。原消息、最近 4 轮保留策略、摘要去重、取消与串行执行不变。
5. 沿用 Trace、HoverCard、Progress、AnimatedContent 和 MotionProvider；只按语义状态切换动画，不按 token 数值重挂载。沿用公共时长、缓动和运行中减少动效。手机工具栏须继续同排。
6. 手动压缩与正常发送共用 loadRunSources，批量读取同一套资料元信息，保留冻结版本并一致投影 currentVersionId/updatedAt；删除或其他对话附件继续按原规则过滤。来源确实变化时仍作废检查点，不放宽指纹判断。没有资料时零额外元信息请求。

## 验收

验收脚本、页面与截图暂存于 tests/assistant-feedback，结束后清理。外部请求全部在浏览器网络边界拦截，使用合成认证和消息，不写真实用户数据。

- 修改前后均经过实际 SDK 事件序列：先上报用量、再收到思考、随后正文。修改后首内容前保留等待、思考继续展开，正文到达后思考转为完成；手动展开状态在最终保存时保留。
- Chromium 与 WebKit 均通过空白文本、只含统计、真实工具部件、后续请求用量替换压缩状态。没有 pageerror。
- 6 轮历史整理较早 4 条，原 12 条消息保留；摘要保存挂起时仍显示“压缩中”，保存成功后才显示“已压缩”。短历史零摘要请求，重复压缩复用检查点，不重复调用模型。
- 模型失败、检查点保存失败与中途停止均未生成成功反馈；压缩中切换会话或账户，旧响应不写检查点或完成状态，串行运行器正常释放。隔离组件中账户切换后按实际运行器释放判断收尾，不把页面阶段文案当作请求完成证据。
- 带资料标签的真实压缩入口再经 prepareConversationContext 回读，使用摘要加最近 8 条消息；没有新增模型摘要请求。修改资料更新时间后，摘要正确失效，完整历史重新参与投影。此项直接覆盖已复现的指纹差异。
- 两个浏览器的 320/390/1280 px 上下文详情均保持视口内边距，完成两轮开关、Escape、退出中反向和运行中减少动效。已查看截图并通读实际文案。
- 正式 Composer 的 320/390/1280 px 工具栏核对控件中心线；320 px 从快捷菜单实际执行压缩后，已压缩状态与发送按钮保持同排。移除拟加入按钮的“上次”前缀，用详情标题和读屏名称区分统计来源；窄屏间距从 6 px 调为 2 px，按钮尺寸保留，桌面仍为原间距。
- TypeScript 应用检查通过，修改源码的 ESLint 与 Prettier 检查无错误或警告。最终生产构建 15.47 秒通过，保留既有超过 500 kB 的分包提示。
- 临时验收页面、脚本、截图、日志与本次独立 Vite 服务已清理。清理后 pnpm format:check 通过：ESLint 0 错误、64 条既有警告，Prettier 全部通过；git diff --check 通过。

## 动效检查

| 原状态                       | 调整后                             | 原因                            |
| ---------------------------- | ---------------------------------- | ------------------------------- |
| 用量部件到达就使等待状态退出 | 首个可见部件到达后才切换           | 避免内容尚未到达时整块退场      |
| 末尾统计令思考立即完成       | 仅由后续可见部件或整轮结束切换     | 保持思考文本增量与原 Trace 实例 |
| 压缩完成只出现一次通知       | 同一入口显示完成状态，详情局部过渡 | 用户关闭通知后仍能辨认结果      |

按 transitions-dev 与 review-animations 核对本轮改动，沿用公共 AnimatedContent 的 0.2s 进入、0.14s 退出和减少动效归零，未新增数值滚动或逐 token 重挂载；重复操作与反向切换实测通过。结论：本轮动效通过，仓库公共参数优先于技能通用默认值。
