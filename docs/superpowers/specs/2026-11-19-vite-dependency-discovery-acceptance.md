# 开发环境依赖补构建刷新修复

日期：2026-11-19。用户反馈打开功能时出现 `new dependencies optimized` 与 `optimized dependencies changed. reloading`，要求覆盖整类问题，不能只补截图中的包。

## 根因与修复

当前使用 Vite 7.3.2。旧配置只有 `optimizeDeps.entries: ['index.html']`，工作台路由来自 `vite-plugin-pages` 的 `~react-pages` 虚拟模块。Vite 扫描器将这类虚拟模块作为外部模块处理，无法沿它扫描全部页面。未打开页面中的日历、富文本编辑器、引导、依赖子路径等因此没有进入首次预构建。

后续浏览器请求这些模块时，Vite 才重新预构建；若共享产物或互操作方式发生变化，就通过开发 WebSocket 发送 `full-reload`。这个消息会影响连接同一个开发服务的其他标签页，包括用户正在操作的页面。图中的普通 `hmr update` 是另一类更新记录，不能与依赖变更引发的整页刷新混为一谈。

修改开发扫描入口：保留 `index.html`，增加 `src/**/*.{ts,tsx}`，直接覆盖所有前端源码。保留现有 `include`、压缩、自动依赖发现和 HMR；没有关闭刷新通知，没有逐个追加截图中的包。生产分包和业务模块的动态导入保持不变。预构建发生在开发服务器，不表示浏览器在首页一次下载全部业务模块。

实际运行服务的收尾核验还发现旧缓存不会因 `entries` 改动而失效。本机 Vite 7.3.2 的 `getConfigHash` 只取 `include`、`exclude`、esbuild 配置等字段，没有 `entries`。因此增加 `cacheDir: 'node_modules/.vite/source-scan'`，使新的扫描规则与旧缓存隔离，并保留后续正常缓存复用。未删除旧服务缓存，也没有配置每次启动强制重建。

扫描限定在 `src`，临时验证目录、技能、文档及构建产物不会成为入口。源码中的静态导入、导出和字面量动态导入都参与覆盖；类型导入、样式与资源文件不冒充 JavaScript 运行时依赖。

参考：[Vite 7 依赖预构建](https://v7.vite.dev/guide/dep-pre-bundling#automatic-dependency-discovery)、[扫描入口配置](https://v7.vite.dev/config/dep-optimization-options#optimizedeps-entries)。同时核对本机 Vite 扫描与 `fullReload` 的实际代码，未将最新 Vite 8 文档的实现直接套到当前版本。

## 全量覆盖与浏览器验证

验证脚本位于 `tests/vite-dependency-discovery/`，使用现有 TypeScript、Vite 和 Playwright。独立服务器使用 5194/5195 端口及独立缓存，未删除或改写运行中 5173 服务的缓存。所有外部数据请求在独立浏览器中拦截，没有真实账户读取或云端写入。

- 用 TypeScript AST 检查 1,657 个前端 TS/TSX 文件，取得 147 个实际 JavaScript 依赖路径，包含深层导入和字面量动态导入；逐项与 Vite 扫描结果比较，遗漏为 0。
- 截图中的 25 个路径在旧配置的首次扫描中全部缺失，在新配置中全部提前覆盖。
- 冷扫描预构建入口由 68 个变为 150 个；其中还包含手工指定项和 JSX 运行时。单次本机扫描加预构建测量为 645ms → 1,355ms，只说明更多工作移到启动时，不作为固定耗时承诺。
- 浏览器验证通过真实 Vite 转换后的临时入口逐个导入全部 147 个依赖，再次导入核对模块复用；没有复制依赖实现或模拟优化器结果。
- 随后通过实际侧栏完成两轮简历、模板、求职、分享、职业档案、优化、历史与工作台切换。私有页面处于匿名状态；所有依赖另行经过完整导入验证，不将匿名门禁页面当成完整业务回归。

新配置的两轮测试均无 `new dependencies optimized`、`optimized dependencies changed. reloading`、`full-reload` 或页面脚本异常。初始加载与后续模块/页面访问后的预构建清单完全相同，文档计数未增加，不能仅以终端没有打印日志作为通过依据。

运行中的 5173 服务另行核验：只改扫描入口时仍使用 101 条旧预构建记录，缺失 49 个源码运行时路径，该次检查失败。隔离新缓存后，真实工作台启动完成，预构建记录为 150，147 个运行时路径全部覆盖，检查窗口内无 `full-reload`。配置生效时 Vite 的服务重启与这次启动后的零补构建刷新分开记录。

本修复针对已有源码在使用过程中因漏扫而重复补构建。开发者新增或升级依赖、更改 Vite 配置，以及不可热替换的源码变更，仍可能需要重启或刷新；没有承诺开发过程永不刷新。正常发布站点不运行 Vite 开发预构建协议。
