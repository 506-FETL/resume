# 简历库 Lighthouse 优化

日期：2026-11-18。用户授权根据所附报告完成优化；按仓库约定先实施与验证，最后交用户审查，在当前分支工作，不推送。

## 证据与范围

报告检查 `localhost:5173/resume`，桌面性能 54、无障碍 92、最佳实践 100、SEO 92；模拟 FCP 3831 ms、LCP 13331 ms、TBT 118 ms。559 次请求中 519 次为脚本，总传输 14686089 B，包含 Vite HMR、React 开发运行时和未压缩源码。报告有 IndexedDB 提示，且使用登录数据，不能与匿名生产空列表直接比较提速倍数。

已确认的应用问题：

- 分享设置静态引用 DateField，再引入 Calendar / react-day-picker；未打开日历也下载。
- 简历分类的 TabsTrigger 指向不存在的面板；单一实际结果区未关联分类。
- 模板标签覆盖 secondary 的前景色为 muted，浅色对比度仅 4.34。
- GitHub 数字动画的滚轮把 0–9 都暴露为链接文字，与链接名称不符。
- `/robots.txt` 不存在，被 SPA 回退成 HTML。
- 账户圆形头像固定输出 512px PNG，报告中 32px 展示下载了 155226 B 原图。

## 方案选择

仅改构建参数无法解决语义和不必要依赖；全面重构预览、字体或账户图片服务会扩大范围。选择针对上述证据做局部修复，生产构建另建同条件基线。

1. DateField 组合已有 Popover、Calendar、Skeleton 与 deferred-content，实际打开才加载日历，保留错误重试、选日、清空、禁用、键盘与回焦；不改变分享写入。
2. 分类控件关联同一个真实结果面板，面板名称跟随当前分类；保留现有 store、列表 DOM、滚动、分页与动画。
3. 标签恢复 secondary 前景色。GitHub 数字使用明确可访问的实际计数，装饰滚轮不进入读屏内容。
4. 添加真实纯文本 robots.txt，不猜测域名或 sitemap，不修改已有索引策略。
5. 新账户头像输出 192px WebP（覆盖账户页 96px 的 2 倍显示），保留圆形透明边角；不改简历证件照、不改旧文件或用户资料。浏览器不支持 WebP 编码时按实际 PNG Blob 类型命名，不伪造 MIME。

## 验收与约束

复用现有组件和动效，新增加载反馈使用已有预设及运行中减少动效。生产首屏不得再提前下载日历。对照同机同路由、同样数据与 Lighthouse 配置，另列用户开发报告；记录资源字节、FCP/LCP/TBT、无障碍和 SEO。

真实页面检查分类键盘、缓存列表、浅深色、320/390px；日历两轮开关、反向、慢模块、503 重试、选日/清空与关闭后焦点。合成图片检查实际像素尺寸、编码、透明度与裁剪位置。类型、格式和构建检查通过后删除 tests 下临时脚本和数据，保留非敏感验收。

不改数据库、Edge、正文、字体、分页或打印；既有内容与成品缓存仍按账户/版本失效。实施、验证、用户审查和前端发布分别记录。
