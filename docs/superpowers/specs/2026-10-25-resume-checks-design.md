# 编辑检查与导出体验

状态：2026-10-25 用户已确认功能、编辑侧栏布局及高亮效果，并授权实施。本文记录已确认范围，不再增加审批步骤。

## 范围

本轮为第二期追加工作：编辑时查看正确性建议，导出时查看摘要。检查错别字、技术名词、联系方式、日期有效性与顺序、经历时间重叠和示例残留。版面可读性仅提供建议。经历表达、职责成果、岗位相关性与关键词证据仍留在第四期 P4-05。

规则能够确定的错误显示红色；存在合理解释的内容显示橙色“待核对”；排版建议显示蓝色。模型返回的疑似错字、陌生专业名词只作为待核对，必须有原文证据，不自动修改。AI 来源单独汇总，不作为待处理问题、不逐条要求确认。常见技术名称采用明确词表，不用模糊匹配把公司名或项目名判错。

## 布局与交互

沿用左侧简历预览与可调宽的右侧编辑栏。右侧增加 shadcn Tabs“填写 / 检查”，两个视图共享固定宽度、保留各自滚动位置；切换不改变预览宽度。检查是可筛选的紧凑 Accordion 列表，同一错误多处出现合并，点击展开一项。展开后显示位置、原文、原因和可用操作。没有逐项理由输入框。

点击问题在预览定位，点击“前往修改”切到相应模块与字段，保留“返回检查”。定位覆盖实际导出的可见内容，不能高亮测量副本。原文定位采用现有 Magic UI Highlighter，action="highlight"、animate={true}，只播放一次荧光笔动画；此处按用户明确要求不受减少动效设置禁用，其他动效仍遵循原约定。高亮为预览上的独立覆盖层，不改正文 DOM、测量几何与打印内容。

可确定的文字更正提供“采用建议”，按原文签名检查后修改；提供撤销，期间字段被其他操作修改则不得覆盖新内容。日期、数值与职责不自动改写。用户可确认无误或保留原文，保存到当前账户、当前简历的检查记录，不强制说明理由。

移动端在现有编辑抽屉内切换填写和检查，查看原文时先关闭抽屉并恢复预览；返回入口明确。使用现有 shadcn Button、Tabs、Accordion、Badge、Dialog、Tooltip，复用已有动效预设。列表与表单之间交接焦点后再隐藏旧面板。

## 检查与状态

本地规则随正文更新，输入时不抢焦点。AI 校对由用户点击启动，调用既有模型服务，仅检查文字与术语，不做简历优化。按钮说明需要登录并使用现有 AI 额度；请求可取消。成功、未检查、检查中、失败、内容已变化分别展示。旧账户、旧简历和旧正文的迟到结果不得覆盖当前结果。检查结果与忽略记录绑定字段身份、内容签名，重排保持身份，修改使旧结论失效。

排版建议基于实际可见分页的内容范围和配置：过小字号、过密间距、标题孤立、内容溢出等只在有证据时提醒，不宣称保证机筛通过。不能完整判断的项目说明检查范围，不伪造通过结论。

## 导出

导出弹窗显示当前简历、错误数量、提醒数量和 AI 来源摘要，提供“查看”回到检查侧栏。2026-10-26 用户调整：删除确认复选框。有未处理明确错误时，PDF 与 Word 按钮使用红色，点击直接导出；没有错误或只有提醒时保持原样式。点击时读取最新正文与排版快照，检查问题不阻拦文件生成。

来源读取或 AI 校对失败必须明确显示，但不阻止用户导出。只有实际无法生成文件的情况（模板、分页或源内容未准备好）禁用对应格式，并显示原因。沿用原有 PDF 与 Word 生成实现，不改变打印副本、模板或分页算法。

## 验收

覆盖真实的错字/术语、非法月份、结束早于开始、未来日期、合法重叠经历、隐藏模块、重排、重复原文、示例分组、来源失败、AI 失败/取消/过期和账户切换。验证修改、保留、撤销和跳转不会误改其他条目。桌面、窄屏、深浅主题、重复切换、减少动效下的专用高亮均检查。

导出覆盖有错误时红色按钮直接导出、无错误时默认样式、仅提醒、来源失败，以及实际 PDF / Word 入口。确认高亮与检查 UI 不出现在文件中，临时验收脚本放 tests/ 并在完成后删除。
