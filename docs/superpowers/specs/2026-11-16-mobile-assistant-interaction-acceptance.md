| 反馈                           | 定位与实现                                                                                                                                                                  | 长期约束                                                                                                                                                                           |

## 本地交互验证

临时夹具挂载正式 SimpleEditor、ActivityTimeline、AnnotationControls、Composer、Drawer 与 MotionProvider。使用合成内容，不接触用户账户或真实简历。临时脚本、截图和日志统一放入 tests/mobile-interaction，验收后删除。

- 时间线：320、390、768、1280 px 各验证三条记录，包含多行长文字；文字和编辑按钮顶端差小于 2 px，按钮不侵入文字区域。
- 富文本：WebKit iPhone 13 视口下检查空白、中文输入、换行、删除、加粗；空白和输入后截图均能看到紫色原生光标。Chromium 验证受控 HTML 回填及抽屉内继续输入。未接入实体手机，不将模拟结果写成所有手机均已修复。
- 引用：Chromium 真实鼠标拖选过程中按钮数量为零，松开后出现；Escape、原生 Selection 清空后消失，再次选择有效；键盘聚焦字段并按 Enter 可引用。
- 动效和触摸事件：Chromium/WebKit 各覆盖正常及运行中开启减少动效，两轮完整显示/关闭、退出中重新选择、拖选期间滚动、pointercancel 后原生选区建立以及外部点击关闭。退出层不再可交互。这里的触摸事件序列模拟不等同于实体系统手柄验收。
- 文案与提示：在实际组件页面通读快捷目录、整理进度和结果文字；菜单保留“使用 AI 额度”的费用说明。悬停提示组件无业务引用，测试页面没有 role=tooltip 或 tooltip-content；读屏名称仍在，头像与模块可见开关补充了名称。

## 压缩验证

使用实际 Composer、useChatStream、prepareConversationContext、Supabase SDK 和摘要请求实现，仅在浏览器网络边界拦截认证、数据库及模型响应。没有替换业务函数，没有真实模型扣费或云端写入。

| 场景                    | 结果                                                                 |
| ----------------------- | -------------------------------------------------------------------- |
| 6 轮短对话，自动模式    | 未达到阈值，不请求摘要。                                             |
| 同一 6 轮对话，手动模式 | 摘要较早 4 条消息，保留最近 8 条，原 12 条消息均保留；只写检查点。   |

| 114 条消息的完整历史    | 读取两页，分两批摘要 106 条，保留最近 8 条；不依赖界面当前加载条数。 |
| 仅 4 轮                 | 零模型请求、零检查点写入。                                           |
| 模型失败                | 报错，不保存检查点，不允许手动模式降级为伪成功。                     |

## 标签用途名追加调整

用户随后提供的截图中已出现“压缩上下文”，并要求标签显示用途，示例为“简历引用”。这次仅调整标签展示，不改变快捷菜单文案或引用协议。

- 触发与原因：标签直接使用引用对象的名称，短宽度下只剩“全栈…”等片段，无法直接表达用途。
- 实施：统一组件改用用途名；简历和划词显示“简历引用”，岗位显示“岗位引用”，文件与职业档案显示“资料引用”。七条快捷指令依次使用“经历优化”“STAR 描述”“成果梳理”“岗位匹配”“技能提炼”“自我评价”“意向润色”；现有简历提升技能显示“简历提升”。历史未知指令和技能分别显示“快捷指令”“技能调用”。
- 具体名称仍用于点击详情及读屏描述，引用原文和资料不可用状态保留。引用标识、版本、去重、持久化与模型输入沿用原值；输入、排队和历史消息共用此展示。
- 宽度：最初调整到 112 px 后，Chromium 320 px 下实测“STAR 描述”需要 58 px 文字区域，只有 54 px，仍会截断；最终统一为 120 px，覆盖旧的 88/100 px 约定。
- 验证：临时页面挂载正式 ReferenceTags、Attachment、Popover 与 MotionProvider，覆盖全部现有用途；Chromium 的 320/390/1280 px 和 WebKit 的 390 px 均无标签文字截断或页面横向溢出。已通读实际渲染文字并查看截图。详情保留完整名称和原选区文字；两轮开关、Escape 回焦、减少动效、已删除资料状态及移除目标标签均通过，移除未触发表单提交，历史只读标签未受影响。
- 静态检查：TypeScript 应用检查通过；修改组件已执行 Prettier 与 ESLint layout 修复，检查无错误或警告。
- 验收使用合成引用和预置的已删除资料状态，浏览器阻断所有非本地请求，未发送消息或修改云端数据。临时页面、脚本与截图放在 tests/reference-tag-purpose，验收后删除。
- 状态：实施完成，以上本地验证通过，用户审查待完成。本次追加改动未推送、未发布前端；前述线上菜单核对是当时记录，不作为当前线上状态的断言。
