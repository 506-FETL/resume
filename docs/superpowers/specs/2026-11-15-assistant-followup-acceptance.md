## Context 的当前实际规则

- 当前代码的任务容量为 65,536 tokens，模型能力配置为 1,048,576。任务给输出和工具各预留 8,192，输入硬预算为 49,152；浮层显示任务容量，没有为了照搬截图伪造 128K。
- 显示最近一步模型调用的输入加完整输出，不累计多步账单。推理已知时从显示的输出分项扣除，总量不变。真实 PDF 调用最后一步为输入 6,674、完整输出 493、推理 32，因此占用为 7,167，展示输出分项为 461。
- 未发送前使用现有 JSON 字符估算：ASCII 约每 3 字符一个 token，非 ASCII 每字符约 1.5 tokens，再按实测输入校准并留 20% 余量；估算明确标“约”。有新草稿、引用、目标或来源指纹变化时，旧用量失效，不能把旧百分比冒充新请求。
- 超过估算 40,000 tokens、72 条模型消息、480,000 bytes 任一阈值，提前整理较早完整轮次，保留最近 4 个用户轮次。摘要区分用户确认事实与未核实资料，不把读取或采用建议等同于核实。
- 持久摘要保存在 `ai_context_checkpoints`，连同消息边界和目标、资料版本等指纹；原 `ai_messages` 不删除。资料范围、版本、目标、历史编辑或投影规则变化会让旧检查点失效。本期把来源投影规则版本加入指纹，防旧摘要带回范围外资料。
- 工具步骤中的临时整理保留在当次运行内，不声称每一步都落数据库。下轮加载持久检查点与剩余消息。压缩失败且仍在硬预算内可继续，超限则明确停止，不静默截断。
- 独立审查发现 SDK 会把缺失推理值归一成 0，已增加对 raw 实际字段的判断。真实安装 SDK 的离线响应三组：缺失→undefined、0→0、12→12；不能仅看归一后的值推断上游已报告。
