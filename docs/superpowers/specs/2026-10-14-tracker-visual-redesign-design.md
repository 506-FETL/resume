# 求职跟进页布局与视觉改版

日期：2026-10-14

状态：用户已确认推荐方案 A；实现、审查与浏览器验收已完成。验证详情见对应实现计划。

## 1. 目标与范围

重新组织求职跟进页的视觉层级、布局比例和内容密度，使其与项目其他成熟页面一致，并让少量职位、多阶段职位、空数据三种情况下都具有完整的页面观感。

范围覆盖页面标题、概览、工作区工具栏、看板、桌面列表、移动端职位卡片及页面加载/空/错误状态。保留现有新增与详情抽屉入口、拖拽、状态更新、批量管理、搜索、排序、归档功能和统计口径；抽屉业务内容不是本次重构对象。

改动限定在 `src/pages/tracker/` 及本次设计/计划文档。复用现有 UI 和动效，不改全局主题、侧栏、其他页面、数据库或 Edge Functions，不引入新依赖。

## 2. 调研依据

已在本地浏览器实际查看求职跟进页的列表、看板，以及分享管理、首页、历史版本、我的简历页面，并对照源码。

| 参考页面 | 可借鉴的设计                                                   | 对应源码                                                                                         |
| -------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 分享管理 | 独立标题与说明、右侧单一主操作；统计与筛选分层；轻边框圆角表面 | `src/pages/share/components/header/index.tsx`、`overview/index.tsx`、`toolbar/index.tsx`         |
| 首页     | 彩色小图标、数字和说明的层级、规则的统计网格                   | `src/pages/index/components/statistical-card/index.tsx`                                          |
| 历史版本 | 页面身份图标；工具区与内容区分开；主次表面层级                 | `src/pages/history/components/header/index.tsx`、`summary.tsx`、`components/workspace/index.tsx` |
| 我的简历 | 标题留白、分段切换、卡片中主体与操作的分区                     | `src/pages/resume/components/head-bars/index.tsx`、`resume-card/index.tsx`                       |

当前页面的具体问题：

1. 标题与搜索、筛选、切换视图、归档、批量管理、新增等控件共用一行，页面身份与操作混杂。
2. 概览是横向拉长的数据条，响应率视觉权重过大，其余数字偏小且缺少口径说明。
3. 看板列最小宽度随视口断点增大至 320px，而页面还有侧栏及内边距，实测宽屏仍无法完整容纳主要流程列。
4. 空列中的虚线投放区通过 `flex-1` 撑满剩余高度，一条职位记录也会产生整屏空框。
5. 职位名称、公司、地点、停留天数集中在卡片头部；下一步跟进内容没有成为稳定的信息层。
6. 桌面列表缺少与工具栏统一的工作区结构，稀疏数据时只剩很薄的一行表格。
7. 页面骨架固定为三条横条，与默认看板不匹配；加载失败主要依赖 toast，页面内缺少清晰的错误呈现。

## 3. 方案选择

### A. 概览与职位工作区（推荐）

采用分享管理的页面层级、首页的紧凑指标卡、历史版本的工作区分层。保留看板与列表，用相同的标题、概览、工具栏承接两种视图。

优点：与现有产品一致；主要使用方式不变；同时解决布局、比例和信息层级问题。取舍：需要拆分当前承载过多职责的 header，并同步调整两种职位视图。

### B. 列表优先的管理台

重点展示高密度表格，将看板作为次级入口。适合大量职位的批量操作，但弱化现有的流程推进体验。

### C. 全屏流程看板

弱化统计，主要空间用于宽列看板。流程清楚，但少量职位时依然空旷，与分享管理、历史版本等页面的节奏差异较大。

推荐 A，以下详细设计均以 A 为准。

## 4. 页面结构

```text
页面图标  求职跟进                              ＋ 新增职位
          管理投递进度，安排每一步跟进。

┌ 已投递 ─────┐ ┌ 面试中 ─────┐ ┌ 已录用 ─────┐ ┌ 待跟进 ─────┐
│ 图标 / 数字 │ │ 图标 / 数字 │ │ 图标 / 数字 │ │ 图标 / 数字 │
│ 统计口径说明│ │ 统计口径说明│ │ 统计口径说明│ │ 统计口径说明│
└─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
响应率  — / xx%     细进度条     已进入筛选及后续阶段的投递占比

职位进展 · 当前数量                              看板 / 列表
搜索公司、岗位或城市        阶段筛选  排序         已归档  批量管理
当前筛选提示 / 批量操作条（按需展开）

看板：已保存 | 已投递 | 筛选中 | 面试中 | 已录用 | 已终止（折叠）
列表：公司与职位 | 地点与薪资 | 当前阶段 | 下一步跟进 | 最近更新 | 操作
```

### 4.1 标题与宽度

- 标题沿用分享管理的图标容器、24px 标题、14px 说明；右侧只放新增职位主按钮。
- 主体使用一套共享的内容宽度，建议最大 1600px；保持两种视图切换时标题和工具栏对齐。
- 桌面水平内边距 24–32px，手机 16px；主要分区间距 24px，卡片间距 12–16px。
- 桌面工作区占据剩余空间；低高度与移动端允许正常页面纵向滚动，保证内容不会被压缩到无法操作。

### 4.2 统计区

- 四张等高轻量卡片：已投递、面试中、已录用、待跟进。包含语义图标、清晰数字、简短说明。
- 颜色仅用于图标、状态和待跟进提示；基础表面使用主题 token 的中性色。
- 响应率收为独立细行，包含百分比、进度条及说明。无历史投递时显示“—”。
- 保留统计点击行为：列表中筛选，看板中定位并高亮对应阶段；界面辅助文字明确两种模式的动作区别。
- 继续使用 `getTrackerOverviewStats`：已投递为历史口径；面试中、已录用排除归档；待跟进沿用既有到期/陈旧规则。说明不能将待跟进简单标成“今日待办”。
- 空数据时保留零值卡片，不让页面框架消失；加载时使用卡片内骨架，错误时显示“—”。
- 手机采用 2×2 网格，待跟进直接可见，不再藏在展开按钮后。

### 4.3 工作区与工具栏

- 工具栏从标题组件中移入职位工作区。工作区标题与视图切换在第一行，搜索、阶段、排序、归档和批量管理在第二行。
- 控件采用统一高度、圆角与轻边框；搜索宽度有上限，低频操作视觉降级。
- 搜索具有可访问名称和清空入口。筛选/归档状态显示明确提示及退出操作。
- 批量操作条按需带动画展开；原有删除和终止确认继续保留。
- 当前结果数量与工作区内容对应：列表使用实际筛选结果，看板使用搜索和归档范围内的结果，阶段定位不误报为筛选后的总数。

### 4.4 看板

- 保留五个主要阶段及可折叠的已终止列。列标题展示状态色点、名称、数量与简短阶段说明。
- 宽屏列宽按可用内容宽度分配；取消视口变宽就强制放大每列最小宽度的策略。窄屏保证卡片可读宽度，并将横向滚动限制在看板内。
- 列背景为轻微灰阶，卡片为独立表面；弱化重复边框。颜色不铺满整列。
- 空列提示放在顶部的紧凑占位区，不再撑成整屏虚线框。拖入时仍保留足够且明确的投放区域和反馈。
- 职位卡片分为三层：公司标识与公司名、突出职位名；地点与薪资；下一步跟进/日期或停留时间。面试轮次、JD 等作为辅助信息。
- 长标题最多两行，长公司名截断；不为了填满卡片制造虚假的薪资、下一步或趋势信息。
- 保留拖拽、横向自动滚动、终态确认和失败回滚。显示样式改动不替换既有拖拽引擎。

### 4.5 列表与移动端卡片

- 列表融入工作区表面，表头、行间距和首列层级保持一致；给予行内容足够的垂直空间。
- 合并地点与薪资的呈现，为下一步跟进保留稳定位置；状态、停留时间、更新时间及原有排序能力仍可访问。
- 主体职位入口支持键盘操作；复选框、菜单与行打开行为不互相触发。
- 移动端用相同信息顺序的职位卡片，保留菜单与批量选择，不依赖横向表格。
- 只有一条数据时保留合理留白与完整工作区，不添加演示职位填充页面。

### 4.6 页面状态

- 看板与列表分别有结构匹配的骨架，并沿用真实的职位加载状态。
- 首次无数据：统一的图标、标题、说明和新增职位入口；看板也不只呈现一排空拖放区。
- 无匹配结果：说明当前搜索/筛选，并提供清除入口。
- 归档为空：专属说明及返回活跃职位入口。
- 加载失败：页面内展示简短错误和重试入口，避免被误认为没有职位；复用现有错误解析。

## 5. 组件、状态和数据

- 维持 `components/`、`hooks/`、`const.ts`、`index.tsx`、`store.ts`、`types.ts`、`utils.ts` 的页面结构。
- header 专注页面身份与新增；overview-bar 专注统计；toolbar 负责搜索、过滤、视图及批量操作；board/list 专注内容；页面状态组件负责骨架、空态与错误态。
- 新建独立组件使用 kebab-case 目录和 `index.tsx` 导出。只拆分为本次布局调整所需的职责边界。
- 页面级筛选、视图、选择和抽屉动作继续使用 `useTrackerStore`；确认弹窗等临时状态保持局部。
- 保持现有数据接口、统计与状态更新函数，不新增数据库字段或外部数据源。
- 重试复用页面加载逻辑；不引入与本页无关的加载阻塞或全局状态。

## 6. 动效、主题与可访问性

- 复用 `src/lib/motion.ts` 的 `EASE`、`DURATION`、`SPRING`：进入淡入与轻微上移，退出更短，卡片入场采用小幅错峰。
- 视图切换、批量工具条、筛选提示、看板折叠与定位高亮都有过渡；不叠加多层入场导致迟滞。
- 每个新增或修改的动效接入 `useReducedMotion()`；CSS 位移/缩放同样需要降级，不能只降级 Motion 动画。
- 使用现有主题 token，阶段色及日期色补齐深色模式对比度；不改全局主题变量。
- 图标按钮提供名称，所有可操作项有键盘焦点；状态不能仅通过颜色表达。
- 不改共享 Dialog/Drawer 动画；若实现确有必要修改弹窗，按仓库约定验证两轮完整开关及退出中反向打开。

## 7. 验收

1. 桌面 1440px、1920px，平板 1024px，手机 390px/430px；包含桌面侧栏展开与收起。页面本身不横向溢出，窄屏仅看板内部横向滚动。
2. 明暗主题、普通动效和减少动效；检查标题、统计、工具栏、看板、列表与状态反馈的一致性。
3. 空数据、单职位、多阶段多职位、长字段、归档、无匹配、加载、失败和重试。
4. 搜索、清除、阶段定位/筛选、统计点击、列表排序、视图切换、批量选择、新增入口和详情入口均可用。
5. 在隔离的本地验证数据中检查跨列拖拽、终态确认和失败回滚；不以用户真实职位作为写入验证数据。
6. 对修改文件执行 ESLint、TypeScript 检查、生产构建；按影响范围运行已有拖拽验证，不新增与实现镜像的测试。
7. 审查最终 diff，仅包含本次求职跟进视觉重构所需文件；记录无关的既有问题，不顺手修改。
