# 邮件手绘插画重设计

日期：2026-11-11。范围已由用户授权，完成实现和验证后交用户审查，不重复请求本期许可。

## 美术返修与市场参考

第一版 SVG 被用户指出不精致、不优雅。主代理查看联系表也确认：同一扁矩形笑脸反复出现，手臂像粗色带而没有手套，人物缺少重心，纸张与口袋没有层次。第一版不算完成，技术检查通过不能替代视觉审查。

已按用户要求先实际浏览并截图查看两组成熟案例：[Jane Song 的 Mailchimp 插画系统](https://www.jane-song.com/mailchimp-illustration-system)、[Pablo Stanley 的 Open Doodles](https://www.opendoodles.com/)。前者用疏密线条、局部排线、大留白与物件比例组织画面；后者通过身体重心、伸展手势和连贯弧线表现动作。仅借鉴绘画方法，不使用其角色、商标或现成场景资产。

新方向采用首页原有的无脸文件夹 IP：有厚度的双层口袋、露出一角的浅蓝纸张、奶油标签和蓝色小印章。黑色柔软手臂连接清晰的奶油手套，蓝色球鞋有奶油鞋底。插画用主体轮廓、内部结构线和局部排线三个层级；保留大面积干净纸色，避免到处抖线或铺噪点。先完成确认邮箱、邀请、密码恢复和品牌图标的代表样张并实际审查，再扩展其余场景。小图标按识别需求精简，不能把插画全量细节强行缩小。

## 目标与方案

重做 public/email 的 13 张 SVG，并由 SVG 重新生成 13 张邮件使用的 PNG。参考 README 的手绘墨线与首屏文件夹卡通角色，重新构图，不沿用旧插画造型。选择场景化角色插画方案：角色参与邮件对应的动作，统一视觉但不使用同一姿态换一个图标。单纯细线图标缺少用户要求的卡通感；复杂整页海报会抢占邮件操作信息，因此采用留白充足的横向小场景。

## 视觉约束

420 × 240 画布，主体占有效宽高约 75%–90%。墨色粗轮廓、少量不规则复线、暖纸白、黄色文件夹、奶油手套、蓝球鞋，辅助使用淡蓝、珊瑚和绿色。线条在邮件 250px 显示宽度仍可辨。动作有重心、四肢连接清楚，道具表达明确。每图最多一个主要动作和两个辅助元素，避免微小装饰堆叠。图片不承载按钮、验证码、安全提示或真实个人资料。

## 文件与数据

public/email/\*-assistant-v2.svg 是可编辑源；同名 PNG 是生成副本，文件名继续兼容当前邮件 HTML。SVG 不依赖外部字体、脚本、动画或远端图片，不嵌入整张栅格图。补充 scripts/render-email-art.py 作为维护生成工具，使用本机已有 sips 输出 PNG。supabase/templates/README.md 更新风格与生成说明；仅在图片 alt 不准确时调整 HTML，不更改认证变量或链接。资源发布仍随前端部署，不触发邮件发送或认证配置修改。

## 验收

检查 13 个 SVG 的 XML、viewBox、标题和描述；生成 13 个 PNG，核对真实尺寸与透明边缘。逐张查看全尺寸和 250px 缩略图，检查手脚、道具、线条和内容区边界。用本地邮件预览检查桌面、手机及图片加载失败时正文和操作仍完整。不新增运行时依赖。生成两次比对 PNG 哈希，记录结果。

临时验证文件放 tests/email-art，结束清理；保留非敏感预览联系表到文档或会话视觉目录。实施完成、验证通过、用户审查分别记录。

## 追加范围：产品 IP 图标

用户随后明确要求产品图标也使用首页黄色文件夹角色。主图标为可识别的文件夹身体、奶油手套和蓝鞋，采用紧凑正方形构图与粗墨线；不添加其他吉祥物，不照搬通用文档加星光造型。公开源保留 public/resume_icon_transparent.svg，站内侧栏沿用这一入口。另提供小尺寸简化 favicon.svg，只保留文件夹轮廓、纸张和一只招呼手套，避免缩小后手脚和纹理糊在一起。apple-touch-icon.png 由 SVG 源生成，使用暖纸底和安全边距；index.html 指向对应浏览器图标与手机图标。

检查 16、24、32、48、180、512px 以及明暗背景。小尺寸轮廓、手套和主体需分明；SVG 无外部字体和脚本，图标不额外动画。生成工具属于维护工具，临时样张放 tests/brand-icon 并在验收后清理。不重绘业务功能图标，也不改变首页已有角色动画。
