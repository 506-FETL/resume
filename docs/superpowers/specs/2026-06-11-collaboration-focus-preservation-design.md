# 实时协作编辑焦点保持设计

- 状态：已确认
- 日期：2026-06-11
- 范围：简历编辑页中 Automerge 远端数据同步到 React Hook Form 的路径

## 1. 背景

简历编辑器通过 Automerge 接收远端协作者变更，再将文档快照写入 Zustand。各表单使用 `useFormRemoteSync` 监听对应的 store 数据，并通过 `form.reset(storeData)` 把远端内容同步到 React Hook Form。

当前实现虽然能显示远端更新，但 `reset` 会重置整个表单。对于 `useFieldArray`，React Hook Form 会重新生成字段项的内部 `id`，使用这些 `id` 作为 React key 的编辑区域会被卸载并重新挂载。普通输入框、字段数组中的输入框以及 Tiptap 编辑器因此失去焦点。远端更新持续到达时，本地用户会持续被打断，无法正常编辑。

## 2. 目标与非目标

### 2.1 目标

- 远端 Automerge 更新继续立即同步到本地表单。
- 无论远端修改其他字段还是当前字段，当前正在操作的输入控件都保持焦点。
- 持续收到远端更新时，本地用户仍能连续输入。
- 避免因同步触发本地 `watch` 回写，从而形成重复广播或同步循环。
- 保持字段数组现有项和 Tiptap 实例的组件身份稳定。

### 2.2 非目标

- 不暂停或延迟远端更新。
- 不修改 Automerge、Supabase 或 Zustand 的文档同步协议。
- 不实现字符级 CRDT 编辑器或改变同字段并发冲突的 Automerge 语义。
- 不通过 `reset` 后强制重新聚焦来模拟焦点保持。
- 不重构简历表单页面结构。

## 3. 方案比较

### 3.1 推荐：按字段路径增量同步

深度比较当前表单值和远端 store 数据，只对变化的叶子字段调用 React Hook Form 的 `setValue`。字段数组长度变化时，通过 `useFieldArray` 的结构操作追加或移除尾部项，再按索引更新保留下来的项，避免更新数组根路径和重新生成所有内部 key。

优点：

- 未变化的控件不会被卸载，浏览器原生焦点和输入法状态得以保留。
- 远端数据仍然立即可见。
- 改动集中在共享同步 hook，所有现有表单统一受益。
- 不需要依赖 DOM 查询和手工恢复 selection。

代价：

- 需要正确生成对象和数组的字段路径。
- 字段数组需要向共享同步 hook 提供不抢焦点的 `append` 和 `remove` 适配器。

### 3.2 备选：保留 `reset`，同步后恢复焦点和光标

在 `reset` 前记录 `document.activeElement`、字段名和 selection，在重建后重新定位并聚焦。

不采用，原因是组件已经卸载，富文本 selection、输入法 composition 和弹层状态难以可靠恢复；持续更新时仍会出现闪烁和输入中断。

### 3.3 备选：编辑期间缓存远端更新

当前控件聚焦时不应用远端更新，失焦后批量同步。

不采用，原因是它破坏实时协作语义，也与已确认的“远端更新立即应用”要求冲突。

## 4. 设计

### 4.1 同步边界

`useFormRemoteSync` 继续作为“远端 store 数据进入 React Hook Form”的唯一共享入口。调用方和本地 `watch → updateForm` 路径不改变。

hook 收到新的 `storeData` 后：

1. 读取 `form.getValues()`。
2. 递归比较当前值和远端值。
3. 收集需要更新的 React Hook Form 字段路径和字段数组结构操作。
4. 将 `isResettingRef.current` 设为 `true`。
5. 逐路径调用 `form.setValue(path, value)`，不触发 dirty、touched 或 validation 状态。
6. 通过字段数组适配器执行必要的追加或尾部移除；远端追加不得自动聚焦新增字段。
7. 在 React Hook Form 同步通知完成后恢复 `isResettingRef.current`。

整个流程不调用 `form.reset()`。

### 4.2 差异路径规则

- 标量、`null` 或类型变化：更新当前路径。
- 普通对象：递归比较键的并集，只更新变化的叶子路径。
- 非字段数组（例如日期范围元组）：按普通数组递归比较；长度变化时允许更新其根路径，因为它不会触发 `useFieldArray` 重建。
- 字段数组长度不变：按索引递归比较，只更新变化的数组元素字段。
- 字段数组变长：先更新原有索引，再通过 `append(value, { shouldFocus: false })` 追加远端尾部数据。
- 字段数组变短：先更新保留索引，再从尾部向前执行 `remove`，使现有低索引项的内部 key 保持不变。
- 远端缺失的对象键：将对应路径设置为 `undefined`，保持表单与远端快照一致。
- 相等值：不调用 `setValue`。

简历现有数组编辑入口只会把新项追加到末尾。对于远端中间插入或删除，由于持久化数据没有稳定 item id，同步器按最终索引更新保留节点，并在尾部追加或移除，使最终表单数据与远端一致，同时最大限度保持现有 DOM 节点。若远端最终数组长度已经不包含当前聚焦索引，则该控件本身必须被删除，无法继续保留焦点；除此之外，任何仍存在的当前控件都必须保持焦点。

### 4.3 当前字段被远端修改

如果远端修改的正是当前字段，`setValue` 会更新该控件的值，但不会卸载控件或主动调用 `blur`。焦点必须保持在原控件上。本设计不额外冻结本地值，也不改变 Automerge 最终合并结果。

对于 Tiptap，表单字段值变化继续通过 `content` prop 进入现有 `setContent` 路径。编辑器实例本身不因字段数组整体 reset 被销毁，因此保持编辑状态。Tiptap 的内容同步和 selection 细节由现有 `SimpleEditor` 外部内容同步逻辑负责。

### 4.4 循环抑制

现有调用方在 `form.watch` 中检查 `isResettingRef.current`。增量 `setValue` 执行期间保持该标志为 `true`，确保远端同步不会再次调用 `updateForm` 并广播回 Automerge。

标志恢复继续放到当前事件循环之后，以覆盖 React Hook Form 的同步订阅通知。effect 清理时取消尚未执行的恢复任务，避免卸载后写入过期状态。

## 5. 测试

使用 Node 24 内置测试运行器为纯差异规划器编写回归测试，并通过浏览器验证真实焦点行为：

- 远端修改其他普通字段时，当前输入框保持焦点且远端值更新。
- 远端修改当前普通字段时，该输入框保持焦点且值更新。
- 远端修改字段数组中另一个字段时，当前数组输入框节点不被替换并保持焦点。
- 连续多次远端更新时，当前输入框持续保持焦点。
- 远端同步不会通过 `watch` 触发本地回写。
- 字段数组长度变化使用追加和尾部移除操作，不更新数组根路径。

最后运行定向测试、完整测试、ESLint、`npx tsc --noEmit` 和生产构建。若浏览器环境可用，再在本地编辑器中验证普通输入框与富文本编辑器的持续协作更新行为。

## 6. 成功标准

- 复现路径中，远端 change 到达后当前编辑控件的 `document.activeElement` 不变。
- 远端数据立即显示，不需要用户失焦或刷新。
- 连续远端 change 不阻止本地持续输入。
- 没有新增同步循环、重复广播、类型错误或构建错误。
