## 结论与测量口径

用户报告来自登录状态的 Vite 开发页面，性能 54、无障碍 92、最佳实践 100、SEO 92。519 个开发脚本与约 14 MB 总传输包含 HMR、未压缩源码和开发运行时。报告提示存在 IndexedDB 数据，其模拟 LCP 13.33 秒、实际观察 LCP 0.668 秒也不是同一个指标。

本轮在同一台机器保存改动前生产构建，使用 Vite preview 与 Lighthouse 13.6.0，比较匿名空简历列表。用户报告为 13.5.0；登录状态、数据量和运行模式不同，不能把 54→95 写成本轮性能收益。真实有内容列表的语义、预览、分类与响应式另作浏览器验收。

| 生产场景      |                改动前 |              交付版本 |
| ------------- | --------------------: | --------------------: |
| 桌面性能      |                    95 |                    95 |
| 桌面无障碍    |                    95 |                   100 |
| 桌面最佳实践  |                   100 |                   100 |
| 桌面 SEO      |                    92 |                   100 |

脚本传输减少 20514 B，约 3.4%；手机 LCP 中位数约 7085→6933 ms，改善约 2.2%，仍接近 7 秒。首轮手机优化后曾比基线慢，不能隐藏该样本或承诺稳定提速。后两轮手机采样的 GitHub 星数 RPC 在两版都遇到 `ERR_CONNECTION_CLOSED`，最佳实践为 96；保留失败记录，不把外部连接错误计为代码收益。最后桌面复测 RPC 正常，四项分数为 95/100/100/100，相关语义审计全部通过。

同一生产网络中，原日历引擎分包传输 20941 B、解压 71701 B；现在首屏只剩 253 B 的日历图标模块，完整日历在打开有效期浮层时加载。没有修改构建压缩配置、删除动画或跳过认证。

原始生产报告保存于 `.superpowers/lighthouse-resume/`；包含改动前、最终桌面 HTML/JSON 与手机重复测量 JSON，不包含用户登录凭据。

## 已实施修复

- 分享有效期复用现有 deferred-content、Popover、Calendar 和 Skeleton。保留局部重试，内容到达后沿公共 140ms 缓动淡入；弹层继续承担原有位移和缩放。关闭期间加载完成不会抢走焦点。
- 简历分类继续使用现有 Tabs 与页面 store，三个触发器指向真实的单一结果面板，面板名称跟随选中项。分类组件独立放入现有页面 components 目录，避免入口超过 400 行。
- 模板标签恢复 secondary 的配套前景色，修复报告中的 4.34 对比度。页面内容容器补充与名称相配的 region 语义；空态创建按钮使用可见文字作为名称。
- GitHub 链接名称包含真实星数，装饰滚轮不进入读屏名称。依据滚轮现有位移隐藏完全离开裁切区域的数字，保留进入区域的相邻数字，避免 0–9 都被当作可见标签。未改变弹簧、数字完成回调与星形反馈时机。
- `public/robots.txt` 实际返回 `text/plain` 和有效规则，开发与生产均 HTTP 200；不再落入 SPA HTML。
- 新账户头像输出 192×192、质量 0.85 的 WebP，覆盖账户页 96px 的两倍显示，圆形保留透明边角。按真实 Blob MIME 命名；简历证件照、已有头像文件、上传持久化和旧资源清理流程不变。

## 浏览器验收

- 真实 `/resume` 使用本轮两份合成本地简历检查标签与预览；未修改既有简历。桌面、390px、320px、深浅色均可读，无横向溢出。稳定状态下 axe WCAG 2 A/AA 与 2.1 A/AA 无违规。
- 方向键切换分类后，焦点、选中状态与面板名称一致；岗位空筛选返回全部，已有预览保留，新增资源请求为零。切换动画仍由已有组件处理。
- 日期使用真实 DateField、Calendar 和正式 MotionProvider 的隔离页面：延迟模块 1.2 秒时显示骨架；真实 503 后局部重试成功；方向键和 Enter 选中 2026-11-19，清除恢复长期有效；Escape 回到日期按钮。
- 连续两轮打开/关闭、退出中反向打开、加载中关闭再打开均正常。迟到模块不复活已关闭浮层；390/320px 与深色完整可操作，运行中减少动效后 CSS 时长为 0，浮层无残留活动动画。
- 数字依次 9→42→100→0→9，最终可见数字正确；快速 100→9 和运行中开启/关闭减少动效后仍为 9。
- 合成图片经过真实 Canvas 裁剪、编码和解码：圆形 PNG 89748 B→WebP 9496 B，方形 PNG 88509 B→WebP 11016 B；尺寸均为 192×192，圆角 alpha=0、中心 alpha=255。浏览器编码边界强制返回 PNG 时，文件名、MIME 与 PNG 魔数一致。此体积只代表该合成图，不是用户现有头像的实际缩小量。
- 文件整理后曾因 Vite 保留旧模块路径出现一次 404；失效父模块缓存后，实际日期入口重新加载与关闭成功，生产构建也已重新通过。该失败没有记作验收成功。

动效复核依据 transitions-dev 与 review-animations，并以仓库公共时长和减少动效规则为准：

| 检查点         | 处理与结果                            | 原因                              |
| -------------- | ------------------------------------- | --------------------------------- |
| 延迟日历进入   | 局部 opacity，140ms，公共缓动         | 浮层已有位移/缩放，避免再叠加位移 |
| 重复与快速反向 | 保留 Popover 生命周期，实测无重复浮层 | 不用请求状态控制卸载              |
| 数字裁切       | 只隐藏完全离开区域的字形              | 保留动画中相邻数字与真实完成回调  |
| 减少动效       | 正式 hook 实时响应，时长归零          | 不依赖刷新或重新打开              |

上述范围通过动效复核。日期属于真实组件隔离验收，未执行新的云端分享写入；没有替换用户真实头像。未覆盖 Safari、真机 GPU 帧率、所有账户状态或登录后生产大列表跑分。本轮未修改正文、字体、模板、打印、数据库或 Edge Functions。
