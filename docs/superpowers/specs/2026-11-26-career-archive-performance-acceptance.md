# 职业档案性能验收

## 原始录制

用户提供的 Trace-20261126T112846 是开发构建中一次 `/experience` 导航。职业档案有一次 Edge POST。导航后 335 毫秒出现标题，910 毫秒才发出列表请求，1,695 毫秒收完 2,986 字节的响应。该次连接已复用，响应头显示 Edge 实际运行在数据库所在的 us-east-1。第一张卡片的标题在 1,932 毫秒绘制，1,955 毫秒成为 LCP 候选。最后一个候选在 2,005 毫秒，是第三张卡片的多行摘要。

录制中有 289 个 localhost 脚本和 3 个扩展脚本。浏览器在列表发出前已请求尚未打开的上传、资料选择、详情和原件模块。55 毫秒处的长任务来自扩展编译，另一段长任务包含 React 开发回调及布局。没有记录到 LayoutShift 事件。

## 同机生产包对照

Chrome 158 无扩展，1200 × 900，DPR 1。每次新建冷上下文，使用相同的 37 份合成档案。新旧接口各固定延迟 420 毫秒，静态资源每个请求固定延迟 25 毫秒。新旧各五次，交替运行。下表取中位数，JavaScript 记录至首卡可操作后 750 毫秒。两边五轮 LCP 均为同一张卡片的摘要。

| 从导航开始的测量项     |         旧包 |       优化后 |
| ---------------------- | -----------: | -----------: |
| 标题骨架可见           |       341 ms |       367 ms |
| 首次内容绘制           |       372 ms |       392 ms |
| 首次列表请求发出       |       955 ms |       387 ms |
| 搜索框可操作           |       953 ms |       675 ms |
| 首卡可操作             |     1,414 ms |       840 ms |

首卡五次范围分别为 1,397–1,444 和 831–842 毫秒；LCP 范围为 1,636–1,688 和 1,052–1,076 毫秒。标题位置一致，没有消失帧。标题和首次内容绘制分别晚了 26 和 20 毫秒，本次提速主要来自更早启动列表读取。此轮对照之后，仅收紧了阅读页复用改名摘要的条件，并用最终生产包复验该路径。

## 实现与功能核验

- 登录确认后即启动当前目标的读取，外壳、页面和数据可并行准备。访客只看到登录入口。普通入口加载十份卡片，深链优先读取指定资料、版本和段落，返回资料库时才读取列表。A→B→A 后，B 的晚到响应没有回填。先于页面分包结束的请求即使失败，也交给页面展示并支持手动重试。
- 普通列表和文件、文字分类使用现有按 owner 隔离的 PostgREST 读取，保护会话附件的过滤条件仍在查询中。每次投影八个摘要字段并取精确总数；搜索词继续经鉴权 POST 传递。用临时账户的 13 份资料比较第一批 10 份，两条路径的字段、顺序与总数完全一致。另一账户读取到 0 条。六组交替公网对照中，原 Edge 列表为 391–689 毫秒，中位数 550 毫秒；直接读取为 348–576 毫秒，中位数 400 毫秒。此对照包含跨网耗时，与下方固定延迟的浏览器测试分别计量。
- 资料上传、详情、关联等实现按入口加载。慢分包可以关闭，503 后可局部重试。已排版的可见列表保留滚动和回焦。普通文字重开可复用同版本结果；不支持预览的文件等用户下载才读取 Blob。真实 UI 中查看未知格式文件时下载为 0 次，按下载后为 1 次，收到的字节与上传样本一致。
- 新的保存操作不再先查一个尚未使用的操作 ID。按实际 UI 粘贴文字、上传原件各只发一次 save。真实重放、不一致内容和模拟响应丢失均核对了服务端结果。45 段资料继续读取时，重复消费者共用一次目标页读取；引用位于已读页时无需额外请求，引用更后面的段落才读取指定段落。
- 改名复用服务端返回的元信息，正确保存的标题、版本正文和原件可以复用。真实入口从改名到返回、重开只发一次 rename。搜索结果中的改名需重新判定是否匹配。关联简历每批投影 ID 和名称，真实账户有 12 份简历，首批 10 份、第二批 2 份。选第 12 份关联、重新打开、取消关联均已核对，期间只发两次候选请求。
- 首次加载四页和回到已访问页使用 37 条样本验证。前三页已缓存后模拟总数降到 21，第四页的 416 触发一次零行计数，并重新读取第三页。界面最终只显示第 21 份，下一页禁用。批量删除最多同时执行两份，每份继续走原有版本与原件清理协议，局部失败只重试失败项。三份文件上传中途有一份失败时，其他两份可以分别完成，关闭弹窗后刷新一次列表。保存、改名、关联和删除的云端核验均使用专用临时账户。

## 工程与发布

本地生产构建和两个 TypeScript 项目检查通过。全仓 `pnpm format:check` 通过，ESLint 报告 0 个错误、62 个警告，Vite 仍提示项目存在超过 500 kB 的分包。临时测试账户、资料、服务和脚本均已清理。

部署前下载并核对了职业档案函数及引用的 22 个源码文件，本轮云端差异只有搜索末页越界处理。已将 `experience-sources` 从 v6 部署为 ACTIVE v7，保留现有鉴权配置。真实账户同一搜索越界请求在旧版返回 503，新版在 us-east-1 返回 200、空列表及正确总数；另外复核了字面通配符、会话附件隔离和匿名请求返回 401。前端改动已落地，尚未发布，等待用户审查。

本轮没有数据库迁移。部署前已核对本地和云端 86 条记录。部署后 CLI 首次复查连接池超时，随后通过 linked 项目只读 SQL 逐项比对远端迁移版本与本地迁移文件，仍为 86 条，差异为 0。
