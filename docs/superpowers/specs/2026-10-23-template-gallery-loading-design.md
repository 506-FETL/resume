# 模板列表渐进加载设计

用户授权：排查滚动重复加载，考虑批次大小并直接实现；在当前分支完成，不增加本地模板资源副本。

## 现状与根因

远端已经按 12 条分页，多读取第 13 条判断是否存在下一页，但页面只提供手动按钮。卡片的 useInView 随可见性反复变化，图片 hook 在离开视口时释放 URL 并返回空值。实测首次与滚回后的 Blob URL 不同，离屏时 img 数量变为零。此外列表追加超过 120 条会删除前面的条目，无法支持连续向上浏览。

## 决策

- 采用 12 条/批的自动追加：桌面 3 列对应 4 行、4 列对应 3 行；移动端只增加轻量目录，图片仍按需请求。6 条请求更频繁，24 条会创建更多暂不使用的卡片，因此保持 12。
- 底部距离实际滚动容器可视边界 480px 时请求下一页，保留手动按钮供键盘和底部自动观察未触发时使用。不做提前遍历全部目录。
- 图片进入可视区域前后 600px 范围后开始读取，一次触发。解码完成再展示，滚出视口不撤销 URL；仅更换图片/卸载卡片时回收。读取完成即释放 Source 缓存固定引用，防止浏览超过 64 张图达到活动资源上限。
- 目录、缩略图和追加请求有各自状态。追加时不卸载已有卡片；失败停止自动重试，显示按钮；没有 nextOffset 时显示全部加载完毕。
- 追加保留已加载条目且按 ID 去重，不截掉前 120 条。同筛选返回页面复用会话列表；主动重试/筛选变更开始新代次，旧请求不能污染新列表。
- 第一阶段保留已访问卡片与图片以保证滚动稳定，不引入复杂虚拟网格；网络请求仍为每批 12 条与图片并发 4。极长会话 DOM/Blob 数量随已浏览数量增长，未来如果需要数千条连续浏览，再加入保留滚动位置的虚拟网格。

## 边界

仅修改模板目录页面、图片 hook 和目录 store。保留分类独立加载、精确资源校验、通用模板渲染和 PDF 行为；无需数据库或 Edge Function 变更。所有新增动效沿用 motion 预设并使用 useReducedMotion。

## 验收

真实 12 套目录首屏按需请求图片、上下滚动 URL 保持、不重复请求、最后一页无加载中。受控 35 条目录验证 12→24→35、没有主动加载全部、请求并发去重、追加失败只重试一次、筛选期间迟到响应隔离；156 条保留首项。移动端、减少动效、缩略图失败重试与缓存引用回收覆盖。保留小型验证脚本，不生成截图/PDF 等大目录。
