# 我的简历首开与按需读取验收

本轮范围是侧栏「我的简历」及其直接调用的共享模块。验收使用本地生产构建。前端尚未发布，本轮没有数据库迁移或 Edge Function 变更。用户审查待进行。

## 原录制及根因

开发录制 Trace-20261126T103600 从导航开始计时。首次内容绘制为 277 毫秒，最后一个文本 LCP 候选在 652 毫秒。库统计和第一页摘要均在 648 毫秒发出，分别在 1,217 和 1,199 毫秒返回。列表读取 11 个摘要字段；3 个不同目标的真实纸页按 ID 各读取 19 个排版字段，前两个在 1,666 和 1,667 毫秒才开始。另有一次打开页面即读取的 AI 额度、可见顶栏的 GitHub 星数和头像资源。录制含 561 次指向 Vite、源码或开发依赖路径的请求。78 毫秒附近的长任务包括扩展脚本编译；1,400 毫秒附近的 144 毫秒长任务在 React 开发运行库回调中。

旧生产包逐帧复现了用户指出的头部闪烁。统计先到时，页面把真实头部放在加载骨架内。列表就绪后，整个容器先退出，标题祖先透明度降至 0，再挂载第二个从 0 入场的标题。一次桌面样本中，旧标题在 1,123 毫秒全透明，重建的标题在 1,191 毫秒才重新可见。

使用无扩展的 Chrome 158，1200 × 900、DPR 1，打开含 23 份简历的样本。统计、列表、正文、模板请求分别施加 240、420、220、65 毫秒的固定延迟。新旧各测五次，交替运行并取中位数。时间从导航开始，显示时间取实际可见的帧，缩略图计入真实模板的排版。主机测试时负载较高，以下数据用于比较本次改动。

首条简历的五次范围为旧包 1,074–1,661 毫秒、新包 535–780 毫秒。LCP 候选大多是第一条简历的标题，新包有一轮取第二条标题。首张和前两张预览在这台机器上仍需约 3.5 秒，五轮中有波动。数字来自本地生产包；真实 Supabase 核验在下方单列。

另用慢分包和慢数据重测。外壳文件在 962、996 毫秒返回的两次，真实搜索框分别在 1,187、1,272 毫秒的下一次可绘制帧出现。统计延迟到 1,789 毫秒时，十条简历在 568 毫秒已可见。标题从第一次可见到列表出现持续在同一个位置，没有全透明或被遮挡的帧。手机与短屏回归中，列表能滚动，分页可操作，没有横向溢出。

五轮时序对照后，针对页脚计数和页头徽标补上数字占位。旧包 CLS 中位数为 0.00000934。修正布局后六次独立冷开在 0.00000934–0.00001239 之间，其中包含最终分享回焦修复的三次冷开均为 0.00001239。计数出现时，先前可见的页脚文案与徽标横向移动都已消除。

## 实际改动

- 外壳、业务页和数据模块并行准备。普通简历库只在身份确认后启动一次库读取，路由挂载接续同一轮结果。已下载的外壳与页面直接取用。恢复回调和岗位上下文保留门禁。
- 外壳或业务分包尚在下载时展示对齐的简历库骨架。实际页的标题、搜索、分类、操作按钮和页脚持续挂载，列表数据只改变列表区域。减少动效沿用系统偏好。
- 云端每批最多 10 条。本地无筛选首屏只按更新时间取前 10 个键，兼容缺少时间的旧简历，精确统计独立读取。搜索仍按名称与描述匹配，翻到深页按实际批次确定边界，确认读完的来源和访问过的页可以复用。跨页父名称、统计或匹配总数单项失败时，已就绪的卡片可以继续使用。
- 可见纸页直接申请预览，模板名在相应徽标进入视口后读取。相同版本成品可复用。编辑、删除、分享、岗位定制及同步面板按实际交互准备。简历卡只订阅自身需要的状态。账户菜单等展示位第一次需要额度时才读取。
- 改名使用数据库返回的名称、描述和更新时间，同次保存与 Realtime 更新通知合并刷新。搜索、外部变更和删除仍确认真实页序。候选及任务的缓存可复用，关闭弹窗后写入不会触发全库候选读取。同步按选中的 ID 逐份准备正文，再执行原有的归属、幂等和上传后删除校验。

## 功能验收

- 用延迟和失败的真实网络边界覆盖了统计、列表、页数、父摘要、模板名和预览。当统计请求被挂起或返回错误时，十条真实列表仍可见，单独重试统计只新增一次计数。父摘要失败保留卡片和正在生成的任务；单 ID 重试成功后两处共享结果。
- 23 条混合数据分页为 10 / 10 / 3。回已访问页无需重新读摘要，末页内容被删除后回到有效的最后一页。搜索的旧响应不会覆盖新条件或抢走输入焦点。完整缓存可直接筛出候选和任务。验证访客空库、实际 IndexedDB 旧记录和账户 A→B→A，对应账户之前的错误不会覆盖最新结果。
- 在 2,000 份本地简历上，首屏没有调用对象主键或更新时间索引的全量 getAllKeys；第二页首次读取一轮完整的有序时间键。18 条含空时间旧样本按有效日期和主键倒序混排。卡片仅保留 JD 片段，在岗位定制中打开后可读取完整的 300 字原文。
- 10 条、两种模板的样本首屏只查可见模板的名称。滚到底再读取第二种。两套官方模板的真实首张纸页 HTML 与旧包逐字节一致，返回顶部没有正文重读。单份正文失败只重试该卡。
- 分享和岗位定制分别经过 1.3 秒慢分包、加载中关闭、503 后原地重试、390 像素减少动效验收。两轮开关和退出中重新打开均保持单个面板，最终焦点返回原行按钮。另验证创建、改名和删除入口、合成模型流下的本地岗位版本保存。岗位上下文请求未获授权时不读取简历库，通过后只启动一次；官网和工作台首页没有误启动库读取。
- 真实 Supabase 临时账户中，首次进入读取 1 次统计、1 次摘要、2 份不同简历的正文，各 19 列。账户菜单打开前后额度请求分别为 0、1 次。通过真实入口创建分享链接并核对保存结果。改名前的两轮重复摘要和计数在实际订阅下复现；新版收到一次实时回声，只刷新一轮，另一客户端修改仍正常显示。删除一份后各刷新一次，云端目标确已删除。临时账户及数据已清理。
- 在已登录的空库阻塞统计请求，列表先返回时直接显示「还没有简历」。加入两份本地简历后，只勾选其中一份，通过真实入口上传。云端仅新增选中的一份，本地保留未选的一份，弹窗显示已选 0 份，用户可继续选择。直接调用迁移入口时，空选读取 0 份正文，重复 ID 只处理一次；模拟上传失败时，第二份正文在第一份上传尝试结束后才读取。
- 连续打开创建、编辑、删除，再在分享占位交接时按 Escape，旧回调曾阻止焦点回到分享按钮。最终生产包复测上述操作，以及在分包放行后的 0、30、100、170、230、290、330 毫秒按 Escape，共八种情况均回到原行的「分享」按钮。
