# 列表分页、加载提示与求职筛选调整

日期：2026-11-11。依据用户本轮四张截图及补充要求：检查项目中所有同类分页场景并修复。用户已授权实施与筛选方案决策，本期完成后统一交用户审查；不另行请求重复授权。

## 目标与边界

1. 简历库页头和分页保留在可见区域，只有中间简历列表滚动。其他带页码翻页的列表一并检查；追加式加载保持原有语义，不强行改成页码。
2. 明确上下文里的短暂读取只显示公共 Spinner，保留无障碍名称。骨架、真实进度、失败原因和重试继续显示；生成、识别、保存、导出等需要知道正在做什么的动作保留必要文字。
3. 求职跟进取消占满整行的等宽指标卡，将其整理成紧凑快捷筛选，提供“全部”及原有已投递、面试中、已录用、待跟进。看板与列表使用相同过滤条件，阶段菜单与快捷指标互斥，搜索、公司、关注、归档仍参与筛选。不得把“已投递”改回单一阶段统计。
4. 截图中的“当前简历信息”实际由历史详情公共组件渲染。标题、操作和信息入口固定，预览单独滚动；展开信息和编辑长内容不得挤掉预览或让工具栏跟随纸张滚动。
5. 用户追加要求：简历库切换“全部 / 原始简历 / 岗位版本”复用已加载的数据，避免重复读取与闪现加载。每页上限、混合排序与数据完整性保持。

## 方案

### 分页与滚动

采用有高度边界的 flex 页面，页头与页脚 `shrink-0`，正文 `min-h-0 flex-1 overflow-y-auto`。分页从列表内部移到同级页脚，页脚保持背景与上分隔线，并处理底部安全区；不使用脱离页面宽度的全局 fixed。筛选统计未知、失败、末页和加载期间继续使用既有数据规则。成功翻页重置正文滚动和焦点，失败保留旧列表并回焦翻页入口。

检查所有可见的页码和上一页/下一页入口；记录其所在容器、滚动归属和最终处理。模板目录、历史、聊天等追加式加载只有确属常驻操作的场景才移动，不把内容末尾的自动加载哨兵固定到视口。

### 简历筛选缓存

复用现有页面 store 的成功统计和分页缓存，不额外下载全库。统计明确为零的分类直接展示空态；分类总数与全部相等时共享已成功读取的分页及后续游标；全部页和父摘要都已完成时，才从完整集合推导分类页。只缓存了部分全部页时，仍读取必要的分类页，不能让当前页的局部结果冒充全库。账户切换、写入失效、失败重试、迟到结果隔离沿用原实现。验收两份原始简历的首次三页签切换零读取、零 loading，以及 23 条混合分页、不完整数据、父摘要失败、写后更新和账户 A→B→A。

### 加载反馈

优先复用 `src/components/ui/spinner`。短暂读取的可见提示使用 Spinner 的 `aria-label`，需要 live region 的地方继续保留 `role=status` 或隐藏说明，避免同一加载被重复播报。保留缓存命中不闪加载、200ms 延后提示、数据源各自加载及真实失败状态。按钮原动作名称、长任务阶段与进度不机械删除。

### 求职筛选

保留现有页面标题、新增、列表/看板、搜索、公司、阶段和批量功能。桌面快捷筛选靠左自然宽度排列，数量从属于名称，不做四等分卡片；当前选择明显，hover 与选中分开。移动端继续使用既有“全部/待跟进”和阶段菜单，保留桌面视图偏好。

看板和列表均按当前阶段或快捷指标过滤实际职位，计数与批量全选使用相同范围。看板保留八阶段流程和现有拖动/确认链路；必要的横向定位仍可辅助导航，但不得取代筛选。零结果可以明确清除筛选，不清空搜索、公司等无关条件。现有归档、关注与公司范围、响应率事实口径不变。

### 历史详情

继续复用 Collapsible、Button 和真实简历预览，信息展开不重挂载预览。信息区在预览外部固定，展开较长内容在受限区域内滚动；预览始终有可用高度。切换版本与编辑状态继续重置适当滚动，保留取消、保存、未保存确认、两轮开关与快速反向，以及焦点交接。
