## 授权与反馈

用户对上一轮反馈「只是把卡片换成列表，主次和设计感不够」，要求继续实现更有自身特色的 App，首页不动。本轮为已授权范围内的视觉深化，完成实现与验证后交用户审查，不重复索要确认。

上一轮实现和技术验证已完成，但视觉审查未通过。不能以去掉边框、零溢出或 detector 无命中证明设计完成。

## 方向

保留现有字体、中性色、灰蓝紫文档类型色、评分语义色和导航。比较「增加装饰和大数字」「所有页面统一主从面板」「让真实内容形成不同构图」三种方案，采用第三种：简历是文档，分享是围绕文档的链接集合，优化是有处理顺序的报告。控制页面级视觉焦点的数量，不把每项都放大。

沿用已实看 Things 的分组节奏、Notion 的文档组织与 Craft 的内容优先思路；不照搬营销站的巨型标题、玻璃卡或工作台统计块。

## 三页构图

- 简历库：最近更新的一份作为明确焦点，以真实纸张预览、较大标题和主动作构成开放横向区域；其他简历密度收紧，保持完整操作。筛选后的文档仍按真实更新日期选择，不把生成失败的岗位版本当作推荐。最多挂载一个真实预览，复用已有缓存与账户边界；预览失败明确反馈，不伪造纸张内容。不改首页组件源文件或其共享样式常量。
- 分享管理：以 resume_id 分组，简历名称形成章节，组内链接左上显示自定义用途（label 优先于 purpose）、权限与复制动作。桌面文档信息和链接区形成不等宽关系，手机自然顺排。不同链接仍明确显示来源，标题仍为真实简历名称，不以自由备注改写权限分类。分组只作用于筛选结果，不改变计数、查询、排序及真实数据。
- 优化报告：评分与评估结论构成明确的报告引言，保留已有评分水印。首个真正待处理的问题按严重程度优先呈现并展开，其余问题保持次级可展开条目；不能把已修复问题标成首要问题。修复清单作为辅助，评分依据和工具保留。展开只改变查看状态，不触发付费、写入或自动修复。

## 约束与验收

沿用 Button、Tabs、Collapsible、DropdownMenu、Skeleton、Empty、Dialog 及现有真实预览，不新增 UI 库或全局视觉变量。数据、权限、账号隔离、菜单回焦、所有真实动作均保留。动画使用公共预设与动态 useReducedMotion，快速反向可用。

实际检查 1440 / 1024 / 768 / 390 / 320 px、深色、长标题、多个链接同简历、单条记录、筛选、空态、失败与加载。先看首屏有无明确焦点，再检查操作可达、键盘焦点、菜单连续两次开关、问题反向展开与减少动效。临时样本放 tests/ 并在结束删除，截图和日志放 .superpowers/personal-app-character/。
