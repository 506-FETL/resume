# AI 助手 AI Elements 完整接入规格

状态：用户已授权实施（“尽可能的能替换的全部替换”）；实现与本地验证完成，用户审查待完成。

## 目标与依据

逐项核对 AI 助手中可复用的交互、输出和流处理，把仍然重复实现的部分交给官方组件与 AI SDK。此前的 Trace 改造没有覆盖手写工具参数解析、多步模型循环、代码块和确认卡，因此不能称为完整替换。

已读取防回归清单第 28 节、Trace 升级规格与计划、滚动连续性验收；本轮沿用这些已确认行为。官方依据为 [AI Elements](https://ui.shadcn.com/docs/ai-elements) 及其 Chat、Message、Prompt Input、Reasoning、Tool、Confirmation 页面。当前官方采用 shadcn 组件组合模式，没有单独的整套 AI Elements 安装包。

## 方案

1. 会话继续使用官方 Message Scroller、Message、Bubble；思考、技能和工具继续使用 Trace。根据官方示例补齐 Item 确认卡、Attachment 引用、Code Block 和 Tooltip 消息操作。保留真实业务内容与中文标签。
2. Markdown 继续使用官方示例采用的 Streamdown，明确流式与完成状态；代码块使用官方 primitive，删除重复的代码高亮和交互实现。共享消费者一并适配，保留复制、下载与代码内容。
3. 多步模型调用改用 AI SDK `ToolLoopAgent` 和官方 DeepSeek provider。SSE、工具参数碎片、思考增量、步数控制与模型消息转换交给 SDK；通过 `createUIMessageStream` / `readUIMessageStream` 产生完整消息快照，删除手写 StreamParser 和页面逐类拼接 token 的代码。
4. 模型仍经过已有 Supabase llm-proxy。抽出共享原始 Response 请求函数，复用登录鉴权、请求标识、额度响应头、额度错误与取消。其他 LLM 消费者继续兼容原入口；不更换模型供应商、不改变服务端计费、不自动重试收费请求。
5. 持久化 AiMessagePart 是既有数据库契约，保留薄的 SDK 消息适配。历史多步因果顺序、DeepSeek 思考回传、技能加载资料和实际工具实现继续保留。

## 必须保留的业务边界

- 简历字段差异、画布联动、版本撤销、岗位与简历读写属于产品业务，官方通用组件没有对应实现；只替换承载它们的界面。
- 写工具确认桥包含真实差异预览及确认后的写入；单个 pendingConfirm 只容纳一个请求。SDK 默认可并行执行工具，因此本轮必须在每次运行内串行执行工具，维持原有顺序，防止两个写入确认相互覆盖。
- Zustand 页面状态与历史分页、保存、重跑截断、账户切换取消仍由原业务维护；使用 SDK 的官方 UI 消息读取器更新快照，无需再叠加一份 useChat 历史状态。
- 只有一个真实模型、没有上传能力的入口，不因文档有 Model Selector 或上传示例而添加虚假功能。

## 不得回退

- 不恢复用户轮次 scrollAnchor、空尾行或结束后的补偿跳转。流式与保存后的行身份连续，手动展开状态保留。
- 深度思考开启态在 hover 时仍明显，无尾部勾选；不显示每轮 token 用量。
- 中文输入法与 Enter、停止时保留草稿、焦点恢复、已执行工具结果、额度状态、失败重试保持原行为。
- 不混用 Radix 与 Base UI 状态选择器；动效复用公共预设，支持运行中切换减少动效。
- 当前分支实施，不提交或推送。无数据库或 Edge 函数修改时不部署后端；前端本地验证与线上发布状态分别说明。

## 验收

- 实际 SDK + 合成上游 SSE 验证文本、推理、片段化参数、多步调用、多个写确认串行、历史因果、取消、工具失败、额度异常、步数上限和用量汇总，不复制解析器逻辑。
- 实际页面覆盖短长回复、保存切换连续帧、上滚阅读、工具展开、复制下载、引用删除、确认和取消、两轮开关与反向切换、键盘、手机及减少动效。
- 完成改动文件 Prettier 与 ESLint layout、应用和 Node 类型检查、全量格式检查、生产构建与 diff 检查。临时验证文件放 tests 下，交付前删除；非敏感证据写入验收文档。
