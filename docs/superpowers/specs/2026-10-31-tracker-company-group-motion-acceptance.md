# 桌面公司分组退出动效修正

日期：2026-10-31。范围为桌面列表按公司分组的进入、退出及职位归位，不调整工具栏布局、手机列表或首页。局部修正，无独立大规模设计和实施计划。

## 根因与实现

原先公司标题退出只改 opacity，AnimatePresence 仍为标题保留表格行高。浏览器逐帧复现：第一条职位在 y=198.5 保持约 200ms，标题卸载时直接跳到 y=153.5。

表体改用 popLayout，退出标题立即脱离布局流，职位同时移动到目标位置。表体使用 relative，自定义 JobTableRow 将 ref 传到真实 tr，保证筛选移除职位时也能测量退出位置。保留稳定职位 key、业务操作与退出节点隔离。

## 动效复核

按 transitions-dev 和 review-animations 检查，以仓库公共预设为准。

| 原行为                       | 调整                                 | 原因                         |
| ---------------------------- | ------------------------------------ | ---------------------------- |
| 标题淡出后才释放位置         | 标题退出与职位归位同时开始           | 消除卸载时突然上跳           |
| 排序弹簧有细小回摆和较长尾段 | 显式 tween，DURATION.base + EASE.out | 200ms 内稳定归位，不缩放文字 |
| 标题退出与进入都为 200ms     | 退出使用 DURATION.fast               | 140ms 淡出，与位置移动衔接   |
| 自定义行没有向下传 ref       | ref 交给 PresenceTableRow            | popLayout 能测量真实表格行   |

复核结论：通过。只使用位置变换与透明度；减少动效时禁用布局动画并归零过渡，快速反向能接续当前状态，不引入等待定时器或整表重挂载。

## 实际验证

临时 tests/tracker-group-motion 入口挂载正式 TrackerToolbar、ListView、MotionProvider、TooltipProvider 和 Zustand store，使用三家公司、九条交错职位。阻止外部网络请求，未写入真实岗位数据；验收后删除临时入口。

- Chromium 768 / 1024 / 1440px：每种宽度两轮完整开关，五次间隔 50ms 的快速反向；最终恰有三条公司标题、九条职位，退出节点无残留，焦点在分组按钮，无页面水平溢出。
- 退出位置采样：0ms 为 198.5px，42ms 为 170.16px，83ms 为 157.51px，125ms 为 154.23px，150ms 为 153.69px；217ms 为最终 153.5px。标题卸载时没有第二次大幅跳变。
- 搜索一家公司后恰有一条标题和三条职位，清空可恢复九条；排序正常；批量全选为九条职位及表头共十个选中复选框。
- Space 两轮开关，按钮保持焦点，焦点不处于 aria-hidden / inert；普通操作控制台 0 errors / 0 warnings。最后开启减少动效时仅有 Motion 的开发提示，没有业务或焦点警告。
- 预先开启减少动效，退出 30ms 后无标题、无位移；运行中开启减少动效后原过渡正常完成，无残留。手机 390px 仍无表格与看板入口，无水平溢出。
