# 分享管理性能验收

本轮覆盖工作台的 `/share`，包括首访、筛选、翻页、创建、改设置、启停和发布。旧版基线取自同一仓库的 `ac2a22fe`。本次没有收到这页的浏览器 trace，以下页面数字来自同机新录的生产包对照。

## 浏览器

最终生产包使用无扩展 Chrome for Testing 158.0.8127.88，桌面视口 1365 × 900，窄屏视口 390 × 844。每个版本各开三个新的浏览器上下文，交替测量，取中位数。43 条分享分三组，72 份简历候选。网络设为 75 ms 延迟、900 KB/s，CPU 减速两倍。合成后端的卡片和统计额外等待 250 ms、450 ms。首卡计时到实际标题进入视口且合成透明度达到 0.5。

| 桌面指标               |         旧版 |       优化后 |
| ---------------------- | -----------: | -----------: |
| 首个分享卡片请求发出   |     1,461 ms |       878 ms |
| 首个分享卡片请求完成   |     1,735 ms |     1,155 ms |
| 首张卡片可见           |     1,952 ms |     1,216 ms |
| 搜索框可用             |     1,458 ms |     1,099 ms |
| 统计数字可见           |     1,953 ms |     1,367 ms |
| 第 2 页卡片可见        |       888 ms |       411 ms |
| 第 3 页卡片可见        |       834 ms |       346 ms |
| 首屏 JavaScript 请求数 |          154 |          108 |
| 首屏 JavaScript，gzip  |    454,656 B |    329,370 B |
| FCP / LCP              | 832 / 832 ms | 832 / 832 ms |

- 两版的 LCP 元素都是「分享管理」标题。首张卡片的改善发生在接口提前发出，以及响应到达后可以立即替换骨架。分阶段核验中，系统 Chrome 第一轮只拆请求和分包，第 2 页仍需 867 ms。第二轮取消等待骨架退出后，同一浏览器测得 430 ms。上表为最终生产包的独立对照。
- 同一窄屏环境的首张卡片从 1,938 ms 降到 1,219 ms，搜索框从 1,443 ms 降到 1,091 ms。以上为合成网络条件，实际线上用户的耗时取决于设备和网络。
- 首屏管理业务读取从 3 次减为 2 次。相同样本的业务响应合计从 25,876 B 降至 19,182 B（未压缩 JSON，不含预检与外壳请求）。卡片附带当前简历名、组内数量和筛选结果总数。摘要返回概览、各状态计数、最近到期时间及是否存在云端简历。翻页或只切换状态各读一次卡片，返回同次访问的已读页为零请求。离开再进入会重读卡片和摘要，以获得新的访问次数和状态。
- 在浏览器分别挂起卡片和统计 3.2 秒，另外一项都能先显示。统计返回 400 时仍可看卡片、翻页。卡片失败时保留概览。重试只读取失败的部分。若预读先失败，实际页面挂载后直接显示该次错误。

## 候选及数据库

- 初次进入和只打开新建抽屉均不读候选。展开选择器才请求名称与 ID，或冻结版本的五个摘要字段。每页展示 20 项，查询额外一项判断是否有下一页。首屏和候选均不读历史快照、简历正文或 JD。
- 限定同一账户，对比 45 条分享、四种搜索、五种状态、三页的旧新卡片 ID 和计数。另用 43 项候选验证 20/20/3、搜索、特殊字符及权限隔离。当前发布版本落在候选页外时，按主键单独核对。
- 隔离 PostgreSQL 引擎 PGlite 使用 1,043 条合成分享交替执行 8 轮，舍弃首轮，取其余 7 轮执行时间中位数。旧分页查询 2.106 ms，新卡片查询 2.270 ms。旧统计 2.755 ms，新摘要 0.396 ms。新摘要的执行计划直接聚合，翻页不再触发该查询。该组数据只衡量本机 SQL 执行。
- 搜索下推到数据库后，按已安装 cmdk 的实际过滤结果对照了有序跳字、相邻换位、重复输入、连字符、空白和字面符号。连续命中优先，同档按名称与 ID 或版本号稳定分页。
- 在真实认证的 43 项候选中，简历第一批未压缩 JSON 从 4,525 B 降到 1,669 B，版本第一批从 5,546 B 降到 2,710 B。跨页多选、页外里程碑、局部 503 重试通过。StrictMode 首次打开绑定历史版本的弹窗，两次重复点查合并为一次。改名称不再触发版本点查。

## 真实写入

本地生产前端连接已链接的 Supabase 云端项目，使用临时账户和临时简历。下表记录页面发出的业务请求，不含浏览器预检。

| 操作                                     | 旧版 | 优化后 |
| ---------------------------------------- | ---: | -----: |
| 设置原样保存                             |    3 |      0 |
| 全部列表中只改分享名称                   |    3 |      1 |
| 全部列表中启用或关闭                     |    3 |      2 |
| 将当前已保存内容建为带密码的正式投递分享 |   12 |      8 |

- 改名称保留原有的精确到期时刻。修改筛选内成员资格时才补读当前卡片，启停仍更新有效数。首次启停额外加载的 JavaScript 由 7,795 B 降到 1,597 B（解压后）。
- 用有意不同的已保存简历与工作版本内容验收。正式投递冻结了已保存的姓名，后来修改源简历没有改变发布快照。创建分享后投递记录仍为空。归档、删除、版本发布和跨账户拒绝均通过，设置写入的 Edge 响应地区为 us-east-1。
- 无登录访问管理页、无效岗位入口、公开阅读页均无管理业务请求。用 SDK 跨标签页会话事件执行 A → B → A 并延迟首次 A 的响应，页面保留最后一次读取的 A 数据。新建分包故障后局部重试恢复。桌面及减少动效的窄屏均验证反复打开、关闭和焦点恢复。
