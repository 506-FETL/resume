# 编辑页内部加载优化设计

用户在已确认根因后授权继续彻底优化编辑页内部加载。本期在当前分支实施，不重复请求批准；保留用户已暂存的前期改动，不提交或推送。实施、验证、用户审查分别记录。

## 目标与证据

进入编辑页后，尽快开始真实文档读取并显示准确正文；打开编辑栏、富文本、评论、检查及工具栏功能时继续保持可用的加载反馈、错误恢复、原有动效和保存语义。

已确认：栏目常量静态导入全部 12 个表单，排序菜单也经过该模块；表单再引入完整 Tiptap。编辑路由、store、协作 URL 解析及保存 slice 还静态引入 Automerge。独立浏览器给原生 WASM 初始化增加 1 秒延迟，两个真实 owner GET 同步后移约 1 秒；两 GET 之间已在上期并发，不能重复计算该收益。模板仅在文档恢复、预览挂载后读取，须核对能否使用现有精确版本缓存提前开始。

## 方案与边界

采用“按实际使用加载 UI，独立数据与引擎并行”的方案。仅拆 UI 不能消除 WASM 阻塞文档 GET；先展示列表缓存或直接用配置正文替代 Automerge 则可能展示过期内容并改变保存真源，本期不采用。无需更换编辑器、数据模型或数据库区域。

1. 栏目名称、图标和排序保持轻量；各表单按打开的栏目加载。共享富文本依赖由实际富文本表单触发。桌面面板、手机抽屉、Tab、Accordion 的外壳和退出生命周期保持，不因为关闭立即破坏原内容。
2. 工具栏保持原位置与真实按钮。模板切换会话、导出 query 参数和其他必要控制逻辑继续常驻；目录、预览、准备记录、导出详情等重内容在首次使用时加载，并按原关闭/焦点生命周期释放或保留，避免退出坍缩。
3. 评论 unread/权限失效/工作文档同步与检查计数所需逻辑保留；评论面板、检查列表和协作设置界面延迟到实际使用。已经访问过的面板保留当前 Tab 草稿与滚动，退出完成前不卸载。
4. 在已有文档加载入口拆开轻量读取与引擎加载，启动 owner 只读 GET 后并行等待引擎；初始化、缺失修复和保存仍在存在性、账户与请求代次核验之后。协作 URL 解析只在有协作参数时需要；不能给普通 owner 路径加载整个 repo 的副作用。
5. 精确模板预取只使用已经取得的有效绑定与现有去重缓存；不额外查询整份配置，不新增全局正文缓存，不把预取失败误写成成功或默认模板。
6. 复用项目既有 Button、Skeleton/PageLoading、ErrorBoundary 和动效。需要跨表单/面板复用的延迟组件边界支持真实本地重试，失败不能使整页消失；重试不刷新页面或丢弃未保存输入。针对实际慢模块导致的字段定位问题，接入真实挂载就绪信号，不仅增加超时。

## 范围与验收

主页面保留 history-style 目录，必要共享状态放现有页面 store，不扩大为全站重构。源样式、字体、打印尺寸与分页算法不变。正常 owner、离线、guest 与协作恢复继续沿用原数据和权限协议。

验收分生产/开发、冷载/热载、直接进入/路由重入；记录 JS/WASM 依赖、文档请求发出、正文出现、首次表单/富文本可用，以及长任务。对照使用同一合成简历和网络条件，禁止真实用户写入。覆盖完整输入与保存重开、慢模块/加载失败后重试、检查定位、模板/准备/导出弹窗的两轮开关和快速反向、手机与减少动效、评论与协作必要生命周期。实际 PDF 入口校验最新输入与分页；不调整字体/分页算法时不扩为全模板协议变更。

类型、定向 lint/layout、生产构建与全仓格式检查通过后交付。临时脚本/数据仅置于 tests/editor-startup，完成后删除，验收结果写入同目录永久记录。本期预期仅前端；若发现确需 Edge/迁移修改，先说明具体必要性并按仓库云端部署规则完成验证。
