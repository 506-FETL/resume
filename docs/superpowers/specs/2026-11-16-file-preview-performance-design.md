# 职业档案原件预览等待优化

日期：2026-11-16。用户在全项目拆分过程中追加授权，要求排查并修复文件原件加载慢。本项与源码拆分一同实施、验证后交用户审查。

## 已确认的调用链

当前详情先等待 `read` 返回版本和提取段落，才挂载原件组件；原件组件等待完整 Blob 下载，才挂载按需加载的 viewer；PDF viewer 再加载 PDF.js 与 worker、解析文件、绘制首屏。列表已有资料 ID、当前版本 ID 和 kind，可以提前发起该明确版本的原件请求并准备对应 viewer。两次独立请求不应串行。

原件 Blob 已按账户代次、资料和版本缓存，但 PDF 的 worker、解析与绘制每次重开都会重做。首屏成品应在同一 Blob 生命周期内复用；不要永久保留 worker、全部页图或旧账户数据。

## 实施边界

1. 进入具体资料详情时，已有明确当前文件版本的原件下载与详情读取并行；仅准备该文件类型的 viewer，不在整个列表加载预览引擎。历史版本按指定 ID 读取，取得该版本的文件名后并行准备引擎和原件，不能用当前资料类型猜测历史版本。详情读失败时继续显示明确错误，不能绕过权限或编造版本信息。
2. viewer 模块在下载期间加载；PDF.js 和 worker URL 与组件一起准备，下载完成即可解析。失败不固化为成功缓存，保留现有局部重试。
3. PDF 首屏复用已绘制成品，以 Blob 身份和渲染尺寸为准；Blob 缓存已在换账户、删除、更新时失效。只保留有限的预览成品，释放 worker，不预渲染全部页；翻页继续按需绘制。
4. 保留现有 skeleton、翻页禁用、错误、键盘、减少动效与进入退出反馈。不使用第三方在线 viewer，不改对象存储为公开，不删最终归属校验。

## 验收

先保留实际旧组件基线，在本机使用同一 PDF、同一受控传输等待比较请求/模块的时间线与首屏出现时间；同时记录真实模块加载、worker 解析、渲染而非仅骨架。覆盖首次打开、重复打开、翻页、损坏 PDF、下载失败重试、版本更换及账户切换。受控实验不能冒充用户文件的真实公网耗时。
