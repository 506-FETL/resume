## 创建流程与背景改版

选择模板后进入填写信息，再创建简历。默认名称“示例简历”，描述为空；提交时去首尾空白，空名称回退为“示例简历”，空描述保留为空。返回模板保留输入与选择；旧草稿补齐缺省字段，结果未知时继续原操作、冻结原正文和信息，避免重复创建。

首轮左侧小卡与右侧顶对齐表单被用户明确否定。按最新要求，选中模板变成铺满左侧正文的背景，宽约 58%，等比例裁切、从左向右渐隐，右侧 44% 区域放表单并垂直居中。详情分支没有卡片按钮、选择描边、勾选及名称条。手机为顶部 176px 背景向下渐隐，表单叠入下方；正文有滚动边界，页脚保留。复用共享 layoutId、公共时长和缓动，减少动效时终止位移，返回恢复目录位置。

真实创建准备和持久化边界的 5 项检查通过：精确模板资源、名称描述写入、正文信息冻结、未知结果重试仅插入一次、账户 A→B→A 隔离。交叉审查发现恢复非首屏模板并直接进入详情时，预览 hook 仍只观察离屏目录占位；已将可见详情背景纳入加载条件，避免一直停在占位图标。实际背景视觉和逐帧轨迹仍需最后浏览器验收，不以这些数据检查代替。

## 搜索、缓存和首屏请求

名称或描述字面包含，英文大小写不敏感；输入防抖 250ms，中文组合期间不查，清空立即恢复。分类和搜索相交，改变条件回第一页。云端参数化搜索函数返回 11 个摘要字段，JD 仅 80 字片段，每批最多 10 项；本地使用名称和描述键索引扫描匹配 ID，不下载全库正文来搜索。

查询成功页和在途请求按规范化搜索词、分类、页与账户/数据代次复用；已完整加载的摘要可推导搜索和分类，部分页不能冒充全库。全库统计、同步候选和任务数据不被当前搜索裁剪。

浏览器初次检查又发现两组首屏请求。根因是页面 `useCurrentUser` 挂载时先 undefined、随后从已有 session 补用户，而 effect 两次刷新并失效缓存。页面现直接订阅已有 user store，同源读取身份与 authStatus，未知时等待，不修改全局鉴权行为。直接提取并执行真实页面 effect 的 5 项检查通过：未知零读、初始化一次、同账户无重复、A→B→A 与登出/卸载清理。

## 求职浮层

两处实际根因：Base UI Combobox Portal 包装层进入 Radix Dialog 的 grid，打开后额外占据 gap；选中嵌套 Select 时事件落到 BODY，外层 Drawer 误当 outside-press 而关闭。

Portal 包装层改为 contents；Dialog 保留用户 Escape 回调后，只在内部 Combobox 展开时阻止外层抢先关闭；Drawer 在上层 Dialog 及其退出节点仍挂载时保留原层。未关闭全部外部点击能力，没有替换组件库或全局拦截事件。

浏览器实测：1440×900 打开职位、公司、城市下拉，弹窗 top=26.25 / height=847.5、网格行 14 / 701.5 / 36 均不变化；旧实现打开会变为 height=868 并移动到 top=16。Escape 只关闭下拉，外层新增职位仍在。真实 Drawer → 记录投递 → 日期、已保存简历、版本的选择与 Escape，抽屉保持；取消回焦“标记已投递”，确认后回焦新阶段入口，close 调用为零。390×844 的新增职位抽屉也完成阶段选择与 Escape 检查。使用合成状态，未写用户岗位数据。
