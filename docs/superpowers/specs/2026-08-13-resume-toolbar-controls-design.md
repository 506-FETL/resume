# 简历编辑器 Toolbar 控件更新设计

## 1. 背景与目标

当前简历编辑器 Toolbar 的间距、字体和历史版本入口存在以下问题：

1. 间距仅提供滑块，虽然取值范围完整，但不便于用户输入带小数的精确值。
2. 字体选项仅有三种抽象分类，无法满足更多视觉风格；字号使用固定下拉选项，调节不够连续。
3. “快速保存”会直接创建历史版本，用户无法在保存前为版本命名。

本次更新在不改变既有粗粒度间距行为的前提下，增加精细间距事务、六款项目自托管字体、连续字号滑杆和可选版本名弹窗。

## 2. 已确认范围

### 2.1 本次包含

- 间距弹层右上角增加“精细控制”开关。
- 粗粒度模式继续使用现有三个滑块及现有即时持久化行为。
- 精细模式改用数值输入，输入时本地实时预览，点击“确认”后才同步正式配置。
- 精细模式有未确认修改时，关闭弹层或切回粗粒度必须提示是否放弃修改。
- 字体下拉替换为六款可随项目分发的开源字体。
- 字号下拉替换为 `10–24px`、`step=1` 的滑杆。
- “快速保存”先弹出小型命名弹窗，版本名可留空。

### 2.2 本次不包含

- 不改变间距、字体、主题的数据库字段结构。
- 不修改历史版本完整管理页的元数据编辑能力。
- 不为粗粒度间距增加确认、取消或退出提示。
- 不把精细/粗粒度模式作为简历配置持久化。
- 不引入专有字体或依赖操作系统已安装字体。
- 不改变字号和字体选择的既有即时同步语义。

## 3. 交互设计

### 3.1 间距弹层结构

弹层标题仍为“间距设置”。标题栏右侧增加：

- 文案：“精细控制”
- `Switch`：未选中表示粗粒度，选中表示精细模式

模式属于当前编辑器会话的 UI 状态，编辑器首次加载时默认进入粗粒度；不写入简历、Local Storage、云端或历史快照。用户在同一编辑器会话内关闭并重新打开弹层时保留上次选择的模式；若保留为精细模式，重新打开时从最新正式 `spacing` 开始一笔新的预览事务。

### 3.2 粗粒度模式

粗粒度模式完全保留现有三个滑块：

| 配置 | 范围 | 步长 | 单位 |
| --- | ---: | ---: | --- |
| 模块上下间距 | 0–100 | 1 | px |
| 行间距 | 1–3 | 0.1 | 倍数 |
| 页面边距 | 0–100 | 1 | px |

每次拖动继续直接调用正式配置更新入口：

1. 页面立即重新排版。
2. 正式 `spacing` 立即更新。
3. 沿用现有 Automerge、云端镜像和协作广播链路。
4. 关闭弹层不提示，因为不存在未保存状态。

精细模式确认的小数值切回粗粒度后仍按真实值显示滑块位置；用户下一次拖动时才按粗粒度步长吸附。

### 3.3 精细模式

精细模式将三个滑块替换为数值输入：

| 配置 | 范围 | 精度 | 输入单位后缀 |
| --- | ---: | ---: | --- |
| 模块上下间距 | 0–100 | 0.1 | px |
| 行间距 | 1–3 | 0.01 | 倍 |
| 页面边距 | 0–100 | 0.1 | px |

进入精细模式时，以当前正式 `spacing` 创建一份预览快照。输入行为如下：

1. 输入框使用适合小数的键盘模式，并保留字符串草稿，允许用户经历空值、小数点等中间输入状态。
2. 当草稿可解析、在范围内且符合精度时，立即更新 `spacingPreview`，当前编辑器画布实时重新分页。
3. 非法、越界或不符合精度的草稿不覆盖最后一个有效预览值；对应输入显示错误状态，确认按钮禁用。
4. 精细弹层不常驻展示“实时预览、确认后同步”等说明文案；字号区域也不展示范围和步长说明文案。

精细模式底部显示“取消”和“确认”：

- “确认”：把完整预览值一次性提交为正式 `spacing`，随后清除预览事务并关闭弹层。
- “取消”：若有变化则进入放弃确认；无变化则直接丢弃预览并关闭。

### 3.4 未确认修改的退出保护

以下动作在精细模式存在未确认变化时均视为退出：

- 点击弹层外部。
- 按 `Escape`。
- 再次点击 Toolbar 的间距按钮关闭弹层。
- 点击“取消”。
- 关闭移动端对应浮层。
- 将“精细控制”开关切回粗粒度。

此时显示确认对话框：

- 标题：“放弃未保存的间距修改？”
- 说明：“当前精细间距尚未确认，放弃后页面将恢复为上次保存的设置。”
- 次要操作：“继续编辑”
- 破坏性操作：“放弃修改”

选择“继续编辑”时恢复精细弹层和原草稿；选择“放弃修改”时清除 `spacingPreview`，页面恢复正式间距，并完成原退出动作。

已确认或未产生变化时不显示提示。

### 3.5 字体设置

字体下拉使用以下六项真实名称：

| UI 名称 | 配置值 | 来源与许可 | 字重策略 |
| --- | --- | --- | --- |
| 思源黑体 | `noto-sans-sc` | Noto Sans SC，SIL OFL 1.1 | 400 / 600 / 700 |
| IBM Plex Sans SC | `ibm-plex-sans-sc` | IBM Plex，SIL OFL 1.1 | 400 / 600 / 700 |
| 思源宋体 | `noto-serif-sc` | Noto Serif SC，SIL OFL 1.1 | 400 / 600 / 700 |
| 霞鹜文楷 | `lxgw-wenkai` | LXGW WenKai，SIL OFL 1.1 | 500 / 500 / 700 |
| Arimo | `arimo` | Arimo，Apache 2.0 | 400 / 600 / 700；中文回退思源黑体 |
| 站酷小薇体 | `zcool-xiaowei` | ZCOOL XiaoWei，SIL OFL 1.1 | 单字重 400，所有文本层级使用同一字重 |

官方来源：

- [Noto CJK](https://github.com/notofonts/noto-cjk)
- [IBM Plex](https://github.com/IBM/plex)
- [霞鹜文楷](https://github.com/lxgw/LxgwWenKai)
- [Google Fonts 仓库](https://github.com/google/fonts)

字体资源必须由构建产物随应用分发，运行时不得请求 Google Fonts、GitHub CDN 或其他第三方字体服务。各依赖自带的许可证文件随依赖保留；若复制字体资源到仓库，则必须同时保留对应许可证文本。

字体下拉变化继续沿用现有正式配置入口，立即应用、持久化并广播，不增加确认步骤。

### 3.6 字号滑杆

“文字大小”改用水平 `Slider`：

- `min=10`
- `max=24`
- `step=1`
- 当前值显示在标题行右侧，格式为 `{value}px`

拖动时直接调用正式字体配置入口，页面立即重排并沿用现有同步行为。界面不额外显示范围、步长或“立即应用”的帮助文案。

### 3.7 快速保存命名弹窗

点击历史版本菜单中的“快速保存”后，先关闭菜单并打开独立 `Dialog`：

- 标题：“快速保存版本”
- 说明：“为当前版本添加一个便于识别的名称，也可以留空。”
- 字段：“版本名称（可选）”
- 占位：“例如：项目优化版、字节投递版”
- 最大长度：60 个字符
- 操作：“取消”“保存版本”

提交规则：

1. 去除版本名首尾空白。
2. 空字符串写入 `version_name: null`。
3. 非空字符串按清理后的值写入 `version_name`。
4. 点击保存或在输入框中按 Enter 均可提交。
5. 保存中禁用关闭和重复提交，按钮显示进行中状态。
6. 成功后关闭并清空弹窗；失败则保留输入并显示现有错误 Toast。

继续保留当前内容哈希去重：若内容与最新版本完全一致，则提示“内容没有变化，已是最新版本”，不创建新记录，即使用户填写了名称也不绕过去重规则。

## 4. 状态与架构设计

### 4.1 正式值与预览值

`useResumeConfigStore` 增加：

```ts
interface ResumeConfigState {
  spacing: ResumeAppearanceConfig['spacing']
  spacingPreview: ResumeAppearanceConfig['spacing'] | null

  beginSpacingPreview: () => void
  updateSpacingPreview: (
    data: Partial<ResumeAppearanceConfig['spacing']>
  ) => void
  commitSpacingPreview: () => void
  discardSpacingPreview: () => void
}
```

职责边界：

- `spacing`：已经确认的事实值；供持久化、协作广播、历史快照、分享和导出配置读取。
- `spacingPreview`：当前编辑器的临时渲染值；不属于简历事实数据。

`beginSpacingPreview` 复制当前正式值；重复调用不得覆盖正在编辑的预览。

`updateSpacingPreview` 只更新 Store 内的预览，不调用 `persistResumeAppearance`。

`commitSpacingPreview` 在一个状态更新中把预览写入正式值并清空预览，然后仅调用一次现有持久化入口，载荷包含完整的最终 `spacing`。

`discardSpacingPreview` 只清空预览。由于正式值从未改变，页面自然恢复，不需要反向写云端。

### 4.2 渲染数据流

编辑器的样式解析采用：

```text
显式 appearance 快照 > 当前编辑器 spacingPreview > 正式 spacing
```

规则如下：

- 当前编辑器传入 `appearance={null}`，因此精细模式预览可参与画布渲染和实时分页。
- 历史版本、分享页、Tracker 只读预览等传入显式 appearance 的消费者必须完全忽略全局预览。
- `useResumeStyles()` 只在没有显式 appearance 时对间距使用 `spacingPreview ?? spacing`；字体和主题仍读取正式值。

### 4.3 副作用隔离

只有正式 `spacing` 变化才能触发：

- `registerResumeConfigPersistence` 注册的 Automerge/云端写入。
- `useConfigBroadcast` 的 `config-spacing` 协作事件。
- 历史版本快照和内容哈希。
- 分享快照。
- Word 导出的配置读取。

精细输入阶段不得触发上述副作用。确认时三项间距无论修改了几次，都只产生一次正式提交和一次协作广播。

PDF 打印消费当前画布 DOM。精细间距弹层存在未确认变化时，用户点击其他 Toolbar 操作会先触发弹层退出保护；在“继续编辑/放弃修改”解决前不得执行导出或快速保存操作，从交互层阻止临时 DOM 被输出。

### 4.4 远端配置与生命周期

- 远端协作间距更新继续写入正式 `spacing`。
- 若本地没有精细事务，画布立即跟随远端正式值。
- 若本地正在精细编辑，当前草稿与预览保持不被覆盖；确认时以本地完整预览作为一次明确提交。
- 切换简历、离开编辑器或 Store hydrate/reset 时必须清除 `spacingPreview`，防止临时配置跨简历泄漏。

本次不新增复杂的远端冲突合并 UI；精细确认属于对三个间距字段的一次完整用户提交，行为与当前滑块最后写入生效的语义一致。

## 5. 字体配置兼容

现有三个规范值保持不变，仅扩充枚举，因此已有简历无需迁移：

```ts
export const RESUME_FONT_FAMILIES = {
  sans: 'noto-sans-sc',
  ibmPlexSans: 'ibm-plex-sans-sc',
  serif: 'noto-serif-sc',
  wenkai: 'lxgw-wenkai',
  arimo: 'arimo',
  zcoolXiaowei: 'zcool-xiaowei',
} as const
```

旧版系统字体值的归一化映射继续保留：

- 系统默认、微软雅黑、黑体、Arial → 思源黑体
- 宋体、Times New Roman、Georgia → 思源宋体
- 楷体 → 霞鹜文楷

这里的旧值只用于读取历史数据，不作为新 UI 选项，也不冒用专有字体名称。

`getFontFamilyName`、`getFontFamilyCSS` 和 `getResumeFontWeights` 必须覆盖六种配置。字体等待、分页稳定检测和打印 iframe 校验继续使用项目注册的字体族名称与对应有效字重。

## 6. 组件边界

Toolbar 目前集中在单个文件中。本次为避免继续扩大职责，拆分为以下边界：

```text
toolbar/
├── index.tsx
├── spacing-settings.tsx
├── font-settings.tsx
├── history-version-dropdown.tsx
└── quick-save-version-dialog.tsx
```

- `index.tsx`：只负责编排 Toolbar 各入口。
- `spacing-settings.tsx`：模式、草稿、验证和退出保护。
- `font-settings.tsx`：字体下拉与字号滑杆。
- `history-version-dropdown.tsx`：历史页跳转与弹窗入口状态。
- `quick-save-version-dialog.tsx`：版本名表单和保存流程。

这些组件仍属于编辑器 Toolbar，不触发 `src/pages` 页面级 history-style 重构。

## 7. 可访问性与键盘操作

- `Switch` 具有可读标签“精细控制”，可使用键盘切换。
- 数值输入关联可见 `Label`，单位不是唯一标识。
- 非法输入通过 `aria-invalid` 暴露，并显示仅在错误时出现的具体错误信息。
- 字号滑杆提供可访问名称及当前 px 值。
- 快速保存弹窗打开后焦点进入版本名称输入框。
- Enter 提交快速保存；Escape 关闭无修改弹层，或触发精细间距放弃保护。
- 放弃确认对话框关闭后，焦点回到触发退出的控件或精细输入区域。

## 8. 错误处理

| 场景 | 行为 |
| --- | --- |
| 精细输入为空或非数字 | 保留最后有效预览；标记错误；禁用确认 |
| 精细输入越界或精度不符 | 保留最后有效预览；显示合法范围或精度错误 |
| 精细确认持久化链路异步失败 | 沿用现有同步服务错误提示和重试机制；本地正式值行为与现有 Toolbar 一致 |
| 新字体未注册或加载失败 | 分页状态进入 error，沿用字体加载失败提示，禁止 PDF 导出 |
| 快速保存内容未变化 | 提示已是最新版本，不创建版本，保留现有去重语义 |
| 快速保存请求失败 | 保持弹窗与版本名，显示错误 Toast，可再次提交 |

## 9. 验证策略

仓库当前没有自动化测试约定，本次不新建测试框架。实现后执行：

1. 针对改动文件运行 ESLint。
2. 运行 `pnpm exec tsc --noEmit --pretty false`。
3. 运行 `pnpm build`。
4. 在本地编辑器手动检查桌面和移动端交互。

手动验证矩阵：

- 粗粒度三个滑块仍按原步长即时渲染和同步。
- 精细三个输入可按规定精度实时重排，但输入阶段不触发正式持久化或协作广播。
- 精细确认只提交一次；取消或放弃恢复正式值。
- 点击外部、Escape、切换模式和点击取消均覆盖未保存提示。
- 非法精细输入不破坏画布，确认不可用。
- 六款字体均实际生效，刷新后保持，预览与 PDF 使用同一项目字体。
- Arimo 的中文稳定回退到项目自托管思源黑体。
- 站酷小薇体按单字重策略稳定渲染，不依赖系统合成。
- 字号滑杆覆盖 10、14、24 三个代表值且步长为 1。
- 旧三种字体值和旧系统字体值均能正确归一化。
- 快速保存空名称和非空名称均正确写入；重复内容仍不创建版本。
- 精细事务期间尝试导出或快速保存，必须先解决未保存退出提示。
- 切换简历或离开编辑器后，不残留上一份简历的预览间距。

## 10. 验收标准

1. 间距标题栏右上角可切换粗粒度和精细模式。
2. 粗粒度 UI 与当前三个滑块及同步行为保持一致。
3. 精细模式支持 `0.1px / 0.01 / 0.1px` 精度并实时预览。
4. 精细输入期间云端、Automerge、协作广播和历史/分享快照不发生变化。
5. 点击确认后只提交一次最终间距；放弃后画布恢复已确认值。
6. 所有精细未保存退出路径均有放弃提示。
7. 字体下拉准确显示六款开源字体，所有字体由应用自身提供且无运行时外链。
8. 字号为 10–24px、步长 1 的滑杆并即时应用。
9. 间距和字号区域不显示用户要求删除的两段说明文案。
10. 快速保存必须先展示可选版本名弹窗，保存和去重逻辑正确。
11. 已有简历字体配置、历史快照、分享、协作和导出链路保持兼容。
12. 静态检查、类型检查和生产构建通过。
