# 求职跟进账号隔离修复

用户已确认单独修复此前报告的账号切换数据残留与保存队列边界问题。范围只包含求职跟进及其职位 API、AI 操作入口；保留此前的 UI 和性能改动。

## 根因与方案

当前 tracker store 不关联身份，退出后仍保留 jobs/isInitialized；防抖计时器、串行写入任务和共享读取 Promise 同样跨账号存活。只清空列表无法阻止旧请求回填，只比较用户 ID 无法覆盖 A → B → A。

采用账号 ID + 会话代次的作用域。身份变化同步清理 store、取消防抖、使所有旧任务失效；同账号的 token 刷新不改变作用域。复用已有简历缓存的身份隔离机制，统一为 tracker 账号作用域。

每次读取、创建、修改、删除都捕获作用域。排队执行前、异步获取用户后且发出数据库请求前、响应回填前均校验作用域。已发出的旧请求可以完成服务器处理，但不得更新新账号的页面或继续发出排队请求。

页面在作用域变化后重新加载职位，清空选中项、筛选关键词、编辑表单及确认框。旧组件的清理回调不得刷新新账号队列；旧操作的成功/失败回调不得关闭新弹窗或显示过期通知。创建职位和 AI 延迟确认同样受作用域约束。

## 保持的行为

- 3 秒防抖、本地草稿立即更新、失焦与关闭刷新、失败保留草稿及显式重试。
- 同账号的请求合并、字段版本保护和精准订阅。
- 现有桌面/移动端布局、动效、阶段流程。
- API 的 user_id 过滤及服务端 RLS；不修改数据库、Edge Functions、登录流程。

## 验收

隔离环境验证未登录不读写、A → B 与 A → B → A、等待身份时切换、旧读取成功/失败、旧写入与排队任务、创建返回、AI 确认过期、令牌刷新保留草稿。回归既有自动保存、缓存与选择器验证，运行相关 ESLint、TypeScript 和构建。最终对照本轮快照审查差异，不提交或推送。
