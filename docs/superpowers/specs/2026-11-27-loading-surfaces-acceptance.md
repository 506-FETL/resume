# 加载反馈与添加职业档案验收

## 浮层和首屏

审查覆盖路由等待、共享分包组件、页面内的 Skeleton 和手写占位。手机导航、分享、资料上传、职位和版本操作只在真实面板就绪时挂载浮层。小菜单、日期选择器和工具分区在等待较久时显示局部状态。已经到达的助手文字和更新日志代码直接可读。列表首读、统计图表与文件预览按对应内容保留占位。

本地用同一版本的 Chromium 打开修改前后的生产包，通过 DOM 观察器记录浮层挂载。使用隔离浏览器会话与固定接口响应，未向云端写入验收数据。

| 实际入口               | 验收结果                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 手机主导航             | 旧版先挂载居中弹窗，再挂载侧栏。新版连续两次打开均只挂载导航抽屉，Escape 关闭后焦点返回菜单按钮。                                               |
| 分享管理 → 新建分享    | 桌面和手机均只挂载右侧抽屉。展开简历选择器才请求候选，慢响应后可选简历、输入链接名称并启用创建按钮。Escape 先关闭日历，关闭抽屉后回到发起按钮。 |
| 职业档案 → 上传资料    | 桌面只挂载表单，手机只挂载底部抽屉。实测切换页签、文字保存、十份文件的队列、保留草稿、两轮开关和退出中重开。                                    |
| 三个入口的首次触屏点击 | 延迟各自的真实分包，等待时仍在原页面。放行分包后只出现一个抽屉。动态开启减少动效后仍能关闭和回焦。                                              |
| 求职跟进 → 新增职位    | 首次分包较慢时可点取消或按 Escape，之后即使模块到达也不会再开。分包首次返回 HTTP 503 时可在当前位置重试，随后正常打开真实抽屉。                 |
| AI 助手 → 已有对话     | 阻塞 Markdown 分包时已经收到的文字立即可读；放行后同一条消息完成排版。                                                                          |

另在 390 px 宽视口检查工作台首页、简历库、历史版本、简历优化、模板库、求职跟进、个人信息、更新日志和登录九个真实路由，均出现预期页面标题，未记录未捕获的页面异常。

## 新建分享首次打开

用 Chromium 在修改前后的本地生产包打开分享管理。首轮等待面板挂载时开始记录 CSS 横向位移和遮罩透明度，再关闭并重复一次。

| 真实入口与条件                  | 修改前首次打开                         | 修改后首次打开                                                 |
| ------------------------------- | -------------------------------------- | -------------------------------------------------------------- |
| 桌面 1280 px，页头按钮已预加载  | 第一次绘制时横向位移为 0，遮罩完全显示 | 横向位移从 730 px 连续降至 0，遮罩透明度从 0 升至 1            |
| 手机 390 px，触屏点击后延迟分包 | 第一次绘制时横向位移为 0，遮罩完全显示 | 等待时没有中转弹窗，真实抽屉从 384 px 连续滑至 0，遮罩同步淡入 |

桌面空状态的“新建分享”也会滑入。两轮开合均保留中间帧，退出中重开继续使用同一个抽屉。Escape 关闭后焦点回到发起按钮。手机开启减少动效时，面板和遮罩直接就位。桌面在滑入途中开启减少动效，当前过渡随即结束。

## 职业档案布局

以下数值来自真实页面元素的边界，单位为 CSS 像素。对照旧版时统一从“上传文件”的空队列进入。新版再切换到“粘贴文字”并切回。

| 视口                           | 面板高度，修改前 → 修改后 | 页签到上传区间距，修改前 → 修改后 |
| ------------------------------ | ------------------------- | --------------------------------- |
| 桌面 1280 × 900                | 540 → 341                 | 77 → 12                           |
| 手机 390 × 844                 | 506 → 360                 | 80 → 12                           |
| 手机 320 × 520，深色、减少动效 | 修改后 360                | 修改后 12                         |

上一版从上传页切换到文字页时，桌面面板从 245 增至 375，手机从 264 增至 394。打开浮层时还观察到组件给仍持有焦点的“上传资料”按钮祖先设置 `aria-hidden`。修正后两个页签共用同一网格，拖放区和文字区域共用尺寸，未选页签设为 `inert`。从不同入口打开时，焦点先移入相应页签，再隔离背景。实测键盘和指针打开后往返切换，逐帧读取面板上边缘、高度、页签和保存按钮的位置，三个视口的四项变化量均为 0 px。对背景设置 aria-hidden 的调用也逐次检查过，未再隐藏持有焦点的祖先。

三个尺寸分别检查了文件限制、选择按钮、文字输入、保存状态和长队列。加入十份文件后正文可以独立滚动，保存按钮留在视口内，表单没有横向溢出。

首屏仍按需加载这几个面板。在同一组受控页面中，点击前实际请求到的脚本按文件 gzip 汇总，档案页从 359,011 增至 360,957 字节，分享页从 341,686 增至 344,874 字节。这组数值只反映脚本体积。
