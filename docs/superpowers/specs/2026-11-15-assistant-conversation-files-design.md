# 当前对话附件与职业档案分离

2026-11-15。用户追加授权：助手“上传文件”只上传到当前对话，不自动存入职业档案。原上下文用量修复继续完成。本规格覆盖旧上传入口自动归档的约定，不改变已存在资料的归属。

## 已查明的原因

`useComposerUploads` 直接使用职业档案保存 API，保存后刷新全局档案库。来源没有对话归属，库列表和默认模型目录都会包含上传内容；切换对话后的提示还明确让用户去职业档案找文件。只修改按钮文字或在列表隐藏一项无法修正保存、去重、后续检索和删除行为。

## 方案

复用现有私有文件、版本、文本提取与预览能力，在 `experience_sources` 增加可空 `conversation_id`。空值为职业档案，非空为指定对话的附件。不复制文件解析器或新建一套相同的存储表。

- “上传文件”保存时必须传当前对话 ID。新对话先使用稳定 ID 建立空会话，再保存附件；多文件共用同一创建请求，失败重试仍用原 ID。创建时冻结账户，创建完成后只在原视图接入，保留输入草稿和已有引用。
- 去重范围包含对话 ID。相同文件在档案、对话 A、对话 B 分别保存，不能因字节相同意外共享或改变归属。同一次操作重试保持幂等；请求哈希包含非空对话 ID，旧档案操作哈希保持兼容。
- 职业档案列表、数量、选择器和默认全库目录仅查询 `conversation_id is null`。当前对话的来源目录合并该对话附件；新会话和其他会话不自动取得它。显式附件仍优先冻结本轮范围；运行和工具重试再次核对元信息中的对话归属。
- 原文、下载、历史引用继续使用原来源/版本 ID。将对话附件关联到别的会话或简历须由服务端拒绝。已有职业档案仍可以通过“从职业档案选择”引用，不复制或移动原档案。
- 删除对话先通过已有文件删除流程清理它的附件原件与元数据，再删除会话；失败保留可重试状态。外键阻止直接删除有附件的会话造成文件失联。删除对话不删除被引用的职业档案。
- 上传后切换视图不得把附件加入新对话；原对话的草稿保留文件引用，重新进入可发送。账户变化取消旧上传，冻结 owner 与现有 generation 约束继续生效。
- 加号菜单将“上传文件”放在“当前对话”分组；“从职业档案选择”仍在档案分组。文案说清去向，不增加未实现的“存入档案”动作。

实现前已检查项目现有 InputGroup、Command、Attachment、原文预览和文件保存流程；全部复用，不新增自制控件。浮层动效沿用现有组件。
