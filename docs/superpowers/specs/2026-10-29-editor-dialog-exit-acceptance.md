# 填写建议与导出弹窗退出修复

日期：2026-10-29。用户已授权修复关闭时高度先坍缩再消失的问题。本次为局部缺陷修复，沿用现有弹窗设计与动效，不另设设计阶段。

## 触发场景与根因

打开编辑器的“填写建议”或“导出”，等待正文出现后关闭。原实现中，Dialog 外框仍执行 140ms 退出动画，业务内容已经变成较短的加载提示：

- 填写建议把 `open` 直接传给 `usePreparationRecord`。关闭会改变请求状态键，退出中的内容立即收到 `loading=true`、`record=null`。
- 导出摘要只在 `open=true` 时计算快照。关闭时快照立即变成 `null`，已展示的摘要被“正在准备简历内容…”替换。
- 隔离浏览器基线逐帧采样：填写建议从 520px 降至 106px，导出从 520px 降至 223px，随后才卸载。

必需的减少动效验收还复现了同一退出流程中的残留：退出途中开启减少动效，原本的 `animate-none!` 移除动画名称，Radix Presence 无法匹配旧动画的取消事件，闭合状态的弹窗可能留在页面。

## 修复范围

仅修改编辑器的 `preparation/index.tsx` 与 `export/index.tsx`：

- 使用 Dialog 实际挂载与卸载时的焦点生命周期，令数据启用条件为 `open || contentMounted`。内容保留至退出完成，随后释放。
- 关闭期间禁用依赖这些数据的操作按钮；原有添加后编辑、检查跳转和触发按钮回焦流程继续执行。
- 减少动效使用 0 秒时长，保留原动画名称，让 Radix 正常完成退出。遮罩与正文一并处理。
- 复用 `DURATION.base/fast` 与 `EASE.out/in`，不增加固定高度、清理定时器或额外动画。共享 Dialog、准备记录 hook、PDF/Word 导出链路均未改动。

## 浏览器验证

使用临时 `tests/dialog-exit/` 页面渲染真实 Preparation、ExportDialog、检查规则与数据 hook，包裹正式 MotionProvider。仅使用合成简历，localStorage/sessionStorage 为内存实现，IndexedDB 使用独立名称，远端与写入请求阻断。

每个弹窗均覆盖：关闭按钮、Escape 两轮完整开关，退出 40ms 后重开，打开前减少动效，以及退出途中开启减少动效。逐帧记录布局高度、正文与遮罩透明度、是否出现加载提示、最终挂载状态及焦点位置。

本轮退出帧的分析窗口为关闭后的 0～400ms。原始记录中已经排队的最后一个 rAF 可能在下一轮打开后才执行，因此超过窗口的末帧不能当作本轮残留；收尾同时核对该轮 `remaining`、`focusReturned` 与窗口内正文、遮罩的实际卸载状态。

- 桌面 1440×900 常规关闭与 Escape：高度始终保持 520px，无中途加载提示，正文和遮罩正常移除，焦点回到入口。
- 手机 390×844：填写建议保持 544px，导出保持 564px；同样无坍缩、残留或回焦失败。
- 反向重开：保留原内容和原高度，最终保持打开；不把正常打开状态误判为残留。
- 减少动效：直接完成退出；过程中切换也能正常卸载和回焦。
- 新浏览器页没有应用错误和无障碍告警；仅有 Motion 提示当前启用了减少动效的预期日志。

逐帧证据位于 `.impeccable/review/dialog-exit/`。该证据证明本次退出过程，不等同于真实手机硬件帧率或 PDF 内容、分页验收。此次未触发真实导出，导出管线未改动。临时验证脚本完成后删除。

## 动效审查

| Before                   | After                    | Why                                               |
| ------------------------ | ------------------------ | ------------------------------------------------- |
| 退出开始即替换为短加载态 | 实际退出完成后再停用数据 | 外框退场期间维持原布局，不用高度动画掩盖内容卸载  |
| 减少动效移除动画名称     | 原名称保持不变，时长归零 | Presence 能收尾正在进行的退出，正文与遮罩均不残留 |

结论：Approve。本次无新增布局属性动画，200ms 进入、140ms 退出与现有公共预设一致；反向切换和运行中减少动效均有浏览器证据。通用技能对缓动和减少动效的建议，以仓库已确认规则为准。
