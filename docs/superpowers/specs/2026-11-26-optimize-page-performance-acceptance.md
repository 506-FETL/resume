# 简历优化页面性能验收

## 范围与测量口径

从工作台进入「简历优化」，覆盖普通直达、侧栏切入、岗位深链、无报告、选择简历、检测、修复清单、单条与批量修复、ATS 纯文本、职位描述比对和行业基准。先保存改动前的生产包，同机使用 Chrome 158 比较。正文时间取真实评分和报告摘要可见，工具时间取实际正文可读或文本框可输入。静态页面由本机服务提供。

受控对照使用 45 份云端简历、23 份报告，另以 23 份含长正文的本地简历验证混合选择器。每次使用新的浏览器上下文和空缓存。接口固定延迟 220 ms，静态资源延迟 65 ms，带宽 1.5 MiB/s，CPU 降速两倍。独立的公网核验使用关联 Supabase 项目中的临时账号、3 份合成简历和 2 份报告，无限速。两组结果分别记录。

## 请求与操作

- 普通直达在确认账号后并行准备报告和界面。之前先取最新一份报告，再查选中简历名称；现在一次查询返回报告及名称。有权限的岗位只查绑定简历的目标报告，即使尚未检测也能显示名称。岗位不存在或无权访问时，网络中只有岗位核验；匿名入口的 ATS 和简历业务读取均为 0。
- 选择器之前会遍历所有云端候选、报告摘要和本地索引。现在云端和本地都在展开后读取，首批各显示 10 条，多读取一条判断是否还有下一页。45 个云端候选分 10/10/10/10/5 展示，23 个本地候选分 10/10/3 展示。首开云端候选和分数的紧凑 JSON 估算从 10,188 B 降至 2,128 B。检测状态读取失败仍可选择简历，并可独立重试。重复开关和切回已读取的报告均无新增业务 GET。
- 1,000 份各带 64 KiB 字段的本地简历中，首次升级由 IndexedDB 创建候选元信息索引，一轮实测用时 56 ms。升级完成后首批读取 1.5 ms。首批没有读取完整行或遍历全部主键；缺少更新时间的旧简历只在读到该项时回退读取这条记录。打开纯文本时才读选中的正文，模板目录暂不可用也能预览。
- 首屏保留评分文字和问题清单。评分字体随实际分数加载，雷达绘图代码随图表靠近视口加载。在 1365×900、1365×540 和 390×844 分别核对真实 SVG。无报告时评分字体和绘图代码的请求均为零。更改清单不会重新扫描所有问题或绘制无关的评分依据。
- 四个工具按点击准备各自的代码，共用当前简历版本的正文与在途请求。岗位首开只取归属与简历定位；正文和 JD 原文从点击比对时并行读取，输入框独立于简历查询。纯文本、统计、风险提示按正文版本复用。在 0/1/5/75 条合成经历中，新旧纯文本、统计、提醒一致；替换正文后预览随之更新。75 条长经历的计算对照中，工具标题所需的经历计数从 0.258 ms 降至 0.009 ms；重开同一版本跳过原来 4.432 ms 的预览数据计算。此处只测纯函数，不含浏览器渲染 Markdown。
- 同样输入 41 个字符，JD 草稿的本地存储写入从 41 次降为 1 次。一段受控的比对流从 17 次写入降为 2 次，刷新能恢复草稿与最终结果。老版本带归属的云端或岗位草稿按目标兼容读取；旧本地草稿缺少账号标识时保留原存储。正文、JD 或分析过程分包失败均可局部重试；过程分包失败时比对结果仍可见，重试没有再次调用模型。
- 从本地简历开始检测时，真实云端 INSERT 返回选中名称、时间和 12 个表单栏，直接使用已保存内容。记录到三笔业务请求：上传、模型 POST、报告 INSERT。没有回读简历正文、标签或空报告。用合成 SSE 验证正常结束可保存 78 分报告，缺结束标志时未产生报告。模型输出可控，实际数据库读写走登录账号和 RLS。
- 勾选、撤回分别写一笔 PATCH，经刷新读回对应值。单条和批量修复按目标读取与写入，报告状态在简历保存成功后更新。让单条修复的正文 PATCH 失败，报告仍为待修复；重试后真实读回更新姓名。批量修复只写选中的岗位意向栏目，两项状态更新，报告仍为 78 分。写成功后复用返回的名称和时间，无额外标签 GET。另一标签页已更改的字段不会被旧建议覆盖。在途旧报告、旧候选与账号 A→B→A 的迟到结果均已检查。

## 浏览器交互

桌面及窄屏分别验证弹窗两轮完整开关、退出中反向打开、键盘续页与焦点返回。工具分包首次 503 后点击局部重试可显示正文。修复详情加载失败期间确认按钮禁用。岗位 JD 的独立重试只读取该岗位原文，保留已输入内容。额外对照过一次只给 Supabase 域名添加预连接的方案，四对冷启动未观察到握手被复用，交付版本沿用现有连接策略。

## 交付构建实测

以下取同一端口、新旧包三组交替的中位数。桌面为 1365×900，窄屏为 390×844；JS 字节为本次导航期间浏览器收到的 gzip 压缩正文。

| 指标                          | 桌面优化前 | 桌面优化后 | 窄屏优化前 | 窄屏优化后 |
| ----------------------------- | ---------: | ---------: | ---------: | ---------: |
| 报告请求开始                  |   4,407 ms |   1,935 ms |   4,349 ms |   1,965 ms |
| 报告正文可见                  |   4,886 ms |   2,400 ms |   4,777 ms |   2,432 ms |
| LCP                           |   4,696 ms |   2,220 ms |   4,596 ms |   2,228 ms |
| 首屏 JS 请求数                |        224 |        160 |        224 |        155 |
| 首屏 JS 字节                  |  960,330 B |  494,844 B |  960,330 B |  396,891 B |
| 直接打开职位比对至可输入      |     552 ms |     393 ms |     565 ms |     389 ms |
| 首次打开 ATS 纯文本至正文可见 |     520 ms |     827 ms |     503 ms |     787 ms |
| 重开 ATS 纯文本               |     106 ms |     105 ms |      57 ms |      48 ms |

- 按需分包把部分开销移到了第一次使用工具。看完纯文本再首次打开职位比对，桌面从 105 ms 变为 358 ms，窄屏从 60 ms 变为 433 ms。直接打开职位比对时无需等简历正文，24 个新增 JS 分包共 47,102 B，不含 Markdown。将正文挂起 2.4 秒，两个视口均可先填完 17 字；取回正文后保留输入并启用比对。另实测首读失败后重新取回正文可继续使用，未产生额外模型请求。
- 同条件下，桌面重开选择器从 121 ms 变为 103 ms，切回原报告从 252 ms 变为 237 ms。桌面从个人信息页切入后 826 ms 看见报告，匿名入口和无报告空状态分别在 1,736 ms 和 2,401 ms 出现。此三项为交付包抽查值。
- 真公网与受控数据分开比较。固定端口下交付包与旧包的三对报告正文耗时分别为 2,045→1,991、1,965→1,703、1,770→1,713 ms，中位数 1,965→1,713 ms。请求开始中位数 803→178 ms，新版本的授权预检更早承担冷 TLS 握手。早先轮次的公网结果存在反向波动，不推算固定线上提速。真实云端验证包括关联查询、勾选与撤回、修复写入及刷新读回。模型流使用可控响应，未测真实模型生成时长或消耗模型额度。
