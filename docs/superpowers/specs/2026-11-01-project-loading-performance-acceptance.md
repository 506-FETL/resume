日期：2026-11-01。对应[规格](2026-11-01-project-loading-performance-design.md)与[计划](../plans/2026-11-01-project-loading-performance.md)。本轮基线已包含前一轮公开分享入口隔离、取消 Tiptap 手工分包及函数同区域调用修复，不能把前期收益重复计入本轮。

## 同机测量

生产资源比较使用真实构建文件及浏览器 ResourceTiming。静态依赖闭包不包含尚未执行的动态模块；解压体积、gzip 估算和实际网络时间分别报告。

| 指标                                           |    本轮基线 |                  本轮最终 |
| ---------------------------------------------- | ----------: | ------------------------: |
| 分享 API 可以发起前的静态 JS 闭包              | 1,347,365 B | 1,047,932 B（减少 22.2%） |
| 上述分包逐个 gzip 后合计                       |   432,100 B |   326,999 B（减少 24.3%） |
| 分享完整初始页面资源，含异步评论与实际字体     | 2,936,796 B |               2,851,988 B |
| 构建时间，含验收报告插件                       |     18.29 s |                   12.54 s |
| 已有云端文档 store 加载，每个 HTTP 固定 150 ms |    339.7 ms |                  189.4 ms |

固定同一份分享响应、HTTP 延迟 200 ms，生产浏览器再施加 100 ms 网络延迟、500 KB/s 下载和 4 倍 CPU 降速，各测两轮：API 发起平均约 1.876 s → 1.624 s；正文出现约 2.402 s → 2.112 s；PDF 就绪约 5.093 s → 4.914 s。该对照用来隔离前端改动，不代表真实公网 SLA。未限速本机的数十毫秒差异不足以作为稳定提速结论。

压缩器对照：移除 TLA 插件后，自动分包 + Terser 为 12.33 s，分享静态 JS gzip 394,169 B；esbuild 为 7.55 s、406,629 B（两者均为进一步延迟评论之前）。本轮优先页面传输体积，保留 Terser，不为节省约 5 秒构建时间增加运行时传输。原手工组即使移除 TLA，分享 JS 仍约 1.34 MB，首页闭包比自动分包多约 258 KB，因此没有保留手工组。

最终清理还发现 Tailwind 默认扫描 tests 中的验收材料，使对照期间的入口 CSS 为 561,380 B，清理后为 547,855 B。已在源样式中加入 `@source not '../tests'`；重新加入包含独有工具类的测试夹具后构建，全部 8 份 CSS 与无夹具构建逐字节一致，且没有生成夹具样式。上述完整页面体积和限速数据保留测量时原值，不把临时样式清理的差额混入 JS 收益；最后一次正式构建耗时 11.17 秒。[Tailwind 扫描排除说明](https://tailwindcss.com/docs/detecting-classes-in-source-files#ignoring-specific-paths)

## 网络与云端边界

- 真实浏览器三个新上下文中，JSON POST 每次都有 OPTIONS；简单 POST 均无 OPTIONS，且返回正常。样本存在 7.1 秒的网络异常值，不能宣称省预检必然减少某个固定秒数。
- 本轮开始时 dev 阅读区约 4.79 秒、PDF 约 4.88 秒；最终一次为 3.44 秒、3.63 秒。生产真实云接口的不同轮次可在约 2.6–7.2 秒间波动，不能把 dev 与 production 或不同时段结果混算收益。
- 同样的 8 次真实接口序列，热请求 Edge 处理中位数 317 → 275 ms，端到端中位数 1,026 → 913 ms。部署后首请求 4,395 ms，其中 Edge 945 ms；另一次生产浏览器请求 Edge 达 1,624 ms。说明跨区域连接和云端冷启动仍会主导偶发慢请求，并非所有延迟都已消失。
- 查询统计显示相关 SQL 平均执行约 0.2–5.8 ms，主要可消除项是串行 HTTP 往返和冗余读取，未据此添加无依据索引或修改数据库区域。
- 正常 current 冷模板路径现为 5 个数据请求、4 层等待：分享元信息 → 当前配置 → 模板与 scope 并行 → 最终授权；模板缓存命中后 4 个请求。history 为 4 个请求、3 层等待。

## 验证范围

- 编辑器真实 store、正式持久化实现，HTTP 边界使用隔离合成数据：20 个在线场景与离线场景通过。包括已有/新建、缺绑定/条目 ID、失败/损坏、null、不存在零写入、外观优先级、目标切换、账户 A→B→A、旧保存失败、guest 零 owner 请求、保存后重开及旧初始化入口。
- 真实 Supabase SDK 的已有会话、首次登录、过期会话刷新后立即加载，共 12 轮通过。没有为了测试修改真实用户资料或简历。
- 正式 Edge handler、Supabase SDK、签名与投影代码，隔离 HTTP 矩阵 17 项通过。覆盖 current/history、scope 创建、P0409 同步重试、最终关闭/归档/过期/换版/换 release/换 source 拒绝、隐私变化、密码代次与错误密码、凭据过期、计数阻塞和失败、模板缺失。
- 历史恢复真实实现验证：先备份，再读/保存 Automerge 和配置；备份失败只有备份请求，不覆盖正文。Lodash 10 种方法、30 项行为对照通过。
- 工具栏首次进入前不加载模块；两轮完整进入/退出、退出 40 ms 时反向打开、减少动效均通过，模块仅请求一次。
- 生产构建通过真实 UI 创建离线简历，姓名手动保存刷新回读、富文本保存后路由往返均通过；390 px 工具栏无横向溢出。实际编辑器导出入口通过布局校验，PDF 为一页，提取文本包含最新输入。助手工具模块的 8 个工具及 7 个提示模板保持；未调用真实模型。
- 生产浏览器检查 18 个入口，无 pageerror；匿名首页、登录、简历列表、模板、历史、分享管理、助手等入口均不下载 Automerge WASM；编辑入口下载并运行原生 WASM。需要登录的页面仅验证登录门禁，不冒称执行了全部账户业务。composer-tools 路径已进入 404，不再是无默认导出的错误页面。
- 真实分享页面桌面与 390 px 手机视口：两轮评论开关、减少动效下再次开关、75% 与适宽切换通过，未提交评论。
- 真实分享 PDF 按钮触发正式字体等待、尺寸签名与区域校验后捕获打印副本，再用 Chromium 输出 PDF。背景关闭/开启均为一页，提取文本一致（745 字符）；未放宽任何布局校验。未修改字体、分页或打印几何，因此没有把此项扩展为全模板分页重验。
- Vercel 缓存规则在本地验证 HTML、SPA、JS、WASM、字体和未哈希 public 文件的互斥匹配。前端尚未发布，不能把本地匹配记为线上 CDN 响应头已生效。

## 已审查且保留的配置

保留页面异步路由、CSS 分包、modulepreload、MDX 的 raw 排除、WASM 初始化、Tiptap core/pm 版本约束和现有字体规则。PDF 解析/worker、Shiki、Streamdown 已有按需加载，产物目录含这些文件不等于首屏下载。图标包具备 tree-shaking；Noto 字体通过 unicode-range 按实际字符加载。没有凭包清单做全库升级、全局删除副作用或替换编辑器。

Vite 默认浏览器目标对应 Chrome/Edge 107、Firefox 104、Safari 16；本轮不再用原 es2024 覆盖。实际运行验收为当前 Chrome，不等同于这些历史浏览器版本已逐一实测。[Vite 7 构建文档](https://v7.vite.dev/config/build-options)

自动分包的选择依据实际依赖图及浏览器测量；手工分包可能改变依赖归属及副作用顺序。[Rollup manualChunks](https://rollupjs.org/configuration-options/#output-manualchunks)

一年缓存只用于不可变内容哈希静态资源；敏感实时数据继续 no-store。[Vercel 缓存说明](https://vercel.com/docs/caching/cache-control-headers)
