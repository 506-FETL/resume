## 实际改动

聊天上传复用了职业档案保存流程，却没有记录对话归属，导致文件被自动归档、其他对话也能默认检索。现在来源记录以可空 conversation_id 区分职业档案和对话附件，保存、去重、目录、关联与删除都使用同一归属。已有资料不迁移、不改写。

新对话上传先以稳定 ID 创建会话，多文件共用请求，保留文字、已有引用和队列状态；迟到结果只回原对话草稿。未知创建重试核对原 ID，账户变化取消旧工作。职业档案选择仍引用原档案；上传文件位于“当前对话”分组。删除提示明确消息与上传附件会一起删除，引用的职业档案保留。

## 真实云端与页面

使用本地正式 Vite 页面、隔离 Playwright 浏览器和两个临时云端账户。没有操作用户已有资料。

1. 从加号菜单的“上传文件”选择两份 TXT。仅创建一个会话；准备/保存期间发送按钮禁用，原输入文字完整保留；完成后两个引用指向同一 conversation_id。实际职业档案接口仍为 items=[]、total=0。
2. 从实际发送按钮请求概括两份附件。模型连续调用两次原文读取，回答包含文件中的项目、接口异常清单、联调记录、测试用例和发布检查项，并保留“成果数字尚未核实”，没有补造量化数据。首次附件会话也生成了真实标题。
3. 回复后输入 `sa`，统计仍为“上次调用，10%”；刷新后草稿、历史附件和统计恢复。附件原文从真实引用入口打开，没有“在职业档案中管理”；点击“下载原件”得到的名称和字节与本地文件一致。
4. 将相同名称、相同字节的文件另外保存到职业档案和对话 B。档案、A、B 的 source ID 均不同，原件 hash 相同；同 operationId 重试返回同一档案 ID。目录实际读取为：库只有档案，A 为库+A 两个附件，B 为库+B 附件。职业档案实际页面只显示一份独立保存的档案，不显示 A 的第二份附件。
5. 将 A 附件关联到 B 被拒绝。账户 B 的档案为空；读取 A 附件返回 source_not_found，向 A 对话上传返回 target_not_found，调用删除 A 对话没有副作用，A 两个附件仍存在。
6. 从真实菜单删除 A，对话、来源、版本及对应 Storage 原件均为零；档案和 B 附件仍存在，下载字节不变。重复删除已不存在的 A 成功。再把档案实际关联到 B 后删除 B，档案记录和原件仍完整保留。
7. 上传菜单在 1440/390/320px 各完成两轮 Enter 打开/Escape 关闭，无页面横向溢出；快速关闭后重开正常。运行中切换减少动效，动画/过渡时长均为 0s，运行中动画为零。删除确认完成两轮取消后再真实删除；通读了提示文案。实际页面 pageerror 为空。[390px 上传菜单截图](../assets/assistant-conversation-files/upload-menu-390.png)。

浏览器脚本曾因选择到被覆盖的文件标签、未等待过渡，以及导入 Vite HMR 下不同身份的 store 失败；改用真实可访问按钮、DOM 完成条件、页面实际模块 URL 和数据库回读后重新验证。失败调用未计入通过。线上未注入 Storage 故障；该失败分支由隔离 handler/数据库检查覆盖。
