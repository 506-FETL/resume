# 创建入口与求职推进返修验收

日期：2026-11-11。本轮已获用户授权；当前分支，未提交、推送或发布前端。对应[规格](2026-11-11-creation-tracker-followup-design.md)与[计划](../plans/2026-11-11-creation-tracker-followup.md)。

## 根因与改动边界

阶段回退来自 Drawer 在发起异步推进时立即清除 viewingStage，早于投递弹窗提交。保存慢包含两个独立因素：必要的投递写入与岗位确认，以及随后重复的全表重读。投递缓存还通过全局 revision 失效，取消也会递增，导致无关数据再次读取。

创建目录原来仍直接调用创建 API，没有走名称和描述步骤。返回目录只恢复焦点、禁止滚动，因此已选项仍可能离屏。恢复草稿时所选条目还未返回，就被当作预览缺失展示 FileText。手机 176px 背景裁切加表单叠入，只能看到页头；首轮改成约 200px 完整纸张后被用户明确纠正。最终保留全宽向下渐隐背景，将高度增至约 320–384px，清晰区域延长至顶部 40%，表单从末端近透明区域衔接。

不修改 Edge、数据库事务、认证或 RLS。既有保存队列、归属确认、正式投递冻结真实已保存原件及幂等编号继续保留。

## 保存链路真实公网对照

环境：本机 Node 24、Supabase JS 2.103.0，经真实公网 HTTPS，完整读取响应体并解析 JSON 后计时。数据库地区通过项目元信息核对为 us-east-1；14 个 Edge 响应及对应平台日志均为 job-submissions v4 / us-east-1 / ES256。未用固定延迟、网络拦截或浏览器渲染时间冒充公网数据。

只使用本轮创建的合成账户、并行公司、23 条岗位、1 份平台简历、两条投递（无原件和平台原件各一条）。首次真实写入单列；随后固定同一操作 UUID 和载荷幂等重放，旧/新顺序各 3 次，AB/BA/AB 交替。旧顺序为 Edge 保存 → 目标职位读取 → 全表读取；新顺序为 Edge 保存 → 目标职位读取。此处目标查询仍采用旧完整字段，用于独立评估删除全表读取的收益；后续字段裁剪另行验证，不混算。

| 材料     | 旧链路三次（ms）   | 新链路三次（ms）   | 旧 / 新中位数（ms） |
| -------- | ------------------ | ------------------ | ------------------- |
| 无原件   | 1508 / 1406 / 1239 | 1048 / 1044 / 1024 | 1406 / 1044         |
| 平台原件 | 1734 / 1231 / 1359 | 1708 / 1032 / 836  | 1359 / 1032         |

首次真实写入分别为 1353ms 和 796ms，各一个样本，不能当成平均值。新平台链路第一次目标读取抖动到 868ms，样本有限，不能保证固定提速比例。未强制冷启动，前置设置已预热 HTTPS；重放不等同于首次事务写入。

载荷为解压后的完整 JSON：23 条全表 96,208B，单目标 4,843B，Edge 无原件 550B / 平台 593B（压缩 Content-Length 460B / 499B）。全表读取中位 378.5ms。REST 平台 upstream_service_time 为 4–27ms，但客户端公网读取为 355–868ms，说明只看 SQL 时间会漏掉等待。重放 Edge execution_time_ms 为 353–855ms，上游 service 为 94–596ms；现有指标不能进一步拆成 JWT 与 SQL，不据此重写认证或移动地区。3 次显式未缓存 OPTIONS 单独测量，未计入上述链路，不将其称为重复业务请求。

清理已验证：撤销合成账户会话并删除账号；job_submission_revisions、job_submissions、company、tracker_companies、resume_config、resume_config_versions 均为零；无 Storage 对象写入。凭据只在测量进程内存解析，不保留在开发服务器可访问目录。

## 求职实现与隔离验证

成功保存现在只调用一次 Edge 和一次目标进度读取。新的 getCompanyProgressById 只读取 status、stage_details、interview_sub_stages、activities、updated_at 和 job_submissions(is_primary)，不返回 JD、联系人或整份岗位资料。真实投递摘要直接接入当前岗位缓存，失效只作用于被更正的当前资源；其他岗位、其他在途请求及固定历史原件继续可用，取消不失效缓存。

可信写入成功后，如果进度确认失败，显示已保存并提供仅重读操作，不将其重新归类为提交结果未知。未知首次投递按原编号查询；更正只依据本次可信响应确认，不因旧记录已有原件而冒认成功。原保存队列、未发送草稿、请求中的后续输入以及账户代次保持。

主代理已独立运行真实源码验证，20/20 通过：真实 Tracker store、保存队列、API 与 Supabase SDK，以及从当前组件源码提取的真实事件处理器；只隔离认证会话和 fetch 响应边界，外部请求为零。覆盖打开/取消、两请求成功、409 拒绝、写入成功后读取失败、未知查询与原编号重试、材料与信息更正、选择旧主记录、普通推进成功/失败、写前草稿失败、精确失效和旧在途响应、无关在途读取、后续输入保护及 A→B→A。

另一轮 SDK 协议检查 7 组通过：精确字段与 owner/id 过滤、单次 GET、primary/legacy/空记录、缺行 null、失败抛错、响应后账户 guard，以及未登录零请求。这些是数据与处理器检查，不替代 React 实际焦点和页面动画。

本节记录此前交接到公共创建向导的实现与验证；用户随后明确否定这种界面复用。现已改为模板预览原窗口内填写，独立草稿和新增浏览器回归见[原地创建验收](2026-11-11-template-inline-creation-acceptance.md)。此前数据与手机渐隐证据仍保留，但不能作为新入口的验收结果。

目录创建使用现有信息表单和创建流水线，保留精确模板/示例和存储模式；已有待确认创建优先恢复，避免覆盖。手机保留加高的全宽渐隐背景，桌面维持左侧渐隐布局。短暂预览等待只显示公共 Spinner，错误或确实缺失才显示说明与重试。

源码处理器复现还发现目录准备和 getExample 等待后仅比较账户 ID，关闭再打开或 A→B→A 时旧任务仍可能继续。现复用创建 flow 的 sessionRef，目录入口也按打开周期记录会话；旧响应、catch 和 finally 不再改写新草稿、错误或 busy，新会话正常复位，已提交待确认操作仍保留。交叉审查 fresh 5 组验证成功与失败路径及新请求锁，无新增网络调用。

## 手机渐隐修正与实际页面复核

用户明确要求保留原本向下渐隐的背景，只增加展示量；独立 200px 纸张方案不符合要求，已撤换。背景为 clamp(20rem, 44svh, 24rem)，390 × 844px 实际宽 358px、高 371.36px；320px 窄屏实际宽 288px、高 320px。选中图片为 object-cover / top，渐隐从 40% 开始，68% 时 alpha 为 0.6，末端完全透明。深蓝侧栏与珊瑚斜幕均能看到页头、教育及工作内容后再渐隐；桌面 1440 × 900px 继续向右渐隐，表单位于右侧。

实际浏览器在 390 × 844、320 × 640、320 × 400px 检查了布局、滚动与输入；320 × 640px 正文滚动约 116.5px 后，创建按钮仍保持 y=545.70px，外部页面 scrollTop=0。400px 短屏聚焦描述会滚到真实表单，关闭和创建均可达。手机深浅色、恢复末屏模板、返回已选项可见及回焦、前后切换输入保留均通过。两轮完整打开与关闭后焦点回到入口；动态开启减少动效后，纸张 transform=none，表单位移归零且 opacity=1。

实际逐帧采样发现仅静态检查未识别的返回跳动：一处是返回投影开始后才滚动目录；另一处是详情 portal 与列表节点采用不同滚动坐标，缩放时放大偏移。现在在详情态提前定位隐藏目录，并让两端节点始终按同一视口坐标投影。修复前末屏返回纸张 y 曾跳到 -1026px，提前定位后仍跳到 769.77px；统一投影后稳定从 114.50px 过渡到 408.89px，目录 scrollTop 始终为 1239，最终已选卡片可见且聚焦。另一轮快速返回/下一步在退出后约 258ms 反向，早于 280ms 布局动画结束；最终纸张 transform=none、表单 opacity=1，输入保留。

| Before                       | After                          | Why                      |
| ---------------------------- | ------------------------------ | ------------------------ |
| 手机独立纸张与原背景形式割裂 | 全宽加高背景，向下逐渐淡出     | 按用户明确纠正增加展示量 |
| 返回后再滚动、跨容器坐标不同 | 详情期间提前定位，统一视口投影 | 避免返回动画跳出视口     |

review-animations 结论：本次改动 Approve，已有动效预设与减少动效保留，实际反向和两轮操作通过。该结论限本次创建工作区，不代替其他弹窗或真实手机硬件帧率测试。

创建夹具必须用 5173：5193 是分页专用服务，将 Supabase 地址设为 invalid，误用时图片必定加载失败。本次已切换到 5173 后以真实公开图片完成视觉复核，未修改生产图片读取。两处入口各清理了 2 个带验收前缀的临时数据库，未写入真实简历；已恢复浏览器尺寸并关闭本轮临时标签页。
