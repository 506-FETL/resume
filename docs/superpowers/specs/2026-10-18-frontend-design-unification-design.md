## 1. 目标与边界

用户要求使用 Taste 对整个项目的前端设计、布局和样式进行锐评并优化，随后明确排除简历模板相关页面，因为该模块将单独重构。

本次覆盖：首页、我的简历、简历正文编辑器、AI 助手、分享管理、公开分享阅读页、求职跟进、历史版本、个人信息、登录/注册/找回密码/重置密码、更新日志与 404，以及直接支撑这些页面的共享界面。

排除 `src/pages/template/**`、模板中心、模板编辑器、模板 manifest、模板渲染逻辑及模板预览外观。保留简历文档排版、字体配置、A4 分页和 PDF 输出；正文编辑器的操作外框与工具布局属于本次范围。

保留现有路由、主导航名称、品牌标识、业务规则、接口和权限。沿用 React、Tailwind、shadcn/Radix、Zustand 和 Motion，不引入另一套组件库。保留共享 AppSidebar、分享网格和求职看板，不另写导航壳。无需数据库迁移、Edge Functions 变更或部署。

已有未提交的技能目录和 `skills-lock.json` 属于本轮之前的工作，不能混入改版差异。默认当前分支工作，不推送远端。

### 2.2 现状判断

产品已经具备中性主题、浅深模式、统一动效预设和共享侧栏。问题集中在跨页设计规则没有收口，以及部分页面按组件堆叠而非用户任务组织。

设计判断：组件库感偏重，产品主次不足。不是每个页面都难看，但同一产品的标题、间距、工具栏、卡片密度和主操作规则差异明显。

## 4. 方案比较与推荐

### A. 保留黑白基调，统一为高效工作台（推荐）

保留现有品牌、组件基础和页面职责，统一排版、表面、操作层级、响应式和状态反馈。调整首页与复杂工作区的组织方式。目标参数：结构变化 4/10，动效 3/10，普通管理页密度 5/10，编辑工作区 6/10。

优势：能解决已观察到的问题，延续此前确认的分享网格、求职看板和共享导航。取舍：不是明显换肤，主要收益来自更清晰、紧凑和顺手。

### B. 中性色加统一品牌强调色

在 A 的布局改进上，用单一克制强调色统一主操作和选中态。优点是品牌辨识更强；取舍是需要用户选定品牌方向，主题和对比度回归范围更大。状态颜色仍独立表达语义，不全部换成品牌色。

### C. 仅修可用性问题

修助手挤压、编辑入口、失败状态与短屏表单，保留各页面当前外观。改动最小，但无法达到用户提出的全站设计、布局和样式优化目标。

以下详细设计以 A 为推荐方案。

## 5. 统一设计规则

### 5.1 应用界面与文档边界

- 应用 UI 使用可选的页面容器/视觉 variant；不无差别更改共享 Card、Button、字体和根主题默认值。
- `/template` 路由及其编辑模式保留原外观，不启用本轮新增视觉 variant。全站调整后单独确认该路由未被共享样式带改。
- 简历文档、模板缩略图、历史/公开分享的 A4 内容不继承应用 UI 的字体和排版改动。编辑器外框与文档样式清晰隔离。
- 字体沿用现有 Inter，并为应用 UI 显式补齐中文系统无衬线回退；不在本轮强制引入大体积全量中文字体下载。简历字体仍由现有配置控制。

### 5.2 排版、空间与表面

- 常规页面标题 24px/32px、字重 600；手机 22–24px。分区标题 16px/24px、字重 600；正文 14px/22px；次要元信息 12px/18px。标题与交互信息不使用 10px 字号。
- 常规管理页内容最大 1280px；求职工作区最大 1600px；助手和正文编辑器使用可用全宽；账户设置与阅读说明采用更窄的内容列。不同宽度服务任务，不统一强制窄栏。
- 页面左右间距手机 16px、平板 24px、桌面 32px，只由一层负责；常规分区 24px，相关控件 8–12px，列表/卡片间距 12–16px。
- 保留现有中性色。用背景层级和分隔线表达分组，减少“外框套内框再套卡片”。阴影用于浮层，普通内容卡以轻边框为主。
- 保留 10px 基础圆角体系；输入/按钮约 8px，内容表面约 12–14px，弹窗约 16px；胶囊仅用于状态标签等明确场景。
- 每页一个明确的主要动作；次要操作使用 outline/ghost，危险和低频操作进入可发现的更多菜单，保留确认与回滚。

### 5.3 动效、状态与可访问性

- 沿用 `src/lib/motion.ts` 的 EASE、DURATION、SPRING；进入淡入并轻移约 8px，退出更短，筛选/列表重排不重挂整个页面。
- 所有新/修改动画使用 `useReducedMotion()` 降级；包括 canvas-confetti 等不受 CSS 动画规则覆盖的效果。
- 空态、无搜索结果、未登录、请求失败、未检测、检测通过分别表达，不能用同一“无数据”或“已完成”代替。
- 骨架匹配最终布局；首页继续独立并发加载，各模块完成即展示，失败只影响自身并可局部重试。
- 图标按钮有中文可访问名称；整卡动作有真实 button/link 入口；移动端触控目标尽量 44px，紧凑桌面控件不低于可操作尺寸。
- Tab 内容切换保留挂载和滚动位置，并提供轻淡入；隐藏区域不保留焦点。共享 Dialog 若无需修改则沿用现有实现。

## 7. 架构与实施边界

- 页面容器、页面标题/动作和状态区仅提取已经有多个调用点的公共模式，使用组合式组件，不创建复杂万能配置框架。
- 沿用各页现有 store；跨组件共享布局状态放页面 store，单组件临时开关使用本地状态。助手画布的有效宽度由容器尺寸推导，不写入业务数据。
- 页面重构遵循 AGENTS.md 的 history-style 模块结构；只为实际职责增加文件，不为了目录齐全创建无用空文件。
- 首页错误状态在前端资源模型中补充，保持接口和统计口径不变；错误时保留可用的旧数据并标明刷新失败。
- 组件展示调整不得顺带修改简历数据、AI 提示词、评论协议、协作逻辑或后端服务。

## 8. 验收标准

1. 按实际页面检查 390、768、1024、1440px，关键公共布局补查 320px；助手同时覆盖主侧栏展开/折叠及保存的画布最大宽度。1024px 不再出现竖排输入提示或不可读聊天窄栏。
2. 手机首页首屏可以看到明确工作入口；零待办不再占大块独立卡片；指标/图表请求失败不会显示为确定的零数据。
3. 简历正文编辑入口可用鼠标、Tab 和 Enter 到达；名称/描述修改有准确文案；主动作不依赖点击普通容器。
4. 账户长内容、认证短屏、错误提示、手机键盘场景可滚动，字段与提交按钮不被裁切。
5. 浅色/深色均检查正文、辅助文字、状态、按钮和 focus ring；激活态可读，不用透明度掩盖低对比度。
6. 空数据、加载、错误、筛选无结果及正常状态具有各自正确展示与下一步；不为验证污染真实账号数据。
7. 抽查创建简历、创建分享、简历优化弹窗，两轮完整开关并覆盖退出中重新打开；检查遮罩与内容、焦点恢复、DialogDescription。
8. 减少动效模式下动画正确降级；快速切换 tab、版本与筛选不丢焦点、不出现隐藏元素可交互。
9. 确认模板中心/编辑器与简历文档排版未被共享样式带改；抽查 A4 预览和 PDF 输出尺寸稳定。
10. 运行 TypeScript、改动文件 ESLint、生产构建与适用的现有专项验证；记录已有基线失败，不把它们当成本轮已修复。
11. 审查最终 diff，仅包含本轮范围，保留先前未提交内容；不提交或推送，除非用户另行要求。

## 9. 实施次序

本节为设计优先级，不替代实现计划。确认规格后调用 writing-plans，在 `docs/superpowers/plans/2026-10-18-frontend-design-unification.md` 编写具体步骤。

1. 应用布局规则与明确可用性问题：助手宽度、简历入口、认证短屏、中文导航。
2. 首屏效率：首页与简历列表；独立加载/错误状态。
3. 管理与工作区：分享、求职、历史、正文编辑器、简历优化。
4. 账户、公开阅读、日志/404及跨页面视觉与动效回归。

设计确认后上述阶段属于同一完整任务，不能只完成第一阶段就声称全站优化完成。
