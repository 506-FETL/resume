# ATS 优化页响应式布局与样式重构设计

## 背景

`/optimize` 已具备完整的 ATS 分析、评分依据、问题修复和高级工具能力，但当前页面以多个等权大卡片纵向堆叠：评分依据占用过高、问题分析与修复清单高度失衡、高级工具入口过于厚重，桌面端产生大面积空白，移动端的信息顺序和弹层滚动也不够稳定。

本次只重构展示层与响应式容器，不改变 ATS 评分、简历选择、分析任务、问题修复和高级工具的数据语义及业务流程。设计继续使用项目现有 shadcn 组件、主题变量和全局明暗主题，不创建新的 ATS 专属视觉体系。

## 已确认的设计原则

1. 保持原有简约风格：白色/主题卡面、细边框、轻阴影、现有圆角、现有主色和语义色。
2. 五维评分继续使用雷达图，不替换为仪表盘、彩色数据面板或其他图表。
3. 主要优化布局、间距、尺寸、信息顺序和空状态，不添加渐变、玻璃拟态、强装饰背景或新的颜色规范。
4. 桌面端高级工具使用 shadcn `Dialog`；移动端使用默认 shadcn `Drawer`。
5. 移动端 `DrawerContent` 只定制高度，不覆盖默认背景、边框、圆角、阴影或动画；继续关闭遮罩模糊。
6. 所有长内容弹层采用“头部固定 + 内容独立滚动 + 底部操作固定”的结构，解决 Drawer 无法正常滚动的问题。

## 目标

- 桌面端首屏直接呈现综合结论与五维雷达图，降低理解成本。
- 消除固定高度导致的空白，使问题区、修复清单和工具区随真实内容自然增长。
- 在移动端建立清晰的纵向阅读顺序，避免桌面双栏直接压缩到小屏。
- 统一高级工具 Dialog/Drawer 的尺寸、头部、滚动区和操作区。
- 保留现有交互、数据源、主题切换和语义色，不引入平行业务状态。

## 非目标

- 不调整 ATS 评分模型、提示词、评分权重或报告字段。
- 不改变简历选择、重新分析、问题修复和高级工具的业务行为。
- 不重做全局 Card、Dialog、Drawer、Badge、Button 等基础组件视觉。
- 不增加新的图表库、动画库或页面级状态管理方案。
- 不在本次重构中重新设计编辑器、简历预览页或评论系统。

## 页面信息架构

### 1. 页面头部

头部继续包含页面标题、说明、简历选择器和分析操作，但减少不必要的左缩进与垂直空隙。

- 桌面端：标题说明在左，简历选择和分析操作在右或紧随标题区排列，保持一到两行内完成。
- 移动端：标题说明独占一行，选择器与主操作在下一行铺满可用宽度。
- Pro Tips 保持单行低优先级提示，不遮挡正文，也不依赖脆弱的魔法间距。
- 加载、分析中和已有报告状态继续由现有 store 驱动。

### 2. 顶部评分总览

原有四张等权指标卡和整行大型“本次评分依据”改为两张主卡。

#### 综合结论卡

展示：

- 综合评分与等级；
- 评分进度条；
- `assessment.basisSummary` 形成的一句话结论；
- 推断岗位方向；
- 可读性指数；
- 优化完成度；
- 已参与评估的内容数量或少量标签。

候选人画像作为结论的补充说明保留，但不再单独占用一张大卡。

#### 五维雷达图卡

- 继续复用现有 `ScoresRadarChart` 和 `chart-*` 主题颜色。
- 桌面端与综合结论卡并列，建议比例约为 `1.35fr / 0.65fr`。
- 移动端紧随综合结论卡单独展示，保持足够图表尺寸。
- 图表旁或图表下保留五个维度的文字分数，确保不依赖颜色即可理解。

### 3. 主工作区

桌面端采用“主内容 + 窄侧栏”，移动端恢复单列文档流。

#### 桌面端

- 主列：简历问题分析 → 各维度判断理由。
- 侧栏：优化修复清单，使用自然高度；内容较多时可在视口内粘滞，但不设置固定内容高度。
- 建议宽度为 `minmax(0, 1fr) / 20rem~22rem`，避免当前 8/4 栅格下侧栏过宽。

#### 移动端

顺序固定为：

1. 综合结论；
2. 五维雷达图；
3. 简历问题分析；
4. 优化修复清单；
5. 各维度判断理由；
6. 高级工具箱。

移动端不保留 sticky 侧栏，也不创建横向溢出区域。

### 4. 简历问题分析

- 保留现有严重程度分组、Badge、问题展开与修复入口。
- 缩小 CardHeader、CardContent 和分组之间的垂直间距。
- 待处理数量继续使用现有 destructive/green 语义样式，不新增状态色。
- 空状态和加载状态改为紧凑自然高度，不再用大段固定 `py` 撑出空白。

### 5. 优化修复清单

- 移除 `ScrollArea` 上的固定 `h-100` 以及加载/空状态的固定高度。
- 清单随项目数自然增长；桌面端只由侧栏的最大可用视口约束滚动，移动端由页面自然滚动。
- 保留点击切换完成状态、必修/可选标识和现有 store 行为。
- 无任务时显示紧凑空状态，不再占据一整列高度。

### 6. 各维度判断理由

原有五张大型理由卡改为单个 shadcn `Accordion` 卡片：

- 每行展示维度名称、当前分数/满分和展开图标；
- 展开后显示完整 `rationale`；
- 默认全部收起，避免页面被长文本撑高；
- 评分上下文、实际参与评估的内容和关键证据信号放在同一卡片的紧凑补充区中；
- 不丢失 `candidateProfile`、`evaluatedSections`、`evidenceSignals` 等已有信息。

### 7. 高级工具箱入口

保留四个工具和现有数据复用逻辑，入口从 `min-h-[180px]` 的展示卡改为紧凑工具项。

- 桌面端：四列或两列网格，单项包含图标、名称、简短说明和进入提示。
- 移动端：单列紧凑列表，整行可点击。
- 继续显示当前简历连接状态，但弱化营销式标题和过长说明。
- 未选择简历时继续禁用并提示，不改变加载上下文和刷新逻辑。

## Dialog 与 Drawer 设计

### 桌面端 Dialog

高级工具共用 `AdvancedToolsModal`：

- 使用现有 shadcn `Dialog` 的默认背景、边框、圆角、阴影、遮罩和进入/退出动画；
- 只增加业务需要的宽高、`min-h-0`、`overflow-hidden` 和响应式最大尺寸；
- 建议宽度为 `min(70rem, calc(100vw - 3rem))`，最大高度为 `min(88dvh, 56rem)`；
- Header 展示工具名称、说明和当前简历摘要；
- Body 是唯一的纵向滚动区域；
- Footer 固定在底部，保留取消和刷新/确认操作。

问题修复详情沿用同一滚动原则，保留其现有业务标题、严重程度和确认动作。

### 移动端 Drawer

- 使用项目现有 Base UI/shadcn `Drawer`，保留默认滑动手柄、圆角、边框、阴影和进出动画。
- `DrawerContent` 仅传入高度，例如 `h-[92dvh]`；不再传入自定义背景、边框、透明度、模糊、padding 或 overflow 外观类。
- 通过 `overlayClassName` 延续“遮罩不模糊”，但保留半透明遮罩和点击/滑动关闭行为。
- 使用真实可见的 `DrawerHeader`、`DrawerTitle`、`DrawerDescription`，避免仅用 `sr-only` 标题后再手写一套伪头部。
- Drawer 内部使用 `flex min-h-0 flex-1 flex-col`：Header 与 Footer 为 `shrink-0`，Body 为 `min-h-0 flex-1 overflow-y-auto overscroll-contain`。
- Footer 保持在 Drawer 底部并考虑安全区；虚拟键盘出现时，输入区域仍可滚动到可见位置。
- 工具内部禁止再使用依赖视口的固定大高度；网格在移动端切换为单列。

## 高级工具内部布局

四个工具保留现有字段和结果，只统一外围节奏：

- JD 岗位匹配：桌面端输入/结果双栏，移动端输入→结论→建议单列。
- 格式检查：摘要、问题列表和操作区在移动端顺序排列，不产生嵌套横向滚动。
- ATS 预览：预览区在容器 Body 内滚动，不让整个 Drawer 失去滚动能力。
- 岗位基准：筛选/摘要在前，详细对比在后；桌面端允许双栏，移动端单列。

每个工具都复用同一个弹层 Shell，不分别维护宽高和滚动规则。

## 视觉与间距

- 页面最大宽度适度放宽至约 `80rem~90rem`，但正文卡片保持清晰行长。
- 页面纵向间距采用移动端 `1rem`、桌面端 `1.5rem` 左右的统一节奏，替换当前多处 `space-y-8`。
- Card 继续使用默认背景、边框和轻阴影；不增加全宽彩色底板。
- 图标底色、主按钮、雷达图继续使用当前 `primary`/`chart-*` 主题变量。
- 警告、严重、完成状态继续使用已有 severity 配置与 semantic tokens。
- 全局浅色、深色及用户已建立的颜色主题无需迁移或新增 token。

## 响应式边界

- 小于现有移动端断点：单列页面、Drawer、满宽操作控件。
- 中等屏幕：总览可以保持单列或两列，工具入口使用两列。
- 大屏：总览双卡并列、主工作区主列加窄侧栏、工具入口四列。
- 所有容器使用 `min-w-0` 防止长文本撑开栅格；长标题允许换行，Badge 区允许自然折行。

## 状态与数据流

- `useAtsStore` 继续作为页面唯一领域状态来源。
- 本次不新增页面 Context，不把现有状态复制到组件本地。
- `OptimizeDashboard` 仍根据 `currentAtsConfig` 计算综合评分、可读性和完成度，只改变组合方式。
- `AssessmentBasisCard` 的数据完整保留，可拆成总览摘要与折叠详情两个展示组件。
- 高级工具继续复用 `advancedTool*` 状态、请求 ID 竞态保护和 `resumeContext` 缓存。
- 弹层关闭时继续取消过期请求；不使用固定 timeout 清理内容。

## 可访问性与交互

- 雷达图必须有五维文字分数和可读标题，不能只靠图形表达。
- Accordion Trigger、工具入口、修复清单项和弹层按钮保持键盘可达及可见焦点。
- Drawer/Dialog 均使用对应语义 Title 与 Description，避免上下文组件错配。
- 图标按钮必须保留中文 `aria-label`。
- 支持 `prefers-reduced-motion` 的现有组件行为，不添加强制自定义动画。
- 移动端交互目标保持至少约 44px 高。

## 加载、空状态与错误状态

- 页面初始加载使用紧凑 Skeleton/Spinner，不改变已有请求时序。
- 无 ATS 报告时保留清晰的“选择简历并开始分析”引导。
- 无问题或无修复项时使用自然高度空状态，不制造占位大卡。
- 高级工具上下文加载失败继续使用现有 toast；弹层本身保持可关闭。
- 长结果、错误详情和输入内容只在 Body 内滚动，Header/Footer 始终可操作。

## 代码结构

优先在现有 `src/pages/optimize/components/` 内重构，不新建平行页面：

- `dashboard/`：总览组合、综合结论、雷达图、评分理由；
- `analysis/`：问题列表和问题修复弹层的密度与滚动；
- `repair-checklist/`：自然高度清单；
- `advanced-tools/`：紧凑入口、共享 Modal Shell、四个工具响应式内容；
- `header/` 与 `pro-tips/`：响应式头部和稳定占位。

若新增组件，沿用现有 kebab-case 文件与文件夹导出习惯；页面级状态仍留在 `src/pages/optimize/store.ts`。

## 验证标准

### 静态验证

- TypeScript 类型检查通过。
- 相关 ESLint 检查通过。
- 生产构建通过。
- `git diff --check` 通过。

### 桌面端视觉与交互

- 1440px 宽度下首屏同时看见综合结论和完整雷达图。
- 问题区与修复清单不存在固定高度造成的大面积空白。
- 五维理由可逐项展开，所有已有字段仍可访问。
- 四个高级工具都能打开 Dialog，Header/Footer 固定，Body 可滚动。

### 移动端视觉与交互

- 以 390×844 为基准检查页面顺序、换行和无横向溢出。
- 雷达图尺寸可读，不被裁切。
- 修复清单和理由区由页面自然滚动。
- 四个高级工具都能打开默认样式 Drawer。
- Drawer 只有高度定制，遮罩不模糊，Body 可连续滚动至末尾，Footer 始终可见。
- 输入框聚焦、软键盘弹出和滑动关闭不破坏滚动。

## 风险与控制

1. **Drawer 外层与内层同时滚动**：只允许 Body 滚动，所有祖先补齐 `min-h-0`。
2. **桌面卡片重排导致内容遗漏**：以现有 ATS v2 字段清单逐项核对，不删除候选人画像、评分理由、参与模块或证据信号。
3. **主题样式漂移**：只使用已有语义 token，不写新的固定品牌色；雷达图继续使用 `chart-*`。
4. **工具各自覆盖共享容器**：宽高和滚动集中在 `AdvancedToolsModal`，工具组件只负责内部响应式布局。
5. **固定/粘滞元素遮挡**：用真实 Header/Pro Tips 占位验证页面顶部，不依赖额外空白补偿。

## 已批准的视觉方向

- 总体方向：Editorial Workbench 的信息结构，但视觉继续沿用原有简约 shadcn 风格。
- 顶部：综合结论卡与五维雷达图卡并列；移动端依次排列。
- 中部：主问题区加窄修复侧栏；移动端单列。
- 评分理由：紧凑 Accordion，保留完整信息。
- 高级工具：紧凑入口，桌面 Dialog、移动 Drawer。
- 否决方案：新 ATS 专属配色、彩色语义面板、渐变/玻璃效果、纯数据仪表盘、移除雷达图。
