# 求职跟进阶段与抽屉交互设计

日期：2026-10-14

状态：用户已确认完整设计及 shadcn / ReUI 组件选型，进入实现与验证。

## 1. 已确认需求

- 阶段顺序为：已保存 → 已投递 → 测评中 → 筛选中 → 笔试中 → 面试中。
- 末端分成同级、互斥的「已录用」与「已结束」，使用平滑曲线连接。
- 用户已确认：「已结束」承接原「已终止」，涵盖未录用、主动放弃等结束情况。
- 当前阶段和面试轮次状态自动维护，不再要求手动选择待处理/进行中/已完成。
- 多轮面试中，较早轮次自动通过，最新轮次自动进行中。
- 用户已确认：名称、日期和备注自动保存，移除保存/取消按钮。
- 联系人放在上方；投递简历放在下方，整块可折叠，默认折叠。
- 保持当前中性色、轻边框、圆角与紧凑排版，优先复用开源组件。
- 用户补充：组件选型以 shadcn 风格为准；已核实项目配置为 `radix-vega`、`neutral` 和 CSS 变量主题。

## 2. 当前实现与问题依据

已对照用户提供的 7 张截图，以及以下源码：

- `components/drawer/progress-timeline.tsx`：当前是 5 个线性节点，已终止未作为末端节点呈现；终止后所有节点均显示红叉，无法保留已通过阶段的语义。
- `utils.ts` 的 `autoCompleteStages`：进入新阶段时仍设置为「待处理」。
- `components/drawer/use-stage-detail.ts`：阶段状态与职位状态分开维护；必须手动完成轮次才能完成面试阶段。
- `components/drawer/interview-sub-stages.tsx`：只有阶段状态为进行中才允许添加轮次；新轮次又是待处理；双栏编辑占用窄抽屉大量宽度。
- `components/drawer/stage-detail.tsx`：阶段状态、完成本阶段、保存与取消重复承担流程控制。
- `components/drawer/document.tsx`：简历预览占据较大纵向空间，且先于联系人显示。
- `supabase/migrations/20260220021810_company.sql`：`company_status_check` 仅允许原有 6 种状态，需要通过增量迁移接受测评与笔试。

本次修改应建立统一的流程规则，覆盖新增、编辑、拖拽、列表快捷操作、批量操作和抽屉；仅隐藏下拉框不能解决状态冲突。

## 3. 方案比较与推荐

| 方案 | 布局与组件 | 取舍 |
| --- | --- | --- |
| A，推荐 | 以 ReUI Stepper 的 Radix 版本为基础组合流程条与曲线终态分支；面试和简历复用现有 shadcn Accordion / Collapsible | 贴近截图目标，适配抽屉，沿用项目的 shadcn 主题 |
| B | 完整 React Flow 图画布 + 节点详情 | 可支持复杂流程编辑，但本次固定流程不需要缩放、拖动节点或自由连线 |
| C | 保留原左右轮次列表，仅移除状态表单 | 实现较少，但窄抽屉仍拥挤，当前轮次不够突出 |

推荐 A。ReUI 是 shadcn 生态的开源扩展，其 Stepper 提供圆点、标题、连接线及受控进度。采用其中的 Progress 布局作为基础，颜色、字号、边框和圆角接入本项目主题。分支曲线使用开源路径生成器；表单、折叠和确认交互复用仓库现有 shadcn 组件。

## 4. 流程模型

### 4.1 阶段与终态

```text
已保存 → 已投递 → 测评中 → 筛选中 → 笔试中 → 面试中
                                                   ╭── 已录用
                                                   ╰── 已结束
```

- 新内部状态使用 `assessment`（测评中）、`written`（笔试中）。
- 已结束继续使用现有 `rejected` 值，更新显示名称，不复制或丢弃旧记录。
- 拆分「线性阶段顺序」与「终态集合」，避免把已结束当作已录用之后的下一阶段。
- 允许从任何在办阶段结束流程，不能要求必须先经过面试；可按实际经历直接选择后续阶段。
- 已录用与已结束的切换、进入终态继续提供二次确认。
- 返回前序阶段属于纠正进度；保留日期、备注和面试记录，不自动删除历史内容。
- 看板、筛选、排序、新增表单、批量操作、列表动作、抽屉及首页使用同一状态配置。
- 保留已结束看板列的折叠能力；本次同级分支指抽屉中的流程图，不增加另一套看板。

### 4.2 自动状态规则

- 职位当前处于某个非终态阶段，该阶段即进行中；旧记录即使存着待处理，也按当前职位状态兼容呈现。
- 真实推进时自动维护前序/当前阶段，保留已有日期与备注；当前阶段可记录本次真实进入日期。
- 不因读取旧数据就批量回写，也不为旧记录虚构测评/笔试的历史日期或活动。缺少记录的新阶段显示未记录的弱态，不伪造完成经历。
- 退出至已结束时，保留之前已通过的阶段，将结束时所在阶段标为已结束；未来阶段维持未开始。不能把所有阶段改成已拒绝。
- 结束发生在较早阶段时，终态说明显示「结束于：筛选中」等实际位置，不能暗示已经完成后续面试。
- 历史漏斗需要识别结束前已到达的阶段；响应率说明和阈值同步适配新增测评阶段，已归档/终态继续排除待跟进。

### 4.3 面试轮次

- 面试中即显示轮次区域，无需先设置阶段状态。
- 没有轮次时，显示紧凑空态和「添加首轮面试」；不创建虚假面试记录。
- 添加首轮后自动进行中；添加下一轮时，之前轮次自动通过，最新轮次自动进行中。
- 轮次顺序以保存的 `order` 为准，不能因为更改面试日期而改变哪轮是当前轮次。
- 最新轮次默认展开；新增后自动展开新增轮次并聚焦名称。历史轮次折叠保留，展开后可回看及修正名称、日期、备注，状态不可编辑。
- 删除轮次需确认；删除当前轮后，在办面试中的上一轮重新成为进行中。删除所有轮次回到空态，不擅自改变职位阶段。
- 已录用时已有轮次均显示已通过；已结束时保留前轮通过、最后一轮已结束，不能把主动放弃显示成所有轮次未通过。
- 终态不允许新增面试轮次；历史记录可回看，若需继续面试，先通过明确的状态操作返回面试中。
- 编辑名称、日期、备注不自动推进到已录用。进入哪个终态必须由用户明确选择。

## 5. 抽屉布局

### 5.1 流程条

- 保留现有圆形节点、细连接线、主色进度和当前节点光环。
- 6 个在办节点沿同一主轴排列，右侧的已录用/已结束上下对齐，共享同一列与相同视觉权重。
- 分支从面试节点边缘向右平滑分开，进入两个终态节点时保持水平切线，曲线端点不穿过圆点或文字。
- 已录用使用克制的绿色，已结束使用中性或柔和结束色；不把整条历史流程染红。
- 当前分支高亮，另一条弱化；图标、标签及说明同时表达状态，不能只靠颜色。
- 用户在实际预览后确认：进度线连续高亮至当前阶段，旧记录未记载的新阶段使用浅色节点和「未记录」说明，不伪造已通过状态。
- 沿用现有流程节点与顶部动作的推进方式，所有入口使用同一状态变更方法及终态确认。
- 桌面保持侧边抽屉，给予内容合理最小宽度，上限仍为现有 56rem；不会修改共享 Drawer。
- 窄屏流程条使用局部横向滚动，并将当前节点滚入视野；保持字号与点击区域，不把 8 个节点挤成小字。

### 5.2 阶段详情

- 删除手动阶段状态、本轮状态、完成本阶段、说明性旧提示及保存/取消栏。
- 普通阶段显示简洁阶段标题、自动状态提示和日期/备注；推进动作放在现有流程入口，编辑内容与推进阶段解耦。
- 面试阶段不再堆叠一层「面试中状态」表单。顶部仅显示「面试轮次」、数量与「添加下一轮」。
- 当前轮次卡片包含名称、自动状态徽标、面试日期、备注；自动保存反馈在卡片头部小字显示。
- 历史轮次通过折叠列表呈现摘要，不使用原来的固定 12rem 左栏与右侧大空框。
- 备注继续复用现有编辑器，不改编辑器内部实现。

### 5.3 联系人与简历

- Tab 名称调整为「联系人与简历」，内容顺序与名称一致。
- 联系人在上方，保留已有联系人编辑、保存与删除行为；本次自动保存范围是阶段详情和面试轮次。
- 下方为「投递简历」折叠卡片，整块默认收起。收起时显示图标、标题、已绑定/未绑定摘要和展开箭头。
- 展开后显示简历选择器及现有预览，不重复多个标题与边框。
- 简历列表与预览按展开需求加载，联系人展示不依赖简历请求；无简历、加载失败分别有局部反馈。
- 同一职位内切换 Tab 保留用户本次展开选择；切换职位或重新打开抽屉恢复默认折叠。
- 更换绑定简历保留成功同步与失败回滚，不改变联系人草稿。

## 6. 自动保存与状态一致性

- 名称/备注输入短暂防抖保存，失焦时尽快提交；日期选择、添加/删除轮次立即提交。
- 轻量反馈为保存中、已保存、保存失败与重试；不要每次输入都弹成功 toast。
- 失败保留本地输入与未保存标识，支持重试，不能静默丢弃或提前显示已保存。
- 保存队列按职位隔离、按顺序写入；合并同一职位的连续内容编辑，避免较早响应覆盖较新输入。
- 阶段推进与轮次保存共用流程写入边界；推进前刷新待保存内容，防止一次更新覆盖另一项修改。
- 切换 Tab、切换职位、关闭抽屉时不能丢弃防抖队列；待保存数据与请求生命周期由页面状态/动作管理，不能只依赖即将卸载组件的计时器。
- 请求响应使用职位 ID 与作用域代次保护，覆盖 A→B→A 情况；仅合并本次修改的字段，避免完整旧响应覆盖联系人、简历绑定或下一步跟进。
- 全部状态入口（包括新增、拖拽、快捷动作、编辑和批量）复用规范化/转换方法；禁止各自复制一份自动阶段/轮次规则。
- 真实数据更新继续使用现有权限边界与接口；乐观更新失败后恢复正确基线，并保留用户尚未保存的内容。

## 7. 开源复用与代码边界

- 流程条首选：ReUI Stepper 的 Radix 版本，采用 Progress 示例的圆点与下方标题布局。所需源码收敛到 tracker 的流程组件中，保留开源许可，使用项目主题变量，不整套替换共享 UI。
- ReUI 的现成 Stepper 是线性步骤条，不原生表达两个互斥终态。仅将 6 个在办阶段交给线性流程，两个终态独立组合在末端，通过受控领域状态联动。不能将已录用/已结束映射为先后两个数字步骤；旧记录未经历的新阶段也不能因序号靠前被自动画成已通过。
- 同风格备选：Dice UI Stepper（Radix 版本），提供可组合步骤、受控值及键盘导航；同样需要适配终态分支。本次首选 ReUI，因为它的 Progress 示例更贴近用户截图中的圆点与标题排布。
- 面试轮次：现有 shadcn Accordion 配合 Badge 和卡片布局，当前轮展开、历史轮折叠。
- 简历折叠：现有 shadcn Collapsible 配合摘要卡片，默认收起。已核实仓库这两类组件底层为 Radix，使用 `data-state="open|closed"`；不能复制 Base UI 版本的状态选择器。
- 日期与表单：现有 shadcn Calendar、Popover、Input、Button、AlertDialog。
- 曲线：D3 `linkHorizontal`，生成有水平切线的平滑连接；仓库 lockfile 已包含 d3-shape 3.2.0，可显式声明直接依赖及相应类型，避免依赖传递安装的偶然可用性。
- 动效：现有 Motion 与 `EASE` / `DURATION` / `SPRING`，每处接入 `useReducedMotion()`；折叠使用仓库现有 class，减少动效时禁用动画。
- 新增或实质重构的独立组件使用 kebab-case 文件夹和 `index.tsx`；页面共享领域状态/动作放入页面 store 或必要 slice，临时展开状态保留局部。
- 允许修改范围：`src/pages/tracker/`、必要的 `src/lib/supabase/resume/company.ts` 数据映射、首页直接消费状态的配置、数据库迁移及对应验证、必要的 package/lockfile、本次 spec/plan。集成发现现有 `src/lib/ai/tools/tracker.ts` 直接写入同一职位，因此仅将这个既有求职跟进入口接入共同状态配置与写入边界，保留原确认流程，不改 AI 框架。
- 不重做上一轮页面整体布局、不改共享 Drawer/Dialog 动画、不修改 Tiptap 内部，不处理无关的既有全选问题。

组件调研来源：

- [ReUI Stepper（Radix）](https://reui.io/docs/components/radix/stepper)：Progress 布局、圆形指示器、标题、受控步骤与可组合部件。
- [ReUI 开源仓库](https://github.com/keenthemes/reui)：确认 shadcn 主题兼容、Radix/Base UI 双版本与 MIT 许可；本次只采用免费组件，不依赖付费区块。
- [Dice UI Stepper（Radix）](https://diceui.com/docs/components/radix/stepper)：同风格备选步骤条及键盘操作。
- [shadcn Accordion（Radix）](https://ui.shadcn.com/docs/components/radix/accordion)：面试轮次折叠的样式与组合依据。
- [shadcn Collapsible（Radix）](https://ui.shadcn.com/docs/components/radix/collapsible)：简历折叠的样式与组合依据。
- [Radix Collapsible](https://www.radix-ui.com/primitives/docs/components/collapsible)：仅用于核对底层交互与状态属性，最终外观沿用仓库 shadcn 组件。
- [D3 Links](https://d3js.org/d3-shape/link)：`linkHorizontal` 与曲线端点方向。
- [React Flow getBezierPath](https://reactflow.dev/api-reference/utils/get-bezier-path)：备选的开源曲线能力；本次采用无需完整画布的 D3 方案。

## 8. 数据库与兼容发布

- 使用新的增量迁移扩展 `company_status_check`，新增 assessment/written；保持现有表、字段、RLS、历史数据和 rejected 值。
- 优先只扩展约束，不批量改写用户 stage_details、interview_sub_stages 或 updated_at；旧记录通过读取规范化兼容，在真实编辑时写入新规则。
- 实施时先核对当前已链接项目的真实约束和迁移账本，再执行迁移；不要只依据旧迁移文件推断云端状态。
- 完成隔离数据库/本地逻辑与 UI 验证后，按仓库约定部署至当前已链接 Supabase 项目并核验迁移账本、约束和线上 smoke；本次未计划修改 Edge Functions。
- 线上验证使用事务回滚或隔离记录，不能拿用户真实职位试改状态。
- 部署顺序为兼容性数据库扩展在前，应用更新在后。Git push 仍需用户明确要求，数据库部署与 Git push 区分。
- 数据库工作流参考：[Supabase Database Migrations](https://supabase.com/docs/guides/deployment/database-migrations)。

## 9. 验收

1. 新建、编辑、拖拽、批量、列表和抽屉均识别 8 种状态，顺序与用户要求一致。
2. 已录用/已结束为同级互斥终态，确认、取消、失败回滚可用；任何在办阶段都可结束。
3. 进入阶段无需状态下拉框；新增 1/2/3 轮面试时，仅最后一轮进行中，之前轮次通过。
4. 删除当前轮、历史轮、全部轮次；终态转换；旧记录的待处理/多个进行中轮次均按统一规则兼容。
5. 自动保存覆盖连续输入、失焦、快速添加、失败重试、切 Tab、关抽屉、A→B→A、编辑后立即推进。
6. 结束流程不把历史阶段统一改成拒绝，也不虚构新阶段的日期或活动。
7. 联系人在上方，简历默认收起，展开/收起与重新打开符合设计；请求失败不阻塞联系人。
8. 桌面/平板/手机、明暗主题、减少动效、键盘焦点、流程局部滚动；弹窗至少两轮开关及退出中的反向切换。
9. 修改文件 ESLint、TypeScript、生产构建；对流程规则与保存顺序做针对性验证，不执行 TDD 流程。
10. 数据库迁移隔离验证、云端账本/约束与 smoke 核验；最终审计 diff，保留上一轮已完成工作。
