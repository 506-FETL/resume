# 评论发送动画连续性

用户已授权修正评论发送动画。当前分支实施，保留已有简历加载优化修改，不重复要求批准。

## 现象和根因

发送时先插入 `local-comment:<requestId>`，确认后替换成数据库 ID。评论树以 ID 为 React key，同一条评论被卸载并重新入场；实时通知也会执行相同的替换。发送状态退出和普通操作栏还会同时占据两行，产生额外高度变化。

## 方案

采用一次入场、原位确认：发送时立即显示正文与发送状态，成功后继续复用原节点，仅切换反馈栏。失败保留正文、重试和移除，重试不再次播放正文动画。相比等服务器成功后才显示，这能保留慢网络下的即时反馈；相比单纯关掉入场动画，能正确维持节点与局部交互状态。

复用已有请求 ID、服务端评论 ID 和事件关联，不根据正文、时间或列表索引猜匹配。前端在当前评论 scope 内保存服务端 ID 到本地渲染身份的映射；响应和实时两条完成路径都使用它，刷新同一 scope 保留，切换 scope 清空。评论树各层和线程列表共用该映射。真实数据 ID、权限、幂等请求与后端协议保持原样。

反馈区域复用 `AnimatedContent` 的单区域先退后进与退出隔离，始终预留原操作行高度。发送时正文保持清晰，不在确认后让整段再次变亮。时长与减少动效继续使用仓库公共组件和预设。

## 长评论补充

用户同轮追加长评论自动折叠。按实际排版超过 6 行默认显示前 6 行，按钮“展开全文”/“收起”保留键盘操作；不按字符数猜行数，窗口宽度、正文或字体变化后重新测量。正文链接继续可用，键盘聚焦正文链接时自动展开，避免隐藏焦点。展开状态属于同一评论组件，发送确认和实时刷新不重置。

用户随后要求收起态以省略号结尾，并带轻微模糊感。第 6 行采用浏览器原生多行省略，末行增加局部渐隐和 1px 背景模糊；展开时淡出修饰并显示清晰全文。收起的高度过渡完成后才恢复多行省略，避免正文先被截断再留下空白。动画中切换减少动效时，结束正文、箭头和渐隐层自身的正在运行过渡。

已检索现有组件及 [Radix Collapsible 文档](https://www.radix-ui.com/primitives/docs/components/collapsible)：其默认动画从 0 高度开合，不适用于保留前 6 行的裁切预览。此处组合已有 Button 与正文容器，局部高度过渡使用 DURATION/EASE，并接入 useReducedMotion；不修改公共 Collapsible 或增加新 primitive。单段文字的高度变化需要推动后续评论，这是本次局部布局动画的用途。

## 验收

本人头像补充：用户要求发送时直接使用已经加载的头像。临时评论原来写死为“我”且 avatarUrl 为空；新线程与回复在入队时从现有 user store 同步取得当前作者快照，昵称沿用既有解析函数。失败、重试和同 scope 刷新继续保留该快照；成功仍使用服务端实际资料。没有额外资料请求，不在渲染时读取另一个账户的当前头像，未加载账户资料时保留原回退。

使用真实评论组件、动作、客户端解析和 store，仅在 HTTP 边界提供隔离响应；不发送真实评论。记录修改前的重复节点，再检查 HTTP 先到、实时先到、后续刷新、新线程、两轮发送、失败重试、快速成功、嵌套回复与线程列表。逐帧比较正文 DOM 身份、数量、位置与操作区高度；覆盖桌面、390px、键盘和运行中减少动效。执行类型、格式与构建检查，清理 tests 下本期临时材料。

实施、验证、用户审查分别在验收记录中更新。
