# 助手上下文计数修复

2026-11-15。范围为用户截图中的首次空白、短输入显示异常大估算、继续输入导致统计消失。沿用已授权修复后统一审查的流程，在当前分支实施。

## 根因与选择

- `ContextUsage` 把草稿、引用、来源和目标变化作为清空统计的条件；只查最后一条消息，又会在新用户消息或技能加载出现时丢掉已有统计。未知状态用循环省略号，误导为正在统计。
- `counter.observe` 用包含工具定义的实际输入除以只有消息的估算，放大了全局比例。下一轮再用这个比例估算消息和工具。同一完整请求、固定模拟 usage=7000，正式运行器连续两次给出 9470 和 23528 的估算；这是 SDK 响应夹具复现，不是真实模型测量。
- 正式初始请求含 28 个工具，工具 JSON 10770 字符，系统消息内容 3871 字符。输入本来就不限于 `sda`，但错误校准进一步夸大了数字。

采用同口径计数与最近调用快照。相比每次键入重新读取历史、资料、技能并组装下一轮请求，这个方案不增加网络和付费调用；相比强行显示 0，它保留未知与真实零值的区别。不是修改额度账单、任务容量或模型请求内容。

## 实施约束

1. 在 provider 已序列化请求的边界，使用实际 `messages` 和 `tools` 估算，并用完全相同的数据校准实际输入。不把 SDK 工具执行对象作为请求内容计算。原压缩阈值、安全余量与前缀复用继续保留。
2. SDK 归一化为 0 不代表上游报告了 0；输入、输出和推理均依据 raw 字段区分未知。显示仍为最近一步，而非多步累计账单。
3. 新会话显示“未发送”；真正加载、历史无统计和失败分别显示状态。草稿、引用与目标变化不删除已发生调用的统计，浮层明确“上次调用”；下一次请求组装后切换“本次调用”。历史编辑、截断、换会话和换账户仅使用当前视图的真实消息，不另建持久缓存。
4. 沿用项目已有的 Radix HoverCard、Progress、InputGroupButton 和 AnimatedContent，移除静态未知状态的循环点。说明模型输入包括对话、资料、系统提示和工具定义，单位为 token。保持总量与输入/输出/推理，推理不重复相加。
5. 沿用公共过渡与运行时减少动效。验证鼠标、键盘、两轮打开关闭、退出中反向、320/390/1440、深浅色。

官方组件依据：[shadcn Context](https://ui.shadcn.com/docs/ai-elements/radix/context)。SDK 行为以本仓库安装版本的 provider 转换源码和真实运行器验证为准。
