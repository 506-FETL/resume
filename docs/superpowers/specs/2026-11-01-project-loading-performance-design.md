## 目标与范围

以用户给出的 localhost:5173 分享入口为开发基线，同时使用独立生产构建测量。拆分 HTML、模块加载、鉴权、API、文档恢复、模板资源、字体、分页及可编辑状态的时间。审计全部页面的静态依赖及构建/发布/开发配置，修复有证据的重复工作与不合理阻塞。

不以减少内容、取消授权、关闭校验、降低字体或移除动效换取速度。保留实时 current、固定 history、精确模板、账户隔离、编辑保存与导出最新内容语义。不迁移框架或无依据升级依赖；不自动 push。涉及 Supabase 函数则完成隔离验证、当前链接项目部署、版本与线上 smoke。

## 方案选择

只调整分包不能消除网络与数据恢复串行；全站长效正文缓存会扩展失效与隐私协议。本期按真实依赖拆加载边界，复用既有资源状态，将独立只读请求并发，收紧后端投影；只有不可变哈希静态资源使用长期缓存。

## 已确认的实施边界

1. 公开分享：后端重复读 scope、current 读旧 release 正文及重复 version snapshot；模板与 scope 可并行，访问统计可复用既有后台任务机制。最终授权、密码策略、同步重试及评论版本保持。匿名读取可使用服务器已支持的简单 POST，JSON 仍在 body 内，验证真实浏览器是否省去 OPTIONS；管理端 JWT 请求不变。
2. 编辑器：owner 已有文档时外观与持久文档 GET 串行。并行只读预取，仍先确认简历存在与归属，之后才创建、迁移或保存文档。不能直接并发整个 initialize，让失效简历被创建。模板预热只使用已取得的精确绑定及既有在途缓存。
3. 应用依赖：公共页头仅在编辑路由加载工具栏；检查分享阅读的评论/导出依赖及其他页面的重库。对已有 lodash 逐方法引用，避免 CJS 总入口；按实际产物决定进一步隔离。
4. 构建配置：对照现有手工分组、自动分包及明确的框架分组；检验 TLA 兼容插件与当前现代浏览器目标是否重复处理，比较构建耗时、压缩尺寸、循环依赖及运行结果。保留 WASM 实际初始化、真实路由和源代码 MDX/raw 行为。只采用测量与回归通过的组合。
5. 开发与发布：排除目录使用递归模式以兼容冷扫描和新增文件 watcher；修正只有命名导出的工具文件被识别成路由；排除测试产物的热更新干扰。HTML/SPA 保持重验证，哈希 assets 使用 immutable。字体、模板与打印几何不改。

## 验收边界

- 同一台机器、视口与样本分别记录 dev/prod 的冷载、热载，报告请求数、JS/WASM及CSS体积、分段耗时、长任务；不混淆本地与线上绝对耗时。
- 真实分享接口测试首读/条件刷新/评论/密码与权限失效，隔离响应测试失败恢复与快切。分享隐私授权不因缓存或并行绕过。
- 真实 store 的已有文档、首次创建、缺绑定/条目ID、外观失败、不存在及账户/目标变更；普通输入与富文本编辑、保存重载、导出。
- 生产浏览器遍历页面入口，验证从轻页面进入编辑后 WASM与编辑器才加载；助手渲染、模板目录、历史、分享管理等重模块按入口出现。静态审计与真实流程覆盖分别记录。
- 触及字体/分页/打印算法时追加短内容、临界页底、多页和默认模板及打印背景开关；仅加载边界变更仍验证真实PDF入口。
- TypeScript、定向 ESLint、生产构建、全项目 format:check；临时测试和数据只放 tests/project-performance，完成后删除。更新防回归清单与验收文档。
