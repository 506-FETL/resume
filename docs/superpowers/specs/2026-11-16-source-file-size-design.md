# 全项目源码按职责拆分

日期：2026-11-16。用户明确要求超过 400 行即拆分，并在范围澄清后选择“拆分全部现有源码”。本期直接实施及验证后交用户审查，不创建分支、不提交或推送。开工基线为 `0ae0920f`，工作区干净。

## 范围与根因

初扫发现 98 个超过 400 行的代码文件：80 个前端源码、6 个 Edge/共享源码、1 个既有 SQL 验证文件，以及 11 个历史数据库迁移。补查 HTML/JSON 后，另有 11 个邮件 HTML 模板和 1 份编辑器示例 JSON 超限，共 110 个。用户已同意保留已执行的历史迁移，本期处理其余 99 个超限维护源码。新增或修改后形成的模块也必须不超过 400 行，空行和注释计入；不得用压行、删除必要注释、扩大 Prettier 行宽或排除业务目录规避限制。

长文件同时承载协议、状态、请求流程、展示与辅助逻辑，入口无法清楚表达主流程。采用按职责划分的目录模块与 `index` 入口，保留现有外部接口、行为、权限、状态生命周期及按需加载边界。大组件拆出明确业务区块与 hooks，store 拆 slice，纯逻辑拆成按概念命名的函数文件。样式按已有区域和层叠顺序拆分，由原入口或目录 index 顺序加载。

## 方案取舍

| 方案                             | 判断                                                     |
| -------------------------------- | -------------------------------------------------------- |
| 按职责拆目录，index 保留公开入口 | 采用；调用方稳定，内部模块可以独立阅读与验证             |
| 按每 400 行机械切片或压缩代码    | 不采用；会切断控制流、隐藏依赖，无法改善维护性           |
| 只给新文件加限制，旧文件逐步偿还 | 用户已选择全量现有源码拆分，本期不能据此留下超限业务文件 |

## 结构与兼容约束

- 原 `foo.ts/tsx` 可改为 `foo/index.ts/tsx`，组件叶子按项目文件夹形式导出；已有组件目录保留入口，只提取内部职责。显式带扩展名且跨运行时使用的契约可保留很短的兼容转出文件。
- index 仅组合入口或转出公开 API，禁止堆放业务细节；叶子直接依赖需要的内部模块，避免从自己的 index 回导形成循环。
- 不引入新运行时、状态管理模式或依赖。React Context 只用于原有子树 UI，页面共享状态沿用 Zustand；不通过新增大型“上下文参数袋”掩盖拆分后依赖。
- `src/pages` 的工具和组件放在现有被路由插件排除的目录，确认新 index 不变成额外页面路由。保留模块级缓存、队列、订阅单例、账户代次和取消信号。
- CSS/SCSS 保持选择器、媒体查询、变量与层叠顺序。正文测量、展示、打印使用原样式和参数，UI 拆分不额外引入影响排版的 DOM。
- Edge 保留每个部署函数唯一 `Deno.serve` 入口、原路由/请求协议/鉴权/CORS/地区/事务和账本；只拆内部模块。共享源码保持前端可导入的纯逻辑边界，不把服务端依赖带入浏览器。
- 已执行的 11 个大迁移以精确路径记录历史例外，不改内容或账本；后续新迁移仍应遵守上限。既有 SQL 验证按原事务、plan 与执行顺序组织，不能改变断言含义。
- 邮件 HTML 需要单文件交给 Supabase，因此维护源码按 head、正文/操作、footer 等既有语义拆到同名目录，index 组合；沿用 Node 与 pnpm 维护命令生成 `supabase/templates/dist/*.html`。完整 HTML 属于生成产物，不再作为手工维护源码；输出必须与原模板逐字节相同，不发布认证配置或发送邮件。示例 JSON 按原文档内容块拆分，由 index 导出相同对象，不接入新的产品入口。

## 长期检查

在仓库 AGENTS 和防回归清单中记录 400 行硬限制。复用现有 ESLint/format 流程，为 JS/TS 启用 `max-lines`，其他源码也在同一配置的检查阶段按实际行数核对，不增加依赖或独立测试框架。临时验证脚本放 tests，完成后删除；长期规则属于现有配置。

## 分工与验证

通过 dispatching-parallel-agents 将互不重叠的文件范围分成后端、跟进/助手/档案、基础库/评论，以及 UI/其他页面四组。每组阅读模块历史规则，保持公开导出，局部格式和类型验证后交主代理集成。配置、文档、云端部署与最终验收由主代理统一处理。

保存原导出与模块图基线，复核导出名称、加载边界和新增循环；检查格式后每个源码实际行数。执行 TypeScript、ESLint、Prettier、生产构建与 Edge Deno 检查。浏览器覆盖首页/主要列表、编辑与保存、助手流式/确认、档案管理、跟进、评论和共享控件的关键操作，检查键盘、减少动效与重复开关；模板/打印相关拆分回归真实 PDF。验证范围与合成/真实边界据实际结果记录，不以构建代替功能验收。

后端全部开发与隔离验证完成后，按仓库规则部署当前链接项目，核对迁移账本未变化、函数版本和线上 smoke。未发布前端则明确记录。官方模块组织参考：[Supabase Edge Function 开发建议](https://supabase.com/docs/guides/functions/development-tips)；本地使用现有锁定版本，不因文档更新升级 SDK/CLI。
