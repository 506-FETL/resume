- 检索并复用现有 shadcn/ui `Button`、`Badge`、`DropdownMenu`、`Avatar`、`Skeleton` 与页面封装；普通文章布局使用语义标签，没有新增原生表单控件或手写菜单。

## 未读提示约定

- 账户头像和账户菜单里的“更新日志”均显示同一个未读状态。红点使用现有 `Badge`，浅深色沿用 `destructive`，不循环闪动。
- 最新条目从 `content/*.mdx` 文件名获得，沿用 `YYYY-MM-DD.mdx` 的日期命名约定。新增日期更新的日志会被新构建自动识别；导航只读取文件名，不执行日志加载函数。
- 只有真实日志页面成功挂载才记为已读。展开菜单、点击后仍在加载、加载失败都不会清除已读提示。查看旧条目不能倒退已经记录的最新阅读位置。
- 全局 Zustand store 在当前浏览器持久化已读记录；游客和各账户分开保存。身份未知时不先按游客处理。不新增服务端状态或跨设备同步。
- 菜单项组合 `DropdownMenuItem asChild` 与真实 `Link`。手机点击后沿用侧栏已有的链接关闭逻辑；键盘操作和返回焦点沿用原菜单。

## 本轮修整与长期约束

1. 初版主标题在逗号后继续挤入半个词，造成“跟进”跨行。发布文案明确两行语意，样式保留换行；验收从 320 px 到桌面检查两行完整显示。
2. 手机加载占位原先按固定三行说明预留，真实内容只有两行，造成 26.6 px 跳动。加载态和正文改为共用轻量 `ReleaseCover` 与同一 metadata，保留真实标题、日期和入口。1440 px 的正式封面矩形为 `[352, 191.75, 960, 404.77]`；阻塞与释放模块时矩形一致。封面不重播进入动画，避免同一等待连续淡入。
3. MDX 插件会自动导出 `frontmatter`，手动重导出同名变量会导致构建失败。需共享轻量发布信息时使用 `metadata` 导出，加载器优先采用它；普通历史日志继续使用原 frontmatter。不得通过导入正文让导航或骨架变重。
4. 导航到日志时立刻写已读会吞掉失败提示。已读动作保持在真实页面挂载后，不能挪到菜单点击或路由骨架；验收必须覆盖慢模块与真实分包失败。
5. 浏览器验证需要等待正式章节挂载，不能把拥有相同布局类名的骨架视为成功。Vite 热更新环境使用实际资源 URL 读取同一 store 实例，不用裸路径创建第二份状态来判断结果。

本轮没有新增保留的测试脚本、测试数据或临时账户。截图保存在会话展示目录 `gresume-1.0/`，已关闭临时 context；本任务启动的生产预览服务在验收后停止，用户原有 5173 开发服务保留。
