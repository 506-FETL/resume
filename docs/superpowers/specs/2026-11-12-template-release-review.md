## 代码检查

- 图片先校验 PNG 签名、声明 MIME、SHA-256、字节数和头部尺寸，再实际调用 `sips` 解码生成 PNG 并回读尺寸。仅伪造正确头部不能绕过该流程。
- 主流程在进入 `publishAsset` 循环前等待 `verifyRemoteReferences`。后者的 DO 块只查询目录、版本和示例并按条件抛异常，没有素材或模板写语句。
- 远端门禁同时检查目录和版本中是否已有模板 ID，并按示例精确版本核对投影参考日期；本地 dry-run 不读取这些远端事实，因此允许旧 ID 与格式有效但云端不一致的日期是既定行为。
- 素材预览引用、候选示例完整性和外观一致性继续复用现有严格 schema 与实际输入校验，没有在复核脚本复制业务实现。

## 追加复核：每组四张素材并发与 SQL 文件隔离

日期：2026-11-12。此次复核对应更新后的源文件 SHA-256：`2d41431ed04c29268df7e8d2dffa223e7c3fe737e5ab3b1404e13628eee9f074`。前文保留首次串行实现与远端负例的当时结果，不将其改写为本轮并发实现的实测结果。

触发背景：主任务实际发布约前 9 张素材耗时约 3 分钟，停止自己启动的串行 publisher，允许已经发出的单素材数据库子进程自然结束；当时尚未进入目录发布事务。为减少独立网络操作的串行等待，主任务将素材处理改为每组最多 4 个并发任务，并为每次数据库 query 分配独立 SQL 文件。本次没有自行发布或控制这些进程。

独立代码审查结论：这两处变更没有发现阻止继续发布的问题。

- `Promise.allSettled` 等待本组全部素材任务结束，再检查第一个失败。只要本组存在失败，就抛出异常，不启动下一组，也不执行最终模板与目录事务。
- `finally` 删除临时目录发生在本组全部任务落定之后，不会因为单个任务提前失败而删除其他仍在读取的 SQL 文件。
- 每次 `query` 使用 `randomUUID()` 命名自己的 SQL 文件，并先完成写入再启动 CLI；不同素材的数据库请求不再覆盖共用的 `release.sql`。
- 单个素材内部仍保持“已有对象校验 / 必要上传 → CDN 回读 SHA-256 → 素材记录插入”的顺序。输入哈希去重仍在本地校验完成；已有对象不得内容不符，素材记录继续 `on conflict do nothing`，没有增加覆盖。
- 远端引用门禁仍在任何素材任务之前等待完成。最终版本与目录的 `begin / insert / insert / commit` 保持原样，且只有全部素材组成功才会执行。

实际复跑 `node tests/template-hundred/release-review/review.mjs`，没有添加 `--remote-rejections`，没有进行本轮远端负例或有效发布。9 项本地正反例均达到预期，退出码 0；包括截断 PNG 完整解码失败、缺少预览、缺失素材、错误哈希、错误模板引用和重复 ID 的拒绝。脚本对运行前后发布源文件哈希一致的断言通过，`node --check scripts/publish-template-release.mjs` 通过。

此前 11 项含远端拒绝的原始结果已保存为 `tests/template-hundred/release-review/remote-rejection-results.json`；`results.json` 当前记录本次 9 项本地结果。前文 131 / 125 / 67 / 63 的只读快照属于首次远端负例时刻，不能当成已经开始上传素材后的当前云端数量。

## 再次复核：对象并发上传，数据库按组串行写入

日期：2026-11-12。最终方案源文件 SHA-256：`e2be9c53744667fcf5c71ed333af7840590718eaede1f6d66e5cecf48d803b4f`。

上一节四路 `publishAsset` 的真实运行随后失败。按主任务实际日志与只读统计：四个 CLI 数据库请求只有一个成功，另三个等待约 3 分钟后出现 `cli_login_postgres` 密码认证失败；目录仍为 63，素材 143 条、预览对象 137 个（初始分别为 131、125）。这些运行事实由主任务提供，本次复核没有重新执行远端查询。上一节只验证了 JavaScript 等待顺序和文件隔离，没有覆盖多个 CLI 进程共同刷新临时数据库角色的外部副作用；不能将上一节“可继续发布”的代码结论当作并发数据库登录已经实测通过。

本次实际读取 [Supabase CLI v2.120.0 的 db_url.go](https://raw.githubusercontent.com/supabase/cli/v2.120.0/apps/cli-go/internal/utils/flags/db_url.go)：未提供数据库密码时，连接配置会初始化登录角色；pooler 路径先初始化角色，再等待 pooler 密码更新并重试连接。结合主任务记录的共用角色认证失败，数据库 CLI 请求需要串行执行。这里没有依赖未实际读取的知识库内容。

最终实现改为：

- `uploadPreview` 只处理对象必要上传、已有对象核验与 CDN 回读 SHA-256，不调用数据库 `query`，每组最多四路并发。
- `Promise.allSettled` 等全部上传结束后检查失败；任一上传或回读失败，就抛错，不执行该组素材 INSERT，也不进入下一组或目录事务。
- 本组全部成功后，`buildAssetsSql` 将本组最多四条完整素材编码为一条多 VALUES INSERT，随后 `await query(...)`。该语句保持哈希、MIME、字节数、尺寸、base64、发布时间字段及 `on conflict do nothing`，没有增加覆盖；单条 INSERT 原子处理这一组记录。
- 数据库写入循环逐组等待，远端门禁、素材组 INSERT、最后模板与目录事务在此脚本内不会并发执行；最终目录事务保持原样。
- SQL 文件继续独立 UUID 命名；素材记录写入失败时可能保留已上传的不可变对象，但不会发布目录，重跑仍验证已有对象哈希后复用。这与分批素材准备、最终目录原子发布的既定流程一致。

独立结论：本次代码检查未发现阻止按最终方案继续发布的问题。真实网络执行、目录事务成功与发布后公开读取仍必须由主任务完成，不以本地检查替代。

已更新临时 `review.mjs` 使用当前 `uploadPreview` / `buildAssetsSql` 名称，并将调用顺序和上传函数不含 DB query 的结构断言纳入不联网的本地运行。实际执行 `node tests/template-hundred/release-review/review.mjs`，九项原有本地正反例全部达到预期，新结构断言和运行前后源文件哈希一致断言通过，退出码 0。`node --check scripts/publish-template-release.mjs` 通过；临时脚本经过 Prettier 与 ESLint layout 修复。本次没有运行 `--remote-rejections`、远端 CLI query 或发布，也没有浏览器操作。
