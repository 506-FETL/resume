## 根因与改动

原页面的加载 hook 与预览、工具栏等工作区静态绑定。生产模块图中，启动入口闭包包含 87 个 JS 分包、1,440 个模块、2,005,358 字节。拆开后为 28 个分包、946 个模块、1,321,365 字节，预览已移出入口静态闭包。这是未压缩传输前的 JS 代码字节，含与外壳共享的模块，不代表每次导航少下载这么多，也不是 gzip 大小。

另一个实际等待来自 `useCurrentUser`：多个展示组件分别 getSession 和订阅认证事件，开发模式首屏出现 8 次展示用 getSession。真实调用边界记录中，文档 getSession 从 1,443 ms 等到 1,662 ms；改用已有 useUserStore 后，另一次相同入口记录为 1,410→1,423 ms。展示 hook 不再重复读取和订阅，文档加载及 SDK 请求仍执行原身份检查，账户取消和保存队列未改。

工作区复用 createDeferredComponent 的加载错误和重试；新增可选的原样 fallback，此入口使用原 RouteSkeleton。其他调用维持原包装和动效。工作区迁移只调整相对导入、单层 props 与导出名称，UI 和业务 effects 保留。

已排除的假设：真实 DOMParser 共 221 次，直接计时约 1–2 ms，未修改文本转换；主入口路由预取没有稳定收益，试验代码已撤回。未跳过 CRDT 校验，也未引入正文缓存或旧快照抢先展示。

测量中曾出现控制扩展的 cursor-chat.png 被计为最大图片、得到 0.x 秒 LCP。通过 trace 中的图片 URL 确认后，仅在测试时隐藏控制光标，未隐藏产品内容；锁屏/后台导致的空 LCP、控制光标 IMG 样本均剔除。该样式及探针已在交付时清理。

## 功能与故障验证

- 真实工作区模块响应额外延迟 2,500 ms：模块请求 1,217→3,727 ms，正文请求 1,755→3,145 ms。文档读取没有等工作区下载完成，且同轮只读一次正文；展示仍等真实内容和工作区就绪。
- 对真实工作区模块返回一次 HTTP 503：出现局部“暂时无法加载简历编辑页”和重试按钮。点击重试后模块重新请求成功，恢复两页、88 个段落节点，无整页错误。10 秒探针恰在重试分包返回时结束，未记录到正文时间；恢复结果以之后的真实 DOM 和页面检查为准，不将该轮用于 LCP 对照。
- 真实编辑入口：姓名、电话、邮箱等输入可用，未改用户正文；检查页签显示本地检查已完成；评论加载、关闭和焦点返回正常。编辑与评论均完成多轮开关和快速反向切换。进入简历库，确认列表标题挂载后返回，正文和两页分页恢复。
- Chrome 临时模拟减少动效：公共时长变量变为 0s，编辑和检查仍可用；结束后取消模拟，变量恢复为 0.14 / 0.2 / 0.28s。按 review-animations 检查：复用既有 EASE、fadeInUp 和动态减少动效，没有新增时长或页面布局动画。
- 独立测试页使用真实 hook/store：25 个消费者，覆盖未知状态、匿名、A→B→A 和退出，展示用 getSession 次数为 0；连同离线保存重开共 12 项断言通过。此处是合成用户状态切换，不冒充真实在线多账户登录。
- 使用真实离线 API 和 store 创建合成简历，读取已发布的默认模板绑定，执行修改、manualSync、持久化读取、重开和删除；确认当前用户所选简历未变、临时记录已删除。初版夹具因先取快照后赋模板绑定而失败，修正夹具顺序后重跑通过；失败不计通过。
