# AI 助手性能验收

## 用户录制

本机 Vite 开发页的文档首字节为 6.4 ms，FCP 为 468 ms。最终的 LCP 是已恢复回复中的 Markdown 列表项，出现在导航后 2968 ms。会话列表请求位于 1251–1682 ms，最新消息请求位于 1764–2302 ms，后者解压后为 199316 B。读取简历与岗位候选的请求在用户打开菜单前就已出现，两类各有两次 20 条查询；画布还发起一次批量简历摘要查询。

单次资料元信息 Edge 请求位于 2750–3367 ms。它在 LCP 之后返回。布局偏移簇从 1677 ms 开始，共五次，得分约 0.0158。记录涉及输入区、会话标题和画布标题。引导浮层静止时仍逐帧获取锚点矩形，该调用栈的布局累计约 22.6 ms。另外有消息滚动组件的必要测量，以及 React DevTools 扩展引起的布局和样式更新。不同栈的归因时长有重叠。

## 实施范围

- 认证后并行准备助手页面和已知会话读取。最近列表按更新时间和主键翻页。列表、正文、较早消息分别处理失败。换回近期对话共享成功数据与在途查询；保存、删除、改名和账户变化按相应范围失效。搜索命中页外消息按主键核对原文。
- 桌面和抽屉画布沿用同一可见状态；已知简历直接取目标，缺失时维持原优先级。未绑定时按原云端顺序只取第一份，云端为空才查本地有序首项。预览请求只取版式、正文和显示标识；重开时核对更新时间，同版本复用快照。看板每页显示 20 项。代码高亮、预览正文、非活动画布面板、发送用模型 SDK 按实际入口加载。
- 输入菜单按首次展开获取候选，分别返回结果、保留重试。只读历史跳过完整档案与会话附件目录，明确职业资料沿用指定版本；需要自动范围时才获取目录并冻结。资料出处通过现有 RLS 查询六个元信息字段。流式正文复用已解析的历史证据。
- 输入区的额度与资料状态共用底栏。画布标题留出实际操作高度。首次引导指向静止按钮时使用按变化更新的位置策略；移动中的引导步骤仍跟随目标。

## 公网核验

隔离的两个云端账号对照旧 Edge 与新数据库直读，核对有效版本、软删除状态、会话归属、未找到的 ID、匿名和跨账号读取。四轮同机交错样本，旧接口为 1011、578、439、424 ms，直读为 503、364、488、334 ms。该项独立于 LCP。测试账户与资料已删除并回查。

## 流式渲染

在受控 Chrome 中使用 61 条消息、360 项工具证据，连续 150 个动画帧提交，直接运行项目新旧解析实现。无出处文本累计耗时从 137.9 降至 31.2 ms，有实际出处的文本从 152.3 降至 33.7 ms。数值反映组件局部工作量。

## 真实入口与边界

- 模拟列表单独延迟 3300 ms，已记住会话的读取延迟约 80 ms；列表仍在等待时，正文已可读，输入器可编辑。单独注入列表或正文故障，均可独立重试。换回刚读过的会话复用消息。
- 独立云端临时账户的 46 个同时间会话按 20/20/6 唯一翻页，消息按 30/30/4 补齐；第 63 条历史搜索结果只取命中原文。覆盖页外恢复、全文搜索后续页、读取失败停止自动重试、真实改名写后重读、账户切换及 RLS 可见性。测试账户与数据已删除并核对。
- 26 份简历中绑定第 25 份时，首开只精确读取该份。重开同版本只查更新时间，版本变化时读取新正文，画布实际呈现更新后的姓名。另验无简历、只有 IndexedDB 本地简历、390 px 抽屉和减少动效。43 个岗位在可见看板按 20/20/3 分页，返回上一页命中缓存。
- 纯阅读时没有目录请求。实际输入才开始读 203 项职业档案与 1 项会话附件，提交时 user 消息保留了全部 204 个版本；指定职业档案引用时只冻结所选项。历史编辑目录失败可原地重试，草稿保留；按历史冻结版本重新生成时不用读新目录。手动压缩经真实菜单触发，对短会话保留最近轮次。
- 简历与岗位候选按第一次打开菜单启动。合成岗位故障仅重试岗位；选择简历后输入焦点恢复，两轮开关成功数据复用。两个宽度下独立延迟额度和目录，textarea、发送按钮和消息视口矩形在三种到达状态均保持相同。
- 真实发送入口配合合成 SSE 验证模型模块加载、流式答复、创建会话和 user / assistant 顺序写入；刷新后读回同一回复。未调用付费模型。引导展开、缩放视口后继续对齐、关闭均经过实际页面。另在独立生产检查中记录提示稳定后的 60 个动画帧，画布按钮矩形读取由 120 次降至 0 次。这项测量针对静止锚点。
