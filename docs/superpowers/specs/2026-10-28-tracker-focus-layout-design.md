# 重点关注与求职详情布局

日期：2026-10-28。

状态：实施完成；已列出的验证通过，完整覆盖范围和已知边界见验收记录；最终用户审查待进行。

## 1. 用户决定与改动范围

- 彻底取消“待补材料”功能，以岗位级“重点关注”替换首页第三张提醒卡。
- 用旗帜图标标记职位，点击变成红色，再点取消。只标记这一条岗位流程，同公司的其他职位不联动。
- 用户确认：进入已结束或已录用后，首页不再展示，但保留红旗；恢复流程后重新出现。归档岗位也不占首页展示位置。
- 保留当前导航、首页总体顺序、看板 / 列表、阶段列、抽屉、流程进度和三个页签。调整截图涉及的提醒卡、投递详情、联系人与简历，以及首页今日待办的内层重复边框。
- 本设计取代旧第三期和公司流程规格中“材料待补、补材料入口、首页待补材料提醒”的要求。一次投递、准备简历与投递原件分离、旧记录和文件保留等已确认约束继续有效。

## 3. 现有问题及根因

1. `submission-list/index.tsx` 的外层 Card 又包含 recordCard 的 MotionCard。同一份投递信息还在阶段详情和联系人页重复展示，形成两层边界和重复操作。
2. 共享 Card 用外侧 ring 描边；抽屉 Tab 面板负责滚动裁剪，业务卡片贴着内容边缘，造成外侧描边被裁掉。代码结构与截图、已有布局复盘一致；实施仍需在真实页面确认修复后的完整边缘。
3. `size='sm'` 将标题降到 14 px，日期和正文也使用 14 px；缺少字段标签，日期、渠道、备注挤成同一级信息。
4. 无原件也出现“查看留档”和“补充材料”，让一次已完成的投递看起来仍欠一项任务。
5. 首页今日待办已经有一层 Card，内部每项再次包圆角边框；本轮在保留外容器的前提下改成信息行。

## 4. 两种布局选择

### 推荐：分区信息行

抽屉本身就是内容容器。投递详情使用分区标题、标签和值、细分隔线；只给确有独立交互的文件行或准备简历保留轻量表面。无需额外的“投递详情外卡 + 记录内卡”。信息更紧凑，长备注和手机布局更自然。

### 备选：单层摘要卡

保留一张完整的投递详情卡，日期、渠道、备注在同一层内排布，移除内部记录卡。与当前界面变化更小，但整个抽屉仍有较多框线，整体连贯性不如推荐方案。

两种方案使用相同的数据规则与红旗入口，不提供独立工作区或新的导航方案。

## 5. 重点关注的操作与展示

### 标记入口

- 看板：职位卡右上角预留固定图标位置；未标记灰色空心，标记后红色填充。标题最多两行，图标不覆盖文本。
- 列表：放在职位名称区域的固定末端，不增加一整列；与批量选择复选框分开。
- 抽屉：标题操作区、更多按钮之前，切换任意页签时仍可访问。
- 同一岗位的三个入口同步状态。标记本身不推进阶段、不创建活动记录、不改变当前排序；用户需要缩小范围时使用工具栏“重点关注”筛选。
- 点击旗帜不打开抽屉、不开始拖拽；其他卡片内容维持整卡拖动。键盘 Enter / Space 可切换，使用 Button 的 aria-pressed 和“标为重点关注 / 取消重点关注”名称，配 Tooltip。
- 桌面命中区至少 32 px，触屏至少 44 px；标记不只依靠颜色，还区分空心 / 填充并提供可读状态。

### 首页

- 顺序仍为“下一场面试 / 到期跟进 / 重点关注”，桌面三列，窄屏按现有断点单列。
- 第三张卡使用左上角淡红旗帜和局部渐变，渐变在进入正文前衰减；标题保持 16 px / 600，数量使用红色系 Badge，正文主信息 14 px，辅助信息 12 px。
- 仅展示手动标记、未归档、非已结束和非已录用的职位。没有手动标记时，不按材料、AI 分数或面试日期自动标记。
- 每项展示公司与职位、当前阶段及已有下一步安排；没有安排时仅显示阶段，不编造提醒。点击信息区域打开原岗位抽屉的“跟进”页签。
- 展示最多两项，按最近标记时间排列，底部“查看全部 N 个”进入现有求职跟进并开启关注筛选。计数为完整结果数量，不是截断后的两项。
- 空态：“还没有重点关注的职位”，辅助说明“在职位旁点击旗帜即可标记”。加载、错误与空态分别呈现。
- 已结束 / 已录用 / 归档不会清除标记；恢复后满足上述条件才回到首页。终态恢复逻辑继续遵守已批准的公司名额规则。

## 6. 待补材料的彻底移除

- 删除首页待补卡、计数、独立 pendingMaterials 加载资源与聚合查询。
- 删除抽屉“材料待补”“补充材料”“稍后补材料”入口和文案，删除对应前端动作及服务补材料动作，不能只换名字后继续保留原工作流。
- 首次确认投递仍可选择是否附上实际提交的平台版本或 PDF / DOCX；不附文件照常完成投递，不生成欠缺任务。表单改为“附上投递原件（可选）”，不再强迫从含“稍后补”的来源下拉里选择。
- 无原件的既有记录展示日期、渠道和备注即可，不显示空文件区域、补传按钮或假预览入口。后续不能通过改名后的“关联简历”重新加入这项功能。
- 已存在的原件与旧修订继续可预览 / 下载；已有原件纠错继续走显式“更正原件”并保留历史，只允许更正已有材料，不成为空记录补材料的替代入口。
- 保留一次投递事实及其时间、渠道、备注、JD 和旧文件；移除功能不等于删除用户历史。旧库的 pending 值只作为“没有保存原件”的存储兼容状态，不再作为待办状态。

## 7. 抽屉的信息分工

### 阶段详情 → 已投递

标题“投递详情”与次级“编辑”同一行。下方为“投递日期 / 投递渠道”两列，窄屏堆叠；备注单独一段，有内容才显示。编辑日期和渠道继续保留更正历史，不改变当前阶段。

已有原件时增加一行：文件图标、文件名 / 固定版本、预览或下载、更多操作；无原件不显示这一行。JD 副本与历史修订放在底部折叠区域，不再与主操作争抢注意力。历史确认为空时不展示空的历史容器，加载失败则提供重试。

### 联系人与简历

联系人保留标题与添加按钮，空态收成一行“暂无联系人”，移除大块虚线占位。准备中的简历保留已有 Collapsible 和真实操作；折叠时显示简历名，展开才加载预览。

移除当前“已提交材料”整张复合卡。已有投递原件时，下面仅显示一个“投递原件”文件信息行，点击直接查看；日期、渠道、备注与更正历史统一到阶段详情，不再重复完整展示。无原件时这一行不存在。

### 首页今日待办

保留当前标题和外层容器；内部改为可点击的信息行，图标、主文案、说明、箭头对齐，行之间用细分隔线。复用 Button / Link 和现有反馈组件，不新增第二层卡片。

## 8. 实现落点与组件复用

- 复用已有 Button、Tooltip、Badge、DropdownMenu、Separator、Collapsible、Dialog、Alert、Spinner、Skeleton 和公共动效；现有 Button 原生支持 aria-pressed，无需为一个二态动作新增 Toggle 库。
- 字段详情用普通 section / dl / dt / dd 组合，符合 AGENTS.md 对语义布局的允许范围。已检索本地，无 Item 组件；本次不为简单布局引入新依赖或整套 registry。
- 抽出跨看板、列表、抽屉复用的岗位关注按钮；共享动作放 tracker store，复用现有持久化队列、字段版本和账户作用域。
- 建议在现有岗位表增加可空 `focused_at`：null 为未关注，时间表示标记顺序。不另建关注表，不复用公司规则或阶段字段。复用当前 RLS；默认 null，不自动回填旧材料待办。
- 标记不应刷新业务跟进的 updated_at，否则会把久未推进的职位从“到期跟进”中错误移除。实施需检查现有更新时间触发器及通用更新入口，对仅关注字段写入保留原业务更新时间；不额外新增一套并发框架。
- 首页查询在现有岗位摘要中带出标记，依赖 jobs 自身加载；返回首页时与服务器同步，不新增独立材料请求。
- 边框修复局限于本轮业务容器：保留裁剪与滚动，使用已有内边距和适合此处的 border / inset 边界。不能全局改 Card 或取消抽屉 overflow 来掩盖断边。

## 9. 动效与验收

- 旗帜仅做短颜色 / 填充过渡，不让卡片抬升或列表自动跳位；复用 DURATION / EASE 并接入 useReducedMotion。
- Tab 与折叠沿用已修复的先退后入，逐帧检查不叠字；焦点先移到有效触发点，再隐藏旧内容。
- 实测看板标题、Logo、留白拖动；旗帜仅切换，复选框仅选择，普通点击和键盘打开详情。
- 核验标记跨页面、刷新、取消、保存失败以及账户切换；使用现有队列，不用复制业务逻辑的测试替代真实实现。
- 核验新记录无材料、原有 pending、已有 PDF / DOCX / 平台快照、旧多条主记录确认与修订读取。取消补材料不破坏历史访问。
- 检查无 / 一 / 多个关注，长公司与职位名，超过两项时的计数和“查看全部”，终态隐藏与恢复重现，归档与取消归档。
- 桌面、390 / 320 px、深色、减少动效；滚动顶部 / 底部的边框和键盘焦点均不被裁切。相关弹窗至少两轮开关及退出中重开。
- 代码完成后按仓库要求格式化、检查、构建；数据库 / Edge 变更完成隔离验证后，由代理部署当前链接项目并检查账本、函数版本和线上 smoke，不进行 git push。
