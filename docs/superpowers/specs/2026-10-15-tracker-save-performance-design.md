# 求职跟进保存性能修复

用户要求频繁编辑与简历编辑一样防抖，保留已确认的自动保存体验。本次仅调整求职跟进的保存调度和相关生命周期，不改数据库、页面布局或手动保存流程。

## 已确认的问题

- 当前 450 ms 定时器只作用于第一次写入；`persistDirty` 在请求返回后循环提交新输入，持续输入时变成按网络响应速度写库。
- 重复失焦、切换、关闭会重复入队，内容相同也被标为 dirty。
- 页面离开缺少统一刷新入口；简单延长计时器不能单独解决此问题。

## 保存约定

- 对齐简历在线保存的 3 秒空闲间隔。输入立即更新本地，阶段备注、轮次名称和笔记在职位级合并保存。
- 任何写入期间发生的新输入仍等待自己的空闲间隔。每次主动刷新仅加速当时的草稿，不把后续连续输入变成无限即时提交。
- 失焦、切换阶段/轮次/职位、关闭详情、站内离开、页面隐藏刷新当前草稿。刷新调用共享在途任务；日期选择、增删轮次及阶段推进保留及时保存。
- 阶段推进必须等待之前的草稿保存成功，最新内容与状态一起提交。每个职位始终串行，不同职位独立。
- 相同内容、空补丁、重复日期和没有修改的刷新不产生网络请求。改回已保存内容且不存在冲突的在途写入时取消待保存。
- 失败保留草稿与错误状态，由重试或新的编辑继续；不自动循环重试。过期响应不能覆盖更新内容或复活已删除职位。
- 浏览器彻底关闭无法保证异步请求完成；离开时发起刷新，仍有未保存内容时用浏览器标准离开保护，避免无提示丢失。

## 验证

使用真实 store 和隔离 API 测量连续输入、请求中继续输入、重复刷新、无变化、改回原值、多职位、失败重试、状态转换、删除、旧查询回写。浏览器复核真实编辑与切换行为，最后运行 ESLint、TypeScript 和生产构建。
