# GResume 全站视觉重设计规格

日期：2026-10-29

状态：用户已于 2026-10-29 批准“专注编辑”方案及本规格，授权实施与验证。实施和最终验收结果单独记录。

## 1. 目标

让用户打开页面时先看到正在处理的简历、岗位、问题或对话，再看到辅助状态与统计。用排版、对齐和内容组织形成统一的产品界面，清理等权卡片、装饰光晕、重复摘要及空泛说明。

本轮覆盖全站界面和现有交互的呈现，不重写业务流程，不增减产品权限，不修改用户简历正文或历史对话。简历纸张、模板正文、分页和打印样式不在视觉替换范围内。

## 4. 方案比较

### 推荐：专注编辑

应用采用连贯的侧栏与正文区域，取消悬浮外壳的厚重卡片感。简历、岗位和对话名称成为视觉中心；最近简历保留独立但轻量的内容块，三类提醒收紧高度，待办占宽栏，统计和动态放在较窄的辅助栏。

优点：适合长时间编辑、阅读和求职跟进；对象卡片仍容易识别，能自然扩展到编辑器、助手与历史版本。代价：辨识度主要来自内容和排版，需要把字号、间距和选中态落实准确。

首页草图：`.impeccable/mocks/decision/workspace.html`。

### 备选：清晰目录

最近简历采用连续信息行，名称、目标岗位、更新时间、操作按列对齐。提醒保留紧凑独立区域，待办与统计通过细线和留白分开。相同语法延伸到简历与分享管理。

优点：扫描和比较效率高，重复容器最少。代价：信息更紧凑，对窄屏列折叠和长名称布局要求更高，文档工具的空间感较弱。

首页草图：`.impeccable/mocks/decision/catalog.html`。

### 对照：沿用现有结构精修

保留浮动侧栏、卡片布局与模块比例，只统一留白和文字。变化较小，不能充分回应用户已选择的整体视觉重设计，因此不推荐作为本轮实施方向。

首页草图：`.impeccable/mocks/decision/canon.html`。

方向探索使用 Impeccable，记录标识为 `seed:2195b55a04c6613b`。草图是静态设计材料，按钮仅表达位置与层级，不是产品功能。最终交付仍必须使用仓库已有真实组件与动作。

## 5. 推荐方案的视觉规则

### 外壳与排版

- 沿用 GResume 品牌、全部导航入口、主题切换和账户入口；侧栏改为连续浅底区域，以一条分隔线连接正文，不使用悬浮阴影和嵌套圆角边框。
- 保留当前可折叠侧栏能力与移动端抽屉。助手会话列表保留可滚动独立区域，不因导航收紧丢失入口。
- 沿用 Inter 与中文回退字体，不新增字体依赖。页面标题 24–28 px、区块标题 16–18 px、正文 14 px、元信息 12–13 px；可操作正文不以小号灰字承载。
- 管理页沿用 `PageLayout` 的宽度约束；工作区继续使用可用空间；认证与设置内容使用适合阅读的窄布局。不将所有页面统一成同一种宽度。
- 页面边距桌面 24–32 px、手机 16 px，区块间距 24–32 px，相关字段间距 12–16 px。通过统一 token/现有类组合落实，不为每页增加不同的魔法数字。
- 页面介绍只补充必要信息；能由标题和操作表达的内容不再重复一遍。保留明确的同步、权限、风险和错误说明。

### 表面、颜色与动作

- 沿用黑白中性色与现有语义颜色。普通内容区以留白和细分隔线组织；只有独立对象、表单组或浮层需要外边框。
- 移除简历卡追随光晕、无意义彩色图标底座、常驻装饰粒子和操作按钮的旋转反馈。保留相关入口及必要的状态反馈。
- 控件圆角沿用 shadcn token，普通内容容器不超过 12 px；阴影仅用于浮层及现有纸张展示，不给每个区块追加阴影。
- 每个页面设一个清楚的主要动作；对象内操作按使用频率排序。重复入口可以保留方便触达，但不能同时使用同等强的主按钮样式。
- 状态颜色总是搭配文字或图标；“本地”“云端”“岗位版本”“已关闭”“失效”等差异继续可辨识。
- 暗色主题沿用同一层级，按现有 token 映射，禁止只完成浅色稿。

### 已确认特色

- 首页面试、到期跟进、重点关注继续使用紫、琥珀、红色，保留左上淡色大图标与局部渐变。收紧外围容器与高度，不把三个功能抹成无差别数字。
- ATS 保留真实分数水印、Racing Sans One 和评分色；装饰不参与布局和读屏。缩减摘要中的重复标题、进度和空白，不能把 ATS 名称改成录用概率。
- 模板纸张沿用真实预览，不添加装饰照片、伪造数据或无关插图。

## 6. 逐模块实施边界

### 首页、简历与分享管理

首页顺序仍为引导/导入草稿、最近简历、求职提醒、待办、统计与分析。桌面将次要统计与动态在主任务下方或右侧组织，手机按阅读顺序单列。各模块使用自己的加载与失败状态，单个模块返回即展示。

简历卡将名称、版本关系、最近编辑、主要动作按稳定顺序组织。存储位置退到元信息，不删本地转云端提示。全局新建入口保留；空态中的创建引导保留；已有数据时不再让大虚线新建卡成为视觉中心。创建向导的三条现有路径与核对步骤不变。

分享卡保留网格和全部权限操作。统计压缩后仍显示真实数据；“当前版本”动态同步和“历史版本”固定快照必须能直接区分，禁止只靠颜色。不会在本轮更改分享服务端或访问规则。

### 跟进、编辑器、历史与助手

跟进保持看板/列表切换、筛选工具栏、列顺序和内部横滚；看板列最小 256 px、结束列 44 px 的约束继续生效。手机保留独立搜索行及公司选择与三个工具按钮。首屏可能没有实际岗位时，保留横向浏览的可发现性，不自动改变阶段顺序。

右侧岗位抽屉保留“跟进 / 阶段详情 / 联系人与简历”三页签。标题区只保留一组岗位/公司/状态信息；收紧阶段概览，不重复外层标题。投递事实、投递原件、准备中的简历仍按现有规则展示。

编辑器只调整应用工具栏、侧栏、表单与辅助区。保留居中工具栏、手机图标、填写/检查与保存/协作/分享同行且窄屏可换行。文档测量页、展示页和打印副本不得因全局样式连带变化。

历史版本保留两区与切换状态；AI 助手保留消息、流式输出、工具状态、会话搜索、模型能力与画布。用户原文和已生成历史内容不做“去 AI 味”改写。代码修改只触及展示和既有交互的视觉反馈。

### 其他页面与浮层

模板目录、更新日志与认证页沿用合理的内容结构，接入统一视觉规则。个人信息将普通设置调整成有分组标题的信息行，危险操作仍明确独立。

弹窗、抽屉、菜单、空态和提示统一使用共享组件。每个新建/修改的 Dialog 必须有关联描述。加载、未知、失败、无权限、失效与真实空数据分别展示，不能以空态代替错误。

## 7. 组件、状态和动效

已检索现有组件，以下覆盖本轮需求，不新增 UI 依赖，也不自行重造基础控件。

| 用途       | 现有组件                           |
| ---------- | ---------------------------------- |
| 操作与提示 | Button、Tooltip、Sonner            |
| 表单       | Field、Input、Select、现有编辑组件 |
| 切换与筛选 | Tabs、Popover、DropdownMenu        |
| 浮层       | Dialog、Drawer、Sidebar            |
| 内容状态   | Card、Empty、Skeleton              |

业务布局组合这些组件。需要重构页面时遵守 history-style 模块组织；共享状态/动作放对应 Zustand store，单组件临时状态保留本地。视觉变化不引入跨页面 Context，不修改 API、数据库或权限模型。

动效继续使用 `src/lib/motion.ts` 的 EASE、DURATION、SPRING 和既有 variants，接入仓库的 `useReducedMotion()`。本轮减少装饰不等于取消进入、退出、切换和折叠动画。不得照搬不匹配 Radix/Base UI primitive 的状态选择器。

微交互实施使用 transitions-dev，完成后按 review-animations 或 Impeccable critique/polish 检查。若调整共享弹窗，创建简历、创建分享、简历优化至少各验证两轮完整开关与快速反向切换。

## 8. 验收要求

- 路由：上表所有页面；每类补充有数据、空态、加载、失败与相关权限状态。无有效凭据或测试条件的状态如实记录，不伪称通过。
- 尺寸：1440 px 桌面、用户实际桌面宽度、768 px、390 px；长中文名称、长说明与多条记录不能遮挡主要操作。工作区允许既有内部滚动，页面不得新增非预期横滚。
- 视觉：标题与主要对象先于元信息被看见；无重复进度、无无效占位交互、无非业务性光晕；首页与 ATS 已确认特色仍在。
- 交互：导航、创建向导、简历卡操作、筛选、看板/列表、详情页签、编辑侧栏、历史预览、分享、助手画布均走真实入口；键盘焦点与减少动效一起检查。
- 数据：不使用真实账号进行破坏性测试，不改写用户正文；保持本地/云端、用户隔离、动态/固定分享与投递原件规则。
- 导出：若任何改动触及公共打印、正文尺寸或模板，必须扩大验收到短内容、页底临界、多页长内容以及背景图形开/关的真实 PDF 导出。单纯构建不替代导出证据。
- 代码：对改动文件运行 Prettier，再执行 ESLint layout 修复；运行仓库已有类型、构建、格式检查，区分原有失败与本轮新增问题。
- 临时验收代码和数据仅放 `tests/`，结束删除本轮脚本；设计草图保留为规格审查材料，不进入生产路由。
- 文案：在实际页面通读一次，删除重复说明和口号，保留完成动作需要的信息，不把内部规范写进用户提示。

## 9. 本轮发现的长期约束
