# AI 助手发送与完成连续性修复

日期：2026-11-13。用户反馈发送后下方有大空白，回复结束时又突然跳到底部。本轮是已授权助手升级的缺陷返修；不增加新的产品能力，不修改模型、保存或取消协议。

## 复现与上一轮遗漏

读取防回归清单第 28 节、Trace 规格与计划、上一轮空白验收，以及已安装 Scroller 和 Motion 源码后，用真实 MessageList、项目 CSS、MemoryRouter、SidebarProvider 和隔离合成会话复现。页面不调用真实模型、不写用户简历。

上一轮检查了最终占位是否消失，没有检查发送到完成的连续帧。其“结束后清占位”方案只修正终态，仍保留产生空白的轮次锚定，也漏掉了组件交接时的高度变化。

1440 × 900 开发页面的实测：

| 触发场景                   | 根因与观测                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------------- |
| 30 条历史后发送短消息      | 最后 user 的 scrollAnchor 将新轮次顶到上方，产生 600px spacer；输出单段后仍有 582px            |
| 短回复完成                 | settleCompletedTurn 立即清理 spacer，scrollTop 从 5400 变为 4852.5，一帧位移 547.5px           |

| 展开 25 段思考后完成       | 临时与保存回复分别挂载，手动展开状态丢失，高度从 6495 降至 5737，差 758px                      |
| 统一回复身份后的分页边界   | 首条已加载消息为 assistant 时，补入前驱使基于前驱的 key 变化；实测旧节点断开、展开状态变 false |

这几个场景均先实测问题，再验证修复。未将静态审查、最终截图或上一轮通过结果作为本轮连续性的证据。

## 最终实现

- 取消自动轮次 anchor，从发送开始使用官方 Scroller 的普通底部跟随；删除完成后清占位的回调和手工定位。主动发送时恢复跟随，流式增量和完成不触发额外定位，上滚阅读及搜索继续由原状态机处理。
- 流式回复与保存回复使用同一个 memo MessageRow / MessageBubble 实例。临时回复按前驱关联最终回复，保存后更新真实 messageId，保留 Trace 的手动展开、收起和正文布局。
- useMessageRowKeys 只在真实 messages 数组变化时保留已有行身份；补入更早历史不会改变已显示回复的 key。Map 只保留当前消息，随会话视图卸载；逐 token 更新不重建 Map，不改全局 store。
- 实际删除的行由 Motion popLayout 处理，避免退出副本继续占正常流；React 19 ref 传到实际 Item 根节点，Content 为相对定位参照。确认卡继续使用公共 fast 退出与减少动效，退出节点 inert。
- 流式助手保留与最终操作行相同的 24px Footer，完成时显示按钮不再改变高度。占位无交互、对读屏隐藏；没有恢复每轮 token 用量展示。

组件依据：[shadcn Message Scroller](https://ui.shadcn.com/docs/components/base/message-scroller) 的 autoScroll / scrollAnchor 区分，以及 [Motion AnimatePresence](https://motion.dev/docs/react-animate-presence) 的 popLayout 与 ref 约束；同时核对本地已安装版本，未修改依赖源码。
