## 体验与步骤

按用户本轮反馈重新收敛：初始为贴近入口的一行短提示，评论提示实测 162 × 32 px，只保留功能名、「看看」及关闭。排序仅用两行短句与关闭。取消初版大标题、说明段、黑色主按钮和大阴影；按用户随后提供的截图反馈，彻底移除入口的透光轮廓、额外高亮与图标放大。箭头改用 Lucide 的标准 ArrowRight（16 px），整体朝向入口，避免自绘曲线与箭头头部方向不一致；仅做一次轻微淡入，保留其他步骤的 GSAP 演示。详细步骤仅在主动点击后出现，宽度上限 248 px，灰色小按钮，步骤数字放在底部。手机提示压至 28 px 高，使用库的虚拟锚点放在工具栏与纸张之间的既有留白中，避让换行后的真实工具栏及简历姓名。不自动展开抽屉，不抢焦点，关闭无 toast，刷新后不再自动出现。

评论在已加载且有真实评论入口的编辑页出现；离线简历、无权限或入口不可见时不显示。点击演示按钮或被提示的评论入口后：

1. 打开与正式评论栏同风格的非模态演示抽屉，简要介绍评论与处理状态。
2. 下一步关闭演示栏，从当前可见简历的非空正文中选一段，动画演示拖选；说明先选中要讨论的文字。
3. 下一步演示点击选区的评论按钮、打开评论栏、输入并发送“666”。使用本地演示数据，清楚标记“演示”，不请求真实评论接口。
4. 下一步关闭演示栏，展示该段文字的评论高亮；完成后清除演示层。

助手在实际页面可用时提示画布入口。主动开始后打开真实画布、介绍选中文字、演示划词与“引用到对话”、展示引用进入输入区以及补充要求。演示使用独立的只读引用预览，不改原草稿、不发消息、不调用模型。手机将画布在演示期间设为非模态，引用阶段关闭画布以展示输入位置。

排序在用户打开填写区且排序入口可见时只提示一次：栏目使用拖动手柄；同一栏目的多条经历使用上下移按钮。手机指向“调整模块顺序”入口。用户操作手柄、关闭或点“知道了”后结束；引导不实际修改顺序。

## 不打断操作与数据范围

同一时刻最多一项引导。所有步骤可关闭、Escape 退出；页面其余点击、输入、滚动正常。用户操作引导之外的控件时结束演示并放行原动作，不拦截、不恢复覆盖用户的新操作。离开页面、换账户、换简历/会话停止动画与观察器。

仅在初始评论提示被主动点击时将这次点击交给演示，随后关闭即可使用正式入口。选区采用 Range 几何绘制独立覆盖层，不修改简历 DOM、原生 Selection 或打印源。文本从实际可见区域选择，避免联系方式；没有合适正文时仅提示先填写内容，不制造示例正文或滚动到不可见位置。

关闭与完成按浏览器中的账户及三种引导 ID 独立记录，游客使用单独标识；沿用 Zustand persist。仅持久化是否已看，不保存姓名、选区或评论。浏览器清理站点数据后可再次出现；本期不增加数据库迁移。

## 动效与响应式

提示淡入与轻微位移、标准箭头淡入、选区从左向右展开、指针移动、抽屉内容输入与发送由 GSAP timeline 编排；共享 Drawer 保留已有进入退出过渡。动作先后对应真实使用次序，步骤按钮在当前演示动画结束前显示实际状态并禁用，关闭始终可用。

每次卸载、换步或中断清理 timeline；减少动效在运行中开启时展示当前步骤最终态。覆盖 320/390 px、桌面、短屏和深浅色。提示用库定位并避让边界，手机可将说明放在目标上方；不添加全屏点击拦截层。

## 追加：螺旋箭头与连续退场

用户报告箭头切换闪现、浮层关闭后再次闪回，明确要求螺旋箭头与旋转绘制。本节覆盖此前只用 Lucide 小直箭头的形状约定，其他低打扰、非模态和仅主动结束规则继续保留。

已在正式 MotionProvider 下采样复现：GSAP 淡出后设置 Popover 关闭，GSAP 清理恢复样式，Radix 又播放默认 CSS 退出，透明度从约 0.09 回到 1。Radix Popper 定位完成时会覆盖传入的内联 animation，因此内联 `animation: none` 未真正禁用 CSS 动画。换步还会先更换内容再等待新目标，出现可见状态下的坐标跳跃；箭头的 revertOnUpdate 会先恢复隐藏状态再执行淡出。

沿用已安装的 Motion AnimatePresence 管理旧步骤保留与卸载，GSAP 单独控制浮层的进入和退出。退出时冻结旧锚点几何并禁用交互，完成后直接卸载，不再启动第二套退出。新步骤等待 Driver 确认目标，Popover 完成定位后再进入。快速反向从当前透明度接续，减少动效立即到达终态。

箭头为小尺寸细线单圈螺旋，沿真实入口方向放置；SVG 路径逐段显现，箭头尖按路径切线旋转前进，终点朝向入口，完成后不循环。既有图标不提供带绘制路径的螺旋箭头，复用现有定位和 GSAP，使用原生 SVG 路径几何，无新交互控件或依赖。绘制为一次性装饰，使用 slow + base 共 480 ms，提示按钮不等待绘制；浮层仍为 200 ms 进入、140 ms 退出，减少动效全部归零。

本轮验证须使用正式 MotionProvider；逐帧确认退出透明度不反弹、坐标不突跳、隐藏后不再次可见，并覆盖完整评论流程、助手画布、排序、两轮开关、绘制中关闭、退出中反向、桌面/手机/320 px、运行中减少动效。临时脚本放 tests 并在交付前删除；本轮不再次重置用户记录、不发布前端。

## 最新修正：浮窗连续移动与箭头实时跟随

用户明确要求步骤之间保留同一个浮窗，在页面上平滑移动，覆盖前文先退旧提示再进入新提示的方案。首次仍先画箭头再显示提示；之后只更新内容与目标，保持浮窗节点和透明度。使用现有 Popover 计算落点，内层卡片以 transform 从当前屏幕位置移动到新落点；目标仍在抽屉动画中时持续读取实际落点，减少动效直接到位。只有明确关闭或完成才淡出卸载。

折叠时箭头停在旧位置的原因是只依赖布局事件，没有持续追踪目标的动画位移。启用 Floating UI 的逐帧追踪，并监听定位外层的 transform；通过 SVG 的 transform 直接更新位置，避免每帧等待 React 重渲染。逐帧验证折叠、展开、反向切换和滚动，比较真实目标、浮窗与箭头的连接位置。返回首次提示须等待浮窗移动完成，不能连接尚未到位的旧卡片。

## 追加：首次箭头只绘制一次

用户继续反馈首次出现后又播放一次箭头。正式组件采样确认：原先 `arrowDrawn` 置为 true 时，浮窗尚未完成进入，`presentedIndex` 仍为空，导致箭头被隐藏并清零；浮窗完成后又触发第二次绘制。将首次绘制、绘制完成与离开首次步骤分成明确阶段，绘制完成只启动浮窗显示，保持箭头可见。返回第一步仍等待同一浮窗移动完成，再绘制一次；折叠和其他布局变化只更新位置。

回归必须从箭头开始绘制一直采样到浮窗进入结束之后，不能在看到首次提示时提前停止；记录路径进度不倒退、完成后透明度不降低，并验证与折叠跟随、前后移动、关闭及减少动效兼容。
