# 全项目代码分段与排版规范

## 目标与依据

按用户提供的第二张截图，将密集代码整理为清晰的逻辑段落，并将要求固化到 ESLint、格式化命令、编辑器保存动作和 AGENTS.md。保留现有语义、导入顺序、命名以及用户在 bindings.ts 中的暂存与工作区内容。

## 规则

- import 连续排列，与正文之间留一个空行。
- 函数、类、类型、接口和导出声明之间留一个空行。
- 变量声明组与条件判断、执行语句、最终 return/throw 之间留一个空行。
- 连续简短变量声明可成组；多行声明单独成段。
- 连续条件分支可以成组，尤其是截图中的连续短 guard；不同职责的判断由作者主动分段。
- 多行表达式、循环、switch、try 以及完成的代码块与相邻阶段分段。
- 每处分隔只留一个空行，不在函数开头、结尾或对象属性之间机械插空行。
- 80 列、两空格、单引号、无分号等细节继续由 Prettier 管理。

## 实现选择

Prettier 只能保留已有空行，不能识别逻辑段落。采用独立的 @stylistic/padding-line-between-statements 规则补充分段，不启用整套风格预设。格式化命令先运行 Prettier，再仅执行 ESLint 的 layout 修复，以便对折行后的多行声明正确分段；代码质量规则仍由 lint 单独负责。

src 下全部 JS/TS/JSX/TSX（含现有共享 UI 和 Tiptap 组件）接受空行与 Prettier 格式化；生成组件继续豁免历史代码质量规则。忽略依赖、构建产物、缓存、外部技能和锁文件。SQL 历史迁移不重写。

用户已确认范围为全部源码，包含 Supabase Edge Functions。五个函数及共享模块统一排版，开发验证完成后部署到当前 linked 项目，核对迁移账本、函数版本及线上响应。

## 验收

- 用户截图中的 resolveText 和 conditionMatches 呈现相同的分段原则。
- 规则能自动补足缺失空行，连续简短判断不被强制拆散；格式化重复执行无新增差异。
- 比较格式化前后源码的编译结果和语法结构，确保无行为修改；暂存区保持原状。
- 执行全量 lint、格式检查、TypeScript 检查、生产构建。
- 编辑器保存能够依次应用 ESLint layout 修复和 Prettier；检查真实 VS Code 输出。
- 临时验收脚本与快照仅存于 tests/code-layout，完成后删除。
