# GResume 产品优化路线图

日期：2026-10-25。主入口文档。当前授权：完成文档并实施第一期，验证后交用户审查。

**目标：** 让求职者顺畅完成真实经历整理、岗位定制、投递留档与面试跟进。

**规划依据：** [产品方向说明](../specs/2026-10-25-product-roadmap-design.md)、本轮产品评审、现有页面与实现。这里规划用户体验和交付范围；逐期实施计划在开工前细化。

## 1. 排期假设与优先级

- 按一条主开发线、约一名全栈开发者稳定投入估算，产品和设计按需配合；包含必要验证与修复。
- 周次为从实际开工起算的有效工作周，不是确定发布日期，不包含节假日、招募等待和不可控外部审批。AI 辅助可缩短工作时间，但不能省略验收。
- 总体基线为 24 周。每期拆成 1～2 周的可审查小批次；一期先交付，后续根据证据调整估时。
- P0：影响首次价值、功能承诺和交付可信度；P1：串联主流程、减少重复劳动；P2：提高持续使用价值；P3：仅在验证需求后扩展。
- 功能优先级不等于开发顺序。例如投递检查是 P0，但基础检查依赖二期取得真实正文；进阶排版检查在五期完成。
- 一期快速修正入口与信任问题；二、三期完成“旧简历导入 → 针对岗位修改 → 导出并留存实际投递版本”的核心路径。
- 所有复选框代表产品交付状态。文档完成不等于功能上线，用户尚未审查不标记“已审查”。

## 3. 一期：可信入口与首次使用体验

**交付结果：** 用户看到的入口能兑现承诺，知道当前可以做什么；首页不把空统计当成首次体验。

**范围：** 修正既有能力的呈现，不引入数据库迁移、新收费服务或外部采集服务。执行详见 [一期实施计划](2026-10-25-product-phase-one.md)。

- [x] **P1-01 不可用上传入口收口。** 移除选择文件、拖拽上传等无后续处理的动作；保留本地与云端简历选择，用简短说明表达暂不支持文件导入。验收：无静默丢文件，已有简历选择不受影响。
- [x] **P1-02 额度入口真实化。** 用“额度说明”替代未开放的升级按钮，展示当前账户可核实的额度和恢复时间；数据未知时明确表达。验收：无点击后重复提示“尚未开放”的假动作，不硬编码所有账户的限额。
- [x] **P1-03 评分表达降歧义。** “行业基准”改为“岗位内容参考”，说明预设参考值；关键词覆盖不称为画像置信度。验收：不暗示行业样本、招聘通过率或统计概率。
- [x] **P1-04 AI 事实边界。** “量化成果”调整为核实成果依据；STAR 与经历优化提示均要求保留真实职责，没有事实时先追问。验收：快捷提示不要求凭空补充数字，修改确认能力保留。
- [x] **P1-05 首页起步体验。** 未登录展示开始制作与本地保存说明、已有本地简历；确认无简历无岗位的登录用户展示起步引导。已有工作用户保留待办与统计，各模块独立加载。验收：加载失败不冒充空账户，账户切换不泄露旧内容。
- [x] **P1-06 持久规则与验收记录。** 将历史约束与按期审查方式写入 `AGENTS.md` 和防回归清单。验收：记录真实检查结果，用户审查状态独立。

**本期不做：** 文件解析、经历素材库、完整首页三阶段体系、投递快照、支付、模板新增、打印或共享弹窗动画重构。

## 4. 二期：带入真实经历并交付第一份简历

**交付结果：** 用户能导入自己的内容，核对后完成一份可编辑、可导出的简历。

**依赖：** 一期功能承诺规范；复用现有编辑器与导出能力。

- [ ] **P2-01 三种开始方式。** “我有旧简历”“从零整理经历”“我有目标岗位”。名称自动生成，说明字段后置；岗位入口在三期前复用现有定制入口，不创建假岗位档案。
- [ ] **P2-02 文本导入。** 支持粘贴内容，逐模块核对字段归属、时间、联系方式与原文；保留未识别段落，确认后写入新简历，不覆盖原稿。
- [ ] **P2-03 文件导入。** 首批支持可提取文本的 PDF 与 DOCX；大小和格式限制在选择前展示。损坏、加密、扫描文件及不支持的 DOC 给出明确原因和粘贴替代路径。扫描 OCR 与旧 DOC 转换不冒充已支持能力，按后续需求评估。
- [ ] **P2-04 分人群填写。** 区分应届生、有工作经验和转岗等起点，显示适合的引导。示例作为参考；复制示例时明确标记，离开前或导出前提示尚未替换的内容。
- [ ] **P2-05 基础投递检查。** 检查缺少联系方式、可确认的示例残留、待核实 AI 表述和明显空白内容；每项可定位、修改或说明忽略理由。无证据不武断判定内容虚假。
- [ ] **P2-06 新用户首页与成功反馈。** 首页显示继续核对、补充关键经历、检查并导出等下一步；完成后明确保存位置和下一次可以继续的动作。
- [ ] **P2-07 首次价值验证。** 邀请 5～8 位目标用户，用自己的旧简历无讲解操作；记录成功完成数、帮助次数、放弃点、耗时中位数。观察目标为多数人能在一次会话完成首份可用输出；具体时间目标用首轮基线校准。

**验收：** 导入结果经过本人核对；原文不静默丢失；中断可恢复；本地和云端状态明确；从真实导出入口获得可读文件。上传数据用途与保存方式应在输入前可见。

**不做：** 识别所有文档格式、扫描件无限兼容、自动编造缺失经历。

## 5. 三期：岗位工作流与实际投递留档

**交付结果：** 用户围绕一个岗位完成准备、定制、投递记录和跟进。

- [ ] **P3-01 岗位档案。** 保存 JD 原文、公司、职位、地点、来源和更新时间；提供手工修正。粘贴一次自动提取已有字段，取消让用户填写公司 Logo 的负担。
- [ ] **P3-02 串联已有能力。** 在岗位内进入相关经历、定制简历、优化、历史和跟进，并自动带入该岗位与对应简历。避免要求用户在每个页面重新选择。
- [ ] **P3-03 实际投递留档。** 用户明确记录“已投递”时固定本次简历内容、外观、JD、时间与渠道；后续编辑不覆盖。平台内导出和外部投递分清，导出不自动等同于投递成功；支持说明外部实际提交的文件。
- [ ] **P3-04 分享按用途选择。** “请人审阅”持续更新并支持评论；“正式投递”固定本次内容；“公开展示”持续更新并提供联系方式展示设置。保留现有 current/history 链接语义，不改变已发链接的内容契约。
- [ ] **P3-05 版本与导航使用求职语言。** “岗位定制”“投给某公司的版本”“审阅后版本”等替代不必要的派生术语。全局页面保留为汇总入口，岗位内完成主要动作。
- [ ] **P3-06 投递期首页。** 优先展示待完成材料、到期跟进、下一场面试入口；统计放在后面。现有“下一步安排”、联系人、轮次继续复用。

**验收：** 完成一个岗位的全过程无需重复粘贴 JD；能找回当时实际投递材料；修改母版、切换模板和继续编辑不改变固定版本；审阅链接仍按原约定更新。

**不做：** 自动发送、自动海投、把访问次数称为招聘方已读人数。

## 6. 四期：经历素材库与 AI 经历访谈

**交付结果：** 用户逐步积累经确认的事实，在不同岗位中复用，减少反复改写。

- [ ] **P4-01 经历素材库。** 保存职责边界、问题、行动、结果、时间、技能、交付物和可选证明材料。区分用户已确认事实、待确认提取与 AI 表达建议。
- [ ] **P4-02 引导式访谈。** 从一段真实经历开始，优先问最缺失的事实，一次少量问题；允许跳过。没有数字时接受交付、范围、影响与问题解决证据。
- [ ] **P4-03 岗位选材。** 解释为何推荐某段经历，允许选择、排序、隐藏与替换；定制版本保留与素材的来源关系，不自动覆盖已投递版本。
- [ ] **P4-04 AI 任务入口。** 提供“整理这段经历”“为该岗位选经历”“补足最关键的事实”等任务，保留自由对话、差异确认与撤销。
- [ ] **P4-05 可执行优化报告。** 首屏突出本次投递最重要的三个问题；显示原文、依据、修改理由、待补事实、建议表达。区分规则检测与 AI 判断，保留完整问题清单。
- [ ] **P4-06 结束条件。** 关键问题处理后给出“可进入投递检查”的明确下一步；未解决的事实问题保持可见，不引导用户无限追逐高分。

**验收：** 同一素材能用于两个岗位且事实一致；缺少数字时不会直接写入编造指标；用户能定位每处建议来源，并独立接受或撤销。

**不做：** 大型个人知识库、未经确认的事实自动入库、将模型自信度当作真实性证明。

## 7. 五期：模板决策与进阶交付检查

**交付结果：** 用户知道为什么选某个模板，并能预先发现交付问题。

- [ ] **P5-01 使用场景筛选。** 在现有风格、布局之外增加求职阶段、内容长度、展示用途等维度；避免无依据贴“保证 ATS 通过”标签。
- [ ] **P5-02 三个有解释的推荐。** 根据现有正文推荐有限选项，解释信息密度、阅读顺序与重点呈现；保留自主浏览所有模板。
- [ ] **P5-03 用户内容预览。** 用自己的正文比较模板，显示实际页数及拥挤提示；正文不足时明确说明示例预览，不把样例页数当作用户输出。
- [ ] **P5-04 进阶投递检查。** 延伸二期检查，覆盖空白页、孤立标题、异常跨页、被隐藏的关键信息和内容拥挤；不自动压缩字体来掩盖问题。
- [ ] **P5-05 导出与分享一致性。** 对检查后的具体版本执行导出，保持固定投递内容与对应展示一致；Word 的排版差异明确提示并可人工核对。

**验收：** 短内容、临界页底、多页内容和默认模板均从真实入口导出；分别验证打印背景开关。模板推荐不会改动事实或评论定位。

**不做：** 为增加数量批量新增模板、没有解释的万能推荐分数。

## 8. 六期：面试准备、日历与低负担采集

**交付结果：** 用户收到面试邀请后可直接准备，并减少重复维护求职记录的成本。

- [ ] **P6-01 岗位面试准备卡。** 基于已投递快照、JD 和确认过的素材，生成自我介绍结构、可能的追问、关键案例及待补事实；显示来源，避免使用投递后新增却未提交的经历冒充对方所见。
- [ ] **P6-02 面试后复盘。** 记录实际问题、回答缺口和下一步，选择性补回素材库；不自动改写原投递记录。
- [ ] **P6-03 面试期首页。** 优先展示下一场面试、准备卡和当时投递材料，减少无关统计。
- [ ] **P6-04 日历与提醒。** 首批提供可导入日历的面试和跟进事件，明确时区、时间变更和取消。外部通知在用户选择渠道后发送，防止重复提醒；无需授权也能继续使用站内待办。
- [ ] **P6-05 链接采集。** 在三期 JD 粘贴基础上，先支持可读取链接，失败保留粘贴路径；区分提取结果和用户确认内容，不承诺所有招聘站都可读取。
- [ ] **P6-06 浏览器采集试点。** 仅在观察到反复复制且目标站点明确时，选 1～2 个实际高频来源试点；没有收益证据时保留粘贴方案，不扩大适配面。

**验收：** 面试准备引用正确版本；改期取消后提醒一致；用户可修改或拒绝提取结果；采集失败不丢失手工录入。

**不做：** 全量招聘站适配、自动代投、先建设完整语音面试系统。

## 9. 七期：求职复盘与付费需求验证

**交付结果：** 用户能从自身记录调整求职方式，团队能验证用户愿意为哪种明确交付付费。

- [ ] **P7-01 有口径的复盘。** 按岗位方向、渠道、阶段和投递时间分组。明确分母、观察窗口、样本量、未知反馈与仍在流程中的岗位；阶段分布不称为转化率。
- [ ] **P7-02 行动建议。** 展示哪些方向值得继续、哪些材料需要回看，并链接具体岗位。样本不足时只提供事实记录；不能推断换模板或提分必然导致面试增加。
- [ ] **P7-03 弱化无用指标。** 平均 ATS 分、编辑活跃度和检测趋势不做首页核心成功指标；保留有明确使用价值的历史比较。
- [ ] **P7-04 付费需求验证。** 对比按次深度修改、短期求职包与订阅的理解和购买意向。先使用真实可交付服务验证，明确服务范围、额度和有效期，不虚构价格或已上线支付。
- [ ] **P7-05 商业化决策。** 记录选择及依据；只有服务交付、支付、退款和权益边界均明确后再单独安排收费上线。七期不默认包含完整支付系统。

**验收：** 用户能理解统计口径；样本不足有降级；收入实验与使用数据分开；保留失败案例，不只展示成功反馈。

## 11. 暂缓池与进入条件

暂缓不等于承诺会做；仅在下列证据成立后重新评估范围和排期。

| 方向                   | 暂缓原因                   | 重新评估条件                                     |
| ---------------------- | -------------------------- | ------------------------------------------------ |
| 大量新增模板           | 选择与交付问题尚未解决     | 高频真实内容无法由已有模板合适呈现               |
| 更多总分、雷达图、排名 | 容易增加解释负担           | 用户明确据此做出更好的修改决策                   |
| 泛化 AI 聊天功能       | 分散求职主线               | 某类高频求职任务无法由现有任务入口完成           |
| 完整招聘信息流         | 数据、时效和供给维护成本高 | 岗位收集成为主要瓶颈且有稳定来源                 |
| 自动海投               | 容易放大错误材料与误发     | 重新独立评估，必须有逐次外部发送授权             |
| 大型社区               | 需要持续内容和运营         | 审阅与互助需求形成稳定重复行为                   |
| 完整语音模拟面试       | 实时交互成本高             | 面试准备卡被持续使用且用户需要追问演练           |
| 顾问、学校协作版本     | 使用者和付费者不同         | 顾问或学校出现重复使用及明确服务需求，再单独立项 |
| 扫描 OCR、旧 DOC 转换  | 文档兼容范围易失控         | 统计实际导入失败类型，按收益决定支持范围         |

## 12. 指标、验收与审查方式

### 产品指标

- 首次价值：开始创建/导入到首次确认可用输出的耗时、完成数、放弃点与求助次数。
- 核心工作流：岗位定制完成、导出完成、用户确认投递和固定版本留档分别记录，不相互替代。
- 使用价值：面试准备卡实际打开、跟进行动完成、素材跨岗位复用；仅计算具备对应场景的用户。
- 质量：导入纠正比例、导出失败、事实修改撤销、错误版本反馈；按失败类型记录。
- 研究记录只保留完成任务所需信息；不将简历正文、联系方式和 JD 全文送入普通行为埋点。
- 先建立基线，再确定改善目标。求职成功受多种因素影响，不把一次分数上涨当成面试效果证明。

### 每期交付流程

1. 核对该期依赖和现有能力，阅读 `AGENTS.md`、防回归清单及涉及模块的历史复盘。
2. 将该期规格与实施计划保存到仓库规定目录，明确可观察验收场景。用户已明确授权的范围直接实施；关键事实不明先查现有资料，无法自行确定时再提出具体问题。
3. 在当前分支工作，保留他人修改；每个小批次形成可体验结果。
4. 完成格式、必要检查、浏览器和相关产品流程验收。涉及 Supabase 时完成规定的云端部署和线上核验。
5. 报告实际完成项、证据、已知限制和审查入口，用户最后审查；用户反馈修复并复验后再标记该期审查通过。
6. 没有授权不推送远端，不因为本期结束自动启动下一期。后续沿用本流程。

### 发布门槛

- 关键流程无静默失败、误写、错账户内容或错误外发版本。
- 动效、减少动效、弹窗往返、窄屏、空态、错误态和独立加载符合既有约束。
- 修改打印或分页时必须走真实 PDF 验收；类型检查不能替代体验验收。
- 不满足门槛时先修复，压缩次要范围，不用降低正确性要求换取按时完成。
